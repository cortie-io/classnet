리눅스는 여러 사람이 한 서버를 함께 쓰는 다중 사용자 운영체제라서, "누가 어떤 파일에 무엇을 할 수 있는지"를 정하는 권한이 아주 중요해요. 이 단원에서는 rwx 권한을 기호와 8진수로 읽고 바꾸는 방법, 새 파일의 기본 권한을 정하는 umask, 특별한 동작을 하는 특수 권한, 그리고 사용자와 그룹을 만들고 관리하는 방법을 배워요. 8진수 변환과 umask 계산은 시험에 거의 빠지지 않으니 예제를 손으로 꼭 풀어 보세요.

> [!GOAL]
> - 파일과 디렉터리에서 r·w·x가 각각 무엇을 허락하는지 설명할 수 있다.
> - 기호 권한과 8진수 권한을 서로 바꾸고, `chmod`·`chown`·`umask`를 쓸 수 있다.
> - SetUID·SetGID·Sticky Bit의 역할과 `ls` 표시(s, S, t, T)를 구분할 수 있다.
> - `/etc/passwd`·`/etc/shadow`·`/etc/group`의 구조를 읽고 사용자·그룹 관리 명령을 쓸 수 있다.

## 권한의 기본

### 세 부류의 사용자

리눅스는 파일마다 사용자를 세 부류로 나누어 권한을 따로 줘요.

| 부류 | 기호 | 뜻 |
|---|---|---|
| 소유자(User) | `u` | 파일을 소유한 사용자 |
| 그룹(Group) | `g` | 파일의 소유 그룹에 속한 사용자 |
| 기타 사용자(Others) | `o` | 그 밖의 모든 사용자 |
| 모두(All) | `a` | 위 셋 전부 |

`ls -l`에서 파일 종류 뒤의 9글자가 바로 이 세 부류의 권한이에요.

```text
 -     rwx     r-x     ---
종류  소유자   그룹    기타
```

### r, w, x의 의미

같은 글자라도 파일과 디렉터리에서 뜻이 조금 달라요.

| 권한 | 파일에서 | 디렉터리에서 |
|---|---|---|
| `r` 읽기(Read) | 파일 내용을 읽을 수 있음 | 안에 있는 파일 **이름 목록**을 볼 수 있음(`ls`) |
| `w` 쓰기(Write) | 파일 내용을 수정할 수 있음 | 안에서 파일을 **만들고, 지우고, 이름을 바꿀** 수 있음 |
| `x` 실행(Execute) | 프로그램·스크립트로 실행할 수 있음 | 디렉터리 **안으로 들어가고**(`cd`) 안의 파일에 접근할 수 있음 |

> [!WARNING]
> 파일을 지울 수 있는지는 파일 자신의 권한이 아니라 **그 파일이 들어 있는 디렉터리의 w(그리고 x) 권한**으로 정해져요. 파일이 `r--`이어도 디렉터리에 쓰기 권한이 있으면 지울 수 있어요. 또 디렉터리에 `x`가 없으면 `r`이 있어도 안의 파일을 제대로 열 수 없어요. 관리자 root는 이런 권한 검사를 대부분 건너뛰어요.

## 기호 표기와 8진수 표기

권한은 글자 대신 숫자로도 나타낼 수 있어요. 각 권한에 값을 정해 두고 더하는 방식이에요.

| 권한 | r | w | x | - |
|---|---|---|---|---|
| 값 | 4 | 2 | 1 | 0 |

세 글자씩 끊어서 값을 더하면 0~7 사이의 숫자 하나가 나와요. 그래서 이것을 **8진수 표기**라고 해요.

### 기호 → 숫자

`rwxr-x---`를 바꿔 볼게요.

```text
rwx   r-x   ---
4+2+1 4+0+1 0+0+0
  7     5     0     → 750
```

| 기호 | 계산 | 숫자 |
|---|---|---|
| `rw-r--r--` | 6 / 4 / 4 | 644 |
| `rwxr-xr-x` | 7 / 5 / 5 | 755 |
| `rw-------` | 6 / 0 / 0 | 600 |
| `rwxrwx---` | 7 / 7 / 0 | 770 |

### 숫자 → 기호

숫자 하나를 4, 2, 1의 합으로 쪼개면 돼요. 예를 들어 640은 이렇게 풀어요.

```text
6 = 4+2   → rw-
4 = 4     → r--
0         → ---      → rw-r-----
```

`711`은 `7 = rwx`, `1 = --x`, `1 = --x`라서 `rwx--x--x`예요.

> [!TIP]
> 자주 나오는 숫자만 외워 두면 계산이 빨라져요. **7 = rwx, 6 = rw-, 5 = r-x, 4 = r--, 0 = ---**.

## chmod — 권한 바꾸기

`chmod`(change mode)는 두 가지 방식으로 쓸 수 있어요.

**8진수 방식**은 세 부류의 권한을 한 번에 정해요.

```bash
chmod 755 deploy.sh       # rwxr-xr-x
chmod 600 secret.key      # rw-------
chmod -R 750 /srv/team    # 디렉터리 안의 모든 파일까지(recursive)
```

**기호 방식**은 `누구` `연산` `권한` 순서로 써서 일부만 바꿔요.

| 연산 | 뜻 | 예 | 결과 |
|---|---|---|---|
| `+` | 권한 추가 | `chmod u+x run.sh` | 소유자에게 실행 권한 추가 |
| `-` | 권한 제거 | `chmod go-w data.txt` | 그룹·기타에게서 쓰기 권한 제거 |
| `=` | 정확히 그 권한으로 설정 | `chmod o=r note.txt` | 기타 사용자는 읽기만 |
| 쉼표 | 여러 개 한 번에 | `chmod u=rwx,g=rx,o= app` | `rwxr-x---`(750) |

### 단계별 예제

현재 `report.txt`의 권한이 `644`일 때 `chmod g+w,o-r report.txt`를 실행하면?

```text
시작        rw- r-- r--   (644)
g+w         rw- rw- r--
o-r         rw- rw- ---   (660)
```

## chown, chgrp — 소유자와 그룹 바꾸기

```bash
chown jiwoo report.txt              # 소유자를 jiwoo로
chown jiwoo:sales report.txt        # 소유자와 그룹을 함께
chown :sales report.txt             # 그룹만
chown -R jiwoo:sales /srv/sales     # 하위까지 모두
chgrp sales report.txt              # 그룹만 바꾸는 전용 명령
```

> [!NOTE]
> 파일의 소유자를 다른 사람으로 바꾸는 것은 root만 할 수 있어요. 일반 사용자는 자기 파일의 그룹을 **자신이 속한 그룹**으로 바꾸는 정도만 가능해요.

## umask — 새 파일의 기본 권한

### 원리

새 파일이나 디렉터리를 만들 때마다 권한을 일일이 정하면 번거롭겠죠. 리눅스는 출발점이 되는 최대 권한에서 **umask**(사용자 마스크)에 적힌 권한을 빼서 기본 권한을 정해요.

| 대상 | 출발점 | 이유 |
|---|---|---|
| 파일 | 666 (`rw-rw-rw-`) | 보안을 위해 처음부터 실행 권한은 주지 않아요 |
| 디렉터리 | 777 (`rwxrwxrwx`) | 디렉터리는 x가 있어야 들어갈 수 있어서 포함해요 |

### 계산 예제

| umask | 파일 (666에서) | 디렉터리 (777에서) |
|---|---|---|
| 022 | 644 `rw-r--r--` | 755 `rwxr-xr-x` |
| 002 | 664 `rw-rw-r--` | 775 `rwxrwxr-x` |
| 027 | 640 `rw-r-----` | 750 `rwxr-x---` |
| 077 | 600 `rw-------` | 700 `rwx------` |

umask 027일 때 디렉터리를 자리별로 풀어 보면 이래요.

```text
디렉터리   7 7 7
umask    - 0 2 7
결과       7 5 0   → rwxr-x---
```

> [!WARNING]
> umask는 정확히는 "빼기"가 아니라 "umask에 있는 권한 비트를 끄는 것"이에요. 대부분은 빼기와 결과가 같지만, 파일에서 umask 자리에 홀수(x 비트)가 있으면 달라요. 예를 들어 umask 033이면 파일은 666-033=633이 아니라, 원래 없던 x는 끌 것이 없으니 **644**가 돼요. 자리마다 "출발점에 있는 권한 중 umask에 있는 것만 지운다"고 생각하면 틀리지 않아요.

### 확인과 설정

```bash
umask           # 현재 값 확인 (예: 0022)
umask -S        # 기호로 보기 (u=rwx,g=rx,o=rx)
umask 027       # 현재 셸에서만 바꾸기
```

맨 앞의 0은 다음에 배울 특수 권한 자리예요. 기본값은 배포판과 사용자에 따라 0022나 0002가 흔해요. 로그인할 때마다 적용하려면 `~/.bashrc`나 `/etc/profile` 같은 셸 설정 파일에 적어 둬요([vi 편집기와 셸](/textbook/nos-vi-shell) 참고).

## 특수 권한

rwx 외에 특별한 동작을 하는 권한 세 가지가 있어요. 8진수로는 일반 권한 세 자리 **앞에** 한 자리를 더 붙여 표시해요.

| 특수 권한 | 값 | 주로 거는 곳 | 효과 | `ls` 표시 위치 |
|---|---|---|---|---|
| SetUID | 4 | 실행 파일 | 실행하는 동안 **파일 소유자의 권한**으로 동작 | 소유자 x 자리에 `s` |
| SetGID | 2 | 실행 파일, 디렉터리 | 실행 파일: **파일 그룹의 권한**으로 동작. 디렉터리: 안에서 만든 파일이 **디렉터리의 그룹을 물려받음** | 그룹 x 자리에 `s` |
| Sticky Bit | 1 | 디렉터리 | 누구나 파일을 만들 수 있지만, **자기 파일만 지우거나 이름을 바꿀** 수 있음 | 기타 x 자리에 `t` |

### 대표 예

```text
-rwsr-xr-x 1 root root ... /usr/bin/passwd    (4755)
drwxrwxrwt 9 root root ... /tmp               (1777)
```

- **`/usr/bin/passwd`** — 비밀번호는 root만 고칠 수 있는 `/etc/shadow`에 저장돼요. 그런데 일반 사용자도 자기 비밀번호를 바꿀 수 있어야 하죠. 그래서 `passwd` 프로그램에는 SetUID가 걸려 있어, 누가 실행하든 실행하는 동안에는 소유자인 root의 권한으로 동작해요.
- **`/tmp`** — 모든 사용자가 임시 파일을 만들어야 하니 `rwxrwxrwx`가 필요하지만, 그대로 두면 남의 파일까지 지울 수 있어요. Sticky Bit가 이를 막아, 파일은 그 소유자(그리고 디렉터리 소유자와 root)만 지울 수 있어요.
- **SetGID 디렉터리** — 팀 공유 폴더 `/srv/team`에 `chmod 2770`을 걸면, 누가 파일을 만들든 그룹이 폴더의 그룹으로 정해져 팀원끼리 함께 쓰기 편해요.

### 소문자와 대문자

| 표시 | 뜻 |
|---|---|
| `s` / `t` (소문자) | 특수 권한**과** 실행 권한 x가 함께 있음 |
| `S` / `T` (대문자) | 특수 권한은 있지만 그 자리의 **x가 없음** |

예를 들어 `chmod 4644 file`을 하면 소유자에게 x가 없으므로 `-rwSr--r--`로 보여요. 실행할 수 없는 파일의 SetUID는 의미가 없으니, 대문자가 보이면 설정이 잘못된 경우가 많아요.

### 설정 방법

```bash
chmod 4755 /usr/local/bin/tool    # SetUID   → -rwsr-xr-x
chmod u+s  /usr/local/bin/tool    # 같은 효과(기호 방식)
chmod 2770 /srv/team              # SetGID   → drwxrws---
chmod g+s  /srv/team
chmod 1777 /srv/upload            # Sticky   → drwxrwxrwt
chmod o+t  /srv/upload
```

> [!EXAM]
> 숫자 네 자리 권한을 기호로 바꾸는 문제가 자주 나와요. 맨 앞 자리가 4면 소유자 x 자리를 `s`로, 2면 그룹 x 자리를 `s`로, 1이면 기타 x 자리를 `t`로 바꾸면 돼요(그 자리에 x가 없었다면 대문자 `S`·`T`). 예: `2755` → `rwxr-sr-x`, `1777` → `rwxrwxrwt`, `4744` → `rwsr--r--`. SetUID 파일은 공격에 악용될 수 있어서 `find / -perm -4000`으로 정기 점검해요([리눅스 파일 다루기](/textbook/nos-linux-files-commands) 참고).

## 사용자와 그룹 정보 파일

### /etc/passwd — 계정 정보

모든 계정의 기본 정보가 한 줄에 하나씩, **콜론(:)으로 구분된 7개 필드**로 들어 있어요. 누구나 읽을 수 있는 파일(644)이에요.

```text
minsu:x:1001:1001:Kim Minsu:/home/minsu:/bin/bash
```

| 순서 | 값 | 필드 |
|---|---|---|
| 1 | `minsu` | 사용자 이름(로그인 이름) |
| 2 | `x` | 비밀번호 자리. `x`는 "실제 암호는 `/etc/shadow`에 있다"는 뜻 |
| 3 | `1001` | UID(사용자 번호) |
| 4 | `1001` | GID(기본 그룹 번호) |
| 5 | `Kim Minsu` | 설명(GECOS). 이름, 연락처 같은 메모 |
| 6 | `/home/minsu` | 홈 디렉터리 |
| 7 | `/bin/bash` | 로그인 셸 |

- UID 0은 root예요. 이름이 무엇이든 UID가 0이면 관리자 권한을 가져요.
- 서비스용 시스템 계정은 낮은 번호, 일반 사용자는 요즘 배포판에서 보통 **1000번부터** 받아요(예전 레드햇 계열은 500번부터였어요).
- 로그인 셸이 `/sbin/nologin`이나 `/bin/false`인 계정은 로그인할 수 없어요. 서비스 전용 계정에 써요.

### /etc/shadow — 암호와 암호 정책

암호화된(해시된) 비밀번호와 비밀번호 사용 기간이 들어 있어요. root만 읽을 수 있도록 권한이 아주 제한되어 있어요. 콜론으로 구분된 9개 필드예요.

```text
minsu:$6$Xk3...생략...:19800:0:90:7:14::
```

| 순서 | 필드 | 예의 값 |
|---|---|---|
| 1 | 사용자 이름 | `minsu` |
| 2 | 암호화된 비밀번호. 앞부분 `$6$`은 SHA-512 방식이라는 표시. `!`로 시작하거나 `*`이면 비밀번호로 로그인할 수 없는(잠긴) 계정 | `$6$...` |
| 3 | 마지막 변경일(1970년 1월 1일부터 센 날짜 수) | `19800` |
| 4 | 최소 사용 기간: 바꾼 뒤 며칠이 지나야 다시 바꿀 수 있나 | `0` |
| 5 | 최대 사용 기간: 며칠마다 바꿔야 하나 | `90` |
| 6 | 경고 기간: 만료 며칠 전부터 경고하나 | `7` |
| 7 | 비활성 기간: 만료 후 며칠 지나면 계정을 잠그나 | `14` |
| 8 | 계정 만료일 | (비어 있음) |
| 9 | 예약 | (비어 있음) |

비밀번호 기간 정책은 `chage -l minsu`로 확인하고, `chage -M 90 minsu`처럼 바꿀 수 있어요.

> [!EXAM]
> `/etc/passwd`는 7개, `/etc/shadow`는 9개 필드예요. 예전에는 `/etc/passwd`의 두 번째 필드에 암호가 들어 있었지만, 누구나 읽을 수 있는 파일이라 위험해서 root만 읽는 `/etc/shadow`로 옮겼다는 흐름을 이해해 두세요.

### /etc/group — 그룹 정보

```text
sales:x:1002:minsu,jiwoo
```

**그룹 이름 : 비밀번호 자리 : GID : 보조 멤버 목록**의 4개 필드예요. 그룹 암호는 `/etc/gshadow`에 따로 있어요.

사용자는 **기본 그룹(Primary Group)** 하나(`/etc/passwd`의 4번째 필드)와, 추가로 여러 **보조 그룹**(Secondary Group)에 속할 수 있어요. 보조 그룹 소속은 `/etc/group`의 마지막 필드에 적혀요.

## 사용자·그룹 관리 명령

### useradd — 계정 만들기

| 옵션 | 뜻 |
|---|---|
| `-m` | 홈 디렉터리 만들기 |
| `-d 경로` | 홈 디렉터리 경로 지정 |
| `-s 셸` | 로그인 셸 지정 |
| `-g 그룹` | 기본 그룹 지정 |
| `-G 그룹1,그룹2` | 보조 그룹 지정 |
| `-u 번호` | UID 지정 |
| `-c "설명"` | 설명 필드 |
| `-e 날짜` | 계정 만료일 |

```bash
useradd -m -d /home/jiwoo -s /bin/bash -g sales -G dev,wheel -u 1500 jiwoo
passwd jiwoo           # 비밀번호 설정 (계정을 만든 뒤 꼭)
```

새 홈 디렉터리에는 `/etc/skel`에 있는 기본 파일(`.bashrc` 등)이 복사돼요. `useradd`의 기본값은 `/etc/default/useradd`와 `/etc/login.defs`에 있어요. 데비안 계열에는 질문에 답하며 계정을 만드는 `adduser` 명령도 있어요.

### 그 밖의 명령

| 명령 | 하는 일 |
|---|---|
| `passwd` | 내 비밀번호 바꾸기 |
| `passwd jiwoo` | (root가) jiwoo의 비밀번호 설정 |
| `passwd -l jiwoo` / `-u` | 계정 비밀번호 잠금 / 해제 |
| `usermod -s /bin/zsh jiwoo` | 로그인 셸 변경 |
| `usermod -aG docker jiwoo` | 보조 그룹 **추가**(기존 보조 그룹 유지) |
| `usermod -L jiwoo` / `-U` | 계정 잠금 / 해제 |
| `userdel jiwoo` | 계정만 삭제(홈 디렉터리는 남음) |
| `userdel -r jiwoo` | 계정과 **홈 디렉터리·메일함까지** 삭제 |
| `groupadd -g 2000 dev` | GID 2000으로 그룹 만들기 |
| `groupdel dev` | 그룹 삭제 |
| `id jiwoo` | UID, GID, 소속 그룹 확인 |
| `groups jiwoo` | 소속 그룹 이름만 |

```text
$ id jiwoo
uid=1500(jiwoo) gid=1002(sales) groups=1002(sales),1003(dev),10(wheel)
```

> [!WARNING]
> `usermod -G dev jiwoo`처럼 `-a` 없이 `-G`를 쓰면 기존 보조 그룹이 모두 사라지고 dev만 남아요. 그룹을 **더하려면** 반드시 `-aG`를 쓰세요.

## su와 sudo — 관리자 권한 얻기

평소에는 일반 계정으로 일하다가 관리 작업이 필요할 때만 관리자 권한을 쓰는 것이 안전해요.

| 구분 | `su` | `sudo` |
|---|---|---|
| 뜻 | 다른 사용자로 **전환**(Switch User) | 허가된 명령 하나를 다른 사용자(보통 root) 권한으로 실행 |
| 입력하는 비밀번호 | **대상 사용자**(root)의 비밀번호 | **내** 비밀번호 |
| 범위 | 전환한 셸에서 `exit` 할 때까지 전부 | 명령 하나(잠시 동안 비밀번호 기억) |
| 기록 | 누가 무엇을 했는지 남기 어려움 | 실행한 명령이 로그에 남음 |

```bash
su -              # root로 전환하고 root의 로그인 환경(홈, 환경 변수)까지 적용
su                # root로 전환하되 지금 환경을 대부분 유지
su - jiwoo        # jiwoo로 전환
sudo dnf install httpd     # 이 명령만 root 권한으로
sudo -i                    # root 셸 얻기
```

`su`와 `su -`의 차이는 하이픈 하나지만, `-`가 있어야 root가 로그인한 것처럼 환경이 바뀌어요.

### /etc/sudoers와 visudo

누가 `sudo`를 쓸 수 있는지는 `/etc/sudoers`에 적어요. 이 파일은 문법이 틀리면 아무도 `sudo`를 못 쓰게 될 수 있어서, 반드시 **`visudo`** 명령으로 편집해요. `visudo`는 저장할 때 문법을 검사하고, 여러 사람이 동시에 고치지 못하게 잠가 줘요.

```text
# 사용자  호스트=(실행할 사용자)  명령
root      ALL=(ALL)       ALL
%wheel    ALL=(ALL)       ALL
jiwoo     ALL=(ALL)       /usr/bin/systemctl restart httpd
```

- `%`로 시작하면 그룹이에요. 레드햇 계열은 **wheel** 그룹, 우분투는 **sudo** 그룹에 넣으면 관리자 명령을 쓸 수 있도록 미리 설정되어 있어요.
- 세 번째 줄은 jiwoo에게 웹 서버 재시작 명령 하나만 허락하는 예예요.

## 핵심 정리

- r(4)·w(2)·x(1)을 더해 소유자·그룹·기타 순서로 적은 것이 8진수 권한: `rwxr-x---` = 750, `rw-r--r--` = 644.
- 디렉터리에서 r은 목록 보기, w는 파일 생성·삭제, x는 들어가기.
- `chmod 755 파일` 또는 `chmod u+x,go-w 파일`, `chown 사용자:그룹 파일`, `chgrp 그룹 파일`.
- umask: 파일은 666, 디렉터리는 777에서 umask 권한을 뺌. 022 → 644/755, 027 → 640/750, 077 → 600/700.
- SetUID(4) 소유자 권한으로 실행(`/usr/bin/passwd`), SetGID(2) 그룹 권한·그룹 상속, Sticky(1) 자기 파일만 삭제(`/tmp`, 1777).
- `s`/`t`는 x 있음, `S`/`T`는 x 없음.
- `/etc/passwd` 7필드(이름:x:UID:GID:설명:홈:셸), `/etc/shadow` 9필드(암호와 기간 정책, root만 읽기), `/etc/group` 4필드.
- `useradd -m -d -s -g -G -u`, `usermod -aG`, `userdel -r`(홈까지 삭제), `id`로 확인.
- `su -`는 대상 사용자 비밀번호로 전환, `sudo`는 내 비밀번호로 명령 실행, `/etc/sudoers`는 `visudo`로 편집.

## 스스로 확인하기

**1.** 파일 권한 `rwxr-----`를 8진수로 바르게 나타낸 것은?
① 740 ② 750 ③ 744 ④ 640

> [!ANSWER]
> 정답: ①
> rwx = 4+2+1 = 7, r-- = 4, --- = 0이므로 740이에요.

**2.** umask가 027인 사용자가 새 파일과 새 디렉터리를 만들었을 때의 기본 권한을 순서대로 고르면?
① 750, 640 ② 640, 750 ③ 751, 750 ④ 644, 755

> [!ANSWER]
> 정답: ②
> 파일은 666에서 027을 빼 640(`rw-r-----`), 디렉터리는 777에서 빼 750(`rwxr-x---`)이에요.

**3.** `ls -l`로 본 공유 업로드 디렉터리의 권한이 `drwxrwxrwt`였어요. 이 디렉터리에 대한 설명으로 옳은 것은?
① SetUID가 설정되어 소유자 권한으로 실행된다 ② 안에서 만든 파일이 디렉터리의 그룹을 물려받는다 ③ 누구나 파일을 만들 수 있지만 다른 사람의 파일은 지울 수 없다 ④ 기타 사용자는 이 디렉터리에 들어갈 수 없다

> [!ANSWER]
> 정답: ③
> 기타 사용자 x 자리의 `t`는 Sticky Bit예요(8진수 1777). 소문자 t이므로 기타 사용자에게 x 권한도 있어서 들어갈 수 있어요.

**4.** `/etc/passwd`의 한 줄 `backup:x:1205:1300::/srv/backup:/sbin/nologin`에 대한 설명으로 옳지 않은 것은?
① 사용자 이름은 backup이다 ② UID는 1205이다 ③ 실제 암호화된 비밀번호는 `/etc/shadow`에 있다 ④ 이 계정은 bash 셸로 로그인할 수 있다

> [!ANSWER]
> 정답: ④
> 일곱 번째 필드가 `/sbin/nologin`이라 대화형 로그인이 막혀 있어요. 다섯 번째 설명 필드는 비어 있고, 네 번째 1300이 기본 그룹 GID예요.

**5.** 사용자 jiwoo를 계정과 함께 홈 디렉터리까지 지우는 명령은?
① `userdel jiwoo` ② `userdel -r jiwoo` ③ `usermod -L jiwoo` ④ `passwd -d jiwoo`

> [!ANSWER]
> 정답: ②
> `-r` 옵션을 붙여야 홈 디렉터리와 메일함까지 삭제돼요. `usermod -L`은 잠금, `passwd -d`는 비밀번호 삭제예요.
