지금까지는 데이터를 실어 나르는 아래 계층을 배웠다면, 이번에는 사용자가 실제로 쓰는 서비스를 만드는 응용 계층 프로토콜을 살펴봐요. 웹을 보는 HTTP, 파일을 옮기는 FTP와 TFTP, 메일을 주고받는 SMTP·POP3·IMAP, 원격 접속용 Telnet과 SSH, 장비를 관리하는 SNMP, 시간을 맞추는 NTP, 디렉터리를 조회하는 LDAP까지 다뤄요. 포트 번호는 [UDP와 포트 번호](/textbook/tcpip-udp-ports)에서 외웠으니, 여기서는 각 프로토콜이 **어떻게 동작하고 무엇이 다른지**에 집중해요.

> [!GOAL]
> - HTTP의 요청·응답 구조, 주요 메서드와 상태 코드, HTTPS의 의미를 설명할 수 있다.
> - FTP의 능동·수동 모드와 TFTP와의 차이를 구분할 수 있다.
> - SMTP·POP3·IMAP의 역할과 MIME이 필요한 이유를 말할 수 있다.
> - Telnet과 SSH, SNMP의 구성 요소와 버전, NTP와 LDAP의 쓰임을 안다.

## HTTP — 웹의 언어

### 요청과 응답

HTTP(HyperText Transfer Protocol)는 웹 브라우저(클라이언트)가 **요청**(Request)을 보내면 웹 서버가 **응답**(Response)을 돌려주는 방식으로 동작해요. TCP **80번** 포트를 써요.

웹 주소인 URL(Uniform Resource Locator)은 다음처럼 나뉘어요.

```text
https://www.example.com:443/notice/list?page=2#top
```

| 부분 | 예 | 뜻 |
|---|---|---|
| 스킴(Scheme) | `https` | 사용할 프로토콜 |
| 호스트(Host) | `www.example.com` | 서버의 도메인 이름 또는 IP 주소 |
| 포트(Port) | `443` | 생략하면 기본 포트(http는 80, https는 443) |
| 경로(Path) | `/notice/list` | 서버 안에서 자료의 위치 |
| 쿼리(Query) | `page=2` | 서버에 넘기는 값 |
| 조각(Fragment) | `top` | 페이지 안의 특정 위치. 서버로는 보내지 않아요 |

HTTP 메시지는 **시작 줄, 헤더, 빈 줄, 본문** 순서로 이루어진 텍스트예요.

```text
GET /notice/list?page=2 HTTP/1.1
Host: www.example.com
Accept: text/html

```

```text
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Content-Length: 5120

(HTML 문서 내용)
```

요청의 첫 줄은 "메서드, 경로, 버전", 응답의 첫 줄은 "버전, 상태 코드, 설명"이에요.

### 무상태와 쿠키

HTTP는 **무상태(Stateless)** 프로토콜이에요. 서버는 요청 하나하나를 독립적으로 처리하고, 앞선 요청을 기억하지 않아요. 그런데 로그인이나 장바구니는 "아까 그 사람"을 기억해야 하죠. 그래서 서버가 응답 헤더 `Set-Cookie`로 작은 정보(쿠키, Cookie)를 주면, 브라우저가 다음 요청부터 `Cookie` 헤더에 담아 돌려보내요. 흔히 쿠키에는 세션 ID만 넣고, 실제 사용자 정보는 서버 쪽 세션(Session)에 보관해요.

### 메서드

| 메서드 | 하는 일 |
|---|---|
| GET | 자료를 요청(조회). 보낼 값은 URL 뒤 쿼리 문자열에 붙여요 |
| POST | 서버에 데이터를 보내 처리를 요청(글쓰기, 로그인 등). 데이터는 본문에 담아요 |
| PUT | 지정한 위치의 자료를 통째로 저장하거나 교체 |
| PATCH | 자료의 일부만 수정 |
| DELETE | 자료 삭제 |
| HEAD | GET과 같지만 본문 없이 헤더만 받음 |
| OPTIONS | 서버가 지원하는 메서드 확인 |
| TRACE | 요청이 서버까지 어떻게 전달됐는지 되돌려 받아 확인. 보안상 보통 막아 둬요 |
| CONNECT | 프록시 서버에 터널 연결을 요청(HTTPS를 프록시로 보낼 때) |

> [!WARNING]
> GET은 값이 주소창에 그대로 보이고 POST는 본문에 들어가지만, **POST라고 암호화되는 것은 아니에요.** HTTP는 둘 다 평문이고, 내용을 보호하려면 HTTPS를 써야 해요.

### 상태 코드

상태 코드는 세 자리 숫자이고, **첫 자리**가 큰 분류예요.

| 분류 | 뜻 | 대표 코드 |
|---|---|---|
| 1xx | 정보: 요청을 받았고 처리 중 | 100 Continue |
| 2xx | 성공 | 200 OK, 201 Created, 204 No Content |
| 3xx | 리다이렉션: 다른 곳을 보거나 추가 동작 필요 | 301 Moved Permanently, 302 Found, 304 Not Modified |
| 4xx | 클라이언트 오류: 요청에 문제가 있음 | 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found |
| 5xx | 서버 오류: 서버가 요청을 처리하지 못함 | 500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable, 504 Gateway Timeout |

| 코드 | 상황 |
|---|---|
| 200 | 정상 처리 |
| 301 | 주소가 영구히 바뀜(새 주소로 안내) |
| 302 | 잠시 다른 주소로 안내 |
| 304 | 바뀐 것이 없으니 브라우저 캐시에 있는 것을 쓰세요 |
| 401 | 인증이 필요함("누구세요?") |
| 403 | 누군지는 알지만 접근 권한이 없음("들어오시면 안 돼요") |
| 404 | 요청한 자료가 없음 |
| 500 | 서버 프로그램 내부 오류 |
| 503 | 서버가 과부하·점검 중이라 지금은 처리 불가 |

### HTTP의 발전과 HTTPS

- **HTTP/1.0**: 요청마다 TCP 연결을 새로 맺었어요.
- **HTTP/1.1**: 한 연결로 여러 요청을 처리하는 지속 연결(Keep-Alive)이 기본이 되고, `Host` 헤더가 필수가 되어 한 서버에서 여러 사이트를 운영할 수 있게 됐어요.
- **HTTP/2**: 메시지를 바이너리로 바꾸고, 한 연결 안에서 여러 요청·응답을 동시에 주고받는(멀티플렉싱) 방식으로 빨라졌어요.
- **HTTP/3**: TCP 대신 UDP 기반의 QUIC 위에서 동작해요.

**HTTPS**는 HTTP를 **TLS**(SSL의 후속 규격)로 감싼 것이고, TCP **443번** 포트를 써요. TLS가 주는 것은 세 가지예요.

- **기밀성**: 내용을 암호화해서 중간에서 엿봐도 읽을 수 없어요.
- **무결성**: 중간에 바뀌면 알아챌 수 있어요.
- **서버 인증**: 인증 기관(CA)이 발급한 인증서로 "진짜 그 사이트"인지 확인해요.

TLS와 인증서의 동작은 [네트워크 보안 기초](/textbook/tcpip-security-protocols)에서 더 배워요.

## FTP와 TFTP — 파일 전송

### FTP의 두 연결

FTP(File Transfer Protocol)는 TCP를 쓰고, **연결 두 개**를 따로 사용하는 것이 특징이에요.

- **제어 연결(Control Connection), 포트 21**: 로그인, 디렉터리 이동 같은 명령과 응답이 오가요. 세션 동안 계속 유지돼요.
- **데이터 연결(Data Connection)**: 파일 내용이나 파일 목록이 실제로 오가요. 전송할 때마다 열고 닫아요. 능동 모드에서는 서버가 **포트 20**을 써요.

### 능동 모드와 수동 모드

데이터 연결을 **누가 먼저 여느냐**에 따라 두 모드로 나뉘어요.

| 구분 | 능동 모드(Active) | 수동 모드(Passive) |
|---|---|---|
| 제어 연결 | 클라이언트 → 서버 21 | 클라이언트 → 서버 21 |
| 사용 명령 | `PORT` (클라이언트가 자기 주소·포트를 알려 줌) | `PASV` (서버가 열어 둔 주소·포트를 알려 줌) |
| 데이터 연결을 여는 쪽 | **서버**가 포트 20에서 클라이언트로 | **클라이언트**가 서버의 임시 포트로 |
| 방화벽 문제 | 클라이언트 쪽 방화벽·NAT가 서버의 접속을 막기 쉬움 | 서버가 수동 모드용 포트 범위를 열어 둬야 함 |

```text
능동 모드: [클라이언트] --제어--> [서버:21]
           [클라이언트] <--데이터-- [서버:20]

수동 모드: [클라이언트] --제어--> [서버:21]
           [클라이언트] --데이터--> [서버:임시 포트]
```

요즘 사용자 PC는 대부분 방화벽과 공유기(NAT) 뒤에 있어서, 바깥에서 PC로 들어오는 연결이 막히기 쉬워요. 그래서 클라이언트가 두 연결을 모두 여는 **수동 모드를 주로 써요**.

> [!TIP]
> 이름은 **서버 입장**에서 붙었다고 생각하면 쉬워요. 서버가 적극적으로 데이터 연결을 걸면 능동(Active), 서버는 가만히 기다리고 클라이언트가 걸어오면 수동(Passive)이에요.

FTP에는 텍스트 줄바꿈을 운영체제에 맞게 바꿔 주는 **ASCII 모드**와, 이미지·실행 파일처럼 바이트를 그대로 옮기는 **바이너리(Binary) 모드**가 있어요. 계정 없이 `anonymous`로 접속하는 익명 FTP도 있어요. 명령줄 FTP 클라이언트에서는 다음과 같이 써요.

```text
ftp> open 192.0.2.21
ftp> binary
ftp> get report.pdf
ftp> put photo.jpg
ftp> bye
```

`get`은 내려받기, `put`은 올리기이고, 여러 파일은 `mget`, `mput`으로 다뤄요. FTP는 아이디와 비밀번호까지 **평문**으로 보내므로, 보안이 필요하면 SSH 위에서 동작하는 **SFTP**(포트 22)나 TLS를 더한 **FTPS**를 써요.

### TFTP

TFTP(Trivial File Transfer Protocol)는 이름 그대로 "아주 단순한" FTP예요. **UDP 69번**을 쓰고, 로그인(인증)도 없고 디렉터리 목록 보기도 없어요. 파일을 읽거나 쓰는 것만 할 수 있어요. 데이터를 정해진 크기의 블록(기본 512바이트)으로 나눠 보내고 블록마다 확인 응답을 받는 단순한 방식이에요.

단순한 만큼 작은 장비에 넣기 쉬워서, 네트워크 부팅(PXE)으로 부팅 파일을 받거나 라우터·스위치의 설정 파일과 운영체제 이미지를 백업·복원할 때 써요. 시스코 IOS 계열 예시예요.

```text
Router# copy running-config tftp:
```

| 구분 | FTP | TFTP |
|---|---|---|
| 전송 프로토콜 | TCP | UDP |
| 포트 | 20(데이터), 21(제어) | 69 |
| 인증 | 아이디·비밀번호 | 없음 |
| 디렉터리 목록 | 가능 | 불가 |
| 주 용도 | 일반 파일 전송 | 장비 설정 백업, 네트워크 부팅 |

## 메일 — SMTP, POP3, IMAP

### 메일이 전달되는 길

민수가 지은에게 메일을 보내는 과정이에요.

```text
[민수 PC] --SMTP--> [보내는 서버] --SMTP--> [받는 서버]
                                                 |
                  [지은 PC] <--POP3/IMAP---------+
```

- **SMTP**(Simple Mail Transfer Protocol, TCP 25): 메일을 **보내는** 프로토콜이에요. 메일 프로그램이 서버로 보낼 때와 서버끼리 메일을 전달할 때 써요. 메일 프로그램이 인증을 거쳐 서버에 메일을 맡길 때는 587번(제출용)이나 465번(TLS)을 쓰는 경우가 많아요.
- **POP3**(Post Office Protocol version 3, TCP 110)와 **IMAP**(Internet Message Access Protocol, TCP 143): 받는 서버의 메일함에서 메일을 **가져오는** 프로토콜이에요.

메일 시스템의 구성 요소를 이렇게 부르기도 해요. 사용자가 쓰는 메일 프로그램은 MUA(Mail User Agent), 메일을 서버 사이로 전달하는 서버는 MTA(Mail Transfer Agent), 받은 메일을 사용자 메일함에 넣는 프로그램은 MDA(Mail Delivery Agent)예요.

SMTP는 사람이 읽을 수 있는 짧은 명령으로 대화해요. `HELO`(또는 `EHLO`)로 인사하고, `MAIL FROM`으로 보낸 사람, `RCPT TO`로 받는 사람을 알린 뒤, `DATA`로 본문을 보내고 `QUIT`로 끝내요.

### POP3와 IMAP

| 구분 | POP3 | IMAP |
|---|---|---|
| 포트(암호화) | 110 (995) | 143 (993) |
| 메일 보관 | 기기로 **내려받고**, 기본적으로 서버에서는 지움 | **서버에 그대로 두고** 읽음 |
| 여러 기기 사용 | 기기마다 메일함이 달라짐 | 읽음 표시·폴더가 모든 기기에서 같게 맞춰짐 |
| 장점 | 단순하고, 받은 뒤엔 오프라인으로 읽기 쉬움 | 어디서나 같은 메일함, 제목만 먼저 받아 보기 가능 |

> [!EXAM]
> "보내기는 SMTP, 받아 오기는 POP3·IMAP"이 기본이에요. 그중 **서버에 메일을 남겨 두고 여러 기기에서 동기화**하는 쪽이 IMAP이에요. "메일 전송 프로토콜이 아닌 것은?" 같은 문제에 SNMP를 섞어 내기도 하니 이름을 헷갈리지 마세요(SNMP는 장비 관리용).

### MIME

초기 SMTP는 **7비트 ASCII 텍스트**만 보낼 수 있었어요. 한글 같은 다른 문자나 사진, 문서 파일은 그대로 보낼 수 없었죠. **MIME**(Multipurpose Internet Mail Extensions)은 메일 헤더에 내용의 종류와 변환 방식을 적어 이 문제를 해결한 확장 규격이에요.

```text
MIME-Version: 1.0
Content-Type: image/png
Content-Transfer-Encoding: base64
```

- `Content-Type`: 내용의 종류. 예: `text/plain`, `text/html`, `image/png`, `application/pdf`, 여러 부분을 묶은 `multipart/mixed`
- `Content-Transfer-Encoding`: 바이너리 데이터를 텍스트로 바꾸는 방식. 대표적으로 **Base64**

MIME 형식은 메일뿐 아니라 HTTP의 `Content-Type` 헤더에서도 똑같이 쓰여요. MIME에 암호화와 전자 서명을 더한 것이 **S/MIME**이에요.

## 원격 접속 — Telnet과 SSH

| 구분 | Telnet | SSH(Secure Shell) |
|---|---|---|
| 포트 | TCP 23 | TCP 22 |
| 암호화 | **없음**. 비밀번호까지 평문 | 모든 통신 암호화 |
| 인증 | 아이디·비밀번호 | 비밀번호 또는 공개 키 인증 |
| 덧붙은 기능 | 없음 | 파일 복사(SCP, SFTP), 포트 포워딩(터널링) |
| 지금의 쓰임 | 보안상 원격 관리용으로는 쓰지 않음 | 서버·네트워크 장비 원격 관리의 표준 |

Telnet은 같은 네트워크에서 누군가 패킷을 엿보면 입력한 비밀번호가 그대로 보여요. 그래서 원격 관리는 SSH로 해요. 처음 접속할 때 SSH는 서버의 호스트 키(Host Key)를 보여 주고, 이후 접속 때 키가 바뀌었으면 경고해서 가짜 서버를 알아챌 수 있게 해 줘요.

```bash
ssh minsu@192.0.2.10            # 기본 22번 포트로 접속
ssh -p 2222 minsu@192.0.2.10    # 다른 포트로 접속
scp report.txt minsu@192.0.2.10:/home/minsu/    # 파일 복사
```

> [!NOTE]
> 특정 포트가 열려 있는지 확인하려고 Telnet 클라이언트를 쓰기도 했지만, Windows에서는 PowerShell의 `Test-NetConnection 192.0.2.25 -Port 25`로 같은 확인을 할 수 있어요. Windows의 그래픽 원격 접속인 RDP(TCP 3389)는 [Windows 네트워크 서비스](/textbook/nos-windows-network-services)에서 다뤄요.

## SNMP — 네트워크 장비 관리

### 구성 요소

SNMP(Simple Network Management Protocol)는 라우터, 스위치, 서버, 프린터 같은 장비의 상태를 한곳에서 모니터링하고 설정하는 프로토콜이에요. 학교의 담임 선생님(관리자)이 각 반 반장(에이전트)에게 출석 상황을 묻고, 반장은 급한 일이 생기면 먼저 보고하는 모습과 비슷해요.

| 구성 요소 | 설명 |
|---|---|
| 관리자(Manager, NMS) | 장비들을 감시·관리하는 시스템. NMS(Network Management System)라고도 해요 |
| 에이전트(Agent) | 관리받는 장비 안에서 동작하며 정보를 알려 주는 프로그램 |
| MIB(Management Information Base) | 에이전트가 관리하는 항목들의 데이터베이스. 나무 구조이고 항목마다 OID가 붙어요 |
| OID(Object Identifier) | MIB 항목의 고유 번호. 예: `1.3.6.1.2.1.1.5`는 장비 이름(sysName) |

### 메시지와 포트

| 메시지 | 방향 | 하는 일 |
|---|---|---|
| GetRequest | 관리자 → 에이전트 | 특정 항목의 값 읽기 |
| GetNextRequest | 관리자 → 에이전트 | 다음 항목 읽기(MIB를 차례로 훑을 때) |
| GetBulkRequest | 관리자 → 에이전트 | 여러 항목을 한 번에 읽기(v2c부터) |
| SetRequest | 관리자 → 에이전트 | 값 바꾸기(설정 변경) |
| Response | 에이전트 → 관리자 | 요청에 대한 응답 |
| Trap | 에이전트 → 관리자 | 요청이 없어도 사건(링크 끊김, 재부팅 등)을 알림. 확인 응답 없음 |
| InformRequest | 에이전트 → 관리자 | 확인 응답을 받는 알림(v2c부터) |

SNMP는 **UDP**를 써요. 관리자의 요청은 에이전트의 **161번**으로, 에이전트의 트랩은 관리자의 **162번**으로 가요. 관리자가 주기적으로 물어보는 것을 폴링(Polling), 에이전트가 먼저 알리는 것을 트랩 방식이라고 해요.

### 버전

| 버전 | 보안 방식 | 특징 |
|---|---|---|
| SNMPv1 | 커뮤니티 문자열(Community String), 평문 | 기본 기능 |
| SNMPv2c | 커뮤니티 문자열, 평문 | GetBulk, Inform 추가 등 기능·성능 개선 |
| SNMPv3 | 사용자 기반 보안 | **인증과 암호화** 지원, 접근 제어 강화 |

커뮤니티 문자열은 일종의 비밀번호예요. 많은 장비가 읽기 전용은 `public`, 읽기·쓰기는 `private`를 기본값처럼 써 왔기 때문에, 반드시 바꾸거나 SNMPv3를 써야 해요. SNMPv3는 보안 수준을 인증·암호화 모두 없음(noAuthNoPriv), 인증만(authNoPriv), 인증과 암호화(authPriv) 중에서 골라요.

> [!EXAM]
> - 구성 요소: 관리자, 에이전트, MIB
> - 트랩(Trap)은 **에이전트가 먼저** 보내는 알림, 포트는 UDP 162
> - 인증·암호화를 지원하는 버전은 **SNMPv3**뿐이에요. v1과 v2c는 커뮤니티 문자열이 평문으로 오가요.

## NTP — 시간 맞추기

NTP(Network Time Protocol)는 네트워크로 컴퓨터의 시계를 정확히 맞추는 프로토콜이고 **UDP 123번**을 써요. 패킷이 오가는 데 걸린 시간까지 계산해서 보정해요.

시간 서버는 **계층**(Stratum)으로 나뉘어요. 원자시계나 GPS 같은 기준 시계가 0계층이고, 여기에 직접 연결된 서버가 1계층, 1계층에서 시간을 받는 서버가 2계층이에요. 숫자가 클수록 기준에서 멀어지고, 16은 "동기화되지 않음"을 뜻해요. 단순하게 줄인 버전으로 SNTP(Simple NTP)도 있어요.

시간이 틀어지면 장비마다 로그 시각이 어긋나 장애 원인을 추적하기 어렵고, 인증서 유효 기간 검사나 Active Directory의 Kerberos 인증이 실패할 수도 있어요(Kerberos는 기본적으로 5분 넘게 시계가 어긋나면 인증을 거부해요).

```powershell
w32tm /query /status    # Windows: 시간 동기화 상태
w32tm /resync           # 지금 다시 맞추기(관리자 권한)
```

```bash
timedatectl        # systemd 배포판: 시간·동기화 상태
chronyc sources    # chrony 사용 배포판: 시간 서버 목록
```

## LDAP — 디렉터리 조회

LDAP(Lightweight Directory Access Protocol)는 사용자, 그룹, 컴퓨터, 프린터 같은 조직 정보를 모아 둔 **디렉터리 서비스**를 조회하고 수정하는 프로토콜이에요. 회사 전체의 주소록이자 출입 명부라고 생각하면 돼요. X.500 디렉터리의 접근 방식(DAP)을 가볍게 만든 것이라 이름에 Lightweight가 붙었어요. **TCP 389번**을 쓰고, TLS로 암호화한 LDAPS는 **636번**이에요.

디렉터리는 나무 구조이고, 항목마다 전체 경로인 DN(Distinguished Name)이 붙어요.

```text
cn=Minsu Kim,ou=Sales,dc=example,dc=com
```

`dc`(Domain Component)는 도메인, `ou`(Organizational Unit)는 부서 같은 조직 단위, `cn`(Common Name)은 사용자 같은 개별 항목의 이름이에요. Windows의 Active Directory도 LDAP로 조회해요([Active Directory와 그룹 정책](/textbook/nos-windows-ad)에서 배워요).

## 한눈에 보기

| 프로토콜 | 포트 | 전송 | 한 줄 요약 |
|---|---|---|---|
| HTTP / HTTPS | 80 / 443 | TCP | 웹 요청·응답 / TLS로 암호화한 웹 |
| FTP | 20, 21 | TCP | 제어와 데이터 연결을 나눈 파일 전송 |
| TFTP | 69 | UDP | 인증 없는 단순 파일 전송 |
| SMTP | 25 | TCP | 메일 보내기·서버 간 전달 |
| POP3 / IMAP | 110 / 143 | TCP | 메일 내려받기 / 서버에 두고 동기화 |
| Telnet / SSH | 23 / 22 | TCP | 평문 원격 접속 / 암호화 원격 접속 |
| SNMP | 161, 162 | UDP | 장비 감시·설정, 트랩 |
| NTP | 123 | UDP | 시간 동기화 |
| LDAP | 389 | TCP | 디렉터리 조회 |

## 핵심 정리

- HTTP는 요청·응답 방식의 무상태 프로토콜이며, 상태 유지는 쿠키와 세션으로 한다. HTTPS는 HTTP + TLS(443).
- 상태 코드 첫 자리: 1 정보, 2 성공, 3 리다이렉션, 4 클라이언트 오류, 5 서버 오류. 401은 인증 필요, 403은 권한 없음, 404는 없음.
- FTP는 제어(21)와 데이터(20) 연결을 나눈다. 능동 모드는 서버가, 수동 모드는 클라이언트가 데이터 연결을 연다.
- TFTP는 UDP 69, 인증·목록 기능이 없고 장비 설정 백업과 네트워크 부팅에 쓴다.
- SMTP는 보내기, POP3는 내려받기(서버에서 삭제가 기본), IMAP은 서버에 두고 여러 기기에서 동기화.
- MIME은 메일로 7비트 ASCII 외의 문자와 첨부 파일을 보내게 해 주는 확장이다(Content-Type, Base64).
- Telnet(23)은 평문, SSH(22)는 암호화와 공개 키 인증, SCP·SFTP를 지원한다.
- SNMP는 관리자·에이전트·MIB로 구성되고 UDP 161(질의)·162(트랩)를 쓴다. 인증·암호화는 v3만 지원한다.
- NTP는 UDP 123, Stratum 계층으로 시간을 맞춘다. LDAP는 TCP 389(LDAPS 636)로 디렉터리를 조회한다.

## 스스로 확인하기

**1.** 다음 HTTP 상태 코드 중 **서버 쪽 오류**를 나타내는 것은?
① 302 ② 403 ③ 404 ④ 503

> [!ANSWER]
> 정답: ④
> 5로 시작하는 코드가 서버 오류예요. 503은 서버가 과부하나 점검으로 지금 요청을 처리할 수 없다는 뜻이에요. 302는 리다이렉션, 403과 404는 클라이언트 오류예요.

**2.** FTP 수동(Passive) 모드에 대한 설명으로 옳은 것은?
① 서버가 포트 20에서 클라이언트 쪽으로 데이터 연결을 연다 ② 클라이언트가 서버가 알려 준 포트로 데이터 연결을 연다 ③ 제어와 데이터를 하나의 연결로 주고받는다 ④ UDP 69번 포트를 사용한다

> [!ANSWER]
> 정답: ②
> 수동 모드에서는 서버가 `PASV` 응답으로 알려 준 포트에 클라이언트가 직접 데이터 연결을 걸어요. ①은 능동 모드, ④는 TFTP 설명이에요.

**3.** 지은은 노트북, 휴대폰, 사무실 PC에서 같은 메일함을 보며 읽음 표시와 폴더 정리가 모든 기기에 똑같이 반영되기를 원해요. 알맞은 메일 수신 프로토콜은?
① SMTP ② POP3 ③ IMAP ④ MIME

> [!ANSWER]
> 정답: ③
> IMAP은 메일을 서버에 두고 상태를 동기화해요. POP3는 기기로 내려받는 방식이라 기기마다 메일함이 달라지고, SMTP는 보내기용, MIME은 메일 형식 확장이에요.

**4.** SNMP에서 에이전트가 관리자의 요청 없이 링크 끊김 같은 사건을 먼저 알리는 메시지는?
① GetRequest ② SetRequest ③ GetNextRequest ④ Trap

> [!ANSWER]
> 정답: ④
> Trap은 에이전트가 먼저 보내는 알림이고 관리자의 UDP 162번으로 가요. 나머지는 관리자가 에이전트에 보내는 요청이에요.

**5.** 원격 관리에 Telnet 대신 SSH를 쓰라고 권하는 가장 큰 이유는?
① 전송 속도가 더 빠르다 ② UDP를 써서 가볍다 ③ 비밀번호를 포함한 통신 내용을 암호화한다 ④ 포트 번호가 더 작다

> [!ANSWER]
> 정답: ③
> Telnet은 비밀번호까지 평문으로 보내 도청에 약해요. SSH는 모든 통신을 암호화하고 공개 키 인증도 지원해요.
