IPv4 주소가 바닥나면서 NAT로 버텨 왔지만, 근본적인 해결책은 주소 자체를 크게 늘린 IPv6예요. IPv6는 주소만 길어진 것이 아니라 헤더 구조, 주소를 얻는 방법, 이웃을 찾는 방법까지 새로 정리했어요. 이 단원에서는 처음 보면 낯선 IPv6 주소를 읽고 줄이는 법부터, 헤더와 자동 설정, IPv4와 함께 쓰는 전환 기술까지 차례로 배워요.

> [!GOAL]
> - 128비트 IPv6 주소를 16진수 8그룹으로 쓰고, 규칙에 맞게 축약하고 복원할 수 있어요.
> - 주소 유형별 접두사(2000::/3, fe80::/10, fc00::/7, ff00::/8)와 특수 주소(::1, ::)를 구분해요.
> - 40바이트 고정 헤더의 필드와 확장 헤더, 단편화 방식이 IPv4와 어떻게 다른지 설명할 수 있어요.
> - NDP 메시지와 SLAAC·EUI-64·DHCPv6로 주소를 얻는 과정을 설명할 수 있어요.
> - 듀얼 스택, 터널링, 변환 같은 전환 기술을 구분해요.

## 왜 IPv6인가
IPv4 주소는 32비트라서 약 43억 개뿐이에요. IPv6(Internet Protocol version 6)는 주소를 128비트로 늘려서 2^128, 약 3.4 × 10^38개의 주소를 만들 수 있어요. 지구의 모든 기기에 주소를 주고도 한참 남는 양이에요.

주소 말고도 이런 점이 달라졌어요.
- 기본 헤더를 40바이트 고정 길이로 단순하게 만들고, 추가 기능은 확장 헤더로 분리했어요.
- 라우터가 단편화를 하지 않아 처리 부담이 줄었어요.
- 브로드캐스트를 없애고, 멀티캐스트와 애니캐스트를 정식 주소 유형으로 정했어요.
- 호스트가 스스로 주소를 만드는 자동 설정(SLAAC)을 기본으로 지원해요.
- 흐름 레이블(Flow Label)로 실시간 트래픽 같은 흐름을 구분할 수 있어요.
- IPSec을 기본으로 지원해요.

> [!NOTE]
> 시험에서는 "IPv6는 IPSec을 기본 지원한다"로 나와요. 초기 규격에서는 IPSec 구현이 필수였고, 지금 규격에서는 권장 사항으로 바뀌었어요.

## 주소 표기

### 기본 형태
128비트를 16비트씩 8개 그룹으로 나누고, 각 그룹을 16진수 4자리로 써서 콜론(:)으로 이어요. 16진수 한 자리가 4비트이므로 4자리 × 4비트 = 16비트, 16비트 × 8그룹 = 128비트예요.

```text
2001:0db8:0000:0000:0000:ff00:0042:8329
```

알파벳은 대문자와 소문자를 구분하지 않지만, 표준 권장 표기는 소문자예요.

### 축약 규칙
긴 주소를 그대로 쓰기 힘들어서 두 가지 규칙으로 줄여요.

1. **각 그룹의 앞쪽 0은 생략할 수 있어요.** 0db8 → db8, 0042 → 42, 0000 → 0. 뒤쪽 0은 생략할 수 없어요(ff00을 ff로 쓰면 다른 값이에요).
2. **0으로만 된 그룹이 연속되면 ::로 한 번 줄일 수 있어요.** 단, ::는 주소 하나에 **한 번만** 쓸 수 있어요. 두 번 쓰면 각각 몇 그룹을 줄였는지 알 수 없기 때문이에요.

### 축약 예제
**예제 1.** 2001:0db8:0000:0000:0000:ff00:0042:8329
1. 앞쪽 0 생략: 2001:db8:0:0:0:ff00:42:8329
2. 연속된 0 그룹 세 개를 ::로: **2001:db8::ff00:42:8329**

**예제 2.** fe80:0000:0000:0000:021a:2bff:fe3c:4d5e
1. 앞쪽 0 생략: fe80:0:0:0:21a:2bff:fe3c:4d5e
2. ::로 줄이기: **fe80::21a:2bff:fe3c:4d5e**

**예제 3.** 2001:0db8:0000:0000:0001:0000:0000:0001
1. 앞쪽 0 생략: 2001:db8:0:0:1:0:0:1
2. 0 그룹 묶음이 두 군데(각 2개)예요. ::는 한 곳에만 쓸 수 있어요.
   - **2001:db8::1:0:0:1** (앞쪽을 줄임, 표준 권장)
   - 2001:db8:0:0:1::1 (뒤쪽을 줄임, 문법상 맞음)
   - 2001:db8::1::1 (틀림, ::가 두 번)

**예제 4.** 2001:0db8:0000:0001:0000:0000:0000:0001
1. 앞쪽 0 생략: 2001:db8:0:1:0:0:0:1
2. 0 그룹이 한 개짜리와 세 개짜리가 있어요. 더 긴 쪽을 줄이는 것이 권장 표기예요: **2001:db8:0:1::1**

**예제 5.** 2001:0db8:0a00:0000:0000:0000:0000:0000
1. 0a00 → a00 (앞의 0만 빠지고 뒤의 00은 남아요)
2. 뒤쪽 0 그룹 다섯 개를 ::로: **2001:db8:a00::**

**특수한 경우**: 0000:0000:0000:0000:0000:0000:0000:0001은 `::1`, 여덟 그룹이 모두 0이면 `::`예요.

> [!WARNING]
> 가장 흔한 실수 두 가지예요.
> - 그룹 안의 **뒤쪽** 0을 지우기: 0a00을 a0으로 쓰면 틀려요. a00이 맞아요.
> - **::를 두 번** 쓰기: 2001:db8::1::1은 잘못된 주소예요.

> [!NOTE]
> 표준 권장 표기에서는 0 그룹이 딱 하나만 있을 때는 ::를 쓰지 않고 0으로 남겨요(예: 2001:db8:0:1:1:1:1:1). 또 길이가 같은 0 묶음이 여럿이면 앞쪽을 줄여요.

### 복원 예제
축약된 주소를 원래 8그룹으로 되돌리는 방법이에요.
1. ::의 왼쪽과 오른쪽에 있는 그룹 수를 세요.
2. 8에서 그 합을 빼면 ::가 대신한 0 그룹 수예요.
3. 모든 그룹을 앞에 0을 채워 4자리로 맞춰요.

**예제 A.** 2001:db8::7:1
- 왼쪽 2개(2001, db8) + 오른쪽 2개(7, 1) = 4 → 0 그룹 8 - 4 = 4개
- **2001:0db8:0000:0000:0000:0000:0007:0001**

**예제 B.** ff02::1:ff3c:4d5e
- 왼쪽 1개 + 오른쪽 3개 = 4 → 0 그룹 4개
- **ff02:0000:0000:0000:0000:0001:ff3c:4d5e**

**예제 C.** 2001:db8:a::b0:0:c
- 왼쪽 3개(2001, db8, a) + 오른쪽 3개(b0, 0, c) = 6 → 0 그룹 2개
- **2001:0db8:000a:0000:0000:00b0:0000:000c**

### 프리픽스 표기
IPv6는 서브넷 마스크를 점 표기로 쓰지 않고 "/프리픽스 길이"로만 써요. 예를 들어 2001:db8:abcd:12::/64는 앞 64비트가 네트워크 부분이라는 뜻이에요.

일반적인 글로벌 주소는 앞 64비트가 네트워크 접두사(글로벌 라우팅 접두사 + 서브넷 ID), 뒤 64비트가 인터페이스 ID(Interface ID)예요. 그래서 LAN 하나에는 보통 /64를 써요.

| 부분 | 글로벌 라우팅 접두사 | 서브넷 ID | 인터페이스 ID |
|---|---|---|---|
| 길이 | 48비트 | 16비트 | 64비트 |
| 예 | 2001:0db8:abcd | 0012 | a1b2:c3ff:fe4d:5e6f |

그룹 하나가 16비트이므로 /16, /32, /48, /64처럼 16의 배수는 그룹 경계와 딱 맞아요. 예를 들어 기관이 /48을 받으면 그 안에서 서브넷 ID 16비트로 /64 서브넷을 2^16 = 65,536개 만들 수 있어요.

경계가 그룹 중간에 걸리면 16진수 자리 단위로 보면 돼요. 2001:db8:abcd:1234::가 속한 /56 네트워크는 앞 3그룹(48비트)에 넷째 그룹의 앞 2자리(8비트)를 더한 것이라 **2001:db8:abcd:1200::/56**이에요.

## 주소 유형

### 세 가지 유형, 브로드캐스트는 없음
IPv6 주소는 유니캐스트(Unicast), 멀티캐스트(Multicast), 애니캐스트(Anycast) 세 가지예요. **브로드캐스트는 없어요.** 같은 링크의 모두에게 보내야 할 때는 "모든 노드" 멀티캐스트 주소 ff02::1을 써요.

또 IPv6에서는 인터페이스 하나에 주소를 여러 개 붙이는 것이 보통이에요. 링크 로컬 주소 하나와 글로벌 주소 하나 이상을 함께 갖는 식이에요.

### 주요 주소와 접두사

| 종류 | 접두사 | 생김새 | 설명 | IPv4로 치면 |
|---|---|---|---|---|
| 글로벌 유니캐스트(Global Unicast) | 2000::/3 | 2 또는 3으로 시작 | 인터넷에서 라우팅되는 공인 주소 | 공인 IP |
| 링크 로컬(Link-Local) | fe80::/10 | fe80 ~ febf로 시작 | 같은 링크 안에서만 유효. IPv6를 켜면 인터페이스마다 자동 생성되고 라우터가 넘기지 않음 | 169.254.0.0/16 |
| 고유 로컬(Unique Local) | fc00::/7 | fc 또는 fd로 시작(실제로 쓰는 것은 fd) | 조직 내부용, 인터넷에서 라우팅되지 않음 | 사설 IP |
| 멀티캐스트(Multicast) | ff00::/8 | ff로 시작 | 그룹 전달 | 224.0.0.0/4 |
| 애니캐스트(Anycast) | 따로 없음 | 유니캐스트 주소 중에서 지정 | 가장 가까운 하나에게 전달 | (해당 없음) |
| 루프백(Loopback) | ::1/128 | ::1 | 자기 자신 | 127.0.0.1 |
| 미지정(Unspecified) | ::/128 | :: | 아직 주소가 없을 때 출발지로 씀 | 0.0.0.0 |
| IPv4 매핑 주소 | ::ffff:0:0/96 | ::ffff:192.0.2.1 | IPv4 주소를 IPv6 형태로 표현 | (해당 없음) |

> [!NOTE]
> 예전 교재에 나오는 사이트 로컬(Site-Local, fec0::/10) 주소는 폐지되었고, 그 역할을 고유 로컬 주소가 이어받았어요. 2001:db8::/32는 이 교재처럼 문서·예시용으로 따로 떼어 둔 대역이에요.

### 알아 둘 멀티캐스트 주소
멀티캐스트 주소 ff0X에서 넷째 자리(X)는 범위(Scope)를 뜻해요. 2는 링크 로컬, 5는 사이트 로컬, e는 글로벌이에요. 그래서 ff02로 시작하는 주소는 같은 링크 안에서만 쓰여요.

| 주소 | 대상 |
|---|---|
| ff02::1 | 링크의 모든 노드(브로드캐스트를 대신함) |
| ff02::2 | 링크의 모든 라우터 |
| ff02::5, ff02::6 | OSPFv3 라우터, OSPFv3 DR·BDR |
| ff02::9 | RIPng 라우터 |
| ff02::1:2 | DHCPv6 서버와 릴레이 에이전트 |
| ff02::1:ffXX:XXXX | 요청 노드 멀티캐스트(Solicited-Node Multicast), 유니캐스트 주소의 마지막 24비트를 붙여 만듦 |

## IPv6 헤더

### 40바이트 고정 기본 헤더
IPv4 헤더는 옵션 때문에 20~60바이트로 길이가 바뀌지만, IPv6 기본 헤더는 항상 **40바이트**예요. 필드는 8개뿐이에요.

| 필드 | 크기 | 역할 | IPv4에서 비슷한 필드 |
|---|---|---|---|
| 버전(Version) | 4비트 | 항상 6 | 버전 |
| 트래픽 클래스(Traffic Class) | 8비트 | 패킷의 우선순위, QoS 표시 | 서비스 유형(ToS) |
| 흐름 레이블(Flow Label) | 20비트 | 같은 흐름에 속한 패킷을 표시해 같은 방식으로 처리하게 함 | 없음(새로 생김) |
| 페이로드 길이(Payload Length) | 16비트 | 기본 헤더 뒤에 오는 확장 헤더와 데이터의 길이 | 전체 길이(헤더 포함) |
| 다음 헤더(Next Header) | 8비트 | 바로 뒤에 오는 헤더의 종류(확장 헤더, TCP 6, UDP 17, ICMPv6 58 등) | 프로토콜 |
| 홉 제한(Hop Limit) | 8비트 | 라우터를 지날 때마다 1씩 줄고 0이 되면 폐기 | TTL |
| 출발지 주소 | 128비트 | 보낸 쪽 주소 | 출발지 주소 |
| 목적지 주소 | 128비트 | 받는 쪽 주소 | 목적지 주소 |

계산해 보면 앞의 여섯 필드가 4 + 8 + 20 + 16 + 8 + 8 = 64비트 = 8바이트이고, 주소 두 개가 16 + 16 = 32바이트라서 합이 40바이트예요.

IPv4 헤더에서 빠진 필드도 기억해 두세요.
- **헤더 길이(IHL)**: 길이가 고정이라 필요 없어요.
- **식별자·플래그·단편 오프셋**: 단편화 확장 헤더로 옮겨 갔어요.
- **헤더 체크섬**: 없앴어요. 2계층과 상위 계층이 오류를 검사하므로 라우터가 홉마다 다시 계산하지 않아도 돼요. 그 대신 IPv6에서는 UDP 체크섬이 필수가 됐어요.
- **옵션**: 확장 헤더로 옮겨 갔어요.

([IP 패킷의 구조와 단편화](/textbook/tcpip-ip-header)에서 배운 IPv4 헤더와 비교해 보세요.)

### 확장 헤더
추가 기능이 필요할 때는 기본 헤더 뒤에 확장 헤더(Extension Header)를 필요한 만큼만 사슬처럼 이어 붙여요. 각 헤더의 "다음 헤더" 필드가 그 뒤에 무엇이 오는지 알려 줘요.

```text
기본 헤더 (다음 헤더 = 43)
  -> 라우팅 헤더 (다음 헤더 = 44)
    -> 단편화 헤더 (다음 헤더 = 6)
      -> TCP 헤더 + 데이터
```

| 확장 헤더 | 다음 헤더 값 | 역할 |
|---|---|---|
| 홉별 옵션(Hop-by-Hop Options) | 0 | 경로상의 모든 라우터가 확인해야 하는 옵션 |
| 라우팅(Routing) | 43 | 거쳐 갈 경로를 지정 |
| 단편화(Fragment) | 44 | 출발지에서 나눈 조각의 정보 |
| 인증 헤더(AH) | 51 | 무결성과 출발지 인증(IPSec) |
| ESP | 50 | 암호화와 무결성(IPSec) |
| 목적지 옵션(Destination Options) | 60 | 목적지에서만 처리하는 옵션 |

확장 헤더가 여러 개면 권장 순서가 있어요. 홉별 옵션이 언제나 맨 앞(기본 헤더 바로 뒤)에 오고, 대체로 라우팅 → 단편화 → AH → ESP → 목적지 옵션 순으로 이어진 뒤 상위 계층 헤더가 와요.

### 단편화는 출발지에서만
IPv4에서는 라우터도 패킷을 잘라 보낼 수 있었지만, IPv6에서는 **출발지 호스트만 단편화할 수 있어요.** 라우터는 다음 링크의 MTU보다 큰 패킷을 받으면 버리고, 출발지에 ICMPv6 "패킷이 너무 큼(Packet Too Big)" 메시지를 보내요. 출발지는 이 메시지로 경로상의 가장 작은 MTU를 알아내는데, 이것을 경로 MTU 탐색(PMTUD, Path MTU Discovery)이라고 해요. 그래도 나눠야 하면 출발지가 단편화 확장 헤더를 붙여 보내요.

IPv6를 쓰는 모든 링크는 MTU가 1280바이트 이상이어야 해요.

## ICMPv6와 NDP

### ICMPv6
ICMPv6는 IPv6에 꼭 필요한 짝 프로토콜이에요(다음 헤더 값 58). IPv4의 ICMP처럼 오류 보고(목적지 도달 불가, 패킷이 너무 큼, 시간 초과, 매개변수 문제)와 진단(에코 요청·응답, 즉 ping)을 맡고, 여기에 더해 IPv4에서 따로 있던 기능들도 흡수했어요.
- ARP의 역할 → NDP(이웃 탐색)
- IGMP의 역할(멀티캐스트 그룹 관리) → MLD(Multicast Listener Discovery)

### NDP의 다섯 가지 메시지
NDP(Neighbor Discovery Protocol, 이웃 탐색 프로토콜)는 ICMPv6 메시지로 같은 링크의 이웃과 라우터를 찾는 프로토콜이에요.

| 메시지 | ICMPv6 타입 | 보내는 쪽 → 받는 쪽 | 하는 일 |
|---|---|---|---|
| RS(Router Solicitation, 라우터 요청) | 133 | 호스트 → 모든 라우터(ff02::2) | "이 링크에 라우터 있나요?" |
| RA(Router Advertisement, 라우터 광고) | 134 | 라우터 → 모든 노드(ff02::1) | 네트워크 접두사, 기본 게이트웨이, 주소 설정 방법을 알림. RS에 대한 응답이자 주기적으로도 보냄 |
| NS(Neighbor Solicitation, 이웃 요청) | 135 | 호스트 → 요청 노드 멀티캐스트 | "이 IPv6 주소의 MAC 주소는?" (ARP 요청 대신), 중복 주소 검사 |
| NA(Neighbor Advertisement, 이웃 광고) | 136 | 호스트 → 요청한 호스트 | "그 주소는 나고, 내 MAC은 이것" (ARP 응답 대신) |
| 리다이렉트(Redirect) | 137 | 라우터 → 호스트 | "그 목적지는 다른 라우터로 보내는 게 더 좋아요" |

NDP가 하는 일을 기능으로 정리하면 주소 해석(MAC 주소 찾기), 라우터와 접두사 발견, 중복 주소 탐지(DAD, Duplicate Address Detection), 이웃에 닿을 수 있는지 확인(NUD, Neighbor Unreachability Detection), 리다이렉트예요.

> [!TIP]
> ARP는 MAC 주소를 물을 때 브로드캐스트로 모두를 깨우지만, NDP는 요청 노드 멀티캐스트 주소로 보내서 주소 끝 24비트가 같은 노드만 반응해요. 예를 들어 2001:db8:1:1:21a:2bff:fe3c:4d5e의 MAC 주소를 물을 때는 ff02::1:ff3c:4d5e로 NS를 보내요.

## 주소 자동 설정

### SLAAC
SLAAC(Stateless Address Autoconfiguration, 상태 비저장 주소 자동 설정)은 DHCP 서버 없이 호스트가 스스로 글로벌 주소를 만드는 방법이에요. 누가 어떤 주소를 쓰는지 서버가 기록(상태)하지 않기 때문에 "상태 비저장"이라고 불러요.

1. 호스트가 fe80::/64에 자기 인터페이스 ID를 붙여 **링크 로컬 주소**를 만들고, NS로 중복 주소 검사(DAD)를 해요. 이때는 아직 주소가 확정되지 않았으므로 출발지로 미지정 주소 ::를 써요.
2. 호스트가 **RS**를 ff02::2로 보내요.
3. 라우터가 **RA**로 네트워크 접두사(예: 2001:db8:1:1::/64)를 알려 줘요. RA를 보낸 라우터의 링크 로컬 주소가 호스트의 기본 게이트웨이가 돼요.
4. 호스트가 접두사 + 인터페이스 ID로 **글로벌 주소**를 만들고, 다시 DAD로 중복을 확인해요.

인터페이스 ID 64비트를 만드는 방법은 두 가지예요. MAC 주소로 만드는 EUI-64 방식과, 무작위 값을 쓰는 방식이에요. MAC 주소가 주소에 드러나면 기기를 추적당할 수 있어서, 요즘 운영체제는 무작위 방식을 기본으로 쓰는 경우가 많아요. 시험에는 계산할 수 있는 EUI-64가 나와요.

### EUI-64 계산
EUI-64(64-bit Extended Unique Identifier)는 48비트 MAC 주소를 64비트 인터페이스 ID로 늘리는 방법이에요.

**예제.** MAC 주소 00-1A-2B-3C-4D-5E
1. MAC을 앞 24비트와 뒤 24비트로 나눠요: 00-1A-2B | 3C-4D-5E
2. 가운데에 FF-FE를 끼워요: 00-1A-2B-FF-FE-3C-4D-5E
3. 첫 바이트의 왼쪽에서 일곱째 비트(U/L 비트)를 뒤집어요.
   - 00 = 0000 0000 → 0000 0010 = 02
4. 16비트씩 묶어요: 021A:2BFF:FE3C:4D5E → 소문자, 앞쪽 0 생략: **21a:2bff:fe3c:4d5e**
5. 접두사와 합쳐요.
   - 링크 로컬: fe80::21a:2bff:fe3c:4d5e
   - 글로벌(접두사 2001:db8:1:1::/64): 2001:db8:1:1:21a:2bff:fe3c:4d5e

> [!TIP]
> 일곱째 비트 뒤집기는 "첫 바이트의 둘째 16진수 자리를 짝꿍으로 바꾸기"로 외우면 빨라요. 짝꿍은 0과 2, 1과 3, 4와 6, 5와 7, 8과 A, 9와 B, C와 E, D와 F예요. 예를 들어 첫 바이트가 1A면 18, 0E면 0C가 돼요.

### DHCPv6
DHCPv6는 IPv6용 DHCP예요. 클라이언트는 UDP 546번, 서버는 UDP 547번 포트를 쓰고, 클라이언트는 ff02::1:2로 서버를 찾아요.
- **상태 저장(Stateful) DHCPv6**: 서버가 주소를 나눠 주고 기록해요. IPv4의 DHCP와 비슷해요.
- **상태 비저장(Stateless) DHCPv6**: 주소는 SLAAC로 만들고, DNS 서버 주소 같은 추가 정보만 DHCPv6에서 받아요.

어느 방식을 쓸지는 라우터가 RA에 담은 플래그로 알려 줘요. M(Managed) 플래그가 1이면 주소를 DHCPv6에서 받고, O(Other) 플래그가 1이면 그 밖의 정보를 DHCPv6에서 받아요.

> [!WARNING]
> DHCPv6는 기본 게이트웨이를 알려 주지 않아요. IPv6에서 기본 게이트웨이는 언제나 라우터의 RA로 알게 돼요.

## IPv4에서 IPv6로 넘어가는 기술
IPv4를 하루아침에 끌 수는 없으므로, 오랫동안 둘을 함께 쓰는 기술이 필요해요.

### 듀얼 스택
듀얼 스택(Dual Stack)은 한 장비에 IPv4와 IPv6를 모두 설정해 두고, 상대에 따라 알맞은 쪽으로 통신하는 방식이에요. 가장 기본적이고 널리 쓰이는 방식이지만, 주소와 설정을 두 벌 관리해야 해요. DNS에서 IPv4 주소는 A 레코드, IPv6 주소는 AAAA 레코드로 찾아요.

### 터널링
터널링(Tunneling)은 IPv6 패킷을 IPv4 패킷 안에 통째로 넣어(캡슐화) IPv4 망을 건너가게 하는 방식이에요. IPv6 섬과 섬 사이를 IPv4 바다 위의 다리로 잇는 셈이에요. 이때 바깥 IPv4 헤더의 프로토콜 번호는 41이에요.

| 터널 방식 | 특징 |
|---|---|
| 수동 터널 | 관리자가 양 끝 주소를 직접 설정 |
| 6to4 | 공인 IPv4 주소를 2002::/16 접두사에 넣어 라우터끼리 자동으로 터널을 만듦 |
| ISATAP | 조직 내부 IPv4 망에서 호스트와 라우터 사이에 자동 터널을 만듦 |
| 테레도(Teredo) | NAT 뒤에 있는 호스트가 IPv6 패킷을 UDP로 감싸서 NAT를 통과함 |

### 변환
변환(Translation)은 IPv6만 쓰는 호스트와 IPv4만 쓰는 호스트가 통신할 수 있도록 중간 장비가 헤더를 바꿔 주는 방식이에요.
- **NAT64**: IPv6 패킷을 IPv4 패킷으로(그 반대로도) 바꿔요. 잘 알려진 접두사 64:ff9b::/96에 IPv4 주소를 붙여 IPv4 서버를 IPv6 주소처럼 보이게 해요.
- **DNS64**: IPv4 주소(A 레코드)만 있는 도메인을 물으면, 그 주소를 NAT64 접두사에 넣어 합성한 AAAA 레코드를 만들어 돌려줘요. NAT64와 짝을 이뤄 동작해요.

| 방식 | 원리 | 비유 |
|---|---|---|
| 듀얼 스택 | 두 프로토콜을 모두 설치 | 두 나라 말을 다 하는 사람 |
| 터널링 | IPv6를 IPv4에 담아 전달 | 외국 편지를 국내 봉투에 넣어 보내기 |
| 변환 | 헤더를 서로 바꿔 씀 | 통역사 |

## IPv4와 IPv6 비교

| 항목 | IPv4 | IPv6 |
|---|---|---|
| 주소 길이 | 32비트 | 128비트 |
| 표기 | 10진수 4개를 점으로 구분 | 16진수 8그룹을 콜론으로 구분 |
| 기본 헤더 | 20~60바이트 가변 | 40바이트 고정 + 확장 헤더 |
| 헤더 체크섬 | 있음 | 없음 |
| 단편화 | 출발지와 라우터 | 출발지만 |
| 브로드캐스트 | 있음 | 없음(멀티캐스트로 대신) |
| MAC 주소 찾기 | ARP | NDP(ICMPv6) |
| 멀티캐스트 그룹 관리 | IGMP | MLD(ICMPv6) |
| 주소 자동 설정 | DHCP | SLAAC, DHCPv6 |
| 루프백 | 127.0.0.1 | ::1 |
| DNS 레코드 | A | AAAA |

## 핵심 정리
- IPv6 주소는 128비트, 16비트씩 8그룹을 16진수로 쓰고 콜론으로 구분해요.
- 축약: 그룹 앞쪽의 0만 생략, 연속된 0 그룹은 ::로 한 번만. 복원할 때는 8에서 남은 그룹 수를 빼요.
- 글로벌 유니캐스트 2000::/3, 링크 로컬 fe80::/10, 고유 로컬 fc00::/7, 멀티캐스트 ff00::/8, 루프백 ::1, 미지정 ::. 브로드캐스트는 없어요.
- 기본 헤더는 40바이트 고정: 버전, 트래픽 클래스, 흐름 레이블, 페이로드 길이, 다음 헤더, 홉 제한, 출발지·목적지 주소. 헤더 체크섬은 없어요.
- 추가 기능은 확장 헤더로 붙이고, 단편화는 출발지만 해요(라우터는 Packet Too Big을 보냄).
- NDP는 ICMPv6의 RS·RA·NS·NA·리다이렉트로 ARP와 라우터 발견을 대신해요.
- SLAAC는 RA의 접두사 + 인터페이스 ID로 주소를 스스로 만들어요. EUI-64는 MAC 가운데에 FFFE를 넣고 일곱째 비트를 뒤집어요.
- 전환 기술: 듀얼 스택(둘 다 설치), 터널링(6to4·ISATAP·테레도), 변환(NAT64·DNS64).

## 스스로 확인하기

**1.** 2001:0db8:0000:0000:00a0:0000:0000:0001을 올바르게 축약한 것은?
① 2001:db8::a0::1 ② 2001:db8::a0:0:0:1 ③ 2001:db8:0:0:a:0:0:1 ④ 2001:db8::a00:0:0:1

> [!ANSWER]
> 정답: ②
> ①은 ::를 두 번 써서 틀렸고, ③은 00a0을 a로, ④는 a00으로 잘못 바꿨어요. 00a0에서는 앞쪽 0만 지워 a0이 돼요.

**2.** 2001:db8:c::42:1을 생략 없이 8그룹으로 쓰면?

> [!ANSWER]
> 정답: 2001:0db8:000c:0000:0000:0000:0042:0001
> ::의 왼쪽 3그룹, 오른쪽 2그룹으로 5그룹이 보이므로 ::는 0 그룹 3개를 대신해요.

**3.** MAC 주소가 0E-11-22-33-44-55인 인터페이스가 EUI-64 방식으로 만든 링크 로컬 주소는?
① fe80::e11:22ff:fe33:4455 ② fe80::c11:22ff:fe33:4455 ③ fe80::c11:2233:4455 ④ fe80::e11:22fe:ff33:4455

> [!ANSWER]
> 정답: ②
> 가운데에 FF-FE를 넣으면 0E11:22FF:FE33:4455이고, 첫 바이트 0E(0000 1110)의 일곱째 비트를 뒤집으면 0C(0000 1100)가 돼요.

**4.** IPv6 기본 헤더에 들어 있지 않은 필드는?
① 흐름 레이블 ② 홉 제한 ③ 헤더 체크섬 ④ 다음 헤더

> [!ANSWER]
> 정답: ③
> IPv6는 라우터의 처리 부담을 줄이려고 헤더 체크섬을 없앴어요. 오류 검사는 2계층과 상위 계층이 맡아요.

**5.** IPv6에서 IPv4의 ARP 요청 역할을 하는 NDP 메시지는?
① RS ② RA ③ NS ④ NA

> [!ANSWER]
> 정답: ③
> NS(이웃 요청)로 상대의 MAC 주소를 묻고, NA(이웃 광고)로 답을 받아요. RS·RA는 라우터를 찾고 접두사를 알려 주는 메시지예요.
