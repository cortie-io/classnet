네트워크 공부를 시작하면 주소, 프로토콜, 패킷, 계층 같은 낯선 말이 한꺼번에 쏟아져요. 이 단원에서는 하나하나를 깊이 파기 전에, 이 말들이 서로 어떻게 연결되는지 큰 그림부터 그려 봐요. 마지막에는 웹 페이지 하나가 열리기까지 무슨 일이 일어나는지 따라가 보면서, 앞으로 배울 단원들이 어디에 자리 잡는지 확인해요.

> [!GOAL]
> - 호스트, 클라이언트와 서버, 패킷, 프로토콜이 무엇인지 쉬운 말로 설명할 수 있어요.
> - MAC 주소, IP 주소, 포트 번호, 도메인 이름이 각각 무엇을 가리키는지 구분할 수 있어요.
> - 웹 페이지가 열릴 때 DNS → TCP → HTTP 순서로 일이 일어난다는 것을 설명할 수 있어요.

## 네트워크란 무엇일까요

**네트워크(Network)**는 둘 이상의 장치가 통신 회선으로 연결되어 데이터를 주고받을 수 있는 상태를 말해요. 집에서 공유기에 노트북과 스마트폰을 연결한 것도 작은 네트워크이고, 학교나 회사의 컴퓨터를 모두 묶은 것도 네트워크예요.

**인터넷(Internet)**은 이런 수많은 네트워크가 서로 연결된 거대한 네트워크예요. 그래서 "네트워크들의 네트워크"라고도 불러요.

> [!TIP]
> 네트워크를 도시의 도로망과 택배 시스템으로 떠올려 보세요. 집(컴퓨터)들이 골목(케이블)으로 이어지고, 골목은 큰길과 고속도로(인터넷)로 이어져요. 택배(데이터)는 주소를 보고 갈림길마다 방향을 정해서 목적지까지 가요. 이 단원의 개념은 대부분 이 비유에 대응시킬 수 있어요.

## 네트워크를 이루는 것들

### 호스트

**호스트(Host)**는 네트워크에 연결되어 주소를 갖고 데이터를 보내거나 받는 끝 장치예요. 데스크톱, 노트북, 스마트폰, 서버, 네트워크 프린터가 모두 호스트예요. 비유하면 택배를 보내고 받는 **집**이에요.

### 네트워크 장비

호스트 사이에서 데이터가 잘 오가도록 길을 이어 주는 장비들이 있어요.

| 장비 | 하는 일 | 비유 |
|---|---|---|
| 스위치(Switch) | 같은 네트워크 안의 장치들을 연결하고, 받은 데이터를 목적지 장치가 연결된 포트로만 보내요. | 동네 골목의 분류 담당 |
| 라우터(Router) | 서로 다른 네트워크를 연결하고, 목적지까지 가는 경로를 골라요. | 고속도로 교차로의 길 안내 |
| 무선 AP(Access Point) | 무선 장치를 유선 네트워크에 연결해요. | 전파로 이어 주는 무선 다리 |

장비는 4과목의 [1·2계층 장비](/textbook/dev-l1-l2-devices)와 [라우터와 상위 계층 장비](/textbook/dev-router-l3)에서 자세히 배워요.

### 전송 매체

데이터가 실제로 지나가는 길을 **전송 매체(Transmission Medium)**라고 해요. 구리선 케이블(UTP), 빛을 보내는 광섬유, 공기 중의 전파가 있어요. 자세한 내용은 [전송 매체와 케이블](/textbook/net-transmission-media)에서 배워요.

## 클라이언트와 서버

네트워크에서 가장 흔한 관계는 **요청하는 쪽**과 **응답하는 쪽**이에요.

- **클라이언트(Client)**: 서비스를 요청하는 쪽이에요. 웹 브라우저, 메일 앱, 게임 앱이 클라이언트예요.
- **서버(Server)**: 요청을 기다리고 있다가 서비스를 제공하는 쪽이에요. 웹 서버, 메일 서버, 파일 서버가 있어요.

분식집으로 비유하면 손님이 "떡볶이 하나요"라고 주문하는 것이 클라이언트의 **요청(Request)**이고, 주방에서 음식을 만들어 내주는 것이 서버의 **응답(Response)**이에요. 서버는 손님이 언제 올지 모르니 항상 주문을 받을 준비를 하고 있어요.

> [!NOTE]
> 클라이언트와 서버는 장치의 종류가 아니라 **역할**이에요. 같은 컴퓨터가 어떤 프로그램에서는 클라이언트, 다른 프로그램에서는 서버가 될 수 있어요. 서버 없이 장치끼리 대등하게 주고받는 방식은 P2P(Peer to Peer)라고 하며, [네트워크의 분류와 토폴로지](/textbook/net-topology-types)에서 비교해요.

## 패킷 — 데이터를 잘게 나눠 보내기

큰 사진 파일을 보낼 때, 네트워크는 그 파일을 한 덩어리로 보내지 않고 **작은 조각으로 나눠서** 보내요. 이 조각을 **패킷(Packet)**이라고 해요.

각 패킷에는 실어 나를 데이터 앞에 **헤더(Header)**가 붙어요. 헤더에는 보내는 쪽과 받는 쪽의 주소, 몇 번째 조각인지 같은 관리 정보가 들어 있어요. 실제로 전달하려는 데이터 부분은 **페이로드(Payload)**라고 불러요.

```text
[ 헤더: 출발지·목적지 주소, 순서 정보 ][ 페이로드: 실제 데이터 ]
```

왜 굳이 잘게 나눌까요?

- **회선을 여럿이 나눠 쓸 수 있어요.** 큰 파일 하나가 길을 오래 독차지하지 않고, 여러 사람의 패킷이 번갈아 지나갈 수 있어요.
- **문제가 생겨도 일부만 다시 보내면 돼요.** 전체를 처음부터 다시 보낼 필요가 없어요.
- **길이 막히면 다른 길로 갈 수 있어요.** 패킷마다 경로를 따로 고를 수도 있어요.

이사할 때 짐을 상자 여러 개에 나눠 담고, 상자마다 주소와 "3번 상자 중 1번" 같은 송장을 붙이는 것과 비슷해요. 받는 쪽은 상자 번호를 보고 짐을 원래대로 맞춰요.

> [!NOTE]
> 엄밀히 말하면 계층마다 데이터 단위의 이름이 달라요. 2계층에서는 프레임(Frame), 3계층에서는 패킷(Packet), 4계층의 TCP에서는 세그먼트(Segment)라고 불러요. 지금은 "잘게 나눈 데이터 조각"을 통틀어 패킷이라고 생각해도 충분해요. 정확한 구분은 [OSI 7계층](/textbook/net-osi-model)에서 배워요.

## 주소 — 누구에게 보낼까

택배에 주소가 필요하듯, 데이터도 목적지를 찾으려면 주소가 필요해요. 네트워크에는 쓰임새가 다른 주소가 여러 개 있어요.

### MAC 주소 — 장치에 붙은 고유 번호

**MAC 주소(Media Access Control Address)**는 네트워크 카드(NIC)에 붙어 있는 **48비트 물리 주소**예요. `00-1A-2B-3C-4D-5E`처럼 16진수 12자리로 적어요. 기본값은 제조 단계에서 정해지며, **같은 네트워크 안에서** 바로 옆 장치에게 데이터를 전달할 때 써요.

### IP 주소 — 네트워크 위의 위치

**IP 주소(Internet Protocol Address)**는 장치가 **어느 네트워크의 몇 번 자리에 있는지**를 나타내는 논리 주소예요. IPv4 주소는 `192.168.0.10`처럼 32비트를 10진수 네 묶음으로 적고, IPv6 주소는 128비트를 16진수로 적어요. 장치가 다른 네트워크로 옮기면 IP 주소도 바뀌어요. 라우터는 IP 주소를 보고 **네트워크와 네트워크 사이**의 경로를 정해요.

> [!TIP]
> IP 주소는 **집 주소**, MAC 주소는 그 집에 사는 사람의 **이름표**라고 생각해 보세요. 택배는 집 주소를 보고 동네까지 찾아가고, 마지막에는 이름표를 보고 정확한 사람에게 전달돼요. 이사를 가면 집 주소(IP)는 바뀌지만 이름표(MAC)는 그대로예요.

### 포트 번호 — 컴퓨터 안의 어느 프로그램인가

컴퓨터 한 대에서도 브라우저, 메신저, 음악 앱이 동시에 통신해요. 도착한 데이터를 어느 프로그램에 넘길지 정하는 번호가 **포트 번호(Port Number)**예요. IP 주소가 아파트 건물 주소라면 포트 번호는 **호수**예요. 웹 서비스는 보통 80번(HTTP)이나 443번(HTTPS)을 써요.

### 도메인 이름 — 사람을 위한 이름

`203.0.113.10` 같은 숫자는 외우기 어려워요. 그래서 `www.example.com` 같은 **도메인 이름(Domain Name)**을 붙이고, 필요할 때 **DNS(Domain Name System)**가 이 이름을 IP 주소로 바꿔 줘요. 전화번호부에서 이름으로 번호를 찾는 것과 비슷해요.

### 한눈에 비교하기

| 구분 | 크기·형식 | 예 | 역할 | 자세히 배우는 단원 |
|---|---|---|---|---|
| MAC 주소 | 48비트, 16진수 | 00-1A-2B-3C-4D-5E | 같은 네트워크 안에서 장치 찾기 | [LAN 표준과 이더넷](/textbook/net-lan-ethernet) |
| IP 주소 | IPv4 32비트, IPv6 128비트 | 192.168.0.10 | 네트워크를 넘어 목적지 찾기 | [IPv4 주소 체계](/textbook/tcpip-ipv4-address) |
| 포트 번호 | 16비트(0~65535) | 80, 443 | 컴퓨터 안의 프로그램 찾기 | [UDP와 포트 번호](/textbook/tcpip-udp-ports) |
| 도메인 이름 | 문자 | www.example.com | 사람이 기억하기 쉬운 이름 | [DNS와 DHCP](/textbook/tcpip-dns-dhcp) |

> [!NOTE]
> IP 주소만 알고 같은 네트워크 안의 MAC 주소를 모를 때는 **ARP(Address Resolution Protocol)**로 물어봐서 알아내요. [ARP·ICMP·IGMP](/textbook/tcpip-arp-icmp)에서 배워요.

## 프로토콜 — 서로 지키는 약속

**프로토콜(Protocol)**은 통신하는 양쪽이 미리 정해 둔 **규칙과 약속**이에요. 사람끼리도 같은 언어를 쓰고, 한 사람이 말하면 다른 사람이 듣는 순서를 지켜야 대화가 되듯이, 장치끼리도 데이터의 모양과 주고받는 순서를 맞춰야 통신이 돼요.

프로토콜이 정하는 내용은 보통 세 가지로 나눠요.

| 요소 | 뜻 | 예 |
|---|---|---|
| 구문(Syntax) | 데이터의 형식과 구조 | 헤더의 몇 번째 비트부터 주소가 오는가 |
| 의미(Semantics) | 각 정보가 뜻하는 것과 그에 따른 동작 | 이 값이 오면 "오류가 났다"는 뜻이다 |
| 타이밍(Timing) | 속도를 맞추고 순서를 정하는 것 | 언제, 얼마나 빨리 보내고 응답할 것인가 |

> [!EXAM]
> "프로토콜의 기본 요소" 문제가 자주 나와요. 정답은 **구문, 의미, 타이밍(순서)** 세 가지예요. 보기에 "암호화", "압축", "라우팅" 같은 그럴듯한 말이 섞여 나오니 세 가지를 정확히 기억하세요.

네트워크에는 일마다 프로토콜이 따로 있어요. 앞으로 자주 만날 대표 프로토콜을 미리 훑어보면 이래요.

| 프로토콜 | 맡은 일 |
|---|---|
| IP | 주소를 보고 패킷을 목적지 네트워크까지 보내기 |
| TCP | 빠짐없이 순서대로 전달되도록 확인하며 보내기 |
| UDP | 확인 절차 없이 빠르게 보내기 |
| DNS | 도메인 이름을 IP 주소로 바꾸기 |
| DHCP | 장치에 IP 주소를 자동으로 나눠 주기 |
| HTTP·HTTPS | 웹 페이지 주고받기(HTTPS는 암호화) |

이 프로토콜들은 한 덩어리로 일하지 않고 **계층(Layer)**으로 나뉘어 각자 맡은 일만 해요. 아래 계층은 신호를 보내는 일을, 위 계층은 사용자 서비스를 맡는 식이에요. 이렇게 나누면 한 계층을 바꿔도 다른 계층에 영향이 적어요. 계층 구조는 [OSI 7계층](/textbook/net-osi-model)과 [TCP/IP 모델과 캡슐화](/textbook/tcpip-model)에서 배워요.

## 웹 페이지 하나가 열리기까지

민수가 노트북 브라우저 주소창에 `www.example.com`을 입력하고 엔터를 눌렀어요. 화면에 페이지가 뜨기까지 대략 이런 일이 일어나요.

```text
(1) 노트북 -> DNS 서버 : www.example.com의 IP 주소는?
    노트북 <- DNS 서버 : 203.0.113.10이에요
(2) 노트북 -> 웹 서버  : 연결해도 될까요?
    노트북 <- 웹 서버  : 좋아요, 저도 연결할게요
    노트북 -> 웹 서버  : 확인했어요
(3) 노트북 -> 웹 서버  : HTTP 요청 - 첫 페이지 주세요
    노트북 <- 웹 서버  : HTTP 응답 - 200 + 페이지 내용
(4) 브라우저가 받은 내용을 해석해 화면에 표시
```

### 0단계 — 준비: 내 주소 받기

노트북은 네트워크에 연결될 때 보통 **DHCP**로 IP 주소, 서브넷 마스크, 기본 게이트웨이(밖으로 나가는 출구 라우터), DNS 서버 주소를 자동으로 받아 둬요. 이 정보가 있어야 바깥과 통신할 수 있어요.

### 1단계 — DNS: 이름을 주소로

컴퓨터는 이름이 아니라 IP 주소로 통신해요. 그래서 먼저 DNS 서버에 "`www.example.com`의 IP 주소가 뭐예요?"라고 물어요. 최근에 물어본 적이 있으면 저장해 둔 답(캐시)을 바로 써요. 답으로 `203.0.113.10`을 받았다고 해 볼게요.

### 2단계 — TCP: 연결 맺기

이제 그 IP 주소의 웹 서버에 **TCP 연결**을 맺어요. TCP는 데이터를 보내기 전에 "연결해도 될까요?" → "좋아요, 저도 연결할게요" → "확인했어요" 하고 세 번 신호를 주고받아 서로 준비됐는지 확인해요. 이것을 **3방향 핸드셰이크(3-way Handshake)**라고 해요. 웹은 보통 HTTP면 80번, HTTPS면 443번 포트로 연결해요. HTTPS라면 이어서 암호화 설정 과정(TLS)도 거쳐요.

### 3단계 — HTTP: 페이지 요청과 응답

연결이 되면 브라우저가 **HTTP 요청**을 보내요. "첫 페이지를 주세요"라는 뜻이에요. 서버는 **HTTP 응답**으로 성공했다는 상태 코드(예: 200)와 함께 페이지 내용(HTML)을 돌려줘요.

### 4단계 — 화면 그리기

브라우저는 받은 HTML을 해석하다가 이미지, 글꼴, 스타일 파일이 더 필요하면 같은 방식으로 추가 요청을 보내요. 모두 받으면 화면에 페이지가 완성돼요.

### 그 사이에 패킷은 어떻게 갈까요

위의 모든 요청과 응답은 패킷으로 나뉘어 이동해요. 노트북에서 나간 패킷은 공유기와 여러 라우터를 거치는데, 라우터는 **IP 주소**를 보고 다음에 보낼 곳을 고르고, 각 구간에서 바로 옆 장비에게 넘길 때는 **MAC 주소**를 써요. 처음 출발할 때 기본 게이트웨이의 MAC 주소를 모르면 ARP로 먼저 알아내요.

| 단계 | 쓰는 프로토콜 | 하는 일 | 자세히 배우는 단원 |
|---|---|---|---|
| 준비 | DHCP | IP 주소 등 설정값 받기 | [DNS와 DHCP](/textbook/tcpip-dns-dhcp) |
| 1 | DNS | 도메인 이름 → IP 주소 | [DNS와 DHCP](/textbook/tcpip-dns-dhcp) |
| 2 | TCP | 연결 맺고 믿을 수 있게 전달 | [TCP](/textbook/tcpip-tcp) |
| 3 | HTTP·HTTPS | 웹 페이지 요청과 응답 | [응용 계층 프로토콜](/textbook/tcpip-application-protocols) |
| 이동 | IP·ARP | 경로 선택, 다음 장비 찾기 | [라우팅의 원리](/textbook/tcpip-routing-basics) |

> [!WARNING]
> 순서를 헷갈리지 마세요. **DNS로 주소를 먼저 알아야** TCP 연결을 맺을 수 있고, **TCP 연결이 맺어져야** HTTP 요청을 보낼 수 있어요. "DNS → TCP → HTTP"로 외워 두세요.

## 핵심 정리

- 네트워크는 장치들이 연결되어 데이터를 주고받는 것이고, 인터넷은 네트워크들의 네트워크예요.
- 호스트는 주소를 갖고 데이터를 보내고 받는 끝 장치예요. 클라이언트는 요청하고 서버는 응답해요.
- 데이터는 패킷으로 잘게 나뉘어 이동하고, 각 패킷에는 주소와 관리 정보를 담은 헤더가 붙어요.
- MAC 주소는 NIC의 48비트 물리 주소로 같은 네트워크 안에서, IP 주소는 논리 주소로 네트워크를 넘어 목적지를 찾을 때 써요.
- 포트 번호는 컴퓨터 안의 프로그램을, 도메인 이름은 사람이 기억하기 쉬운 이름을 가리켜요.
- 프로토콜은 통신 규칙이고, 기본 요소는 구문·의미·타이밍이에요.
- 웹 페이지는 DNS(이름 → IP) → TCP(연결) → HTTP(요청·응답) 순서로 열려요.

## 스스로 확인하기

**1.** 프로토콜의 기본 요소에 해당하지 않는 것은?

① 구문 ② 의미 ③ 타이밍 ④ 암호화

> [!ANSWER]
> 정답: ④
> 프로토콜의 기본 요소는 구문(형식), 의미(뜻과 동작), 타이밍(속도와 순서) 세 가지예요. 암호화는 보안 기능이지 기본 요소가 아니에요.

**2.** 사용자가 입력한 도메인 이름을 IP 주소로 바꿔 주는 것은?

① DHCP ② DNS ③ ARP ④ HTTP

> [!ANSWER]
> 정답: ②
> DNS는 도메인 이름을 IP 주소로 바꿔 줘요. DHCP는 IP 주소를 자동으로 나눠 주고, ARP는 IP 주소로 MAC 주소를 찾아요.

**3.** 주소에 대한 설명으로 옳은 것은?

① IPv4 주소는 48비트로 이루어져 있다.
② MAC 주소는 네트워크 카드에 부여된 48비트 물리 주소이다.
③ IP 주소는 장치가 어느 네트워크로 옮겨 가도 절대 바뀌지 않는다.
④ 포트 번호는 같은 네트워크 안의 네트워크 카드를 구분하는 번호이다.

> [!ANSWER]
> 정답: ②
> IPv4 주소는 32비트이고, IP 주소는 연결된 네트워크에 따라 바뀌어요. 포트 번호는 한 컴퓨터 안의 프로그램(서비스)을 구분해요.

**4.** 브라우저로 웹 페이지를 처음 열 때 일어나는 일의 순서로 알맞은 것은?

① HTTP 요청 → DNS 조회 → TCP 연결
② DNS 조회 → TCP 연결 → HTTP 요청
③ TCP 연결 → DNS 조회 → HTTP 요청
④ DNS 조회 → HTTP 요청 → TCP 연결

> [!ANSWER]
> 정답: ②
> 먼저 DNS로 서버의 IP 주소를 알아내고, 그 주소로 TCP 연결을 맺은 뒤, 연결 위에서 HTTP 요청을 보내요.
