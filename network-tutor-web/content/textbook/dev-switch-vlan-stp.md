앞 단원에서 스위치가 MAC 주소로 프레임을 나르는 원리를 배웠어요. 이번에는 실제 회사 네트워크에서 스위치에 꼭 켜 두는 기능들, 즉 하나의 스위치를 여러 네트워크로 나누는 VLAN, 고리 모양 연결이 생겨도 네트워크가 멈추지 않게 하는 STP, 그리고 링크 묶기·PoE·포트 미러링을 배워요. 규격 번호와 숫자가 많이 나오니 표를 중심으로 정리하세요.

> [!GOAL]
> - VLAN의 목적과 액세스 포트·트렁크 포트, 802.1Q 태그 구조를 설명할 수 있다.
> - 서로 다른 VLAN끼리 통신하게 하는 두 가지 방법을 비교할 수 있다.
> - STP가 루트 브리지와 포트 역할을 정하는 과정을 직접 따라갈 수 있다.
> - 포트 상태와 타이머, RSTP·LACP·PoE·SPAN의 규격과 용도를 구분할 수 있다.

## VLAN — 스위치 하나를 여러 네트워크로

### 왜 필요할까

스위치는 브로드캐스트 도메인을 나누지 못해요. 그래서 PC가 수백 대인 회사에서 스위치만 이어 붙이면 ARP 요청 같은 브로드캐스트가 모든 PC로 퍼져 대역폭을 낭비하고, 부서 간 트래픽도 섞여요.

**VLAN**(Virtual LAN, 가상 LAN)은 물리적으로는 같은 스위치에 꽂혀 있어도 **논리적으로 서로 다른 LAN처럼** 나누는 기술이에요. 한 건물의 같은 층에 있어도 칸막이로 사무실을 나누는 것과 비슷해요.

- **브로드캐스트 도메인 분리**: VLAN 하나가 브로드캐스트 도메인 하나예요.
- **보안**: 다른 VLAN의 트래픽은 라우팅을 거치지 않으면 볼 수 없어요.
- **유연성**: 자리를 옮겨도 케이블을 다시 깔 필요 없이 포트의 VLAN 설정만 바꾸면 돼요.

VLAN을 정하는 기준은 여러 가지가 있지만, 가장 흔한 것은 **포트 기반 VLAN**(정적 VLAN)이에요. "1~12번 포트는 VLAN 10(영업팀), 13~24번 포트는 VLAN 20(개발팀)"처럼 포트마다 VLAN을 지정해요. 이 밖에 MAC 주소 기반, 프로토콜 기반 같은 동적 VLAN도 있어요.

### 액세스 포트와 트렁크 포트

| 구분 | 액세스 포트(Access Port) | 트렁크 포트(Trunk Port) |
|---|---|---|
| 속하는 VLAN | 하나 | 여러 개 |
| 주로 연결되는 장치 | PC, 프린터 같은 단말 | 다른 스위치, 라우터, 가상화 서버 |
| 프레임 태그 | 붙이지 않음 | VLAN 태그를 붙여서 구분 |

스위치 두 대에 VLAN 10과 20이 모두 있다면, 스위치 사이를 VLAN 수만큼 케이블로 잇는 대신 **트렁크 링크 하나**로 연결해요. 이때 프레임마다 "나는 VLAN 10 소속"이라는 꼬리표를 붙여야 받는 쪽이 구분할 수 있어요.

### IEEE 802.1Q 태그

표준 트렁크 방식은 **IEEE 802.1Q**예요. 이더넷 프레임의 출발지 MAC 주소 바로 뒤에 **4바이트 태그**를 끼워 넣어요.

```text
 +--------+--------+---------+------+------+-----+
 | 목적지 | 출발지 | 802.1Q  | 타입 | 데이터| FCS |
 |  MAC   |  MAC   | 태그 4B |      |      |     |
 +--------+--------+---------+------+------+-----+
                   |
     TPID 16비트(0x8100) + PCP 3 + DEI 1 + VID 12
```

| 필드 | 크기 | 의미 |
|---|---|---|
| TPID | 16비트 | 값 0x8100, "이 프레임에는 태그가 있다"는 표시 |
| PCP | 3비트 | 우선순위(802.1p, QoS에 사용) |
| DEI(옛 이름 CFI) | 1비트 | 혼잡 시 먼저 버려도 되는지 표시 |
| VID | 12비트 | VLAN 번호 |

VID가 12비트이므로 `2^12 = 4096`개의 값이 가능하지만, 0과 4095는 예약되어 있어서 **실제로 쓸 수 있는 VLAN은 1~4094**예요. 태그가 들어가면 프레임 내용이 바뀌므로 FCS도 다시 계산해요.

> [!NOTE]
> 시스코가 예전에 쓰던 자체 트렁크 방식으로 **ISL**(Inter-Switch Link)이 있어요. 프레임 전체를 새 헤더로 감싸는 방식인데, 지금은 거의 802.1Q만 써요.

### 네이티브 VLAN

802.1Q 트렁크에서는 **한 VLAN만 태그 없이** 보낼 수 있는데, 이것을 **네이티브 VLAN**(Native VLAN)이라고 해요. 태그가 없는 프레임이 트렁크로 들어오면 네이티브 VLAN 소속으로 취급해요. 기본값은 보통 **VLAN 1**이에요.

> [!WARNING]
> 트렁크 양쪽의 네이티브 VLAN 번호가 다르면 프레임이 엉뚱한 VLAN으로 들어가는 문제가 생겨요. 또 보안을 위해 네이티브 VLAN을 기본값 1에서 사용하지 않는 번호로 바꾸는 것을 권장해요.

### 시스코 IOS 계열 예시 — VLAN과 트렁크 설정

```text
Switch(config)# vlan 10
Switch(config-vlan)# name SALES
Switch(config-vlan)# exit
Switch(config)# interface fastEthernet 0/1
Switch(config-if)# switchport mode access
Switch(config-if)# switchport access vlan 10
Switch(config-if)# exit
Switch(config)# interface gigabitEthernet 0/1
Switch(config-if)# switchport mode trunk
Switch(config-if)# switchport trunk native vlan 99
```

ISL도 지원하는 일부 기종에서는 `switchport mode trunk` 앞에 `switchport trunk encapsulation dot1q`를 먼저 입력해야 해요. CLI 모드는 [라우터·스위치 기본 설정](/textbook/dev-router-config) 단원에서 자세히 배워요.

## VLAN 간 라우팅

VLAN이 다르면 브로드캐스트 도메인, 즉 IP 네트워크도 달라요. 그래서 VLAN 10의 PC가 VLAN 20의 PC와 통신하려면 **3계층 장비의 라우팅**이 반드시 필요해요.

### 라우터 온어스틱

**라우터 온어스틱**(Router-on-a-Stick)은 라우터의 물리 인터페이스 하나를 스위치의 트렁크 포트에 연결하고, 그 안에 VLAN마다 **서브인터페이스**를 만들어 각각 게이트웨이 역할을 시키는 방법이에요.

```text
Router(config)# interface gigabitEthernet 0/0
Router(config-if)# no shutdown
Router(config-if)# exit
Router(config)# interface gigabitEthernet 0/0.10
Router(config-subif)# encapsulation dot1Q 10
Router(config-subif)# ip address 192.168.10.1 255.255.255.0
Router(config-subif)# exit
Router(config)# interface gigabitEthernet 0/0.20
Router(config-subif)# encapsulation dot1Q 20
Router(config-subif)# ip address 192.168.20.1 255.255.255.0
```

장비가 적게 들지만, 모든 VLAN 간 트래픽이 링크 하나를 오가므로 병목이 생기기 쉬워요.

### L3 스위치의 SVI

**L3 스위치**는 스위치 안에 라우팅 기능이 들어 있어요. VLAN마다 **SVI**(Switched Virtual Interface, 가상 VLAN 인터페이스)를 만들고 IP 주소를 주면, 그 주소가 해당 VLAN의 기본 게이트웨이가 돼요.

```text
Switch(config)# ip routing
Switch(config)# interface vlan 10
Switch(config-if)# ip address 192.168.10.1 255.255.255.0
Switch(config-if)# no shutdown
```

하드웨어로 라우팅하므로 빨라서, 오늘날 회사 내부망에서는 이 방식을 주로 써요.

## STP — 루프를 막는 스패닝 트리

### 루프가 생기면 무슨 일이

장애에 대비해 스위치를 여러 경로로 연결하면 **고리 모양 경로**(루프)가 생겨요. 이더넷 프레임에는 IP의 TTL 같은 수명 필드가 없어서, 루프에 들어간 브로드캐스트는 끝없이 돌아요.

- **브로드캐스트 폭풍(Broadcast Storm)**: 브로드캐스트가 계속 복제되어 대역폭과 CPU를 다 써 버려요.
- **MAC 테이블 불안정(MAC Flapping)**: 같은 출발지 MAC이 여러 포트에서 번갈아 들어와 테이블이 계속 바뀌어요.
- **중복 프레임**: 같은 프레임이 목적지에 여러 번 도착해요.

**STP**(Spanning Tree Protocol, IEEE 802.1D)는 물리적으로는 여러 경로를 연결해 두되, 일부 포트를 **논리적으로 막아(블로킹)** 루프 없는 나무 구조를 만들어요. 쓰던 링크가 끊기면 막아 둔 포트를 열어 대체 경로로 써요. 스위치끼리는 **BPDU**(Bridge Protocol Data Unit)라는 메시지를 주고받으며 이 과정을 진행해요.

### 브리지 ID

모든 스위치는 8바이트의 **브리지 ID**(BID)를 가져요.

- **브리지 우선순위(Priority)** 2바이트: 기본값 **32768**, 관리자가 바꿀 수 있어요(4096 단위).
- **MAC 주소** 6바이트

브리지 ID는 **작을수록 우선**이에요. 우선순위를 먼저 비교하고, 같으면 MAC 주소가 작은 쪽이 이겨요.

> [!NOTE]
> 시스코 장비는 VLAN마다 STP를 따로 돌리기 때문에 우선순위에 VLAN 번호를 더해서 보여 줘요. 예를 들어 VLAN 1의 기본 우선순위는 32768 + 1 = 32769로 표시돼요.

### 선출 4단계

| 단계 | 정하는 것 | 기준 |
|---|---|---|
| 1 | 루트 브리지(Root Bridge) — 전체에서 하나 | 브리지 ID가 가장 작은 스위치 |
| 2 | 루트 포트(Root Port) — 루트가 아닌 스위치마다 하나 | 루트 브리지까지 경로 비용이 가장 작은 포트 |
| 3 | 지정 포트(Designated Port) — 링크(세그먼트)마다 하나 | 그 링크에서 루트까지 비용이 작은 쪽 포트 |
| 4 | 나머지 포트 | 블로킹(대체 포트) |

비용이 같으면 상대 스위치의 브리지 ID가 작은 쪽, 그다음 포트 ID가 작은 쪽을 골라요. 루트 브리지의 포트는 모두 지정 포트예요.

경로 비용(Path Cost)은 링크 속도로 정해지며, 빠를수록 작아요.

| 링크 속도 | 10Mbps | 100Mbps | 1Gbps | 10Gbps |
|---|---|---|---|---|
| STP 비용 | 100 | 19 | 4 | 2 |

### 따라가 보기

스위치 3대가 1Gbps 링크(비용 4)로 삼각형 모양으로 연결돼 있고, 우선순위는 모두 기본값 32768이에요.

```text
              [SW1] MAC 끝 :01
             /     \
          (4)       (4)
           /         \
 MAC 끝 :02 [SW2]---(4)---[SW3] MAC 끝 :03
```

1. **루트 브리지**: 우선순위가 같으니 MAC을 비교해요. 가장 작은 **SW1**이 루트예요.
2. **루트 포트**: SW2는 SW1로 직접 가면 비용 4, SW3를 거치면 8이므로 **SW1 쪽 포트**가 루트 포트예요. SW3도 마찬가지로 SW1 쪽 포트가 루트 포트예요.
3. **지정 포트**: SW1의 두 포트는 루트 브리지 포트라서 지정 포트예요. SW2–SW3 링크에서는 양쪽 모두 루트까지 비용이 4로 같으므로, 브리지 ID가 작은 **SW2 쪽 포트**가 지정 포트예요.
4. **블로킹**: 남은 **SW3의 SW2 쪽 포트**가 막혀요. 이제 루프가 사라졌어요.

### 포트 상태와 타이머 (802.1D)

| 상태 | BPDU | MAC 학습 | 데이터 전달 | 머무는 시간 |
|---|---|---|---|---|
| 블로킹(Blocking) | 수신만 | X | X | 최대 20초(Max Age) |
| 리스닝(Listening) | 송수신 | X | X | 15초(Forward Delay) |
| 러닝(Learning) | 송수신 | O | X | 15초(Forward Delay) |
| 포워딩(Forwarding) | 송수신 | O | O | 정상 동작 |
| 디스에이블(Disabled) | X | X | X | 관리자가 끈 상태 |

| 타이머 | 기본값 | 의미 |
|---|---|---|
| Hello Time | 2초 | 루트 브리지가 BPDU를 보내는 주기 |
| Max Age | 20초 | BPDU를 못 받아도 정보를 유지하는 최대 시간 |
| Forward Delay | 15초 | 리스닝·러닝 상태에 각각 머무는 시간 |

블로킹 포트가 포워딩이 되기까지 최대 `20 + 15 + 15 = 50초`가 걸려요. 네트워크가 50초 가까이 멈출 수 있다는 뜻이라 느린 편이에요.

> [!TIP]
> 상태 순서는 "**블·리·러·포**"로 외우세요. 이름 그대로 리스닝은 "듣기만", 러닝은 "MAC을 배우기 시작", 포워딩은 "드디어 전달"이에요.

### RSTP와 그 밖의 STP

- **RSTP(Rapid STP, IEEE 802.1w)**: 스위치끼리 직접 협상해서 대개 수 초 이내로 수렴해요. 포트 상태는 **디스카딩(Discarding)·러닝·포워딩** 세 가지로 줄었고, 대체(Alternate)·백업(Backup) 포트 역할이 추가됐어요. 지금은 802.1D 표준에 통합되었어요.
- **MSTP(Multiple STP, IEEE 802.1s)**: 여러 VLAN을 몇 개의 그룹으로 묶어 그룹마다 STP를 돌려요.
- **PortFast**(시스코 기능): PC가 연결된 액세스 포트는 루프가 생길 일이 없으므로 리스닝·러닝을 건너뛰고 바로 포워딩해요. 실수로 스위치가 연결되는 것을 막는 **BPDU 가드**와 함께 써요.

> [!EXAM]
> 루트 브리지 선출(가장 작은 BID), 우선순위 기본값 32768, 타이머 2·20·15초, 상태 순서, RSTP = 802.1w가 단골 문제예요. "우선순위가 가장 높은 값"이 아니라 "**가장 작은 값**"이 이긴다는 점을 함정으로 내요.

## 링크 묶기 — 링크 애그리게이션

**링크 애그리게이션**(Link Aggregation)은 여러 개의 물리 링크를 **하나의 논리 링크**로 묶는 기술이에요. 1Gbps 링크 4개를 묶으면 최대 4Gbps처럼 쓸 수 있고, 한 가닥이 끊겨도 나머지로 통신이 이어져요. STP도 묶인 링크를 하나로 보므로 블로킹하지 않아요.

| 이름 | 정체 |
|---|---|
| LACP(Link Aggregation Control Protocol) | 표준 협상 프로토콜. IEEE 802.3ad로 나왔고 지금은 802.1AX |
| PAgP | 시스코 전용 협상 프로토콜 |
| 이더채널(EtherChannel) | 시스코가 링크 묶음을 부르는 이름 |

- 묶을 포트들은 속도·이중 방식·VLAN 설정이 같아야 해요.
- 보통 최대 8개 링크를 동시에 활성화해요.
- 트래픽은 MAC·IP 주소 등의 해시로 링크에 나눠 실려요. 그래서 **연결 하나(흐름 하나)의 속도는 링크 한 가닥 속도를 넘지 않아요.**

## PoE — 랜선으로 전기까지

**PoE**(Power over Ethernet)는 UTP 케이블로 데이터와 함께 **전력**을 보내는 기술이에요. 천장에 다는 무선 AP나 IP 카메라, IP 전화기처럼 콘센트를 따로 끌어오기 어려운 장치에 편리해요.

- **PSE(Power Sourcing Equipment)**: 전기를 주는 쪽. PoE 스위치나 PoE 인젝터.
- **PD(Powered Device)**: 전기를 받는 쪽. AP, IP 카메라, IP 전화기.

| 규격 | 흔한 이름 | PSE 포트 출력(대략) | PD가 받는 전력(대략) |
|---|---|---|---|
| IEEE 802.3af | PoE | 15.4W | 13W |
| IEEE 802.3at | PoE+ | 30W | 25.5W |
| IEEE 802.3bt Type 3 | PoE++ | 60W | 51W |
| IEEE 802.3bt Type 4 | PoE++ | 90W | 71W |

표준 PoE의 PSE는 먼저 상대가 PoE 장치인지 확인한 뒤에 전력을 보내므로, 일반 PC를 꽂아도 고장 나지 않아요. 스위치 전체가 줄 수 있는 총 전력(PoE 예산)이 정해져 있으니 장치가 많으면 합계를 따져 봐야 해요.

## 포트 미러링과 포트 보안

### 포트 미러링(SPAN)

**포트 미러링**(Port Mirroring)은 특정 포트나 VLAN을 지나는 트래픽을 **복사해서 다른 포트로 내보내는** 기능이에요. 시스코에서는 **SPAN**(Switched Port Analyzer)이라고 불러요. 스위치는 원래 목적지 포트로만 프레임을 보내기 때문에, 분석 장비를 아무 포트에나 꽂으면 남의 트래픽을 볼 수 없어요. 그래서 침입 탐지 시스템(IDS)이나 패킷 분석기를 연결할 때 미러링 포트를 써요. 다른 스위치로 복사본을 보내는 방식은 RSPAN이라고 해요.

### 포트 보안

**포트 보안**(Port Security)은 포트에 연결할 수 있는 **MAC 주소의 수나 목록을 제한**하는 기능이에요. 허락되지 않은 장치가 연결되면 시스코 기준으로 다음 셋 중 하나로 대응해요.

| 위반 모드 | 동작 |
|---|---|
| protect | 허용되지 않은 프레임을 조용히 버림 |
| restrict | 버리고 로그를 남기며 위반 횟수를 셈 |
| shutdown(기본값) | 포트를 오류 비활성(err-disabled) 상태로 꺼 버림 |

처음 학습한 MAC을 설정에 자동으로 기록하는 **스티키(Sticky) MAC** 기능도 있어요.

## 핵심 정리

- VLAN은 스위치에서 **브로드캐스트 도메인을 나누는** 기술이며, 포트 기반 VLAN이 가장 흔해요.
- 액세스 포트는 VLAN 하나, 트렁크 포트는 여러 VLAN을 태그로 구분해 실어 날라요.
- 802.1Q 태그는 **4바이트**, VLAN ID는 **12비트**로 사용 가능한 범위는 **1~4094**예요. 태그 없이 오가는 VLAN이 **네이티브 VLAN**이에요.
- VLAN 간 통신에는 라우터 온어스틱(서브인터페이스) 또는 L3 스위치의 SVI가 필요해요.
- STP(802.1D)는 루프로 생기는 브로드캐스트 폭풍과 MAC 테이블 불안정을 막아요. **브리지 ID가 가장 작은** 스위치가 루트 브리지예요(기본 우선순위 32768).
- 포트 상태는 블로킹 → 리스닝 → 러닝 → 포워딩, 타이머는 Hello 2초·Max Age 20초·Forward Delay 15초예요.
- RSTP는 **802.1w**, 링크 묶기 표준 LACP는 **802.3ad**(현 802.1AX)예요.
- PoE는 802.3af(약 15.4W), 802.3at(PoE+, 약 30W), 802.3bt(약 60~90W) 순으로 전력이 커져요.
- 분석 장비 연결에는 포트 미러링(SPAN), 무단 장치 차단에는 포트 보안을 써요.

## 스스로 확인하기

**1.** IEEE 802.1Q에서 VLAN ID 필드의 크기와 실제로 사용 가능한 VLAN 번호 범위로 옳은 것은?
① 10비트, 1~1022 ② 12비트, 1~4094 ③ 12비트, 0~4095 ④ 16비트, 1~65534

> [!ANSWER]
> 정답: ②
> VID는 12비트라 4096개의 값이 가능하지만 0과 4095가 예약되어 있어서 1~4094를 써요.

**2.** 다음 세 스위치 중 STP 루트 브리지로 선출되는 것은? (SW-A: 우선순위 32768, MAC 끝자리 0A / SW-B: 우선순위 28672, MAC 끝자리 0F / SW-C: 우선순위 32768, MAC 끝자리 01)
① SW-A ② SW-B ③ SW-C ④ 우선순위가 같은 SW-A와 SW-C가 번갈아 맡는다

> [!ANSWER]
> 정답: ②
> 브리지 ID는 우선순위를 먼저 비교해요. SW-B의 우선순위가 가장 작으므로 MAC 주소와 상관없이 SW-B가 루트예요.

**3.** 802.1D STP에서 BPDU를 주고받고 MAC 주소도 학습하지만, 아직 사용자 데이터 프레임은 전달하지 않는 포트 상태는?
① 블로킹 ② 리스닝 ③ 러닝 ④ 포워딩

> [!ANSWER]
> 정답: ③
> 러닝 상태에서는 MAC 주소를 미리 학습해 두지만 데이터 전달은 포워딩 상태가 되어야 시작해요. 리스닝은 MAC 학습도 하지 않아요.

**4.** 802.1Q 트렁크 링크에서 태그를 붙이지 않은 채 전송되는 VLAN을 무엇이라고 하는가?
① 관리 VLAN ② 네이티브 VLAN ③ 음성 VLAN ④ 확장 VLAN

> [!ANSWER]
> 정답: ②
> 네이티브 VLAN의 프레임은 태그 없이 오가며, 기본값은 보통 VLAN 1이에요. 트렁크 양 끝의 설정이 같아야 해요.

**5.** 무선 AP에 약 30W까지 전력을 공급하는 PoE+ 규격은?
① IEEE 802.3af ② IEEE 802.3at ③ IEEE 802.1Q ④ IEEE 802.1w

> [!ANSWER]
> 정답: ②
> 802.3at가 PoE+예요. 802.3af는 약 15.4W의 초기 PoE, 802.1Q는 VLAN 태깅, 802.1w는 RSTP예요.
