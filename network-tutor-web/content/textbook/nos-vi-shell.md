리눅스 서버의 설정은 대부분 텍스트 파일이라서, 화면 없이 터미널에서 파일을 고칠 줄 알아야 해요. 그때 어느 서버에나 깔려 있는 편집기가 vi예요. 이 단원에서는 vi의 세 가지 모드와 핵심 명령을 익히고, 명령을 받아 주는 셸의 종류, 환경 변수와 설정 파일, 별칭과 히스토리, 그리고 아주 짧은 셸 스크립트까지 만들어 봐요. 리눅스 단원의 마지막 조각이에요.

> [!GOAL]
> - vi의 명령 모드·입력 모드·ex 모드를 구분하고 서로 오가는 방법을 말할 수 있다.
> - vi에서 이동·삭제·복사·붙여넣기·검색·치환·저장·종료 명령을 쓸 수 있다.
> - 셸의 종류와 확인·변경 방법, 환경 변수와 설정 파일(`/etc/profile`, `~/.bashrc` 등)의 역할을 설명할 수 있다.
> - shebang, 변수, if, for를 사용한 간단한 셸 스크립트를 읽고 실행할 수 있다.

## vi와 vim

**vi**(visual editor)는 유닉스 시절부터 쓰여 온 화면 편집기로, 거의 모든 유닉스·리눅스 시스템에 기본으로 들어 있어요. 오늘날 리눅스에서 `vi`를 입력하면 대개 그 개량판인 **vim**(Vi IMproved)이 실행돼요. vim은 vi의 명령을 그대로 쓰면서 구문 강조, 여러 번 되돌리기 같은 기능을 더했어요. 그 밖에 초보자용으로 쉬운 `nano`, 기능이 아주 많은 `emacs` 같은 편집기도 있어요.

```bash
vi notes.txt         # 파일 열기 (없으면 새로 만들 준비)
vi +10 notes.txt     # 10번째 줄에서 시작
vi + notes.txt       # 마지막 줄에서 시작
vi -R notes.txt      # 읽기 전용으로 열기 (view notes.txt 와 같음)
```

## vi의 세 가지 모드

vi가 처음 쓰는 사람에게 어려운 이유는 **키보드가 지금 어떤 모드인지에 따라 다르게 동작**하기 때문이에요. 같은 `d` 키도 명령 모드에서는 "삭제" 명령의 시작이고, 입력 모드에서는 그냥 글자 d예요.

| 모드 | 하는 일 | 들어가는 법 |
|---|---|---|
| 명령 모드(Command Mode, 일반 모드) | 커서 이동, 삭제, 복사, 붙여넣기. vi를 열면 이 모드에서 시작해요 | 다른 모드에서 `Esc` |
| 입력 모드(Insert Mode) | 글자를 입력. vim은 화면 아래에 `-- INSERT --` 표시 | 명령 모드에서 `i`, `a`, `o` 등 |
| ex 모드(라인 명령 모드, Last Line Mode) | 화면 맨 아래 줄에 명령을 입력해 저장, 종료, 치환 등 | 명령 모드에서 `:` |

```text
                i a o I A O
   +-----------+ ---------> +-----------+
   | 명령 모드 |            | 입력 모드 |
   +-----------+ <--------- +-----------+
      |     ^       Esc
    : |     | Enter(실행) / Esc
      v     |
   +-----------+
   |  ex 모드  |
   +-----------+
```

> [!WARNING]
> 입력 모드에서 바로 ex 모드로 갈 수는 없어요. 입력 모드에서 `:wq`를 치면 글자 ":wq"가 문서에 들어가 버려요. 언제나 **`Esc`로 명령 모드에 먼저 돌아온 뒤** `:`를 눌러요. 지금 무슨 모드인지 모르겠다면 `Esc`를 한두 번 누르는 것이 안전해요.

## 입력 모드로 들어가기

| 키 | 입력이 시작되는 위치 |
|---|---|
| `i` | 커서 **앞**(현재 위치)에 끼워 넣기(insert) |
| `a` | 커서 **뒤**에 덧붙이기(append) |
| `o` | 현재 줄 **아래**에 새 줄을 열고 입력(open) |
| `I` | 현재 줄의 **맨 앞**(첫 글자 앞) |
| `A` | 현재 줄의 **맨 끝** |
| `O` | 현재 줄 **위**에 새 줄을 열고 입력 |

> [!TIP]
> 소문자는 "커서 근처", 대문자는 "줄의 끝 쪽이나 반대 방향"이라고 기억하면 쉬워요. i ↔ I(줄 맨 앞), a ↔ A(줄 맨 끝), o(아래) ↔ O(위).

## 커서 이동 (명령 모드)

| 키 | 이동 |
|---|---|
| `h` `j` `k` `l` | 왼쪽, 아래, 위, 오른쪽 한 칸 |
| `w` / `b` | 다음 단어의 시작 / 이전 단어의 시작 |
| `0` / `$` | 줄의 맨 앞 / 줄의 맨 끝 |
| `^` | 줄에서 공백이 아닌 첫 글자 |
| `gg` / `G` | 파일의 첫 줄 / 마지막 줄 |
| `숫자G` (예: `15G`) | 15번째 줄로 |
| `:숫자` (예: `:15`) | 15번째 줄로(ex 모드) |
| `Ctrl + f` / `Ctrl + b` | 한 화면 아래 / 위로 |

`5j`처럼 앞에 숫자를 붙이면 그만큼 반복해요(5줄 아래로). 줄 번호를 보고 싶으면 `:set nu`, 감추려면 `:set nonu`예요.

> [!TIP]
> 손가락을 키보드 가운데 두고 쓰도록 만든 배치예요. `h`는 가장 왼쪽이라 왼쪽, `l`은 가장 오른쪽이라 오른쪽, `j`는 아래로 갈고리가 내려간 모양이라 아래라고 기억해 보세요.

## 편집: 삭제·복사·붙여넣기·되돌리기 (명령 모드)

| 키 | 동작 |
|---|---|
| `x` | 커서 위치의 한 글자 삭제 |
| `dd` | 현재 줄 삭제(잘라내기). `3dd`는 세 줄 |
| `dw` | 커서부터 단어 끝까지(뒤 공백 포함) 삭제 |
| `D` (또는 `d$`) | 커서부터 줄 끝까지 삭제 |
| `yy` | 현재 줄 복사(yank). `3yy`는 세 줄 |
| `yw` | 단어 복사 |
| `p` / `P` | 커서 뒤(줄이면 아래) / 앞(줄이면 위)에 붙여넣기 |
| `u` | 실행 취소(undo) |
| `Ctrl + r` | 취소한 것 다시 실행(redo, vim) |
| `cw` | 단어를 지우고 입력 모드로(단어 바꾸기, change word) |
| `cc` | 줄 전체를 지우고 입력 모드로 |
| `r` | 커서 위치 한 글자만 다른 글자로 바꾸기 |
| `J` | 아래 줄을 현재 줄 끝에 이어 붙이기 |
| `.` | 마지막 편집 명령을 한 번 더 |

`dd`로 지운 줄은 버려지는 것이 아니라 잘라 둔 상태라서, 다른 곳에 가서 `p`를 누르면 줄을 옮긴 셈이 돼요. ex 모드에서 `:3,7d`처럼 줄 범위를 지정해 한꺼번에 지울 수도 있어요.

## 검색과 치환

| 명령 | 동작 |
|---|---|
| `/단어` | 커서 아래쪽(앞 방향)으로 검색 |
| `?단어` | 커서 위쪽(뒤 방향)으로 검색 |
| `n` | 같은 방향으로 다음 결과 |
| `N` | 반대 방향으로 다음 결과 |

치환은 ex 모드에서 `:범위s/찾을말/바꿀말/옵션` 형식으로 해요.

| 명령 | 범위 |
|---|---|
| `:s/old/new/` | 현재 줄에서 **처음 나온 하나**만 |
| `:s/old/new/g` | 현재 줄의 **모든** old |
| `:%s/old/new/g` | **파일 전체**의 모든 old (`%`는 모든 줄) |
| `:%s/old/new/gc` | 파일 전체를 하나씩 확인(confirm)하며 |
| `:10,20s/old/new/g` | 10~20번째 줄에서만 |

예를 들어 설정 파일에 적힌 옛 서버 이름 web01을 모두 web02로 바꾸려면 `:%s/web01/web02/g`를 입력해요.

> [!EXAM]
> 끝의 `g`(global)는 "한 줄 안에서 전부"라는 뜻이고, 파일 전체를 바꾸려면 앞에 `%`가 있어야 해요. `:s/a/b/g`는 현재 줄만, `:%s/a/b/`는 각 줄의 첫 번째만 바꿔요. 이 차이를 묻는 문제가 자주 나와요.

## 저장과 종료

| 명령 | 동작 |
|---|---|
| `:w` | 저장 |
| `:w 새이름` | 다른 이름으로 저장 |
| `:q` | 종료(바뀐 내용이 없을 때만) |
| `:q!` | 저장하지 않고 강제 종료 |
| `:wq` | 저장하고 종료 |
| `:x` | 바뀐 내용이 있으면 저장하고 종료 |
| `ZZ` | 명령 모드에서 대문자 Z 두 번. `:x`와 같음 |
| `:w!` / `:wq!` | 강제로 저장(읽기 전용 파일이지만 권한이 있을 때) |

ex 모드에서 쓰는 몇 가지 명령도 더 알아 두세요. `:e 파일`은 다른 파일 열기, `:r 파일`은 다른 파일의 내용을 커서 아래에 끼워 넣기, `:!ls`처럼 `!`를 붙이면 vi를 떠나지 않고 셸 명령을 실행해요.

> [!WARNING]
> 내용을 고친 뒤 `:q`만 입력하면 "저장하지 않은 변경 사항이 있다"는 경고와 함께 종료되지 않아요. 저장하려면 `:wq`, 버리려면 `:q!`예요. vi가 비정상적으로 끝나면 `.파일이름.swp` 같은 스왑 파일이 남아, 다음에 열 때 복구할지 묻기도 해요.

## 셸의 종류

**셸**(Shell)은 사용자가 입력한 명령을 해석해 커널에 전달하는 명령어 해석기예요([리눅스 기초](/textbook/nos-linux-intro) 참고). 셸에도 여러 종류가 있어요.

| 셸 | 이름의 뜻과 특징 |
|---|---|
| `sh` | 본 셸(Bourne Shell). AT&T 벨 연구소의 스티븐 본이 만든 초기 유닉스의 표준 셸 |
| `bash` | 본 어게인 셸(Bourne Again Shell). GNU 프로젝트에서 만든 sh 호환 셸로, 명령 히스토리·자동 완성·별칭 등을 갖춤. **대부분 리눅스의 기본 셸** |
| `csh` | C 셸. 버클리(BSD)의 빌 조이가 만든 셸로, 문법이 C 언어와 비슷해요 |
| `tcsh` | csh를 개선한 셸. 명령줄 편집과 자동 완성을 더함 |
| `ksh` | 콘 셸(Korn Shell). AT&T의 데이비드 콘이 만든, sh와 호환되면서 csh의 장점을 더한 셸 |
| `zsh` | Z 셸. 기능과 꾸미기 옵션이 매우 많고, 최근 macOS의 기본 셸 |

> [!NOTE]
> 많은 배포판에서 `/bin/sh`는 실제 본 셸이 아니라 다른 셸을 가리키는 링크예요. 레드햇 계열은 bash, 데비안·우분투는 가볍고 빠른 dash를 가리켜요.

### 셸 확인과 변경

```bash
echo $SHELL          # 내 로그인 셸 (예: /bin/bash)
echo $0              # 지금 실행 중인 셸
cat /etc/shells      # 이 시스템에서 쓸 수 있는 셸 목록
chsh -s /bin/zsh     # 내 로그인 셸을 zsh로 변경 (다음 로그인부터)
```

`chsh`로 바꾸면 `/etc/passwd`의 일곱 번째 필드(로그인 셸)가 바뀌어요. root는 `usermod -s /bin/zsh jiwoo`로 다른 사용자의 셸을 바꿀 수 있어요. 지금 셸 안에서 `bash`, `csh`처럼 이름을 입력하면 그 셸이 새로 실행되고, `exit`로 원래 셸로 돌아와요.

## 셸 변수와 환경 변수

### 만들고, 보고, 내보내기

```bash
SITE=example.com        # 셸 변수 만들기 (= 양쪽에 공백 없이!)
echo $SITE              # 값 꺼내 쓰기 → example.com
export SITE             # 환경 변수로 내보내기
export MODE=test        # 만들면서 바로 내보내기
unset MODE              # 변수 삭제
```

- **셸 변수**는 지금 셸 안에서만 쓰여요.
- **환경 변수**(Environment Variable)는 `export`로 내보낸 변수로, 이 셸에서 실행하는 **자식 프로세스(다른 프로그램, 스크립트)에게도 전달**돼요.
- `env`(또는 `printenv`)는 환경 변수만, `set`은 셸 변수와 환경 변수(그리고 함수)까지 모두 보여 줘요.

> [!WARNING]
> `SITE = example.com`처럼 등호 양쪽에 공백을 넣으면 셸이 `SITE`라는 명령을 실행하려다 오류가 나요. 변수 대입에서는 공백을 넣지 마세요.

### 자주 쓰는 환경 변수

| 변수 | 뜻 |
|---|---|
| `PATH` | 명령어를 찾을 디렉터리 목록(콜론으로 구분) |
| `HOME` | 내 홈 디렉터리 |
| `USER` | 내 사용자 이름 |
| `SHELL` | 내 로그인 셸 |
| `PWD` | 현재 디렉터리 |
| `PS1` | 프롬프트 모양 |
| `HISTSIZE` | 기억할 명령 히스토리 개수 |
| `LANG` | 언어와 문자 인코딩(예: `ko_KR.UTF-8`) |
| `HOSTNAME` | 호스트 이름 |

`ls`라고만 입력해도 실행되는 이유는 셸이 `PATH`에 적힌 디렉터리를 차례로 뒤져 `ls` 파일을 찾아 주기 때문이에요. 현재 디렉터리는 보안상 `PATH`에 들어 있지 않아서, 지금 위치의 스크립트는 `./script.sh`처럼 경로를 붙여 실행해요. 새 디렉터리를 추가하려면 기존 값 뒤에 이어 붙여요.

```bash
export PATH=$PATH:/opt/tools/bin
```

## 셸 설정 파일

환경 변수나 별칭을 로그인할 때마다 자동으로 적용하려면 셸 설정 파일에 적어요. bash 기준으로 정리하면 이래요.

| 파일 | 적용 범위 | 읽는 때 |
|---|---|---|
| `/etc/profile` | 모든 사용자 | 로그인할 때. 이 안에서 `/etc/profile.d/*.sh`도 읽어요 |
| `/etc/bashrc` (데비안 계열 `/etc/bash.bashrc`) | 모든 사용자 | bash를 대화형으로 열 때(보통 `~/.bashrc`를 통해) |
| `~/.bash_profile` | 해당 사용자 | 로그인할 때. 보통 안에서 `~/.bashrc`를 불러와요 |
| `~/.bashrc` | 해당 사용자 | 새 bash 창(로그인하지 않는 대화형 셸)을 열 때마다. 별칭·함수를 주로 여기에 |
| `~/.bash_logout` | 해당 사용자 | 로그아웃할 때 |

로그인할 때 읽는 흐름은 대략 이래요(레드햇 계열 기준).

```text
로그인 → /etc/profile → ~/.bash_profile → ~/.bashrc → /etc/bashrc
```

- `~/.bash_profile`이 없으면 bash는 `~/.bash_login`, 그다음 `~/.profile`을 찾아요. 우분투는 기본으로 `~/.profile`을 써요.
- 설정 파일을 고친 뒤 다시 로그인하지 않고 바로 적용하려면 `source ~/.bashrc` 또는 `. ~/.bashrc`를 실행해요.
- 새 사용자를 만들 때 홈 디렉터리에 복사되는 기본 설정 파일은 `/etc/skel`에 있어요([리눅스 권한과 사용자](/textbook/nos-linux-permissions-users) 참고).

> [!EXAM]
> "모든 사용자에게 공통으로 적용되는 환경 설정 파일" → `/etc/profile`, "특정 사용자만의 별칭·함수를 두는 파일" → `~/.bashrc`, "로그인할 때 읽는 개인 설정 파일" → `~/.bash_profile`. 시스템 전체는 `/etc`, 개인은 홈(`~`)의 숨김 파일이라고 구분하세요.

## alias와 history

### alias — 명령에 별명 붙이기

```bash
alias ll='ls -l'            # ll만 쳐도 ls -l 실행
alias rm='rm -i'            # 지우기 전에 항상 확인
alias                       # 설정된 별칭 목록
unalias ll                  # 별칭 해제
```

명령줄에서 만든 별칭은 셸을 닫으면 사라져요. 계속 쓰려면 `~/.bashrc`에 적어 둬요. 레드햇 계열의 root 계정에는 `rm`, `cp`, `mv`에 `-i`를 붙인 별칭이 기본으로 들어 있어요.

### history — 지난 명령 다시 쓰기

| 명령 | 하는 일 |
|---|---|
| `history` | 지금까지 입력한 명령 목록(번호와 함께) |
| `!!` | 바로 전 명령 다시 실행 |
| `!번호` (예: `!105`) | 그 번호의 명령 다시 실행 |
| `!문자열` (예: `!sys`) | 그 글자로 시작하는 가장 최근 명령 다시 실행 |
| `history -c` | 히스토리 지우기 |
| `↑` `↓` | 이전·다음 명령 불러오기 |
| `Ctrl + r` | 지난 명령을 글자로 거꾸로 검색 |

히스토리는 로그아웃할 때 `~/.bash_history` 파일에 저장되고, 개수는 `HISTSIZE`(메모리)와 `HISTFILESIZE`(파일) 변수로 정해요. 그 밖에 `Tab`(명령·파일 이름 자동 완성), `Ctrl + C`(실행 중인 명령 중단), `Ctrl + D`(입력 끝, 빈 줄에서 누르면 로그아웃), `Ctrl + L`(화면 지우기)도 자주 써요.

## 셸 스크립트 맛보기

**셸 스크립트**(Shell Script)는 명령어들을 파일에 적어 두고 한 번에 실행하는 프로그램이에요. 매일 하는 점검이나 백업을 스크립트로 만들어 cron에 걸어 두면 자동화가 돼요([리눅스 프로세스와 시스템 관리](/textbook/nos-linux-process-system) 참고).

```bash
#!/bin/bash
# check_dirs.sh - 사용법: ./check_dirs.sh 이름

if [ $# -eq 0 ]; then
    echo "사용법: $0 이름"
    exit 1
fi

NAME=$1
TODAY=$(date +%F)
echo "안녕하세요, ${NAME}님. 오늘 날짜는 ${TODAY}예요."

for DIR in /etc /var/log /backup; do
    if [ -d "$DIR" ]; then
        echo "$DIR : 있음"
    else
        echo "$DIR : 없음"
    fi
done
```

```text
$ chmod +x check_dirs.sh
$ ./check_dirs.sh 민수
안녕하세요, 민수님. 오늘 날짜는 2026-03-02예요.
/etc : 있음
/var/log : 있음
/backup : 없음
```

한 줄씩 뜯어 볼게요.

- **`#!/bin/bash`** — 첫 줄의 `#!`를 **셔뱅**(shebang)이라고 해요. "이 파일은 `/bin/bash`로 실행하라"는 표시예요. 그 밖의 `#`로 시작하는 줄은 주석이에요.
- **`$#`, `$0`, `$1`** — 스크립트에 넘긴 인자의 개수, 스크립트 이름, 첫 번째 인자예요. 인자가 하나도 없으면 사용법을 알려 주고 `exit 1`로 끝내요.
- **`NAME=$1`, `$(date +%F)`** — 변수에 값을 넣어요. `$(명령)`은 명령의 실행 결과를 값으로 쓰는 방법이에요.
- **`if [ 조건 ]; then ... else ... fi`** — 조건에 따라 갈라져요. `[` 와 `]` 안쪽에는 반드시 공백이 있어야 해요. `if`를 거꾸로 쓴 `fi`로 닫아요.
- **`for 변수 in 목록; do ... done`** — 목록의 값을 하나씩 변수에 넣으며 반복해요.
- **`chmod +x`** — 실행 권한을 줘야 `./check_dirs.sh`로 실행할 수 있어요. 실행 권한 없이 `bash check_dirs.sh 민수`처럼 셸에 파일을 넘겨 실행하는 방법도 있어요.

`[ ]` 안에서 자주 쓰는 조건은 이래요.

| 조건 | 뜻 |
|---|---|
| `-eq` `-ne` | 숫자가 같다 / 다르다 |
| `-gt` `-ge` `-lt` `-le` | 크다 / 크거나 같다 / 작다 / 작거나 같다 |
| `=` `!=` | 문자열이 같다 / 다르다 |
| `-f 파일` | 일반 파일이 있다 |
| `-d 디렉터리` | 디렉터리가 있다 |
| `-e 경로` | 무엇이든 존재한다 |

명령이 끝나면 성공했는지를 **종료 상태**(Exit Status)로 남기는데, `$?`로 확인할 수 있어요. **0이면 성공, 0이 아니면 실패**예요.

> [!TIP]
> 따옴표도 구분해 두세요. 큰따옴표 안에서는 변수가 값으로 바뀌고(`"$HOME"` → `/home/minsu`), 작은따옴표 안에서는 글자 그대로 남아요(`'$HOME'` → `$HOME`).

## 핵심 정리

- vi의 세 모드: 명령 모드(시작 모드, 이동·삭제·복사), 입력 모드(`i` `a` `o` `I` `A` `O`로 진입), ex 모드(`:`로 진입). 돌아올 때는 `Esc`.
- 이동: `h` `j` `k` `l`, `w` `b`, `0` `$`, `gg` `G`, `:숫자`.
- 편집: `x` 한 글자, `dd` 한 줄 삭제, `yy` 복사, `p` 붙여넣기, `u` 취소, `Ctrl + r` 다시 실행, `cw` 단어 바꾸기.
- 검색 `/` `?` `n` `N`, 전체 치환 `:%s/old/new/g`.
- 저장·종료: `:w`, `:q`, `:wq`, `:q!`(저장 안 함), `:x`와 `ZZ`(저장 후 종료).
- 셸: sh(본), bash(리눅스 기본), csh·tcsh(C 문법), ksh(콘), zsh. 목록은 `/etc/shells`, 변경은 `chsh -s`, 확인은 `echo $SHELL`.
- `export`로 환경 변수를 자식 프로세스에 전달, `env`는 환경 변수, `set`은 모든 변수. `PATH`는 명령 검색 경로.
- `/etc/profile`(전체 사용자, 로그인), `~/.bash_profile`(개인, 로그인), `~/.bashrc`(개인, 별칭·함수), 바로 적용은 `source`.
- 스크립트: 첫 줄 `#!/bin/bash`, `chmod +x` 후 `./파일`, `if [ ]; then fi`, `for in; do done`, `$?`가 0이면 성공.

## 스스로 확인하기

**1.** vi로 설정 파일을 고치다가 내용을 저장하지 않고 그대로 끝내려고 해요. 명령 모드에서 입력할 명령은?
① `:wq` ② `:q!` ③ `ZZ` ④ `:x`

> [!ANSWER]
> 정답: ②
> `:q!`는 변경 내용을 버리고 강제 종료해요. `:wq`, `ZZ`, `:x`는 모두 저장한 뒤 종료해요.

**2.** vi에서 파일 전체에 있는 `http`라는 글자를 모두 `https`로 바꾸는 명령은?
① `:s/http/https/` ② `:s/http/https/g` ③ `:%s/http/https/g` ④ `/http/https/g`

> [!ANSWER]
> 정답: ③
> `%`는 모든 줄, 끝의 `g`는 한 줄 안의 모든 일치 항목을 뜻해요. ①은 현재 줄의 첫 번째만, ②는 현재 줄 전체만 바꾸고, ④는 검색 명령이에요.

**3.** vi의 명령 모드에서 현재 줄의 **위쪽**에 새 줄을 만들고 바로 입력을 시작하는 키는?
① `o` ② `O` ③ `A` ④ `I`

> [!ANSWER]
> 정답: ②
> 대문자 `O`는 위에, 소문자 `o`는 아래에 새 줄을 열어요. `A`는 줄 끝, `I`는 줄 맨 앞에서 입력을 시작해요.

**4.** 시스템의 모든 사용자가 로그인할 때 공통으로 적용되도록 환경 변수를 설정하려면 어느 파일에 적는 것이 알맞을까요?
① `~/.bashrc` ② `~/.bash_logout` ③ `/etc/profile` ④ `/etc/shells`

> [!ANSWER]
> 정답: ③
> `/etc/profile`은 모든 사용자의 로그인 셸이 읽는 시스템 전체 설정 파일이에요. `~/.bashrc`는 개인 설정이고, `/etc/shells`는 사용할 수 있는 셸의 목록이에요.

**5.** 다음 스크립트를 `./count.sh`로 실행했을 때 출력되는 줄 수는?

```bash
#!/bin/bash
for N in 1 2 3; do
    if [ $N -ne 2 ]; then
        echo "번호 $N"
    fi
done
```

① 1줄 ② 2줄 ③ 3줄 ④ 0줄

> [!ANSWER]
> 정답: ②
> N이 1, 2, 3으로 바뀌며 세 번 반복하지만, `-ne 2`(2가 아님) 조건 때문에 N이 2일 때는 출력하지 않아요. 그래서 "번호 1", "번호 3" 두 줄이 나와요.
