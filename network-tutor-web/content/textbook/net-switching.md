세상의 모든 컴퓨터를 서로 한 줄씩 직접 이을 수는 없어요. 그래서 통신망은 중간에 교환기(Switching Node)를 두고, 데이터를 이 교환기에서 저 교환기로 넘겨 가며 목적지까지 보내요. 이 단원에서는 그 "넘겨 주는 방식"인 교환 방식 세 가지와, 패킷 교환 안의 데이터그램·가상 회선 방식을 비교해요. 각 방식의 특징을 보고 이름을 고르는 문제가 꾸준히 나오는 단원이에요.

> [!GOAL]
> - 회선 교환·메시지 교환·패킷 교환의 동작 방식과 장단점을 비교할 수 있다.
> - 축적 교환(저장 후 전달)이 무엇인지, 패킷 교환이 메시지 교환보다 빠른 이유를 설명할 수 있다.
> - 데이터그램 방식과 가상 회선 방식의 차이를 연결 설정·경로·순서 관점에서 구분할 수 있다.

## 교환이란 무엇일까

교환(Switching)은 여러 사용자가 통신망을 나눠 쓰도록, 송신자와 수신자 사이에 **그때그때 길을 만들어 주거나 데이터를 다음 노드로 넘겨 주는 일**이에요. 교환 방식은 크게 두 갈래예요.

- **회선 교환**: 통신을 시작하기 전에 길을 통째로 예약해 두고 그 길로만 보내요.
- **축적 교환(Store-and-Forward)**: 미리 길을 예약하지 않고, 각 교환기가 데이터를 일단 받아 저장했다가 다음 교환기로 넘겨요. 저장하는 단위에 따라 **메시지 교환**과 **패킷 교환**으로 나뉘어요.

> [!TIP]
> 생활 속에 비유하면 이래요.
> - 회선 교환: 출발 전에 목적지까지 차선 하나를 통째로 비워 두고, 도착할 때까지 다른 차는 그 차선을 못 쓰게 하는 방식
> - 메시지 교환: 이사 짐 전체를 트럭 한 대에 싣고, 중간 창고마다 다 내렸다가 다시 싣는 방식
> - 패킷 교환: 짐을 작은 상자 여러 개로 나눠 택배로 보내는 방식

```text
교환 방식
 +-- 회선 교환
 +-- 축적 교환(저장 후 전달)
      +-- 메시지 교환
      +-- 패킷 교환
           +-- 데이터그램
           +-- 가상 회선
```

## 회선 교환

### 동작 과정

회선 교환(Circuit Switching)은 전화를 떠올리면 쉬워요. 통신은 세 단계로 이루어져요.

1. **회선 설정(Setup)**: 송신자에서 수신자까지 교환기들을 거쳐 물리적인 전용 경로를 연결해요.
2. **데이터 전송**: 연결된 경로를 두 사람만 독점해서 데이터를 주고받아요.
3. **회선 해제(Release)**: 통신이 끝나면 경로를 끊어 다른 사용자가 쓸 수 있게 돌려줘요.

### 특징

- 한 번 연결되면 대역폭이 **고정**되고 지연이 **일정하고 짧아서** 음성 통화 같은 실시간 통신에 잘 맞아요.
- 연결된 동안에는 다른 사용자와 다투지 않으므로 전송 중 혼잡이 생기지 않아요.
- 대신 **아무 말도 하지 않는 동안에도 회선을 차지**하므로 효율이 낮아요. 데이터가 띄엄띄엄 생기는(버스트성) 컴퓨터 통신에서는 낭비가 커요.
- 통신 전에 회선 설정 시간이 필요하고, 경로가 이미 다 쓰이고 있으면 연결 자체가 거부돼요(통화 중 상태).
- 교환기가 데이터를 저장하지 않고 그대로 흘려보내므로, **양쪽 단말의 전송 속도와 코드 형식이 같아야** 해요. 중간에서 속도 변환이나 코드 변환을 해 줄 수 없어요.
- 대표 예: 일반 공중 전화망(PSTN)

> [!NOTE]
> 회선 교환기는 내부 구조에 따라 **공간 분할 교환**(입력선과 출력선을 물리적으로 따로 이어 주는 방식)과 **시분할 교환**(디지털 신호를 시간 칸에 나눠 순서를 바꿔 끼워 주는 방식)으로 나뉘기도 해요.

## 메시지 교환

메시지 교환(Message Switching)은 보낼 내용을 **메시지 하나 통째로** 다음 교환기에 넘기는 축적 교환 방식이에요. 각 교환기는 메시지 전체를 받아 저장장치에 보관한 뒤, 다음 회선이 비면 그때 넘겨요.

- 전용 경로를 잡지 않으므로 회선을 여러 사용자가 나눠 써서 **회선 효율이 높아요**.
- 메시지 길이에 제한이 없고, 교환기마다 메시지 전체를 저장해야 하므로 **큰 저장 공간**이 필요해요.
- 교환기마다 메시지를 다 받은 뒤에야 넘기므로 **지연이 길고 들쭉날쭉**해서 실시간·대화형 통신에는 맞지 않아요.
- 교환기가 메시지를 저장하므로 수신자가 당장 받을 수 없어도 보관해 두었다가 나중에 전달할 수 있고, 같은 메시지를 여러 곳에 보내는 **동보 전송**, **우선순위** 처리, **속도·코드 변환**이 가능해요.
- 대표 예: 옛 전보와 텔렉스 같은 서비스

## 패킷 교환

### 동작 방식

패킷 교환(Packet Switching)은 메시지를 **일정한 크기 이하의 패킷**(Packet)으로 잘라 보내는 축적 교환 방식이에요. 각 패킷에는 목적지 정보와 순서 번호 등이 담긴 헤더가 붙어요. 교환기(오늘날에는 라우터)는 패킷을 잠깐 메모리에 저장했다가 알맞은 다음 노드로 넘기고, 수신 측은 패킷들을 모아 원래 메시지로 다시 조립해요.

### 특징

- 회선을 여러 사용자의 패킷이 번갈아 쓰므로 **회선 효율이 높아요**. 데이터가 있는 사용자만 회선을 쓰는 통계적 다중화의 장점을 그대로 누려요([다중화와 다중 접속](/textbook/net-multiplexing) 참고).
- 패킷이 작아서 교환기의 디스크가 아닌 **메모리 버퍼**에 잠깐 저장했다가 바로 넘길 수 있고, 여러 구간을 동시에 쓸 수 있어서(아래 예제) 메시지 교환보다 지연이 훨씬 짧아요.
- 경로 중 한 곳이 고장 나도 다른 길로 돌아갈 수 있어 **신뢰성이 높아요**.
- 서로 다른 속도나 형식의 단말 사이에서도 **속도·코드 변환**이 가능해요.
- 대신 패킷마다 헤더가 붙어 **오버헤드**가 생기고, 사용자가 몰리면 대기가 길어지거나 패킷이 버려지는 **혼잡**이 생길 수 있어요. 지연이 일정하지 않은 것도 단점이에요.
- 대표 예: 인터넷(IP), X.25

### 패킷 교환이 메시지 교환보다 빠른 이유

A에서 B까지 교환기 두 대(R1, R2)를 거쳐 3,000비트를 보낸다고 해 봐요. 각 회선의 속도는 1,000bps이고, 계산을 쉽게 하려고 전파 지연·처리 시간·헤더 크기는 무시할게요.

```text
 A ------ R1 ------ R2 ------ B     (회선 3개, 각 1,000bps)
```

**메시지 교환**: 3,000비트를 한 회선으로 넘기는 데 3초가 걸리고, 교환기는 메시지를 다 받은 뒤에야 다음으로 넘겨요. 회선이 3개이므로 3초 × 3 = **9초**가 걸려요.

**패킷 교환**: 1,000비트짜리 패킷 3개(P1, P2, P3)로 나누면 한 회선을 건너는 데 패킷당 1초예요. R1이 P1을 R2로 넘기는 동안 A는 P2를 R1으로 보낼 수 있어서, 여러 회선이 동시에 일해요.

| 시간 구간 | A→R1 회선 | R1→R2 회선 | R2→B 회선 |
|---|---|---|---|
| 0~1초 | P1 | | |
| 1~2초 | P2 | P1 | |
| 2~3초 | P3 | P2 | P1 |
| 3~4초 | | P3 | P2 |
| 4~5초 | | | P3 |

마지막 패킷이 **5초**에 도착해요. 일반적으로 `(회선 수 + 패킷 수 − 1) × 패킷 하나의 전송 시간` = (3 + 3 − 1) × 1초 = 5초예요. 이렇게 잘게 나눠 여러 구간을 동시에 쓰는 효과(파이프라이닝) 덕분에 패킷 교환이 더 빨라요.

> [!NOTE]
> 같은 조건의 회선 교환이라면 회선 설정을 마친 뒤에는 교환기가 저장하지 않고 그대로 흘려보내므로 전송에 3초(+전파 지연)가 걸려요. 대신 맨 앞에 회선 설정 시간이 더해지고, 통신하는 동안 세 회선을 모두 독점해요.

## 데이터그램과 가상 회선

패킷 교환은 패킷들이 길을 어떻게 찾느냐에 따라 두 방식으로 나뉘어요.

### 데이터그램 방식

데이터그램(Datagram) 방식은 **연결 설정 없이** 패킷 하나하나를 독립적으로 다뤄요. 각 패킷에 목적지 주소 전체가 들어 있고, 교환기는 패킷이 도착할 때마다 그 순간 가장 좋은 경로로 보내요.

- 같은 메시지의 패킷들이 **서로 다른 경로**로 갈 수 있어서 **도착 순서가 뒤바뀔 수 있어요**. 순서 맞추기는 수신 측 몫이에요.
- 미리 연결을 맺을 필요가 없어 짧은 메시지를 보낼 때 빠르고, 어느 노드가 고장 나도 다른 길로 돌아가기 쉬워요.
- 비연결형(Connectionless) 서비스라고 불러요. 인터넷의 IP가 대표적인 데이터그램 방식이에요.

### 가상 회선 방식

가상 회선(Virtual Circuit) 방식은 데이터를 보내기 전에 **송신자와 수신자 사이의 논리적인 경로를 먼저 설정**해요. 이후 모든 패킷은 그 경로를 그대로 따라가요.

- 회선 교환처럼 "설정 → 전송 → 해제" 세 단계를 거치지만, 물리 회선을 독점하는 것이 아니라 **논리적인 길만 정해 두고 회선은 다른 사용자와 나눠 써요**.
- 모든 패킷이 같은 길로 가므로 **보낸 순서대로 도착**해요.
- 패킷에는 긴 목적지 주소 대신 짧은 **가상 회선 번호**만 붙여도 돼요.
- 연결형(Connection-oriented) 서비스라고 불러요. X.25, 프레임 릴레이, ATM이 대표적이에요.
- 관리자가 미리 고정해 두고 계속 쓰는 **PVC**(영구 가상 회선)와, 필요할 때마다 설정했다가 끊는 **SVC**(교환 가상 회선)가 있어요. 이 기술들은 [WAN 기술](/textbook/net-wan-technologies)에서 다시 만나요.

| 항목 | 데이터그램 | 가상 회선 |
|---|---|---|
| 연결 설정 | 없음(비연결형) | 있음(연결형) |
| 경로 결정 | 패킷마다 따로 | 설정 때 한 번, 모든 패킷이 같은 경로 |
| 도착 순서 | 뒤바뀔 수 있음 | 보낸 순서대로 |
| 헤더의 주소 정보 | 목적지 전체 주소 | 가상 회선 번호 |
| 노드 장애 시 | 다른 경로로 쉽게 우회 | 회선을 다시 설정해야 함 |
| 어울리는 데이터 | 짧고 산발적인 데이터 | 길고 연속적인 데이터 |
| 대표 예 | IP | X.25, 프레임 릴레이, ATM |

> [!WARNING]
> "가상 회선 방식은 물리적인 전용 회선을 할당한다"는 틀린 설명이에요. 전용으로 잡는 것은 **경로라는 약속**일 뿐, 실제 회선은 다른 사용자의 패킷과 함께 써요. 또 인터넷에서 TCP는 연결형이지만, 그 아래 IP망 자체는 데이터그램 방식이라는 점도 구분해 두세요.

## 세 가지 교환 방식 비교

| 항목 | 회선 교환 | 메시지 교환 | 패킷 교환 |
|---|---|---|---|
| 경로 | 전용 물리 경로 설정 | 경로 예약 없음 | 데이터그램: 없음 / 가상 회선: 논리 경로 |
| 전송 단위 | 연속된 비트 흐름 | 메시지 전체 | 일정 크기 이하의 패킷 |
| 중간 저장 | 하지 않음 | 메시지 전체를 저장 | 패킷을 메모리에 잠깐 저장 |
| 지연 | 설정 후 짧고 일정 | 길고 불규칙 | 짧지만 불규칙 |
| 회선 효율 | 낮음 | 높음 | 높음 |
| 실시간 통신 | 적합 | 부적합 | 비교적 적합 |
| 속도·코드 변환 | 불가 | 가능 | 가능 |
| 대표 예 | 전화망(PSTN) | 전보, 텔렉스 | 인터넷, X.25 |

> [!EXAM]
> 단서가 되는 표현을 이름과 짝지어 두세요.
> - "통신 중 전용 경로 독점", "실시간 음성에 적합", "속도·코드 변환 불가" → 회선 교환
> - "메시지 전체를 저장 후 전달", "대용량 저장 장치 필요", "실시간 부적합" → 메시지 교환
> - "일정 크기로 나누어 전송", "회선 효율 높음", "장애 시 우회" → 패킷 교환
> - "패킷마다 독립 경로, 순서 뒤바뀜 가능" → 데이터그램 / "논리 경로 설정, 순서 보장" → 가상 회선

> [!NOTE]
> 패킷 중에서도 크기를 53바이트로 고정한 작은 단위를 **셀**(Cell)이라 하고, 이를 쓰는 교환을 셀 교환이라고 해요. ATM이 대표적이며, WAN 단원에서 함께 다뤄요.

## 핵심 정리

- 교환 방식은 회선 교환과 축적 교환(메시지 교환, 패킷 교환)으로 나뉜다.
- 회선 교환은 설정–전송–해제 3단계, 전용 경로라 지연이 일정하고 실시간에 적합하지만 회선 효율이 낮고 속도·코드 변환이 불가능하다.
- 메시지 교환은 메시지 전체를 교환기마다 저장 후 전달한다. 효율은 높지만 지연이 길어 실시간에 부적합하다.
- 패킷 교환은 일정 크기 패킷으로 나눠 저장 후 전달한다. 회선 효율과 신뢰성이 높고, 파이프라이닝으로 메시지 교환보다 빠르다.
- 데이터그램은 비연결형으로 패킷마다 경로가 달라 순서가 바뀔 수 있다(IP).
- 가상 회선은 연결형으로 논리 경로를 먼저 설정해 순서대로 도착한다(X.25, 프레임 릴레이, ATM). PVC와 SVC가 있다.

## 스스로 확인하기

**1.** 다음 설명에 해당하는 교환 방식은?
"통신이 시작되기 전에 경로를 확보하며, 통신하는 동안 다른 사용자가 그 경로를 쓸 수 없다. 전송 지연은 일정하지만 데이터가 없는 순간에도 경로를 점유한다."
① 메시지 교환 ② 데이터그램 패킷 교환 ③ 회선 교환 ④ 가상 회선 패킷 교환

> [!ANSWER]
> 정답: ③
> 경로를 독점하고 비어 있는 시간에도 점유하는 것은 회선 교환이에요. 가상 회선은 논리 경로만 정할 뿐 회선을 다른 사용자와 나눠 써요.

**2.** 데이터그램 방식에 대한 설명으로 옳지 않은 것은?
① 패킷마다 목적지 주소가 들어 있다. ② 패킷들이 서로 다른 경로로 전달될 수 있다. ③ 수신 측에서 패킷 순서를 다시 맞춰야 할 수 있다. ④ 전송 전에 논리적인 연결을 반드시 설정해야 한다.

> [!ANSWER]
> 정답: ④
> 데이터그램은 비연결형이라 연결 설정 없이 바로 보내요. 논리 경로를 먼저 설정하는 것은 가상 회선 방식이에요.

**3.** 송신자와 수신자 사이에 회선이 4개(교환기 3대) 있고, 각 회선의 속도가 같아 패킷 하나를 한 회선으로 보내는 데 2초가 걸려요. 메시지를 패킷 5개로 나눠 패킷 교환으로 보내면 마지막 패킷이 도착하기까지 몇 초가 걸릴까요? (전파 지연·처리 시간은 무시)
① 10초 ② 16초 ③ 18초 ④ 40초

> [!ANSWER]
> 정답: ②
> (회선 수 + 패킷 수 − 1) × 패킷당 시간 = (4 + 5 − 1) × 2초 = 16초예요. 메시지 교환이라면 메시지 전체(10초 분량)를 회선 4개에서 차례로 넘겨 40초가 걸려요.

**4.** 메시지 교환 방식의 특징으로 옳은 것은?
① 같은 메시지를 여러 수신자에게 보내는 동보 전송이 가능하다. ② 교환기에 저장하지 않으므로 저장 장치가 필요 없다. ③ 실시간 음성 통화에 가장 적합하다. ④ 송수신 단말의 속도가 반드시 같아야 한다.

> [!ANSWER]
> 정답: ①
> 메시지 교환은 교환기가 메시지를 저장하므로 동보 전송, 우선순위 처리, 속도·코드 변환이 가능해요. 대신 지연이 길어 실시간 통신에는 맞지 않아요.
