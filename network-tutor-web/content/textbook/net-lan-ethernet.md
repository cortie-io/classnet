오늘날 사무실과 집의 유선 LAN은 거의 모두 이더넷(Ethernet)이고, 무선 LAN도 같은 IEEE 802 가족에 속해요. 이 단원에서는 LAN 표준을 정리한 IEEE 802 시리즈, 장비마다 붙는 MAC 주소, 이더넷 프레임의 구조, 이더넷의 전송 규칙인 CSMA/CD, 그리고 "1000BASE-T" 같은 규격 이름을 읽는 법을 배워요. 표준 번호와 규격 이름은 외워 두면 바로 점수가 되는 부분이에요.

> [!GOAL]
> - IEEE 802.1·802.2·802.3·802.5·802.11·802.15 등 주요 표준이 무엇을 다루는지 짝지을 수 있다.
> - MAC 주소의 길이와 구조(OUI)를 설명할 수 있다.
> - 이더넷 프레임의 필드와 크기, 최소·최대 프레임 길이를 말할 수 있다.
> - CSMA/CD의 동작 순서를 설명하고, 전이중 스위치 환경에서 왜 쓰이지 않는지 이해한다.
> - 10BASE-T, 100BASE-TX, 1000BASE-SX/LX, 10GBASE-T 같은 규격 이름을 해석할 수 있다.

## IEEE 802 위원회와 LAN 표준

### 802 시리즈

IEEE(Institute of Electrical and Electronics Engineers, 전기전자기술자협회)의 **802 위원회**는 LAN과 MAN 표준을 만드는 곳이에요. 802 뒤에 붙는 번호마다 다루는 기술이 정해져 있어요.

| 표준 | 다루는 내용 | 메모 |
|---|---|---|
| 802.1 | 상위 계층 인터페이스, 브리징, 네트워크 관리 | 802.1D(STP), 802.1Q(VLAN), 802.1X(포트 기반 인증) 등이 여기 속함 |
| 802.2 | LLC(Logical Link Control, 논리 링크 제어) | 데이터 링크 계층의 위쪽 부계층 |
| 802.3 | CSMA/CD(이더넷) | 유선 LAN의 사실상 표준 |
| 802.4 | 토큰 버스(Token Bus) | 물리적 버스 + 논리적 링 |
| 802.5 | 토큰 링(Token Ring) | 토큰을 돌려 전송 권한을 넘김 |
| 802.6 | MAN(DQDB) | 도시권 통신망 |
| 802.7 | 브로드밴드 LAN | |
| 802.8 | 광섬유 LAN | |
| 802.9 | 음성·데이터 통합 LAN | |
| 802.10 | LAN 보안 | |
| 802.11 | 무선 LAN(Wi-Fi) | CSMA/CA 사용 |
| 802.12 | 100VG-AnyLAN | 우선순위 요청 방식 |
| 802.14 | 케이블 모뎀 | |
| 802.15 | 무선 PAN(WPAN) | 802.15.1 블루투스, 802.15.4 저전력 근거리(지그비의 기반) |
| 802.16 | 광대역 무선 MAN | WiMAX, 국내 와이브로의 기반 기술 |

> [!TIP]
> 시험에 가장 많이 나오는 것만 먼저 묶어 외우세요. "**1 관리·브리지, 2 LLC, 3 이더넷(CSMA/CD), 4 토큰 버스, 5 토큰 링, 6 MAN, 11 무선 LAN, 15 블루투스(WPAN), 16 WiMAX**". 3과 11이 짝(유선 이더넷과 무선 LAN), 4와 5가 짝(토큰 버스와 토큰 링)이라고 보면 쉬워요.

> [!NOTE]
> 802.4·802.5·802.6 등 여러 작업 그룹은 기술이 쓰이지 않게 되면서 지금은 활동을 멈췄어요. 현재 활발한 것은 802.1, 802.3, 802.11, 802.15 등이에요. 시험은 옛 번호까지 묻기 때문에 표 전체를 알아 두는 편이 안전해요.

### LLC와 MAC 부계층

IEEE 802는 OSI의 데이터 링크 계층을 두 부계층으로 나눴어요.

- **LLC(Logical Link Control, 802.2)**: 위쪽 부계층이에요. 아래에서 어떤 매체를 쓰든 네트워크 계층에 똑같은 모습의 서비스를 제공해요.
- **MAC(Media Access Control)**: 아래쪽 부계층이에요. 매체를 언제 쓸지 정하는 접근 방식과 MAC 주소를 다뤄요. 802.3(CSMA/CD), 802.5(토큰 링), 802.11(CSMA/CA)처럼 기술마다 달라요.

| OSI 계층 | IEEE 802에서의 구분 |
|---|---|
| 3계층 네트워크 | (IEEE 802의 범위 밖) |
| 2계층 데이터 링크 — 위쪽 | LLC 부계층(802.2) |
| 2계층 데이터 링크 — 아래쪽 | MAC 부계층(802.3, 802.5, 802.11 등) |
| 1계층 물리 | 각 표준의 물리 계층 규격 |

## MAC 주소

### 구조

MAC 주소(Media Access Control Address)는 네트워크 인터페이스마다 붙는 **48비트(6바이트)** 물리 주소예요. 보통 16진수 12자리로 적고, 운영체제나 장비마다 표기 모양이 조금 달라요.

| 표기 예 | 주로 쓰는 곳 |
|---|---|
| `00-00-5E-00-53-1A` | Windows |
| `00:00:5e:00:53:1a` | 리눅스 |
| `0000.5e00.531a` | 시스코 IOS 계열 장비 |

(위 주소는 문서 예시용으로 따로 떼어 둔 값이에요.)

48비트는 앞뒤 절반으로 나뉘어요.

```text
00-00-5E-00-53-1A
|______| |______|
   |        |
   |        +-- 뒤 24비트: 제조사가 붙이는 고유 번호
   +----------- 앞 24비트: OUI(제조사 식별 번호)
```

- **앞 24비트 — OUI(Organizationally Unique Identifier)**: IEEE가 제조사(조직)마다 나눠 주는 식별 번호예요. OUI를 보면 어느 회사가 만든 랜카드인지 알 수 있어요.
- **뒤 24비트**: 제조사가 자기 제품마다 겹치지 않게 붙이는 번호예요.

MAC 주소는 공장에서 랜카드의 ROM에 기록되어 나와서 흔히 하드웨어 주소라고 불러요. 다만 운영체제 설정으로 다른 값으로 바꿔 쓰는 것도 가능해요.

### 특별한 비트와 주소

- 첫 바이트의 **맨 마지막 비트**(I/G 비트)가 0이면 한 장치를 가리키는 **유니캐스트**, 1이면 여러 장치를 가리키는 **멀티캐스트(그룹)** 주소예요.
- 첫 바이트의 **끝에서 두 번째 비트**(U/L 비트)가 0이면 제조사가 부여한 전역 주소, 1이면 관리자가 임의로 정한 로컬 주소예요.
- `FF-FF-FF-FF-FF-FF`(48비트가 모두 1)는 같은 LAN의 모든 장치에게 보내는 **브로드캐스트** 주소예요.

내 컴퓨터의 MAC 주소는 이렇게 확인해요.

```powershell
ipconfig /all
getmac
```

```bash
ip link show
```

> [!EXAM]
> "MAC 주소는 몇 비트인가?"(48비트), "앞 24비트를 무엇이라 하는가?"(OUI)가 단골이에요. 주소 길이를 비교하는 문제도 나와요. **MAC 48비트, IPv4 32비트, IPv6 128비트**로 묶어 외우세요. IP 주소로 MAC 주소를 알아내는 ARP는 [ARP·ICMP·IGMP](/textbook/tcpip-arp-icmp)에서 배워요.

## 이더넷 프레임

### Ethernet II 프레임 구조

오늘날 IP 통신에서 가장 많이 쓰는 형식은 **Ethernet II(DIX)** 프레임이에요.

```text
+---------+---------+---------+------+---------+-----+
| Pre+SFD | Dst MAC | Src MAC | Type |   Data  | FCS |
|    8    |    6    |    6    |  2   | 46~1500 |  4  |
+---------+---------+---------+------+---------+-----+
                                             (단위: 바이트)
```

| 필드 | 크기 | 하는 일 |
|---|---|---|
| 프리앰블(Preamble) | 7바이트 | 1과 0이 번갈아 나오는 패턴으로 수신 측이 신호 박자(클록)를 맞추게 함 |
| SFD(Start Frame Delimiter) | 1바이트 | `10101011`. "여기서부터 진짜 프레임"이라는 표시 |
| 목적지 MAC 주소 | 6바이트 | 받을 장치의 MAC 주소 |
| 출발지 MAC 주소 | 6바이트 | 보낸 장치의 MAC 주소 |
| 타입(EtherType) | 2바이트 | 데이터에 담긴 상위 프로토콜. `0x0800` IPv4, `0x0806` ARP, `0x86DD` IPv6 |
| 데이터(Payload) | 46~1500바이트 | 위 계층에서 내려온 패킷. 46바이트보다 짧으면 의미 없는 채움 데이터(패딩)를 붙여 46바이트로 맞춤 |
| FCS(Frame Check Sequence) | 4바이트 | CRC-32 값. 수신 측이 오류를 검출 |

- 프리앰블과 SFD는 신호를 맞추기 위한 앞머리라서 보통 **프레임 길이에는 넣지 않아요**.
- 그래서 이더넷 프레임 길이는 목적지 MAC부터 FCS까지 **최소 64바이트, 최대 1518바이트**예요. (6 + 6 + 2 + 46 + 4 = 64, 6 + 6 + 2 + 1500 + 4 = 1518)
- 데이터 부분의 최대 크기 1500바이트를 이더넷의 **MTU**(Maximum Transmission Unit)라고 해요.

> [!NOTE]
> 최소 길이 64바이트(512비트)에는 이유가 있어요. 뒤에 나오는 CSMA/CD에서는 보내는 쪽이 **아직 전송하고 있는 동안** 충돌 소식이 돌아와야 충돌을 알아챌 수 있어요. 그래서 케이블 끝에서 끝까지 신호가 다녀오는 시간보다 오래 전송하도록 최소 길이를 정해 두었어요.

### IEEE 802.3 프레임과의 차이

IEEE 802.3 원래 형식은 타입 자리에 **길이**(Length)를 적고, 데이터 앞에 802.2 LLC 헤더를 붙여요. 장비는 이 2바이트 값을 보고 구분해요. 값이 1500 이하이면 길이, 1536(`0x0600`) 이상이면 타입이에요. 그래서 두 형식이 같은 네트워크에서 함께 쓰일 수 있어요.

## CSMA/CD

### 회의실 규칙으로 이해하기

여러 사람이 한 회의실에서 마이크 하나 없이 이야기한다고 해 보세요. 예의 바른 사람은 이렇게 행동해요.

1. 말하기 전에 다른 사람이 말하고 있는지 **귀를 기울여요**.
2. 조용하면 **말을 시작해요**.
3. 말하는 도중에도 누가 동시에 말을 시작했는지 **계속 들어요**.
4. 목소리가 겹치면 **즉시 멈추고** "잠깐만요!" 하고 모두에게 알려요.
5. 각자 **무작위로 잠깐 기다렸다가** 다시 1번부터 시도해요.

이것이 바로 CSMA/CD(Carrier Sense Multiple Access with Collision Detection, 반송파 감지 다중 접속/충돌 검출)예요. 이름을 풀면 이래요.

- **CS(Carrier Sense, 반송파 감지)**: 보내기 전에 매체에 신호가 흐르는지 감지
- **MA(Multiple Access, 다중 접속)**: 여러 장치가 한 매체를 함께 사용
- **CD(Collision Detection, 충돌 검출)**: 보내는 중에 충돌이 나면 알아챔

### 동작 순서

1. 보낼 프레임이 생기면 매체를 감지해요. 다른 장치가 보내는 중이면 매체가 빌 때까지 기다려요.
2. 매체가 비면 전송을 시작하고, 보내는 동안 충돌이 나는지 계속 감시해요.
3. 충돌이 없이 프레임을 다 보냈다면 성공이에요.
4. 충돌을 검출하면 즉시 전송을 멈추고, 짧은 **재밍 신호**(Jam Signal)를 보내 모든 장치가 충돌을 확실히 알게 해요.
5. **이진 지수 백오프**(Binary Exponential Backoff)로 기다려요. n번째 충돌 뒤에는 0부터 `2^n − 1` 사이의 수 중 하나를 무작위로 골라 그만큼의 슬롯 시간을 기다려요(n은 10에서 더 커지지 않아요). 충돌이 거듭될수록 기다리는 범위가 두 배씩 넓어져서 다시 부딪칠 확률이 줄어요.
6. 다시 1단계부터 시도해요. 16번 시도해도 실패하면 그 프레임을 포기하고 상위 계층에 알려요.

```text
[보낼 프레임 발생]
  |
  v
[매체가 비었나?] --아니오--> [빌 때까지 대기]
  | 예
  v
[전송 시작 + 충돌 감시]
  |
  v
[충돌 발생?] --아니오--> [전송 완료]
  | 예
  v
[전송 중단, 재밍 신호 송출]
  |
  v
[무작위 시간 대기(백오프)] --> 처음으로
```

### 충돌 도메인과 오늘날의 이더넷

신호가 서로 부딪칠 수 있는 범위를 **충돌 도메인**(Collision Domain)이라고 해요. 동축 케이블 버스나 허브로 연결한 네트워크는 전체가 하나의 충돌 도메인이라서 장치가 늘수록 충돌이 늘고 성능이 떨어져요.

스위치를 쓰면 상황이 달라져요.

- 스위치는 **포트마다 충돌 도메인을 나눠요**. 한 포트에는 장치 하나만 연결돼요.
- 트위스티드 페어 이더넷은 보내는 선과 받는 선이 따로 있어서, 스위치 포트와 PC가 **전이중**(Full Duplex)으로 동시에 보내고 받을 수 있어요.
- 전이중으로 1:1 연결되면 **충돌이 원리적으로 일어날 수 없으므로 CSMA/CD를 꺼요**.
- 10기가비트 이더넷부터는 아예 전이중만 지원해서 CSMA/CD를 쓰지 않아요.

그래서 CSMA/CD는 이더넷의 출발점을 이해하는 개념으로는 중요하지만, 오늘날 스위치 기반 LAN에서는 실제로 거의 동작하지 않아요. 허브와 스위치의 차이, 충돌 도메인과 브로드캐스트 도메인은 [1·2계층 장비](/textbook/dev-l1-l2-devices)에서 자세히 배워요.

> [!WARNING]
> **CSMA/CD는 유선 이더넷(802.3)**, **CSMA/CA는 무선 LAN**(802.11)이에요. 무선에서는 보내면서 동시에 충돌을 듣기 어려워서, 충돌을 "검출(Detection)"하는 대신 미리 "회피(Avoidance)"해요. CSMA/CA는 [무선 LAN과 근거리 무선 통신](/textbook/net-wireless-lan)에서 배워요.

## 이더넷 규격 이름 읽는 법

### 이름의 세 부분

이더넷 규격 이름은 세 조각으로 읽어요.

```text
100  BASE  -TX
 |    |     |
 |    |     +-- 매체·거리: TX = 트위스티드 페어(Cat5, 2쌍)
 |    +-------- 전송 방식: 베이스밴드
 +------------- 속도: 100Mbps
```

- **앞 숫자 — 속도**: Mbps 단위예요. 10은 10Mbps, 100은 100Mbps, 1000은 1Gbps예요. 10G처럼 G가 붙으면 Gbps예요.
- **가운데 — 전송 방식**: **BASE**는 베이스밴드(Baseband)로, 디지털 신호를 변조 없이 그대로 보낸다는 뜻이에요. 드물게 BROAD(브로드밴드)도 있어요.
- **뒤 — 매체 또는 거리**:
  - 숫자이면 최대 세그먼트 길이를 대략 100m 단위로 나타내요. 10BASE5는 약 500m, 10BASE2는 약 200m(정확히는 185m)예요.
  - 문자이면 매체 종류예요. **T**는 트위스티드 페어, **F**는 광섬유예요. 광섬유 규격의 **S**는 단파장(Short wavelength, 850nm), **L**은 장파장(Long wavelength, 1310nm), **E**는 확장(Extended, 1550nm)이에요. **X**는 특정한 블록 부호화 방식을 쓴다는 표시예요.

### 주요 규격 표

| 규격 | 속도 | 매체 | 최대 거리(대략) | 비고 |
|---|---|---|---|---|
| 10BASE5 | 10Mbps | 굵은 동축(Thicknet) | 500m | 초기 이더넷, 버스형 |
| 10BASE2 | 10Mbps | 얇은 동축(Thinnet) | 185m | BNC 커넥터, 버스형 |

속도별 이름도 함께 기억해 두세요. 10Mbps는 이더넷, 100Mbps는 **패스트 이더넷(Fast Ethernet)**, 1Gbps는 **기가비트 이더넷(Gigabit Ethernet)**, 10Gbps는 **10기가비트 이더넷**이라고 불러요.

> [!EXAM]
> "1000BASE-T에서 T의 의미"(트위스티드 페어), "10BASE5의 5의 의미"(최대 세그먼트 길이 약 500m), "BASE의 의미"(베이스밴드 전송)가 자주 나와요. SX와 LX의 차이는 **S = 단파장·멀티모드·짧은 거리**, **L = 장파장·싱글모드도 가능·긴 거리**로 정리하세요. 케이블 카테고리는 [전송 매체와 케이블](/textbook/net-transmission-media)에서 정리했어요.

## 토큰 링 간단히

토큰 링(Token Ring, IEEE 802.5)은 이더넷과 경쟁하던 LAN 기술이에요. 노드들이 고리 모양으로 연결되고, **토큰**(Token)이라는 짧은 특수 프레임이 고리를 계속 돌아요.

1. 보낼 데이터가 있는 노드는 토큰이 올 때까지 기다려요.
2. 토큰을 잡은 노드만 데이터 프레임을 보낼 수 있어요.
3. 프레임은 고리를 돌아 목적지가 복사해 가고, 다시 보낸 노드로 돌아오면 보낸 노드가 프레임을 거둬들인 뒤 토큰을 다음 노드로 넘겨요.

- 한 번에 한 노드만 보내므로 **충돌이 없어요**.
- 토큰이 차례로 돌기 때문에 최대 대기 시간을 계산할 수 있어 **지연이 예측 가능**(결정적)해요. 우선순위도 줄 수 있어요.
- 속도는 4Mbps와 16Mbps가 대표적이었어요. 선은 MAU라는 집선 장치에 별 모양으로 꽂지만 데이터는 고리를 따라 흘러서, **물리적으로는 성형, 논리적으로는 링형**이에요.
- 지금은 값싸고 빨라진 이더넷에 밀려 거의 쓰이지 않아요.

같은 토큰 방식으로 버스형 회선을 쓰는 **토큰 버스(802.4)**, 광섬유 이중 링으로 100Mbps를 내던 **FDDI**도 있어요.

| 항목 | CSMA/CD(이더넷) | 토큰 패싱(토큰 링) |
|---|---|---|
| 전송 권한 | 매체가 비면 누구나 경쟁 | 토큰을 가진 노드만 |
| 충돌 | 생길 수 있음(공유 매체일 때) | 없음 |
| 부하가 적을 때 | 바로 보내서 빠름 | 토큰을 기다려야 해서 손해 |
| 부하가 많을 때 | 충돌이 늘어 성능 급락 | 안정적 |
| 지연 예측 | 어려움(비결정적) | 가능(결정적) |
| 구현 | 단순하고 저렴 | 토큰 관리가 필요해 복잡 |

## 핵심 정리

- IEEE 802.1 관리·브리징, 802.2 LLC, 802.3 CSMA/CD 이더넷, 802.4 토큰 버스, 802.5 토큰 링, 802.6 MAN(DQDB), 802.11 무선 LAN, 802.15 WPAN(블루투스), 802.16 무선 MAN(WiMAX).
- 데이터 링크 계층은 LLC(위)와 MAC(아래) 부계층으로 나뉜다.
- MAC 주소는 48비트. 앞 24비트 OUI(제조사), 뒤 24비트 제조사 일련번호. 브로드캐스트는 FF-FF-FF-FF-FF-FF.
- Ethernet II 프레임: 프리앰블·SFD 8, 목적지 MAC 6, 출발지 MAC 6, 타입 2, 데이터 46~1500, FCS 4바이트. 프레임 길이는 최소 64바이트·최대 1518바이트, MTU 1500.
- CSMA/CD: 감지 → 전송·감시 → 충돌 시 중단·재밍 → 이진 지수 백오프 → 재시도(16번 실패 시 포기).
- 스위치 전이중 연결에서는 충돌이 없으므로 CSMA/CD를 쓰지 않는다. 무선 LAN은 CSMA/CA.
- 규격 이름은 속도 + BASE(베이스밴드) + 매체·거리. T는 트위스티드 페어, F는 광섬유, S는 단파장, L은 장파장, 숫자는 대략 100m 단위 길이.
- 토큰 링(802.5)은 토큰을 가진 노드만 전송해 충돌이 없고 지연이 예측 가능하다.

## 스스로 확인하기

**1.** IEEE 802 표준과 내용의 짝으로 옳지 않은 것은?
① 802.2 – LLC ② 802.3 – CSMA/CD ③ 802.5 – 무선 LAN ④ 802.15 – 무선 PAN

> [!ANSWER]
> 정답: ③
> 802.5는 토큰 링이에요. 무선 LAN은 802.11이에요.

**2.** 이더넷 프레임의 데이터 필드에 20바이트짜리 데이터만 담아 보내야 해요. 어떻게 처리될까요?
① 20바이트 그대로 보내고 프레임 길이는 38바이트가 된다. ② 26바이트의 패딩을 붙여 데이터 필드를 46바이트로 맞춘다. ③ 프레임을 보낼 수 없어 오류가 난다. ④ 다른 프레임과 합쳐서 1500바이트를 채운다.

> [!ANSWER]
> 정답: ②
> 데이터 필드는 최소 46바이트여야 해서 부족한 26바이트를 패딩으로 채워요. 그래야 프레임 전체가 최소 길이 64바이트가 돼요.

**3.** 규격 이름 `1000BASE-LX`에 대한 해석으로 옳은 것은?
① 1000Mbps, 브로드밴드 전송, 트위스티드 페어 ② 1000m 거리, 베이스밴드 전송, 동축 케이블 ③ 1Gbps, 베이스밴드 전송, 단파장 멀티모드 광섬유 전용 ④ 1Gbps, 베이스밴드 전송, 장파장 광섬유

> [!ANSWER]
> 정답: ④
> 1000은 1000Mbps(1Gbps), BASE는 베이스밴드, LX의 L은 장파장(1310nm) 광섬유를 뜻해요. 단파장 멀티모드는 SX예요.

**4.** 민수네 사무실은 모든 PC가 스위치에 전이중으로 연결되어 있어요. 이 환경에서 CSMA/CD에 대한 설명으로 옳은 것은?
① 충돌이 매우 자주 일어나 백오프가 계속 동작한다. ② 스위치가 토큰을 나눠 줘서 충돌을 막는다. ③ 포트마다 1:1로 송수신 선이 분리되어 충돌이 일어나지 않으므로 CSMA/CD가 동작하지 않는다. ④ 무선 LAN과 같은 CSMA/CA로 자동 전환된다.

> [!ANSWER]
> 정답: ③
> 전이중 1:1 연결에서는 보내는 선과 받는 선이 따로라서 충돌이 생기지 않아요. 그래서 CSMA/CD를 끄고 동시에 송수신해요.

**5.** MAC 주소에 대한 설명으로 옳은 것은?
① 앞 24비트는 IEEE가 제조사에 할당한 OUI이다. ② 32비트로 이루어지며 점으로 구분한 10진수로 적는다. ③ 모든 비트가 0인 주소가 브로드캐스트 주소이다. ④ 네트워크 계층에서 경로를 찾는 데 쓰는 논리 주소이다.

> [!ANSWER]
> 정답: ①
> MAC 주소는 48비트이고 앞 24비트가 OUI예요. 브로드캐스트는 모든 비트가 1인 FF-FF-FF-FF-FF-FF이고, 경로를 찾는 논리 주소는 IP 주소예요.
