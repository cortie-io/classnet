리눅스 서버 관리는 대부분 키보드로 명령어를 입력하는 일이에요. 이 단원에서는 디렉터리를 오가고, 파일을 만들고 지우고, 내용을 보고, 원하는 파일을 찾고, 묶고 압축하는 명령어를 익혀요. 마지막으로 명령의 출력을 파일로 보내거나 다른 명령에 넘겨주는 리다이렉션과 파이프까지 배우면, 여러 명령을 조립해서 쓰는 리눅스다운 방법이 보이기 시작해요.

> [!GOAL]
> - 이동·목록·생성·삭제·복사·이동 명령과 주요 옵션을 쓸 수 있다.
> - `ls -l` 출력의 각 열이 무엇을 뜻하는지 읽을 수 있다.
> - `find`와 `grep`으로 파일과 내용을 찾고, 하드 링크와 심볼릭 링크를 구분할 수 있다.
> - `tar`와 압축 명령, 리다이렉션과 파이프를 활용할 수 있다.

## 명령어의 기본 모양

리눅스 명령은 대부분 이런 모양이에요.

```text
명령어  [옵션]  [대상]
ls      -l      /etc
```

- **대소문자를 구분**해요. `ls`와 `LS`는 다른 명령이에요.
- 짧은 옵션은 `-l`처럼 하이픈 하나, 여러 개를 붙여 `-la`처럼 쓸 수 있어요. 긴 옵션은 `--all`처럼 하이픈 두 개예요.
- 명령의 사용법이 궁금하면 `man ls`(설명서) 또는 `ls --help`를 입력해요. `man` 화면에서는 `q`로 나와요.

### 경로 표기

| 표기 | 뜻 | 예 |
|---|---|---|
| 절대 경로 | `/`부터 시작하는 전체 경로 | `/home/minsu/docs` |
| 상대 경로 | 현재 위치를 기준으로 한 경로 | `docs/report.txt` |
| `.` | 현재 디렉터리 | `./run.sh` |
| `..` | 한 단계 위(상위) 디렉터리 | `cd ..` |
| `~` | 내 홈 디렉터리 | `cd ~` |

이름이 `.`으로 시작하는 파일(예: `.bashrc`)은 **숨김 파일**이라서 그냥 `ls`로는 보이지 않아요.

## 이동하고 목록 보기

| 명령 | 하는 일 |
|---|---|
| `pwd` | 지금 있는 디렉터리의 절대 경로 출력(Print Working Directory) |
| `cd /etc` | `/etc`로 이동 |
| `cd ..` | 상위 디렉터리로 |
| `cd` 또는 `cd ~` | 홈 디렉터리로 |
| `cd -` | 바로 전에 있던 디렉터리로 |
| `ls` | 현재 디렉터리의 파일 목록 |
| `ls -l` | 자세히(권한, 소유자, 크기, 시간) |
| `ls -a` | 숨김 파일까지 모두(all) |
| `ls -lh` | 크기를 K, M, G 단위로 읽기 쉽게(human-readable) |
| `ls -R` | 하위 디렉터리까지 모두 |
| `ls -i` | 아이노드 번호 함께 표시 |

### `ls -l` 출력 읽기

`ls -l`의 한 줄에는 파일에 대한 정보가 빼곡히 들어 있어요. 시험에서도 이 출력을 보여 주고 해석하라는 문제가 자주 나와요.

```text
-rw-r--r-- 1 minsu sales 2310 Mar  5 14:20 report.txt
drwxr-xr-x 2 minsu sales 4096 Mar  5 14:18 docs
lrwxrwxrwx 1 root  root     7 Mar  1 09:00 bin -> usr/bin
```

첫 줄 `report.txt`를 왼쪽부터 하나씩 읽어 볼게요.

| 순서 | 값 | 뜻 |
|---|---|---|
| 1 | `-` | **파일 종류**. 맨 앞 한 글자 |
| 2 | `rw-r--r--` | **권한**. 소유자·그룹·기타 사용자 순서로 3글자씩 |
| 3 | `1` | **하드 링크 수** |
| 4 | `minsu` | **소유자** |
| 5 | `sales` | **소유 그룹** |
| 6 | `2310` | **크기**(바이트) |
| 7 | `Mar  5 14:20` | **마지막 수정 시각** |
| 8 | `report.txt` | **파일 이름**. 심볼릭 링크면 `-> 원본`이 붙어요 |

맨 앞 글자로 알 수 있는 파일 종류는 다음과 같아요.

| 기호 | 종류 |
|---|---|
| `-` | 일반 파일 |
| `d` | 디렉터리(directory) |
| `l` | 심볼릭 링크(link) |
| `b` | 블록 장치(디스크 등, block) |
| `c` | 문자 장치(터미널 등, character) |
| `p` | 이름 있는 파이프(pipe) |
| `s` | 소켓(socket) |

권한 9글자를 읽는 법은 [리눅스 권한과 사용자](/textbook/nos-linux-permissions-users)에서 자세히 배워요. 디렉터리 `docs`의 링크 수가 2인 이유는, 디렉터리 이름 자체와 그 안의 `.`(자기 자신)이 같은 디렉터리를 가리키기 때문이에요.

## 만들고, 복사하고, 옮기고, 지우기

| 명령 | 하는 일 |
|---|---|
| `mkdir project` | 디렉터리 만들기 |
| `mkdir -p a/b/c` | 중간 디렉터리가 없으면 함께 만들기(parents) |
| `rmdir project` | **빈** 디렉터리만 삭제 |
| `touch memo.txt` | 빈 파일 만들기. 이미 있으면 수정 시각만 지금으로 바꿈 |
| `cp a.txt b.txt` | 파일 복사 |
| `cp -r docs backup` | 디렉터리를 안의 내용까지 통째로 복사(recursive) |
| `mv a.txt docs/` | 파일 이동 |
| `mv old.txt new.txt` | 이름 바꾸기 |
| `rm a.txt` | 파일 삭제 |
| `rm -r docs` | 디렉터리와 그 안의 모든 것 삭제 |
| `rm -f a.txt` | 확인 없이 강제(force) 삭제 |
| `rm -i a.txt` | 지우기 전에 하나씩 확인(interactive) |

- 리눅스에는 이름만 바꾸는 별도 명령 대신 `mv`를 써요. 같은 디렉터리 안에서 "옮기면" 이름이 바뀌는 거예요.
- `cp`, `mv`는 대상 파일이 이미 있으면 덮어쓸 수 있으니, 불안하면 `-i` 옵션을 붙여요.

> [!WARNING]
> 명령줄의 `rm`에는 휴지통이 없어요. 특히 `rm -rf`는 묻지도 않고 디렉터리 전체를 지우므로, 경로를 두 번 확인한 뒤 실행하세요. 또 `rmdir`은 안에 파일이 하나라도 있으면 실패해요. 내용까지 지우려면 `rm -r`을 써야 해요.

## 파일 내용 보기

| 명령 | 하는 일 |
|---|---|
| `cat file` | 내용 전체를 한 번에 출력. `cat a b`처럼 여러 파일을 이어 붙여 출력(concatenate). `-n`은 줄 번호 |
| `more file` | 한 화면씩 끊어서 보기. `Space` 다음 화면, `Enter` 한 줄, `q` 종료. 주로 앞으로만 넘겨요 |
| `less file` | 앞뒤로 자유롭게 이동하며 보기. `/단어`로 검색, `q` 종료 |
| `head file` | 앞부분 10줄. `head -n 5 file`은 5줄 |
| `tail file` | 끝부분 10줄. `tail -n 20 file`은 20줄 |
| `tail -f file` | 끝부분을 보여 준 뒤, 새로 추가되는 내용을 실시간으로 계속 출력(follow). `Ctrl + C`로 끝내요 |
| `wc file` | 줄 수, 단어 수, 바이트 수를 세요(word count). `-l` 줄, `-w` 단어, `-c` 바이트 |

```bash
tail -f /var/log/messages      # 로그가 쌓이는 모습을 실시간으로 지켜보기
wc -l /etc/passwd              # 줄 수 = 등록된 계정 수
```

> [!TIP]
> "less is more"라는 말처럼 `less`는 `more`보다 기능이 많아요. 로그 감시에는 `tail -f`가 단골이에요.

## 파일과 내용 찾기

### find — 조건으로 파일 찾기

`find`는 지정한 위치부터 아래로 내려가며 조건에 맞는 파일을 실제로 하나하나 찾아요.

```text
find  [어디서부터]  [조건]  [찾은 뒤 할 일]
```

| 조건 | 뜻 |
|---|---|
| `-name "*.conf"` | 이름이 패턴과 일치(대소문자 구분). `-iname`은 구분 안 함 |
| `-type f` / `-type d` / `-type l` | 일반 파일 / 디렉터리 / 심볼릭 링크 |
| `-size +100M` | 100MB보다 큰 파일. `-size -10k`는 10KB보다 작은 파일 |
| `-perm 644` | 권한이 정확히 644인 파일 |
| `-perm -4000` | SetUID 비트가 **포함된** 파일(다른 비트는 상관없음) |
| `-user minsu` | 소유자가 minsu인 파일 |
| `-mtime -7` | 최근 7일 이내에 수정된 파일. `+30`은 30일보다 더 전에 수정 |
| `-exec 명령 {} \;` | 찾은 파일마다 명령 실행(`{}` 자리에 파일 이름이 들어가요) |

```bash
find /etc -name "*.conf"                        # /etc 아래의 .conf 파일
find /home -user minsu -type f                  # minsu가 소유한 일반 파일
find / -perm -4000 -type f 2>/dev/null          # SetUID 파일 점검(오류 메시지는 버림)
find /var/log -mtime -1                         # 하루 안에 바뀐 로그
find /tmp -size +50M -exec ls -lh {} \;         # 50MB 넘는 파일을 자세히 출력
```

### grep — 파일 안의 글자 찾기

`grep`은 파일 내용에서 원하는 문자열(패턴)이 들어 있는 **줄**을 찾아 출력해요.

| 옵션 | 뜻 |
|---|---|
| `-i` | 대소문자 무시(ignore case) |
| `-v` | 일치하지 **않는** 줄만 출력(invert) |
| `-r` | 하위 디렉터리까지 재귀적으로 검색 |
| `-n` | 줄 번호 함께 출력 |
| `-c` | 일치하는 줄의 개수만 |
| `-l` | 일치하는 줄이 있는 파일 이름만 |

```bash
grep -n minsu /etc/passwd              # minsu가 들어간 줄과 줄 번호
grep -v "^#" /etc/ssh/sshd_config      # #으로 시작하는 주석 줄을 뺀 나머지
grep -ri "listen" /etc/httpd/          # 디렉터리 전체에서 대소문자 무시 검색
```

패턴의 `^`는 줄의 시작, `$`는 줄의 끝을 뜻해요. 그래서 `grep -v "^#"`은 "#으로 시작하지 않는 줄"이에요.

### locate, which, whereis, file

| 명령 | 하는 일 | 예 |
|---|---|---|
| `locate 이름` | 미리 만들어 둔 파일 이름 데이터베이스에서 빠르게 검색. 데이터베이스는 `updatedb`로 갱신 | `locate sshd_config` |
| `which 명령` | `PATH`에 등록된 경로에서 실행 파일 위치 찾기 | `which ls` → `/usr/bin/ls` |
| `whereis 명령` | 실행 파일, 소스, 설명서(man) 위치를 함께 찾기 | `whereis ls` |
| `file 파일` | 내용을 살펴보고 파일 종류 판별 | `file /etc/passwd` → ASCII text |

> [!WARNING]
> `locate`는 디스크를 직접 뒤지지 않고 데이터베이스를 찾아보기 때문에 아주 빠르지만, 데이터베이스를 갱신한 뒤에 새로 만든 파일은 나오지 않을 수 있어요. 실시간으로 정확히 찾으려면 `find`를 써요.

## 링크와 아이노드

### 아이노드란

리눅스 파일 시스템은 파일마다 **아이노드**(inode)라는 정보 상자를 하나씩 만들어요. 아이노드에는 권한, 소유자, 크기, 시간, 실제 데이터가 디스크 어디에 있는지가 들어 있고, 각 아이노드에는 고유 번호가 붙어요. 재미있는 점은 **파일 이름은 아이노드 안에 없다**는 거예요. 이름은 디렉터리 안에 "이름 → 아이노드 번호" 형태의 목록으로 저장돼요.

도서관에 비유하면 아이노드는 책의 실제 위치가 적힌 카드이고, 파일 이름은 그 카드를 가리키는 색인 쪽지예요. 같은 카드를 가리키는 쪽지를 여러 장 만들 수도 있고(하드 링크), "저 쪽지를 보세요"라고 적힌 안내 쪽지를 만들 수도 있어요(심볼릭 링크).

### 하드 링크와 심볼릭 링크

```bash
echo hello > orig.txt
ln orig.txt hard.txt          # 하드 링크
ln -s orig.txt soft.txt       # 심볼릭(소프트) 링크
ls -li
```

```text
1310722 -rw-r--r-- 2 minsu minsu 6 Mar  5 10:00 hard.txt
1310722 -rw-r--r-- 2 minsu minsu 6 Mar  5 10:00 orig.txt
1310725 lrwxrwxrwx 1 minsu minsu 8 Mar  5 10:01 soft.txt -> orig.txt
```

- `hard.txt`와 `orig.txt`는 **아이노드 번호가 같고**(1310722), 링크 수가 2로 늘었어요. 둘은 원본과 사본이 아니라 같은 파일에 붙은 이름 두 개예요.
- `soft.txt`는 **아이노드 번호가 다른** 별도의 파일이에요. 내용은 원본의 경로 `orig.txt`(8글자)뿐이라 크기가 8이고, 종류가 `l`이에요. Windows의 바로 가기와 비슷해요.

| 구분 | 하드 링크(Hard Link) | 심볼릭 링크(Symbolic Link) |
|---|---|---|
| 만드는 명령 | `ln 원본 링크` | `ln -s 원본 링크` |
| 아이노드 | 원본과 **같음** | 원본과 **다름** |
| 원본을 지우면 | 데이터가 남아 있어 계속 열림 | 가리킬 대상이 없어 **깨진 링크**가 됨 |
| 디렉터리에 걸기 | 불가 | 가능 |
| 다른 파일 시스템(파티션)의 파일 | 불가 | 가능 |
| `ls -l` 표시 | 일반 파일과 똑같고 링크 수만 증가 | `l`로 시작, `-> 원본` 표시 |

> [!EXAM]
> "원본을 삭제해도 내용을 볼 수 있는 것은?" → 하드 링크. "다른 파티션의 파일이나 디렉터리를 가리킬 수 있는 것은?" → 심볼릭 링크. 하드 링크로 연결된 파일은 링크 수가 0이 될 때, 즉 마지막 이름까지 지워졌을 때 비로소 데이터가 삭제돼요.

## 묶기와 압축

### tar — 여러 파일을 하나로 묶기

`tar`(tape archive)는 여러 파일과 디렉터리를 파일 하나로 **묶는** 명령이에요. 묶기만 할 뿐 크기를 줄이지는 않아요. 압축은 옵션으로 gzip, bzip2, xz를 함께 불러서 해요.

| 옵션 | 뜻 |
|---|---|
| `c` | 새 묶음 만들기(create) |
| `x` | 묶음 풀기(extract) |
| `t` | 묶음 안의 목록 보기(list) |
| `v` | 처리 과정을 화면에 보여 주기(verbose) |
| `f` | 묶음 파일 이름 지정(file). 바로 뒤에 파일 이름이 와요 |
| `z` | gzip으로 압축·해제(`.tar.gz`, `.tgz`) |
| `j` | bzip2로 압축·해제(`.tar.bz2`) |
| `J` | xz로 압축·해제(`.tar.xz`) |
| `-C 경로` | 지정한 디렉터리에 풀기 |

```bash
tar cvf backup.tar /home/minsu          # 묶기
tar tvf backup.tar                      # 안에 뭐가 있나 보기
tar xvf backup.tar                      # 현재 위치에 풀기
tar cvzf site.tar.gz /var/www/html      # 묶으면서 gzip 압축
tar xvzf site.tar.gz -C /tmp            # gzip 묶음을 /tmp에 풀기
tar cvjf logs.tar.bz2 /var/log          # bzip2 압축
tar xvJf data.tar.xz                    # xz 묶음 풀기
```

> [!TIP]
> `c`(만들기)·`x`(풀기)·`t`(보기) 중 **하나**를 고르고, 압축 방식 `z`·`j`·`J`를 더하고, `v`로 과정을 보고, 마지막에 `f 파일이름`. 이 순서로 외우면 쉬워요. `f` 바로 뒤에 파일 이름이 와야 하므로 `f`를 옵션 묶음의 맨 끝에 두는 습관을 들이세요.

### gzip, bzip2, xz — 파일 하나를 압축

| 명령 | 압축 후 확장자 | 풀기 |
|---|---|---|
| `gzip file` | `file.gz` | `gunzip file.gz` 또는 `gzip -d` |
| `bzip2 file` | `file.bz2` | `bunzip2 file.bz2` 또는 `bzip2 -d` |
| `xz file` | `file.xz` | `unxz file.xz` 또는 `xz -d` |

- 이 명령들은 파일을 **하나씩** 압축하고, 압축하면 원본 파일이 압축 파일로 바뀌어요. 여러 파일을 한 번에 압축하려면 먼저 `tar`로 묶는 거예요.
- 일반적으로 압축률은 gzip < bzip2 < xz 순서로 높아지고, 대신 시간이 더 걸려요.
- 아주 오래된 `compress`(확장자 `.Z`)와 Windows와 주고받기 좋은 `zip`/`unzip`도 있어요.

## 리다이렉션과 파이프

### 표준 입력·출력·오류

명령은 실행될 때 세 개의 통로를 가지고 있어요. 각 통로에는 번호(파일 디스크립터)가 붙어요.

| 번호 | 이름 | 기본 연결 |
|---|---|---|
| 0 | 표준 입력(stdin) | 키보드 |
| 1 | 표준 출력(stdout) | 화면 |
| 2 | 표준 오류(stderr) | 화면 |

**리다이렉션**(Redirection)은 이 통로를 화면이나 키보드 대신 파일로 돌리는 거예요.

| 기호 | 뜻 | 예 |
|---|---|---|
| `>` | 출력을 파일로(파일이 있으면 **덮어쓰기**) | `ls -l > list.txt` |
| `>>` | 출력을 파일 끝에 **덧붙이기** | `date >> log.txt` |
| `<` | 파일 내용을 입력으로 | `wc -l < /etc/passwd` |
| `2>` | 오류 메시지만 파일로 | `find / -name x 2> err.txt` |
| `2>&1` | 오류(2)를 출력(1)과 같은 곳으로 | `cmd > all.txt 2>&1` |

`/dev/null`로 보내면 그 내용은 버려져요. 그래서 `2>/dev/null`은 "오류 메시지는 보지 않겠다"는 뜻이에요.

> [!WARNING]
> `cmd > all.txt 2>&1`은 출력과 오류를 모두 파일에 저장하지만, 순서를 바꾼 `cmd 2>&1 > all.txt`는 오류가 여전히 화면으로 나와요. `2>&1`은 "지금 1번이 가리키는 곳으로 2번도 보내라"는 뜻이라, 1번을 먼저 파일로 돌려 둔 다음에 써야 해요.

### 파이프

**파이프**(Pipe, `|`)는 앞 명령의 출력을 뒤 명령의 입력으로 곧장 이어 주는 관이에요. 작은 명령을 레고처럼 연결할 수 있어요.

```bash
ps aux | grep sshd             # 실행 중인 프로세스 중 sshd만
ls -l /etc | less              # 긴 목록을 한 화면씩
cat /etc/passwd | wc -l        # 계정 수 세기
```

### sort, uniq, cut

| 명령 | 하는 일 | 자주 쓰는 옵션 |
|---|---|---|
| `sort` | 줄 정렬 | `-n` 숫자 순, `-r` 거꾸로, `-t` 구분자, `-k` 기준 열 |
| `uniq` | **이웃한** 중복 줄을 하나로 | `-c` 몇 번 나왔는지 세기 |
| `cut` | 줄에서 원하는 부분만 잘라내기 | `-d` 구분자, `-f` 필드 번호 |

`uniq`는 바로 붙어 있는 중복만 없애기 때문에 보통 `sort` 뒤에 써요. 예를 들어 `/etc/passwd`의 7번째 필드(로그인 셸)를 셸 종류별로 세고, 많은 순서로 다시 정렬해 보면 이렇게 돼요(출력은 예시예요).

```bash
cut -d: -f7 /etc/passwd | sort | uniq -c | sort -rn
```

```text
     18 /sbin/nologin
      3 /bin/bash
      1 /bin/sync
```

## 핵심 정리

- `pwd` 현재 위치, `cd -` 직전 위치, `ls -l` 자세히, `-a` 숨김 포함, `-h` 읽기 쉬운 크기.
- `ls -l` 열 순서: 종류·권한 → 링크 수 → 소유자 → 그룹 → 크기 → 수정 시각 → 이름.
- `mkdir -p` 중간 디렉터리까지, `rmdir`은 빈 디렉터리만, `rm -r` 재귀 삭제, `cp -r` 디렉터리 복사, `mv`는 이동과 이름 바꾸기.
- `head`/`tail` 기본 10줄, `tail -f` 실시간 감시, `wc -l` 줄 수.
- `find`는 이름·종류·크기·권한·소유자·수정일로 실제 검색, `grep`은 내용 검색(`-i` `-v` `-r` `-n`).
- 하드 링크는 같은 아이노드(원본 지워도 유지), 심볼릭 링크는 다른 아이노드(원본 지우면 깨짐, `ln -s`).
- `tar`: `c` 묶기, `x` 풀기, `t` 목록, `v` 과정 표시, `f` 파일 이름, `z` gzip, `j` bzip2, `J` xz.
- `>` 덮어쓰기, `>>` 덧붙이기, `<` 입력, `2>` 오류, `2>&1` 오류를 출력과 함께, `|` 파이프.

## 스스로 확인하기

**1.** `ls -l`의 결과가 `drwxr-x--- 3 jiwoo dev 4096 Apr  2 11:05 project`일 때 옳지 않은 설명은?
① project는 디렉터리이다 ② 소유자는 jiwoo이다 ③ 소유 그룹은 dev이다 ④ 파일 크기는 3바이트이다

> [!ANSWER]
> 정답: ④
> 세 번째 열의 3은 링크 수예요. 크기는 그룹 이름 뒤에 오는 4096(바이트)이에요.

**2.** 원본 파일을 지워도 같은 내용을 계속 읽을 수 있고, `ls -i`로 보면 원본과 같은 번호가 나오는 링크를 만드는 명령은?
① `ln -s a.txt b.txt` ② `ln a.txt b.txt` ③ `cp -s a.txt b.txt` ④ `mv a.txt b.txt`

> [!ANSWER]
> 정답: ②
> 옵션 없는 `ln`은 같은 아이노드를 공유하는 하드 링크를 만들어요. `ln -s`로 만든 심볼릭 링크는 원본이 지워지면 깨져요.

**3.** `/srv/web` 디렉터리를 gzip으로 압축한 `web.tar.gz` 하나로 묶는 명령으로 옳은 것은?
① `tar xvzf web.tar.gz /srv/web` ② `tar cvjf web.tar.gz /srv/web` ③ `tar cvzf web.tar.gz /srv/web` ④ `tar tvzf web.tar.gz /srv/web`

> [!ANSWER]
> 정답: ③
> 만들기는 `c`, gzip은 `z`, 파일 이름은 `f` 뒤에 써요. `x`는 풀기, `t`는 목록 보기, `j`는 bzip2예요.

**4.** `/var/log` 아래에서 최근 3일 안에 수정된 일반 파일만 찾는 명령은?
① `find /var/log -type d -mtime +3` ② `find /var/log -type f -mtime -3` ③ `grep -r -mtime 3 /var/log` ④ `locate /var/log -3`

> [!ANSWER]
> 정답: ②
> 일반 파일은 `-type f`, "3일 이내"는 `-mtime -3`이에요. `+3`은 3일보다 더 오래된 파일을 뜻해요.

**5.** 명령의 정상 출력과 오류 메시지를 모두 `result.txt` 하나에 기존 내용을 지우고 저장하려면 빈칸에 들어갈 것은? `./backup.sh ____`
① `>> result.txt` ② `2> result.txt` ③ `> result.txt 2>&1` ④ `< result.txt`

> [!ANSWER]
> 정답: ③
> `>`로 표준 출력을 파일로 돌린 다음 `2>&1`로 오류도 같은 곳으로 보내요. `2>`만 쓰면 오류만 저장되고, `>>`는 덧붙이기예요.
