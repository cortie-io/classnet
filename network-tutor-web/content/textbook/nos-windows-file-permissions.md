같은 폴더라도 누구는 읽기만 하고, 누구는 고치고, 누구는 아예 열지 못하게 정하는 것이 권한이에요. 이 단원에서는 Windows 파일 시스템의 차이, NTFS 권한과 공유 권한을 함께 쓸 때 실제 권한을 구하는 법, 복사·이동할 때 권한이 어떻게 바뀌는지, 그리고 디스크 할당량·암호화·볼륨 관리를 배워요. 시험에서는 권한 계산 문제가 단골로 나오니 단계별 계산법을 꼭 익혀 두세요.

> [!GOAL]
> - FAT32·NTFS·ReFS의 특징과 한계를 비교할 수 있다
> - NTFS 권한과 공유 권한을 조합해 실제로 적용되는 권한을 구할 수 있다
> - 복사·이동 시 권한 변화, 소유권, 디스크 할당량, EFS와 BitLocker를 설명할 수 있다
> - 기본·동적 디스크와 볼륨 종류(단순·스팬·스트라이프·미러·RAID-5)를 구분할 수 있다

## Windows의 파일 시스템

[운영체제와 네트워크 운영체제](/textbook/nos-os-basics)에서 파일 시스템이 무엇인지 간단히 봤어요. Windows Server에서 만나는 세 가지를 자세히 비교해 볼게요.

| 항목 | FAT32 | NTFS | ReFS |
|---|---|---|---|
| 이름 | File Allocation Table 32 | New Technology File System | Resilient File System |
| 파일 하나 최대 크기 | 4GB(정확히는 4GB에서 1바이트 모자람) | TB급 이상으로 매우 큼 | 매우 큼 |
| 볼륨 최대 크기 | 이론상 약 2TB, 다만 Windows Server의 포맷 도구로는 32GB까지만 생성 | 매우 큼(클러스터 크기에 따라 다름) | 매우 큼 |
| 파일·폴더 권한(ACL) | 없음 | 있음 | 있음 |
| 장애 대비 | 없음 | 저널링(변경 내용을 로그에 먼저 기록) | 체크섬으로 손상 감지, 저장소 공간과 함께 쓰면 자동 복구 |
| EFS 암호화·파일 압축 | 없음 | 있음 | 없음 |
| 디스크 할당량 | 없음 | 있음 | 없음 |
| Windows를 설치하는 볼륨(C:) | 불가 | 가능(필수) | 불가 |
| 주 용도 | USB 메모리, 여러 기기와 호환 | Windows의 기본 | 대용량 데이터, 가상 디스크 저장소 |

NTFS는 모든 파일과 폴더의 정보를 MFT(Master File Table, 마스터 파일 테이블)라는 표에 기록해요. ReFS는 Windows Server 2012에서 처음 나왔고, 데이터 손상에 강한 대신 NTFS의 일부 기능을 지원하지 않아요.

> [!NOTE]
> exFAT는 플래시 메모리용으로 만든 파일 시스템이에요. FAT32처럼 여러 기기에서 읽히면서도 4GB 파일 크기 제한이 없어서 대용량 USB 메모리나 메모리 카드에 많이 써요. 권한 기능은 없어요.

## NTFS 권한

### 표준 권한

NTFS 볼륨의 파일이나 폴더에서 [속성] → [보안] 탭을 열면 다음 표준 권한이 보여요. 각 권한마다 허용(Allow)과 거부(Deny)를 고를 수 있어요.

| 권한 | 할 수 있는 일 |
|---|---|
| 읽기(Read) | 파일 내용과 폴더 목록 보기, 속성·권한·소유자 보기 |
| 쓰기(Write) | 새 파일·하위 폴더 만들기, 파일 내용 바꾸기·덧붙이기, 속성 바꾸기(삭제는 포함되지 않음) |
| 폴더 내용 보기(List Folder Contents) | 폴더 안 목록 보기와 하위 폴더로 이동(폴더에만 있는 권한) |
| 읽기 및 실행(Read & Execute) | 읽기 + 프로그램 실행 + 하위 폴더 통과 |
| 수정(Modify) | 읽기 및 실행 + 쓰기 + 삭제 |
| 모든 권한(Full Control) | 수정 + 권한 바꾸기 + 소유권 가져오기 + 하위 폴더 및 파일 삭제 |

폴더에는 표준 권한이 여섯 가지이고, 파일에는 '폴더 내용 보기'가 없어서 다섯 가지예요. 표준 권한은 더 잘게 나눈 고급 권한(특별한 권한, Special Permissions)의 묶음이에요. [고급] 버튼을 누르면 '하위 폴더 및 파일 삭제', '권한 변경', '소유권 가져오기' 같은 세부 항목을 따로 줄 수 있어요.

> [!TIP]
> 큰 권한이 작은 권한을 품는 계단이라고 생각하세요. 읽기 → 읽기 및 실행 → 수정 → 모든 권한 순서로 올라가요. '쓰기'만으로는 파일을 지울 수 없고, 지우려면 '수정' 이상이 필요해요.

### 권한을 정하는 규칙

한 사용자는 보통 여러 그룹에 속해 있으므로 권한이 여러 곳에서 겹쳐 들어와요.

1. 누적: 사용자 본인에게 준 권한과 속한 모든 그룹의 권한을 합쳐요. 가장 넓은 권한이 적용돼요.
2. 거부 우선: 어느 한 곳에서라도 거부한 권한은 허용보다 우선해요.
3. 직접 준 권한 우선: 파일에 직접 준 권한이 폴더에서 물려받은 권한보다 우선해요.

> [!NOTE]
> 정확한 우선순위는 '명시적 거부 > 명시적 허용 > 상속된 거부 > 상속된 허용'이에요. 그래서 파일에 직접 '허용'을 주면 상위 폴더에서 물려받은 '거부'를 이길 수 있어요. 시험에서는 보통 "거부가 허용보다 우선한다"로 물어요.

### 상속

폴더에 준 권한은 기본적으로 그 안의 하위 폴더와 파일로 물려 내려가요. 이것을 상속(Inheritance)이라고 해요. 상속받은 권한은 [보안] 탭에서 체크 표시가 흐리게 보이고 그 자리에서 바로 바꿀 수 없어요. 특정 폴더만 다르게 하고 싶으면 [고급] → [상속 사용 안 함]을 눌러요. 이때 물려받던 권한을 명시적 권한으로 바꿔 남길지, 모두 지울지 선택해요.

명령으로는 `icacls`를 써요. 권한 약어는 F(모든 권한), M(수정), RX(읽기 및 실행), R(읽기), W(쓰기)이고, (OI)는 파일로, (CI)는 하위 폴더로 상속하라는 뜻이에요.

```text
C:\> icacls D:\Sales
C:\> icacls D:\Sales /grant "HANBIT\G_Sales:(OI)(CI)M"
C:\> icacls D:\Sales /inheritance:d
```

첫 줄은 현재 권한 보기, 둘째 줄은 G_Sales 그룹에 하위 폴더와 파일까지 수정 권한 주기, 셋째 줄은 상속을 끊되 기존 상속 권한은 복사해서 남기기예요.

### 소유권

파일이나 폴더를 만든 사용자가 그 개체의 소유자(Owner)가 돼요. 소유자는 권한 목록에 자기가 없더라도 그 개체의 권한을 바꿀 수 있어요. 퇴사자의 폴더처럼 아무도 접근할 수 없게 된 파일은 관리자(Administrators 그룹)가 '소유권 가져오기(Take Ownership)'로 소유자가 된 뒤 권한을 다시 설정해요.

```text
C:\> takeown /f D:\Old /r
C:\> icacls D:\Old /setowner "HANBIT\minsu" /t
```

`takeown /r`은 하위 항목까지 소유권을 가져오고, `icacls /setowner`는 소유자를 지정한 사용자로 바꿔요.

## 공유 권한

폴더를 네트워크에 공유하면 다른 컴퓨터에서 `\\FS01\Sales` 같은 UNC(Universal Naming Convention) 경로로 접근할 수 있어요. 파일 공유는 SMB(Server Message Block) 프로토콜, TCP 445 포트를 써요. 공유 폴더에는 NTFS 권한과 별개로 공유 권한이 있어요.

| 공유 권한 | 할 수 있는 일 |
|---|---|
| 읽기(Read) | 파일 이름과 내용 보기, 프로그램 실행 |
| 변경(Change) | 읽기 + 파일·폴더 만들기, 내용 바꾸기, 삭제 |
| 모든 권한(Full Control) | 변경 + NTFS 권한 바꾸기와 소유권 가져오기 |

- 공유 권한은 네트워크로 접근할 때만 적용돼요. 그 컴퓨터에 직접 로그온한 사용자에게는 영향이 없어요.
- 새로 공유를 만들면 기본값은 Everyone 그룹에 '읽기'예요.
- FAT32 볼륨의 폴더를 공유하면 NTFS 권한이 없으므로 공유 권한이 유일한 보호 수단이에요.
- 공유 이름 끝에 `$`를 붙이면(예: `Data$`) 네트워크 목록에 보이지 않는 숨김 공유가 돼요. `C$`, `ADMIN$`, `IPC$` 같은 관리 공유는 Windows가 자동으로 만들어요.

공유는 폴더 속성의 [공유] 탭 → [고급 공유]에서 만들거나 명령으로 만들어요.

```powershell
New-SmbShare -Name Sales -Path D:\Sales -ChangeAccess "HANBIT\G_Sales" -ReadAccess "Everyone"
```

## NTFS 권한과 공유 권한을 함께 쓸 때

### 계산 순서

공유 권한을 건물 정문, NTFS 권한을 사무실 문이라고 생각해 보세요. 밖에서 들어오는 사람은 두 문을 모두 통과해야 하니 더 좁은 문이 한계가 돼요. 건물 안에 있는 사람(로컬 로그온)은 사무실 문만 통과하면 돼요.

1. 공유 권한끼리 합쳐요(누적, 거부가 있으면 거부 우선).
2. NTFS 권한끼리 합쳐요(누적, 거부가 있으면 거부 우선).
3. 네트워크로 접근하면 1과 2 중 더 제한적인 쪽이 실제 권한이에요. 로컬로 접근하면 2만 적용돼요.

### 예제

민수는 `G_영업` 그룹과 Everyone 그룹에 속해 있어요. 공유 폴더 `\\FS01\Sales`의 권한이 다음과 같아요.

| 대상 | 공유 권한 | NTFS 권한 |
|---|---|---|
| Everyone | 읽기 | — |
| G_영업 | 변경 | 읽기 및 실행 |
| 민수(개인) | — | 쓰기 |

- 1단계(공유): 읽기 + 변경 → 변경
- 2단계(NTFS): 읽기 및 실행 + 쓰기 → 읽기·실행·쓰기 가능, 삭제 불가
- 3단계(네트워크): 변경과 '읽기 및 실행 + 쓰기' 중 더 좁은 쪽 → 읽기·실행·쓰기는 되지만 삭제는 안 돼요.

민수가 FS01에 직접 로그온해서 D:\Sales를 열면 공유 권한은 무시되고 NTFS 결과인 '읽기 및 실행 + 쓰기'가 적용돼요. 만약 민수 개인에게 NTFS '쓰기 거부'가 걸려 있다면, 그룹에서 무엇을 허용했든 쓰기는 불가능해요.

> [!EXAM]
> "공유 권한 읽기, NTFS 권한 모든 권한일 때 네트워크 사용자의 실제 권한은?"처럼 묻는 문제가 많아요. 답은 더 제한적인 '읽기'예요. 실무에서는 공유 권한을 넓게 두고 세밀한 통제는 NTFS 권한으로 하는 방식을 많이 써요.

## 복사와 이동에 따른 권한 변화

파일을 옮길 때 권한이 따라가는지는 '새 파일이 생기느냐'로 판단하면 쉬워요.

| 작업 | 결과 |
|---|---|
| 같은 NTFS 볼륨 안에서 이동 | 원래 권한 유지(파일 위치 정보만 바뀜) |
| 다른 NTFS 볼륨으로 이동 | 대상 폴더의 권한을 상속(실제로는 복사 후 원본 삭제) |
| 복사(같은 볼륨이든 다른 볼륨이든) | 대상 폴더의 권한을 상속(새 파일이 생김) |
| FAT32 볼륨으로 복사·이동 | NTFS 권한이 모두 사라짐. EFS 암호화와 압축도 유지할 수 없음 |

복사하려면 대상 폴더에 '쓰기' 권한이 있어야 하고, 이동하려면 원본에 '수정' 권한(지우기 위해)과 대상 폴더에 '쓰기' 권한이 있어야 해요. 복사한 파일은 복사한 사람이 새 소유자가 돼요.

> [!TIP]
> "같은 볼륨 안에서 이동할 때만 권한 유지, 나머지는 모두 도착한 폴더를 따름"으로 외우세요. 권한을 그대로 옮겨야 하면 `robocopy`의 `/COPYALL` 옵션처럼 보안 정보까지 복사하는 도구를 써요.

## 디스크 할당량

디스크 할당량(Disk Quota)은 NTFS 볼륨에서 사용자마다 쓸 수 있는 용량을 제한하는 기능이에요. 볼륨 [속성] → [할당량] 탭에서 켜요.

- 볼륨 단위로 설정하고, 파일의 소유자를 기준으로 사용량을 계산해요.
- 제한(Limit)과 경고 수준(Warning Level)을 정하고, '할당량 제한을 초과하는 사용자에게 디스크 공간 거부'를 체크하면 제한을 넘는 저장을 막아요. 체크하지 않으면 기록만 남기고 저장은 허용해요.
- 압축된 파일도 압축 전 크기로 계산해요.
- Administrators 그룹은 기본적으로 제한을 받지 않아요.
- 폴더 단위 할당량이나 '동영상 파일 저장 금지' 같은 파일 차단은 파일 서버 리소스 관리자(FSRM, File Server Resource Manager)로 설정해요.

## 암호화: EFS와 BitLocker

| 구분 | EFS(Encrypting File System) | BitLocker 드라이브 암호화 |
|---|---|---|
| 암호화 단위 | 파일·폴더 | 볼륨(드라이브) 전체 |
| 파일 시스템 | NTFS만 | 운영체제 드라이브는 NTFS, 이동식 드라이브는 FAT 계열도 가능 |
| 키 보관 | 사용자 인증서(공개 키)로 파일 암호화 키를 보호 | TPM(Trusted Platform Module, 신뢰할 수 있는 플랫폼 모듈), PIN, USB 키. 48자리 복구 키 |
| 막아 주는 위협 | 같은 컴퓨터의 다른 사용자가 파일을 여는 것 | 디스크를 떼어 가거나 노트북을 잃어버렸을 때 데이터 유출 |
| 명령 | `cipher` | `manage-bde` |
| 참고 | 파일 압축과 동시에 쓸 수 없음, 복구 에이전트가 대신 복호화 가능 | 서버에서는 '기능'으로 추가. 이동식 드라이브용은 BitLocker To Go |

EFS는 파일을 대칭 키(파일 암호화 키)로 빠르게 암호화하고, 그 키를 사용자의 공개 키로 다시 암호화해 두는 방식이에요. 암호화한 사용자는 평소처럼 파일을 열 수 있지만, NTFS 권한이 있는 다른 사용자라도 열 수 없어요.

```text
C:\> cipher /e D:\Secret
C:\> manage-bde -status
```

## 디스크와 볼륨 관리

### MBR과 GPT

| 구분 | MBR(Master Boot Record) | GPT(GUID Partition Table) |
|---|---|---|
| 최대 디스크 크기 | 2TB(512바이트 섹터 기준) | 사실상 제한을 느끼기 어려울 만큼 큼 |
| 파티션 수 | 주 파티션 4개(또는 주 3개 + 확장 1개 안에 논리 드라이브 여러 개) | Windows에서 128개 |
| 부팅 방식 | BIOS(레거시) | UEFI |

### 기본 디스크와 동적 디스크

- 기본 디스크(Basic Disk): 파티션(주 파티션, 확장 파티션, 논리 드라이브) 단위로 나눠 써요. 새 디스크의 기본값이에요.
- 동적 디스크(Dynamic Disk): '볼륨' 단위로 관리하며, 여러 디스크를 묶는 스팬·스트라이프·미러·RAID-5 볼륨을 만들 수 있어요.
- 기본 디스크를 동적 디스크로 바꿀 때는 데이터가 유지돼요. 반대로 동적 디스크를 기본 디스크로 되돌리려면 모든 볼륨을 지워야 해요.

> [!NOTE]
> Microsoft는 동적 디스크를 앞으로 쓰지 않을 기능으로 분류하고, 여러 디스크를 묶을 때는 저장소 공간(Storage Spaces)을 권장해요. 시험에서는 여전히 동적 디스크의 볼륨 종류를 물어요.

### 볼륨 종류

| 볼륨 | 디스크 수 | 방식 | 사용 가능 용량 | 내결함성 | RAID 대응 |
|---|---|---|---|---|---|
| 단순(Simple) | 1 | 디스크 하나의 공간 사용 | 전체 | 없음 | — |
| 스팬(Spanned) | 2~32 | 여러 디스크의 빈 공간을 이어 붙여 차례로 채움 | 합계 | 없음(하나만 고장 나도 전체 손실) | — |
| 스트라이프(Striped) | 2~32 | 데이터를 잘게 나눠 여러 디스크에 동시에 기록 | 합계(디스크마다 같은 크기만 사용) | 없음 | RAID-0 |
| 미러(Mirrored) | 2 | 같은 데이터를 두 디스크에 똑같이 기록 | 절반 | 있음(1개 고장 견딤) | RAID-1 |
| RAID-5 | 3~32 | 데이터와 패리티를 모든 디스크에 나눠 기록 | 전체의 (n−1)/n | 있음(1개 고장 견딤) | RAID-5 |

- 성능: 스트라이프가 읽기·쓰기 모두 가장 빨라요. RAID-5는 읽기는 빠르지만 쓸 때마다 패리티를 계산해서 쓰기가 느린 편이에요.
- 미러 볼륨에는 시스템·부팅 볼륨을 둘 수 있지만, RAID-5 볼륨에는 둘 수 없어요. 소프트웨어 RAID-5 볼륨은 서버용 Windows에서만 만들 수 있어요.
- 예: 1TB 디스크 3개로 만들면 스팬 3TB, 스트라이프 3TB, RAID-5 2TB예요. 미러는 2개로 만들어 1TB예요.

하드웨어 RAID와 RAID 레벨 전체는 [서버·스토리지와 이중화](/textbook/dev-server-storage)에서 자세히 배워요.

### convert 명령

`convert` 명령은 FAT 또는 FAT32 볼륨을 데이터를 지우지 않고 NTFS로 바꿔요. 한 방향 변환이라 NTFS를 FAT32로 되돌리려면 포맷해야 해요.

```text
C:\> convert D: /fs:ntfs
```

디스크 형식은 `diskpart` 안에서 `select disk 1`처럼 디스크를 고른 뒤 `convert`로 바꿔요.

| diskpart 명령 | 하는 일 | 조건 |
|---|---|---|
| `convert dynamic` | 기본 → 동적 | 데이터 유지 |
| `convert basic` | 동적 → 기본 | 디스크가 비어 있어야 함 |
| `convert gpt` | MBR → GPT | 디스크가 비어 있어야 함 |
| `convert mbr` | GPT → MBR | 디스크가 비어 있어야 함 |

### chkdsk와 defrag

- `chkdsk`: 파일 시스템 오류와 불량 섹터를 검사해요. `chkdsk D:`는 검사만, `/f`는 오류 수정, `/r`은 불량 섹터를 찾아 읽을 수 있는 정보를 복구(`/f` 포함)해요. 사용 중인 C: 드라이브는 다음 재시작 때 검사하도록 예약돼요.
- `defrag`: 흩어진 파일 조각을 모아 하드 디스크(HDD)의 읽기 속도를 높이는 조각 모음이에요. `/A`는 분석만, `/U`는 진행률 표시, `/V`는 자세히 표시, `/O`는 매체 종류에 맞게 최적화(SSD는 TRIM 실행)해요. GUI 이름은 '드라이브 최적화'이고 기본으로 주 1회 자동 실행돼요.

```text
C:\> chkdsk D: /f
C:\> defrag D: /A
```

## 핵심 정리

- FAT32는 파일 하나 최대 4GB, 권한·암호화·할당량이 없어요. NTFS는 권한·저널링·EFS·압축·할당량을 지원해요. ReFS는 손상에 강하지만 부팅·EFS·할당량을 지원하지 않아요.
- NTFS 표준 권한은 모든 권한 > 수정 > 읽기 및 실행 > 읽기 순서로 넓고, '쓰기'만으로는 삭제할 수 없어요.
- 공유 권한은 읽기·변경·모든 권한 세 가지이고, 네트워크 접근에만 적용돼요. 기본값은 Everyone 읽기예요.
- 같은 종류의 권한끼리는 누적, 거부는 허용보다 우선, 네트워크 접근 시 공유와 NTFS 중 더 제한적인 쪽이 실제 권한이에요.
- 같은 NTFS 볼륨 안에서 이동할 때만 권한이 유지되고, 복사나 다른 볼륨으로 이동하면 대상 폴더 권한을 상속해요.
- 디스크 할당량은 NTFS 볼륨 단위·소유자 기준이고, EFS는 파일 단위, BitLocker는 볼륨 전체 암호화예요.
- 스팬·스트라이프는 내결함성이 없고, 미러(2개, 용량 절반)와 RAID-5(3개 이상, (n−1)/n)는 디스크 1개 고장을 견뎌요.
- `convert D: /fs:ntfs`는 데이터를 유지한 채 FAT32를 NTFS로 바꾸며 되돌릴 수 없어요.

## 스스로 확인하기

**1.** 공유 폴더에 Everyone 공유 권한 '읽기', NTFS 권한 '수정'이 설정되어 있다. 사용자가 네트워크로 이 폴더에 접근할 때 실제 권한은?
① 읽기 ② 변경 ③ 수정 ④ 모든 권한

> [!ANSWER]
> 정답: ①
> 네트워크 접근에서는 공유 권한과 NTFS 권한 중 더 제한적인 쪽이 적용되므로 '읽기'예요. 서버에 직접 로그온하면 NTFS의 '수정'이 적용돼요.

**2.** NTFS 볼륨 D:의 `D:\Plan\보고서.docx`를 같은 D: 볼륨의 `D:\Archive` 폴더로 이동했다. 파일의 권한은 어떻게 되는가?
① 원래 권한이 유지된다 ② D:\Archive의 권한을 상속한다 ③ 모든 권한이 사라진다 ④ Everyone 모든 권한으로 바뀐다

> [!ANSWER]
> 정답: ①
> 같은 NTFS 볼륨 안에서 이동하면 파일 위치 정보만 바뀌므로 원래 권한이 유지돼요.

**3.** 1TB 디스크 4개로 RAID-5 볼륨을 만들면 사용할 수 있는 용량은?
① 1TB ② 2TB ③ 3TB ④ 4TB

> [!ANSWER]
> 정답: ③
> RAID-5는 디스크 1개 분량을 패리티에 쓰므로 (4−1) × 1TB = 3TB를 쓸 수 있어요.

**4.** 다음 중 NTFS 볼륨에서 사용자 인증서를 이용해 파일·폴더 단위로 암호화하는 기능은?
① BitLocker ② EFS ③ 디스크 할당량 ④ chkdsk

> [!ANSWER]
> 정답: ②
> EFS는 NTFS 전용의 파일 단위 암호화예요. BitLocker는 볼륨 전체를 암호화해요.

**5.** 동적 디스크 볼륨 중 여러 디스크에 데이터를 나눠 동시에 기록해 속도는 가장 빠르지만 내결함성이 없는 것은?
① 미러 볼륨 ② RAID-5 볼륨 ③ 스트라이프 볼륨 ④ 단순 볼륨

> [!ANSWER]
> 정답: ③
> 스트라이프 볼륨(RAID-0)은 성능이 가장 좋지만 디스크 하나만 고장 나도 전체 데이터를 잃어요.
