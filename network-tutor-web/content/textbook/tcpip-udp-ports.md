TCP가 도착을 하나하나 확인하는 등기우편이라면, UDP는 우체통에 넣으면 끝인 엽서예요. 확인 절차가 없는 대신 빠르고 가벼워서, 짧게 묻고 답하는 서비스나 실시간 음성·영상에 쓰여요. 이 단원에서는 UDP의 구조와 특징을 TCP와 비교하고, 한 컴퓨터 안에서 어느 프로그램에 데이터를 넘길지 정하는 포트 번호를 배워요. 잘 알려진 포트 번호는 시험에 매회 나온다고 봐도 될 만큼 중요해요.

> [!GOAL]
> - UDP 헤더의 네 필드와 UDP의 특징을 말할 수 있다.
> - TCP와 UDP의 차이를 표로 정리하고, 서비스마다 어느 쪽을 쓰는지 판단할 수 있다.
> - 포트 번호의 세 가지 범위를 구분할 수 있다.
> - 주요 잘 알려진 포트 번호와 TCP·UDP 사용 여부를 외운다.

## UDP — 가볍고 빠른 전송

### UDP의 특징

UDP(User Datagram Protocol)는 TCP와 같은 전송 계층 프로토콜이고, IP 헤더의 프로토콜 번호는 **17**이에요. UDP가 다루는 데이터 단위는 **데이터그램**(Datagram)이라고 불러요.

- **비연결형(Connectionless)**: 연결을 맺는 절차 없이 바로 보내요.
- **비신뢰성**: 확인 응답, 재전송, 순서 맞추기를 하지 않아요. 필요하면 응용 프로그램이 직접 해야 해요.
- **흐름 제어·혼잡 제어 없음**: 보내는 속도를 스스로 조절하지 않아요.
- **작은 헤더**: 8바이트 고정이라 부담이 적고 빨라요.
- **메시지 경계 유지**: 한 번 보낸 데이터는 한 덩어리의 데이터그램으로 도착해요. 바이트 흐름으로 다루는 TCP와 달라요.
- **1:N 전송 가능**: 연결이 없으니 브로드캐스트와 멀티캐스트에도 쓸 수 있어요.

### UDP 헤더

UDP 헤더는 16비트 필드 네 개, 모두 **8바이트**가 전부예요.

```text
0           8           16          24          31
+-----------------------+-----------------------+
|      Source Port      |   Destination Port    |
+-----------------------+-----------------------+
|        Length         |       Checksum        |
+-----------------------+-----------------------+
|                 Data (payload)                |
+-----------------------------------------------+
```

| 필드 | 크기 | 하는 일 |
|---|---|---|
| 출발지 포트(Source Port) | 16비트 | 보내는 프로그램의 포트. 답장이 필요 없으면 0으로 둘 수 있어요 |
| 목적지 포트(Destination Port) | 16비트 | 받을 프로그램의 포트 |
| 길이(Length) | 16비트 | **헤더 + 데이터**의 전체 길이(바이트). 최솟값은 헤더만 있는 8 |
| 체크섬(Checksum) | 16비트 | 헤더와 데이터의 오류 검사. IPv4에서는 생략 가능(0), IPv6에서는 필수 |

> [!WARNING]
> UDP 헤더에는 순서 번호, 확인 응답 번호, 윈도 크기가 **없어요**. "UDP 헤더에 포함되지 않는 필드는?"이라는 문제에서 이런 TCP 필드가 정답 보기로 나와요.

### UDP를 쓰는 서비스

UDP를 고르는 데는 분명한 이유가 있어요.

| 이유 | 예 |
|---|---|
| 짧게 한 번 묻고 답하면 끝나서 연결을 맺는 게 오히려 낭비 | DNS 질의, SNMP, NTP |
| 아직 IP 주소가 없어 브로드캐스트를 써야 함 | DHCP |
| 단순함이 중요한 작은 장비·부팅 과정 | TFTP |
| 늦게 도착한 데이터는 쓸모가 없어 재전송보다 속도가 중요 | 인터넷 전화(VoIP), 실시간 방송, 온라인 게임 |
| 같은 내용을 여러 곳에 한 번에 | 멀티캐스트 방송, RIP 라우팅 정보 |

> [!NOTE]
> 최신 웹 프로토콜 HTTP/3는 UDP 위에서 동작하는 QUIC을 써요. 재전송과 암호화 같은 기능을 TCP 대신 QUIC이 응용 쪽에서 직접 구현한 거예요. UDP가 "신뢰성이 필요 없는 곳에만" 쓰인다고 단정하지 않도록 기억해 두세요.

## TCP와 UDP 비교

| 구분 | TCP | UDP |
|---|---|---|
| 연결 | 연결 지향(3-way 핸드셰이크) | 비연결형 |
| 신뢰성 | 확인 응답·재전송으로 보장 | 보장하지 않음 |
| 순서 | 보장 | 보장하지 않음 |
| 흐름·혼잡 제어 | 있음 | 없음 |
| 헤더 크기 | 20–60바이트 | 8바이트 고정 |
| 데이터 단위 | 세그먼트 | 데이터그램 |
| 데이터 경계 | 바이트 스트림(경계 없음) | 메시지 단위로 유지 |
| 통신 대상 | 1:1 | 1:1, 1:N(브로드캐스트·멀티캐스트) |
| 속도·부담 | 상대적으로 느리고 무거움 | 빠르고 가벼움 |
| 프로토콜 번호 | 6 | 17 |
| 대표 서비스 | HTTP, FTP, SMTP, SSH, Telnet | DNS 질의, DHCP, TFTP, SNMP, NTP |

TCP의 연결 설정과 혼잡 제어는 [TCP](/textbook/tcpip-tcp)에서 자세히 배웠어요.

## 포트 번호

### 포트란

IP 주소가 건물 주소라면 포트 번호(Port Number)는 건물 안의 호수예요. 한 컴퓨터에서 웹 브라우저, 메일 프로그램, 메신저가 동시에 통신해도, 포트 번호 덕분에 도착한 데이터가 올바른 프로그램으로 들어가요. 포트 번호는 TCP·UDP 헤더에 들어 있는 **16비트** 값이라 0부터 65,535까지 쓸 수 있어요.

- 서버는 정해진 번호에서 기다려요. 웹 서버는 80번, DNS 서버는 53번처럼요.
- 클라이언트는 연결할 때마다 운영체제가 임시 번호를 골라 줘요.

민수가 브라우저 탭 두 개로 같은 웹 서버에 접속하면 이렇게 돼요.

```text
탭 1: 192.168.0.25:51515  -->  203.0.113.80:80
탭 2: 192.168.0.25:51516  -->  203.0.113.80:80
```

목적지는 같지만 출발지 포트가 달라서 응답이 각 탭으로 정확히 돌아가요. 이렇게 IP 주소와 포트 번호를 묶은 통신의 끝점을 **소켓**(Socket)이라고 하고, 연결 하나는 "프로토콜, 출발지 IP, 출발지 포트, 목적지 IP, 목적지 포트" 다섯 가지 값으로 구별해요.

> [!WARNING]
> TCP와 UDP의 포트는 서로 **별개의 번호 공간**이에요. TCP 53번과 UDP 53번은 다른 포트이고, 그래서 DNS처럼 같은 번호를 TCP와 UDP 양쪽에서 쓰는 서비스도 있어요.

### 포트 번호의 범위

| 범위 | 이름 | 설명 |
|---|---|---|
| 0–1023 | 잘 알려진 포트(Well-known Port) | 대표 서비스에 배정된 번호. 유닉스 계열에서는 보통 이 포트를 열려면 관리자(root) 권한이 필요해요 |
| 1024–49151 | 등록된 포트(Registered Port) | 특정 응용 프로그램용으로 등록된 번호. 예: 3389 RDP, 3306 MySQL |
| 49152–65535 | 동적·사설 포트(Dynamic/Private Port) | 클라이언트가 잠깐 쓰는 임시 포트(Ephemeral Port) |

포트 번호는 IANA(Internet Assigned Numbers Authority)가 관리해요. 동적 포트 범위는 IANA 권고 기준이고, 실제로 임시 포트를 고르는 범위는 운영체제마다 다를 수 있어요.

> [!EXAM]
> 범위의 경계 숫자 **1023 / 1024**, **49151 / 49152**를 정확히 외워 두세요. "잘 알려진 포트의 범위는?" "동적 포트의 시작 번호는?"처럼 숫자를 직접 묻는 문제가 나와요.

| 포트 | 서비스 | TCP/UDP | 용도 |
|---|---|---|---|
| 20 | FTP 데이터 | TCP | 파일 내용 전송(능동 모드) |
| 21 | FTP 제어 | TCP | 로그인, 명령 주고받기 |
| 22 | SSH | TCP | 암호화된 원격 접속, SFTP·SCP |
| 23 | Telnet | TCP | 암호화 없는 원격 접속 |
| 25 | SMTP | TCP | 메일 보내기, 메일 서버 간 전달 |
| 53 | DNS | UDP, TCP | 질의는 주로 UDP, 영역 전송·큰 응답은 TCP |
| 67 | DHCP 서버 | UDP | 서버가 요청을 받는 포트 |
| 68 | DHCP 클라이언트 | UDP | 클라이언트가 응답을 받는 포트 |
| 69 | TFTP | UDP | 인증 없는 간단한 파일 전송 |
| 80 | HTTP | TCP | 웹 |
| 110 | POP3 | TCP | 메일 내려받기 |
| 123 | NTP | UDP | 시간 동기화 |
| 143 | IMAP | TCP | 서버에 둔 메일 읽고 관리하기 |
| 161 | SNMP | UDP | 관리 시스템이 장비(에이전트)에 질의 |
| 162 | SNMP Trap | UDP | 장비가 관리 시스템에 경보 전송 |
| 389 | LDAP | TCP(UDP도 가능) | 디렉터리 정보 조회 |
| 443 | HTTPS | TCP(HTTP/3는 UDP) | 암호화된 웹 |
| 445 | SMB | TCP | Windows 파일·프린터 공유 |
| 3389 | RDP | TCP(UDP도 함께 사용) | Windows 원격 데스크톱 |

### 더 알아 두면 좋은 포트

| 포트 | 서비스 | TCP/UDP |
|---|---|---|
| 137, 138 / 139 | NetBIOS 이름·데이터그램 / 세션 | UDP / TCP |
| 179 | BGP | TCP |
| 465 | SMTPS(암호화된 메일 제출) | TCP |
| 514 | Syslog(로그 전송) | UDP |
| 520 | RIP | UDP |
| 587 | 메일 제출(Submission) | TCP |
| 636 | LDAPS(암호화된 LDAP) | TCP |
| 993 | IMAPS(암호화된 IMAP) | TCP |
| 995 | POP3S(암호화된 POP3) | TCP |
| 1812, 1813 | RADIUS 인증, 과금 | UDP |
| 3306 | MySQL | TCP |
| 8080 | HTTP 대체 포트(프록시·테스트 서버) | TCP |

> [!TIP]
> 숫자를 이야기로 묶으면 오래 남아요.
> - **20번대는 접속과 전송**: 20·21 FTP 형제, 22 SSH, 23 Telnet, 25 SMTP. 안전한 SSH(22)가 옛 Telnet(23)보다 한 칸 앞에 서 있어요.
> - **53은 "이름 물어보삼"**: DNS.
> - **67·68·69는 부팅 삼총사**: 네트워크 부팅을 하는 PC는 DHCP(67 서버, 68 클라이언트)로 주소를 받고 곧바로 TFTP(69)로 부팅 파일을 받아요. 서버가 작은 번호, 클라이언트가 큰 번호예요.
> - **메일 받기는 110 → 143**: POP3가 먼저, IMAP이 다음. 암호화판은 9로 시작하는 995(POP3S)·993(IMAPS)예요.
> - **161은 묻고, 162는 알리고**: SNMP 질의와 트랩.
> - **HTTP(80)에 S가 붙으면 443**: 암호화된 웹 HTTPS.
> - **UDP 팀은 "짧게 묻고 바로 답하기"**: 이름(DNS), 주소(DHCP), 작은 파일(TFTP), 장비 상태(SNMP), 시계(NTP).

> [!EXAM]
> - **FTP**(TCP 20·21)와 **TFTP**(UDP 69)를 맞바꾼 보기가 단골 함정이에요.
> - DNS는 UDP와 TCP를 **둘 다** 써요. "DNS는 UDP만 쓴다"는 틀린 설명이에요.
> - SNMP는 161(질의)과 162(트랩)를 구분해서 물어요.
> - "TCP를 쓰는 서비스를 고르시오"에는 HTTP, FTP, SMTP, POP3, IMAP, SSH, Telnet이 정답 쪽이에요.

### 열려 있는 포트 확인하기

컴퓨터에서 어떤 포트가 연결을 기다리고 있는지 다음 명령으로 볼 수 있어요.

```powershell
netstat -an | findstr LISTENING   # 대기 중인 TCP 포트
netstat -ano                      # PID까지 함께 보기
```

```bash
ss -tuln    # 대기 중인 TCP·UDP 포트를 숫자로
```

서비스 이름과 포트 번호의 대응표는 리눅스의 `/etc/services`, Windows의 `C:\Windows\System32\drivers\etc\services` 파일에도 들어 있어요.

## 핵심 정리

- UDP는 비연결형·비신뢰성 전송 프로토콜이며, 프로토콜 번호 17, 데이터 단위는 데이터그램이다.
- UDP 헤더는 8바이트: 출발지 포트, 목적지 포트, 길이, 체크섬(각 16비트).
- UDP는 빠르고 가벼우며 브로드캐스트·멀티캐스트가 가능하다. DNS 질의, DHCP, TFTP, SNMP, NTP, 실시간 음성·영상에 쓴다.
- 포트 번호는 16비트(0–65535). TCP와 UDP는 포트 번호 공간이 따로다.
- 범위: 0–1023 잘 알려진 포트, 1024–49151 등록된 포트, 49152–65535 동적·사설 포트.
- TCP: 20·21 FTP, 22 SSH, 23 Telnet, 25 SMTP, 80 HTTP, 110 POP3, 143 IMAP, 443 HTTPS, 445 SMB, 3389 RDP.
- UDP: 67·68 DHCP, 69 TFTP, 123 NTP, 161·162 SNMP. DNS 53은 UDP와 TCP 모두.
