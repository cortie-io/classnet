라우터가 수십 대만 되어도 경로를 모두 손으로 입력하기는 어렵고, 링크 하나가 끊길 때마다 관리자가 달려가 고칠 수도 없어요. 그래서 라우터들은 라우팅 프로토콜로 서로 경로 정보를 주고받으며 라우팅 테이블을 스스로 만들고 고쳐요. 이 단원에서는 라우팅 프로토콜을 나누는 기준과 RIP, OSPF, EIGRP, BGP의 특징을 비교하며 정리해요.

> [!GOAL]
> - IGP와 EGP, 거리 벡터·링크 상태·고급 거리 벡터·경로 벡터 방식의 차이를 설명할 수 있어요.
> - RIP의 메트릭, 최대 홉 수, 갱신 주기, 버전별 차이와 라우팅 루프 방지 기법을 알아요.
> - OSPF의 SPF 알고리즘, 비용, 영역, DR/BDR, 사용하는 멀티캐스트 주소를 알아요.
> - EIGRP와 BGP의 핵심 특징을 알고, 네 프로토콜을 표로 비교할 수 있어요.

## 동적 라우팅의 기본 개념

### 라우팅 프로토콜이 하는 일
라우팅 프로토콜(Routing Protocol)은 라우터끼리 "나는 이 네트워크에 이만큼의 비용으로 갈 수 있어"라는 정보를 주고받는 규칙이에요. 이 정보로 각 라우터가 라우팅 테이블을 만들고, 링크가 끊기거나 새로 생기면 테이블을 다시 계산해요.

변화가 생긴 뒤 모든 라우터가 같은 망 상태를 반영한 테이블을 갖게 되는 것을 수렴(Convergence)이라고 해요. 수렴 시간이 짧을수록 장애가 나도 통신이 빨리 회복돼요.

> [!NOTE]
> 라우팅 프로토콜과 라우티드 프로토콜(Routed Protocol)은 달라요. 라우티드 프로토콜은 IP처럼 라우터가 실어 나르는 대상이고, 라우팅 프로토콜은 RIP·OSPF처럼 그 길을 만드는 프로토콜이에요.

### IGP와 EGP
인터넷은 수많은 자율 시스템이 연결된 것이에요. 자율 시스템(AS, Autonomous System)은 한 관리 주체가 하나의 라우팅 정책으로 운영하는 네트워크 묶음으로, 통신사(ISP)나 큰 기업·기관이 하나의 AS가 되는 경우가 많아요. 각 AS는 AS 번호(ASN)로 구별해요.

| 구분 | 뜻 | 대표 프로토콜 |
|---|---|---|
| IGP(Interior Gateway Protocol, 내부 게이트웨이 프로토콜) | 하나의 AS 안에서 경로를 교환 | RIP, OSPF, EIGRP, IS-IS |
| EGP(Exterior Gateway Protocol, 외부 게이트웨이 프로토콜) | 서로 다른 AS 사이에서 경로를 교환 | BGP |

> [!WARNING]
> EGP는 분류 이름이면서, BGP 이전에 쓰이던 옛 프로토콜의 이름이기도 해요. 오늘날 AS 사이 라우팅에 실제로 쓰이는 프로토콜은 사실상 BGP 하나예요.

### 동작 방식에 따른 분류
**거리 벡터**(Distance Vector)는 이웃이 알려 준 "거리(메트릭)"와 "방향(다음 홉)"만으로 경로를 정해요. 갈림길마다 서 있는 이정표만 보고 길을 찾는 것과 같아서, 망 전체의 모양은 알지 못해요. 주기적으로 자기 라우팅 테이블 전체를 이웃에게 보내고, 벨만-포드(Bellman-Ford) 알고리즘으로 계산해요. 구조가 단순하지만 수렴이 느리고 라우팅 루프가 생기기 쉬워요.

**링크 상태**(Link State)는 각 라우터가 자기에게 붙은 링크의 상태를 망(영역) 전체에 퍼뜨려서, 모든 라우터가 같은 네트워크 지도를 갖게 해요. 각 라우터는 이 지도로 다익스트라(Dijkstra)의 SPF(Shortest Path First) 알고리즘을 돌려 최단 경로를 직접 계산해요. 지도를 들고 내비게이션을 쓰는 것과 같아요. 수렴이 빠르고 루프가 잘 생기지 않지만, 메모리와 CPU를 더 쓰고 설계가 복잡해요.

**고급 거리 벡터**(Advanced Distance Vector)는 거리 벡터를 바탕으로 링크 상태의 장점(변화가 있을 때만 갱신, 빠른 수렴)을 더한 방식이에요. 두 방식을 섞었다는 뜻에서 하이브리드(Hybrid, 혼합형)라고도 하며, EIGRP가 여기에 속해요.

**경로 벡터**(Path Vector)는 목적지까지 거쳐 가는 AS의 목록을 함께 주고받는 방식이에요. BGP가 여기에 속해요.

| 항목 | 거리 벡터 | 링크 상태 |
|---|---|---|
| 아는 정보 | 이웃이 알려 준 거리와 방향 | 영역 전체의 링크 지도 |
| 알고리즘 | 벨만-포드 | 다익스트라(SPF) |
| 갱신 방식 | 주기적으로 테이블 전체를 이웃에게 | 변화가 있을 때 링크 상태 정보만 전체에 |
| 수렴 속도 | 느림 | 빠름 |
| 자원 사용 | 적음 | 많음(메모리·CPU) |
| 라우팅 루프 | 생기기 쉬움 | 잘 생기지 않음 |
| 대표 | RIP | OSPF, IS-IS |

## RIP

### RIP의 특징
RIP(Routing Information Protocol)은 가장 오래되고 단순한 거리 벡터 프로토콜이에요.
- **메트릭은 홉 수**예요. 거쳐 가는 라우터 수만 세고 링크 속도는 보지 않아요.
- **최대 15홉**까지 쓸 수 있고, 16홉은 무한대, 즉 "도달할 수 없음"을 뜻해요. 그래서 작은 망에 알맞아요.
- **30초마다** 라우팅 테이블 전체를 이웃에게 보내요.
- **UDP 520번 포트**를 써요.
- 시스코 기준 관리 거리는 120이에요.

경로 정보가 끊기면 쓰는 타이머도 있어요. 180초 동안 갱신이 오지 않으면 그 경로를 무효(Invalid)로 보고, 시스코 기준으로는 홀드다운 180초, 테이블에서 지우는 플러시(Flush) 240초를 써요.

> [!WARNING]
> RIP는 홉 수만 보기 때문에, 느린 링크로 2홉 가는 경로와 빠른 링크로 3홉 가는 경로가 있으면 느린 2홉 경로를 골라요. 시험에서 "RIP는 대역폭을 고려한다"는 보기는 틀린 문장이에요.

### RIPv1과 RIPv2

| 항목 | RIPv1 | RIPv2 |
|---|---|---|
| 주소 방식 | 클래스풀(Classful): 서브넷 마스크를 보내지 않음 | 클래스리스(Classless): 서브넷 마스크를 함께 보냄 |
| VLSM·CIDR | 지원하지 않음 | 지원 |
| 갱신 전송 | 브로드캐스트(255.255.255.255) | 멀티캐스트(224.0.0.9) |
| 인증 | 없음 | 지원(평문, MD5) |

IPv6용으로는 RIPng가 있어요. UDP 521번 포트와 멀티캐스트 주소 ff02::9를 써요.

## 라우팅 루프와 방지 기법

### 무한대 카운트 문제
거리 벡터는 이웃의 말을 그대로 믿기 때문에 잘못된 정보가 돌고 돌 수 있어요. 아래처럼 연결된 망을 생각해 봐요.

```text
 [N]---[C]-------[B]-------[A]
        1         2         3     (N까지의 홉 수)
```

N은 목적지 네트워크예요. C는 N에 1홉, B는 C를 거쳐 2홉, A는 B를 거쳐 3홉으로 알고 있어요.

1. C와 네트워크 N 사이 링크가 끊겨요. C는 N 경로를 지워요.
2. C가 이 소식을 알리기 전에, B의 정기 갱신 "N까지 2홉"이 C에 도착해요.
3. C는 "B를 거치면 N에 3홉으로 갈 수 있구나"라고 믿어 버려요. 사실 B의 경로는 C를 거치는 경로였는데도요.
4. 이제 N으로 가는 패킷은 B와 C 사이를 오가며 맴돌아요. 이것이 라우팅 루프(Routing Loop)예요.
5. B는 C에게서 "3홉"을 듣고 4홉으로, C는 다시 5홉으로… 숫자가 계속 커져요. 이것을 무한대 카운트(Count to Infinity)라고 해요. RIP에서는 16에 이르러서야 "도달 불가"로 정리돼요.

### 방지 기법

| 기법 | 동작 | 한 줄 비유 |
|---|---|---|
| 최대 홉 수 제한 | 16홉을 무한대로 정해, 숫자가 끝없이 커지지 않게 함 | 소문은 15번까지만 전달 |
| 스플릿 호라이즌(Split Horizon) | 어떤 인터페이스로 배운 경로를 그 인터페이스로 다시 광고하지 않음 | 들은 사람에게 그 얘기를 되돌려 말하지 않기 |
| 경로 포이즈닝(Route Poisoning) | 끊긴 경로를 바로 지우지 않고 메트릭 16(무한대)으로 광고해 즉시 알림 | "그 길 막혔어요"라고 바로 공지 |
| 포이즌 리버스(Poison Reverse) | 어떤 인터페이스로 배운 경로를 그 인터페이스로 무한대 메트릭으로 되돌려 알림 | "나도 그쪽으로는 못 가요"라고 확인해 주기 |
| 홀드다운 타이머(Hold-down Timer) | 경로가 끊겼다는 소식을 받으면 일정 시간 동안 그 경로에 대해 원래보다 나쁜 정보를 무시 | 사고 소식 직후 들려오는 헛소문 무시 |
| 트리거 업데이트(Triggered Update) | 변화가 생기면 30초를 기다리지 않고 즉시 갱신을 보냄 | 정기 회의를 기다리지 않고 바로 전화 |

앞의 예에서 B가 스플릿 호라이즌을 지켰다면, C에게서 배운 N 경로를 C에게 다시 알리지 않았을 테니 루프가 생기지 않았을 거예요.

> [!EXAM]
> "어떤 인터페이스로 받은 경로 정보를 같은 인터페이스로 다시 보내지 않는 기법"은 스플릿 호라이즌, "끊긴 경로의 메트릭을 무한대로 바꿔 알리는 기법"은 경로 포이즈닝이에요. 이름과 설명을 짝짓는 문제가 자주 나와요.

## OSPF

### OSPF의 동작
OSPF(Open Shortest Path First)는 가장 널리 쓰이는 개방형 표준 링크 상태 IGP예요. IPv4용은 OSPFv2, IPv6용은 OSPFv3이에요.

1. **이웃 발견**: Hello 패킷을 주고받아 이웃(Neighbor)을 찾고 관계를 유지해요. 이더넷 같은 망에서는 기본적으로 10초마다 Hello를 보내고, 40초(Dead 간격) 동안 소식이 없으면 이웃이 사라진 것으로 봐요. 이웃이 되려면 Hello·Dead 간격, 영역 번호, 서브넷 같은 값이 서로 맞아야 해요.
2. **지도 맞추기**: 인접 관계(Adjacency)를 맺은 라우터끼리 링크 상태 광고(LSA, Link State Advertisement)를 교환해 같은 링크 상태 데이터베이스(LSDB, Link State Database)를 갖춰요.
3. **최단 경로 계산**: 각 라우터가 LSDB를 바탕으로 다익스트라 SPF 알고리즘을 돌려 자신을 뿌리로 한 최단 경로 트리를 만들고, 그 결과로 라우팅 테이블을 채워요.
4. **변화 반영**: 링크 상태가 바뀌면 그 LSA만 즉시 퍼뜨리고(플러딩, Flooding), 받은 라우터들이 다시 계산해요. RIP처럼 짧은 주기로 테이블 전체를 보내지 않아요. (각 LSA를 30분마다 한 번씩 새로 고쳐 보내기는 해요.)

OSPF는 TCP나 UDP를 쓰지 않고 IP 위에 바로 실리며, **IP 프로토콜 번호 89**를 써요. 패킷 종류는 Hello, DBD(데이터베이스 설명), LSR(링크 상태 요청), LSU(링크 상태 갱신), LSAck(링크 상태 확인) 다섯 가지예요.

### 메트릭: 비용
OSPF의 메트릭은 비용(Cost)이에요. 인터페이스 비용은 "기준 대역폭 ÷ 인터페이스 대역폭"으로 계산하고, 경로의 비용은 지나가는 출구 인터페이스 비용을 모두 더한 값이에요. 시스코 장비의 기본 기준 대역폭은 100Mbps라서 10Mbps 링크는 비용 10, 100Mbps 이상 링크는 모두 비용 1이 돼요. (그래서 실무에서는 기준 대역폭을 더 크게 바꿔 쓰기도 해요.)

```text
             (1)
   [A]---------------[D]
    |                 |
 (2)|                 |(4)
    |                 |
   [B]---------------[C]
             (3)
```

- (1) A–D: 10Mbps, 비용 10
- (2) A–B, (3) B–C, (4) C–D: 모두 100Mbps, 비용 1

A에서 D로 갈 때 직접 가는 길은 1홉이지만 비용이 10이고, B와 C를 거치는 길은 3홉이지만 비용이 1+1+1 = 3이에요. RIP는 홉 수가 적은 직접 경로를, OSPF는 비용이 작은 A→B→C→D 경로를 골라요.

### 영역과 백본
라우터가 많아지면 LSA가 너무 많이 오가고 SPF 계산도 무거워져요. 그래서 OSPF는 망을 여러 영역(Area)으로 나누는 계층 구조를 써요. LSA의 자세한 정보는 영역 안에서만 퍼지고, 영역 사이에는 요약된 정보만 오가요.

- **백본 영역(Backbone Area)**: 영역 0(Area 0)이에요. 다른 모든 영역은 Area 0에 연결되어야 해요.
- **ABR(Area Border Router, 영역 경계 라우터)**: 두 개 이상의 영역에 걸쳐 있는 라우터예요.
- **ASBR(AS Boundary Router, AS 경계 라우터)**: 다른 라우팅 프로토콜이나 외부 AS의 경로를 OSPF 안으로 가져오는 라우터예요.

### DR과 BDR
이더넷처럼 한 네트워크에 라우터 여러 대가 함께 붙는 망을 다중 접근(Multi-access) 망이라고 해요. 라우터 10대가 모두 서로 인접 관계를 맺으면 10 × 9 ÷ 2 = 45개의 관계가 필요해요. 그래서 대표 라우터 DR(Designated Router)과 예비 대표 BDR(Backup Designated Router)을 뽑고, 나머지 라우터(DROTHER)는 DR·BDR하고만 인접 관계를 맺어요. 그러면 관계 수가 8 × 2 + 1 = 17개로 줄어요.

- 선출 기준: 인터페이스 우선순위(Priority, 기본값 1)가 가장 높은 라우터가 DR, 다음이 BDR이 돼요. 우선순위가 같으면 라우터 ID가 높은 쪽이 이겨요. 우선순위 0은 선출에 참여하지 않아요.
- 멀티캐스트 주소
  - **224.0.0.5**: 모든 OSPF 라우터(AllSPFRouters). Hello와 DR이 보내는 갱신에 써요.
  - **224.0.0.6**: DR과 BDR(AllDRouters). DROTHER가 DR·BDR에게 갱신을 보낼 때 써요.

### 그 밖의 특징
- 홉 수 제한이 없어 큰 망에 쓸 수 있어요.
- VLSM과 CIDR을 지원하고, 인증을 지원해요.
- 시스코 기준 관리 거리는 110이에요.

> [!TIP]
> OSPF 숫자 묶음: "89번 프로토콜, 224.0.0.5와 .6, 영역 0이 중심, 관리 거리 110". 이 네 가지를 한 문장처럼 외워 두면 대부분의 OSPF 문제를 풀 수 있어요.

## EIGRP
EIGRP(Enhanced Interior Gateway Routing Protocol)는 시스코가 만든 고급 거리 벡터(하이브리드) IGP예요. 오랫동안 시스코 장비 전용이었고, 나중에 기본 사양이 공개됐어요.

- **DUAL(Diffusing Update Algorithm)**: 루프 없는 경로를 계산하는 알고리즘이에요. 현재 최선 경로의 다음 홉인 후속자(Successor)뿐 아니라, 루프가 없다고 보장되는 예비 경로인 가능 후속자(Feasible Successor)를 미리 골라 둬요. 주 경로가 끊기면 다시 계산하지 않고 바로 예비 경로로 바꾸므로 수렴이 아주 빨라요.
- **복합 메트릭(Composite Metric)**: 대역폭, 지연, 신뢰성, 부하를 조합할 수 있어요. 기본 설정에서는 경로상 가장 낮은 대역폭과 지연의 합만 써요.
- **부분 갱신**: Hello로 이웃 관계를 유지하고, 변화가 있을 때 바뀐 부분만 보내요.
- 서로 비용이 다른 여러 경로로 트래픽을 나누는 부등 비용 부하 분산(Unequal-cost Load Balancing)을 지원해요.
- IP 프로토콜 번호 88, 멀티캐스트 224.0.0.10을 써요.
- 시스코 기준 관리 거리는 내부 경로 90, 외부에서 가져온 경로 170이에요. `show ip route`에서는 D로 표시돼요.

## BGP
BGP(Border Gateway Protocol)는 AS와 AS 사이에서 경로를 주고받는 EGP로, 인터넷 전체를 이어 주는 뼈대 프로토콜이에요. 현재 쓰는 버전은 BGP-4예요.

- **경로 벡터 방식**: 경로마다 거쳐 온 AS 번호 목록(AS_PATH)을 붙여 보내요. 받은 경로의 AS_PATH에 자기 AS 번호가 있으면 한 바퀴 돌아온 것이니 버려서 루프를 막아요.
- **정책 기반 선택**: 단순히 가장 짧은 길이 아니라, 경로 속성(AS_PATH, NEXT_HOP, LOCAL_PREF, MED 등)과 관리자가 정한 정책으로 경로를 골라요. 예를 들어 "비용이 싼 ISP 쪽으로 먼저 보내기" 같은 사업상 판단을 반영할 수 있어요.
- **TCP 179번 포트**로 이웃(피어, Peer)과 연결을 맺어요. 처음에 경로를 한꺼번에 교환한 뒤에는 바뀐 부분만 보내고, KEEPALIVE로 연결을 확인해요. 메시지 종류는 OPEN, UPDATE, KEEPALIVE, NOTIFICATION이에요.
- **eBGP와 iBGP**: 서로 다른 AS의 라우터끼리 맺는 것이 eBGP(외부 BGP), 같은 AS 안의 라우터끼리 맺는 것이 iBGP(내부 BGP)예요. 시스코 기준 관리 거리는 eBGP 20, iBGP 200이에요.
- AS 번호는 처음에 16비트였고, 번호가 모자라 32비트로 늘어났어요.

> [!NOTE]
> IS-IS(Intermediate System to Intermediate System)도 OSPF처럼 링크 상태 방식의 IGP예요. 큰 통신사 내부망에서 많이 쓰이고, 시스코 기준 관리 거리는 115예요.

## 네 프로토콜 한눈에 비교

| 항목 | RIP | OSPF | EIGRP | BGP |
|---|---|---|---|---|
| 분류 | IGP | IGP | IGP | EGP |
| 방식 | 거리 벡터 | 링크 상태 | 고급 거리 벡터(하이브리드) | 경로 벡터 |
| 알고리즘 | 벨만-포드 | 다익스트라(SPF) | DUAL | 경로 속성과 정책 |
| 메트릭 | 홉 수 | 비용(대역폭 기반) | 복합(기본: 대역폭+지연) | 경로 속성 |
| 홉 제한 | 15(16은 도달 불가) | 없음 | 넉넉함 | 없음 |
| 갱신 | 30초마다 전체 테이블 | 변화 시 LSA | 변화 시 부분 갱신 | 변화 시 증분 갱신 |
| 전송 | UDP 520 | IP 프로토콜 89 | IP 프로토콜 88 | TCP 179 |
| 멀티캐스트 | 224.0.0.9(v2) | 224.0.0.5, 224.0.0.6 | 224.0.0.10 | 쓰지 않음(TCP 연결) |
| 관리 거리(시스코) | 120 | 110 | 90 | eBGP 20, iBGP 200 |
| 표준 | 개방형 | 개방형 | 시스코 개발 | 개방형 |
| 알맞은 규모 | 소규모 | 중대형 | 중대형 | AS 사이(인터넷) |

> [!EXAM]
> - "전송 계층으로 TCP를 쓰는 라우팅 프로토콜"은 BGP(179), "UDP를 쓰는 것"은 RIP(520)예요. OSPF와 EIGRP는 IP 위에 바로 실려요.
> - "링크 상태 방식"을 고르라면 OSPF나 IS-IS, "AS 사이 라우팅"을 고르라면 BGP예요.
> - 최대 홉 15, 30초 주기 갱신이 나오면 RIP를 떠올려요.

## 핵심 정리
- IGP는 AS 내부(RIP, OSPF, EIGRP, IS-IS), EGP는 AS 사이(BGP) 라우팅이에요.
- 거리 벡터는 이웃의 거리·방향 정보로 계산하고(벨만-포드), 링크 상태는 전체 지도로 직접 계산해요(다익스트라 SPF).
- RIP: 홉 수 메트릭, 최대 15홉(16 = 도달 불가), 30초 주기 전체 갱신, UDP 520. v1은 클래스풀·브로드캐스트, v2는 클래스리스·멀티캐스트 224.0.0.9.
- 루프 방지: 최대 홉 수, 스플릿 호라이즌, 경로 포이즈닝, 포이즌 리버스, 홀드다운 타이머, 트리거 업데이트.
- OSPF: 링크 상태, 비용 메트릭, Area 0 중심의 영역 구조, DR/BDR 선출, 224.0.0.5/224.0.0.6, IP 프로토콜 89.
- EIGRP: 시스코가 만든 하이브리드, DUAL로 빠른 수렴, 복합 메트릭, IP 프로토콜 88.
- BGP: 경로 벡터, AS_PATH로 루프 방지, 정책 기반 선택, TCP 179, eBGP와 iBGP.

## 스스로 확인하기

**1.** RIP에서 메트릭이 16인 경로가 뜻하는 것은?
① 16개의 라우터를 거쳐 도달할 수 있다 ② 가장 우선하는 경로이다 ③ 도달할 수 없는 경로이다 ④ 16초 뒤에 갱신된다

> [!ANSWER]
> 정답: ③
> RIP는 최대 15홉까지 쓰고, 16을 무한대로 정해 "도달 불가"를 나타내요.

**2.** OSPF에 대한 설명으로 옳지 않은 것은?
① 다익스트라 알고리즘으로 최단 경로를 계산한다. ② 30초마다 라우팅 테이블 전체를 이웃에게 보낸다. ③ 모든 영역은 백본 영역(Area 0)에 연결되어야 한다. ④ IP 프로토콜 번호 89를 사용한다.

> [!ANSWER]
> 정답: ②
> 주기적으로 테이블 전체를 보내는 것은 RIP 같은 거리 벡터 방식의 특징이에요. OSPF는 변화가 있을 때 해당 LSA만 퍼뜨려요.

**3.** 라우터가 어떤 인터페이스로 받은 경로 정보를 그 인터페이스로는 다시 광고하지 않아 라우팅 루프를 막는 기법은?
① 홀드다운 타이머 ② 트리거 업데이트 ③ 경로 포이즈닝 ④ 스플릿 호라이즌

> [!ANSWER]
> 정답: ④
> 스플릿 호라이즌은 "배운 쪽으로 되돌려 말하지 않기"예요. 경로 포이즈닝은 끊긴 경로를 무한대 메트릭으로 알리는 기법이에요.

**4.** 서로 다른 자율 시스템(AS) 사이에서 경로를 교환하며, TCP 179번 포트로 이웃과 연결을 맺는 프로토콜은?
① RIP ② OSPF ③ EIGRP ④ BGP

> [!ANSWER]
> 정답: ④
> BGP는 AS 사이 라우팅에 쓰는 경로 벡터 방식 EGP이고, 신뢰성 있는 전송을 위해 TCP 179번을 써요.

**5.** OSPF 다중 접근 망에서 DROTHER 라우터가 DR과 BDR에게만 갱신을 보낼 때 쓰는 목적지 주소는?
① 224.0.0.5 ② 224.0.0.6 ③ 224.0.0.9 ④ 224.0.0.10

> [!ANSWER]
> 정답: ②
> 224.0.0.6은 DR·BDR 전용, 224.0.0.5는 모든 OSPF 라우터용이에요. 224.0.0.9는 RIPv2, 224.0.0.10은 EIGRP가 써요.
