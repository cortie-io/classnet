인터넷은 수많은 남의 장비를 거쳐 데이터를 나르는 공용 도로예요. 그 위에서 비밀번호나 카드 번호를 안전하게 주고받으려면 내용을 숨기고, 바뀌지 않았는지 확인하고, 상대가 진짜인지 따져야 해요. 이 단원에서는 보안의 목표와 암호의 기본 원리, 이를 실제 통신에 적용한 SSL/TLS·IPSec·VPN, 그리고 시험에 자주 나오는 공격 기법과 기본 대응을 정리해요.

> [!GOAL]
> - 기밀성·무결성·가용성과 인증·부인 방지의 뜻을 구분할 수 있어요.
> - 대칭키와 공개키 암호의 차이, 대표 알고리즘, 해시 함수의 역할을 설명할 수 있어요.
> - 전자 서명과 인증서(PKI), SSL/TLS의 동작 흐름을 설명할 수 있어요.
> - IPSec의 AH·ESP, 전송·터널 모드, IKE와 VPN의 종류를 구분해요.
> - 대표적인 네트워크 공격의 원리와 기본 대응을 짝지을 수 있어요.

## 보안의 목표
정보 보안의 3대 목표는 머리글자를 따서 CIA라고 불러요. 여기에 인증과 부인 방지를 더해 기억하면 좋아요.

| 목표 | 뜻 | 대표 수단 | 이것을 깨는 공격 |
|---|---|---|---|
| 기밀성(Confidentiality) | 허가받은 사람만 내용을 볼 수 있음 | 암호화 | 스니핑(도청) |
| 무결성(Integrity) | 허가 없이 내용이 바뀌지 않음 | 해시, 메시지 인증 코드 | 변조, 중간자 공격 |
| 가용성(Availability) | 필요할 때 언제든 쓸 수 있음 | 이중화, 백업, 트래픽 차단 | DoS·DDoS |
| 인증(Authentication) | 상대가 주장하는 그 사람(장비)인지 확인 | 비밀번호, 인증서, OTP | 스푸핑(위장) |
| 부인 방지(Non-repudiation) | 보내거나 받은 사실을 나중에 부인하지 못함 | 전자 서명 | (송수신 사실 부인) |

> [!WARNING]
> 보안에서 말하는 MAC(Message Authentication Code, 메시지 인증 코드)은 이더넷의 MAC(Media Access Control) 주소와 전혀 다른 말이에요. 메시지 인증 코드는 비밀키를 섞어 만든 짧은 값으로, 내용이 바뀌지 않았고 키를 가진 상대가 보냈다는 것을 확인해 줘요.

## 암호의 기본

### 용어
- 평문(Plaintext): 암호화하기 전의 원래 내용
- 암호문(Ciphertext): 암호화해서 알아볼 수 없게 만든 내용
- 암호화(Encryption)와 복호화(Decryption): 평문 → 암호문, 암호문 → 평문
- 키(Key): 암호화·복호화에 쓰는 값. 보통 알고리즘은 공개하고, 안전성은 키를 비밀로 지키는 데서 나와요.

### 대칭키 암호
대칭키 암호(Symmetric Key Cryptography)는 암호화와 복호화에 **같은 키**를 쓰는 방식이에요. 비밀키 암호 또는 관용 암호라고도 해요. 같은 열쇠로 잠그고 여는 자물쇠와 같아요.
- 계산이 빨라서 많은 양의 데이터를 암호화하는 데 알맞아요.
- 하지만 키를 상대에게 안전하게 건네는 **키 분배** 문제가 있어요. 또 n명이 서로 비밀 통신을 하려면 짝마다 키가 필요해서 n(n-1)/2개의 키가 있어야 해요.

| 알고리즘 | 특징 |
|---|---|
| DES | 옛 미국 표준. 블록 64비트, 키 56비트. 키가 짧아 지금은 안전하지 않음 |
| 3DES(Triple DES) | DES를 세 번 적용해 키 길이를 늘림. 느려서 퇴역하는 중 |
| AES | 현재 미국 표준이자 가장 널리 쓰임. 블록 128비트, 키 128·192·256비트 |
| SEED | 우리나라 한국인터넷진흥원(KISA)이 개발. 블록 128비트, 키 128비트 |
| ARIA | 우리나라 학계·연구소·정부 기관이 함께 개발. 블록 128비트, 키 128·192·256비트 |

### 공개키 암호
공개키 암호(Public Key Cryptography)는 암호화와 복호화에 서로 짝을 이루는 **다른 두 개의 키**를 써서 비대칭키 암호라고도 해요. 공개키(Public Key)는 누구에게나 공개하고, 개인키(Private Key)는 본인만 보관해요. 한 키로 잠근 것은 짝이 되는 다른 키로만 열 수 있어요.

- **비밀 전달**: 받는 사람의 공개키로 암호화 → 받는 사람의 개인키로만 풀 수 있어요. 열린 자물쇠(공개키)를 여러 사람에게 나눠 주고, 그 열쇠(개인키)는 나만 갖고 있는 것과 같아요.
- **서명**: 보내는 사람의 개인키로 서명 → 누구나 보내는 사람의 공개키로 확인할 수 있어요.
- 키 분배가 쉽고, n명이면 각자 한 쌍씩 2n개의 키면 돼요. 대신 계산이 대칭키보다 훨씬 느려요.

| 알고리즘 | 바탕이 되는 어려운 문제 | 주 용도 |
|---|---|---|
| RSA | 큰 수의 소인수분해 | 암호화, 전자 서명 |
| ECC(Elliptic Curve Cryptography, 타원 곡선 암호) | 타원 곡선 위의 이산 로그 | 짧은 키로 RSA와 같은 강도. 모바일·IoT에 유리 |
| 디피-헬만(Diffie-Hellman) | 이산 로그 | 키 교환(공개된 통로에서 같은 비밀키 만들기) |
| DSA | 이산 로그 | 전자 서명 |

> [!NOTE]
> 디피-헬만은 데이터를 암호화하는 알고리즘이 아니라, 두 사람이 공개된 통로로 값을 주고받아 같은 비밀키를 만들어 내는 **키 교환** 방법이에요. 상대를 인증하지 않으면 중간자 공격에 속을 수 있어서, 실제로는 인증서나 서명과 함께 써요.

### 대칭키와 공개키 비교

| 항목 | 대칭키 암호 | 공개키 암호 |
|---|---|---|
| 키 | 암호화·복호화에 같은 키 | 공개키와 개인키 한 쌍 |
| 속도 | 빠름 | 느림 |
| 키 분배 | 어려움 | 쉬움 |
| n명에게 필요한 키 수 | n(n-1)/2 | 2n |
| 주 용도 | 대량 데이터 암호화 | 키 교환, 전자 서명 |
| 대표 | DES, 3DES, AES, SEED, ARIA | RSA, ECC, 디피-헬만, DSA |

예를 들어 10명이 서로 비밀 통신을 한다면 대칭키는 10 × 9 ÷ 2 = 45개, 공개키는 10 × 2 = 20개가 필요해요.

실제 통신에서는 두 방식을 섞어 써요. 공개키 암호(또는 디피-헬만)로 이번 통신에만 쓸 대칭키인 세션 키(Session Key)를 안전하게 나눠 갖고, 실제 데이터는 빠른 대칭키로 암호화해요. 이것을 하이브리드 방식이라고 하고, 뒤에서 볼 TLS가 바로 이렇게 동작해요.

### 해시 함수
해시 함수(Hash Function)는 길이에 상관없이 어떤 입력이든 정해진 길이의 짧은 값(해시값, 메시지 다이제스트)으로 바꾸는 함수예요.
- **일방향**: 해시값에서 원래 입력을 거꾸로 알아낼 수 없어요.
- **충돌 저항성**: 같은 해시값이 나오는 서로 다른 두 입력을 찾기가 매우 어려워야 해요.
- 입력이 한 글자만 바뀌어도 해시값은 완전히 달라져요.

파일을 받은 뒤 해시값을 비교해 바뀌지 않았는지 확인하거나(무결성), 비밀번호를 그대로 저장하지 않고 해시값으로 저장하는 데 써요. 해시에 비밀키를 섞으면 메시지 인증 코드가 되는데, 대표적인 방식이 HMAC이에요.

| 알고리즘 | 해시 길이 | 현재 평가 |
|---|---|---|
| MD5 | 128비트 | 충돌을 쉽게 만들 수 있어 보안 용도로 쓰지 않음 |
| SHA-1 | 160비트 | 충돌이 실제로 만들어져 퇴출됨 |
| SHA-2 계열(SHA-224·256·384·512) | 224~512비트 | 현재 널리 쓰이는 표준 |
| SHA-3 | 224~512비트 | SHA-2와 다른 구조의 새 표준 |

> [!WARNING]
> 해시는 암호화가 아니에요. 키로 되돌리는 복호화 과정이 없어요. "해시값을 복호화해 원문을 얻는다"는 보기는 틀린 문장이에요.

## 전자 서명과 인증서

### 전자 서명
전자 서명(Digital Signature)은 이렇게 만들고 확인해요.
1. 보내는 사람이 메시지의 해시값을 구하고, 그 해시값을 **자기 개인키**로 암호화해 서명을 만들어요.
2. 메시지와 서명을 함께 보내요.
3. 받는 사람은 **보낸 사람의 공개키**로 서명을 풀어 해시값을 얻고, 받은 메시지로 직접 구한 해시값과 비교해요. 같으면 통과예요.

개인키는 본인만 갖고 있으므로 인증, 무결성, 부인 방지를 제공해요. 메시지 자체를 숨기지는 않으므로 기밀성은 제공하지 않아요.

### 인증서와 PKI
남은 문제는 "이 공개키가 정말 그 사람의 것인가"예요. 공격자가 자기 공개키를 남의 것이라고 속여 내밀 수 있으니까요. 그래서 믿을 수 있는 제3자가 확인 도장을 찍어 주는데, 이것이 인증서예요.
- **인증서(Certificate)**: "이 공개키의 주인은 누구다"라는 내용에 인증 기관이 전자 서명한 전자 문서예요. 표준 형식은 X.509예요.
- **인증 기관(CA, Certificate Authority)**: 신원을 확인하고 인증서를 발급하는 기관이에요. 운영체제와 웹 브라우저에는 믿을 수 있는 최상위(루트) CA의 인증서가 미리 들어 있어서, 루트 CA → 중간 CA → 서버 인증서로 이어지는 신뢰의 사슬을 따라 확인해요.
- **PKI(Public Key Infrastructure, 공개키 기반 구조)**: 인증서를 발급·관리·폐기하는 전체 체계예요. CA, 신청자의 신원을 확인하는 등록 기관(RA), 인증서 저장소, 그리고 유효 기간 전에 무효가 된 인증서를 알리는 인증서 폐기 목록(CRL)이나 온라인 인증서 상태 프로토콜(OCSP)로 이루어져요.

## SSL/TLS

### 개요
SSL(Secure Sockets Layer)은 웹 통신을 보호하려고 만든 프로토콜이고, 이것을 표준으로 다듬은 것이 TLS(Transport Layer Security)예요. 지금은 SSL과 초기 TLS(1.0, 1.1)는 쓰지 않고 TLS 1.2와 1.3을 써요. 그래도 습관처럼 "SSL"이라고 부르는 경우가 많아요.

TLS는 TCP 위, 응용 계층 아래에서 동작해요. 응용 프로그램의 데이터를 받아 암호화한 뒤 TCP로 넘기는 구조라서, HTTP·메일·FTP 같은 여러 프로토콜에 덧씌울 수 있어요. 제공하는 기능은 다음과 같아요.
- 서버 인증(필요하면 클라이언트 인증도): 인증서로 확인
- 기밀성: 세션 키로 대칭키 암호화
- 무결성: 메시지 인증 코드 등으로 변조 확인

### 핸드셰이크 흐름
본격적인 통신 전에 핸드셰이크(Handshake)로 암호 방식과 세션 키를 정해요. TLS 1.2를 기준으로 단순하게 그리면 이래요.

```text
클라이언트 -> 서버 : ClientHello (지원 암호 목록, 난수)
클라이언트 <- 서버 : ServerHello (고른 암호, 난수)
클라이언트 <- 서버 : Certificate (서버 인증서)
  [클라이언트가 CA 서명으로 인증서를 검증]
클라이언트 -> 서버 : 키 교환 (세션 키를 만들 재료)
  [양쪽이 같은 세션 키를 계산]
클라이언트 <-> 서버 : Finished, 이후 암호화된 데이터
```

1. 클라이언트가 자신이 지원하는 암호 방식 목록을 보내요.
2. 서버가 그중 하나를 고르고 자기 인증서를 보내요.
3. 클라이언트는 인증서가 믿을 만한 CA의 서명을 받았는지, 접속하려는 도메인 이름과 맞는지 확인해요.
4. 공개키 암호나 디피-헬만으로 양쪽이 같은 세션 키를 갖게 돼요.
5. 이후 모든 데이터를 세션 키로 암호화해 주고받아요.

TLS 1.3은 핸드셰이크 왕복 횟수를 줄여 더 빨리 연결하고, 안전하지 않은 옛 알고리즘을 빼 버렸어요.

### TLS를 쓰는 프로토콜과 포트

| 프로토콜 | 포트 | 설명 |
|---|---|---|
| HTTPS | TCP 443 | HTTP + TLS |
| SMTPS | TCP 465 | 메일 보내기 + TLS |
| IMAPS | TCP 993 | IMAP + TLS |
| POP3S | TCP 995 | POP3 + TLS |
| LDAPS | TCP 636 | 디렉터리 서비스 + TLS |

원격 접속에 쓰는 SSH(TCP 22)는 TLS가 아니라 자체 암호 프로토콜이지만, 역시 텔넷(23)을 대신하는 암호화 통신이에요.

## IPSec

### 개요
IPSec(IP Security)은 3계층인 IP 계층에서 패킷 자체를 보호하는 표준 프로토콜 묶음이에요. 응용 프로그램이 따로 신경 쓰지 않아도 그 위의 모든 IP 트래픽(TCP든 UDP든)을 보호할 수 있어요. IPv4에서는 선택 기능이고, IPv6에서는 기본 지원 기능으로 들어갔어요.

| 구성 요소 | 하는 일 |
|---|---|
| AH(Authentication Header, 인증 헤더) | 무결성, 출발지 인증, 재전송 공격 방지. **암호화는 하지 않음.** IP 프로토콜 번호 51 |
| ESP(Encapsulating Security Payload, 캡슐화 보안 페이로드) | **암호화**(기밀성)에 더해 무결성, 출발지 인증, 재전송 방지. IP 프로토콜 번호 50 |
| IKE(Internet Key Exchange, 인터넷 키 교환) | 양쪽이 쓸 암호 방식과 키를 협상하고 보안 연관(SA, Security Association)을 맺음. UDP 500번 |

보안 연관(SA)은 "이 상대와는 이 알고리즘, 이 키로 보호한다"는 약속이에요. 한 방향마다 하나씩이라 양방향 통신에는 두 개가 필요해요.

| 항목 | AH | ESP |
|---|---|---|
| IP 프로토콜 번호 | 51 | 50 |
| 기밀성(암호화) | 없음 | 있음 |
| 무결성·인증 | 있음(바깥 IP 헤더의 변하지 않는 부분까지 검사) | 있음(ESP로 감싼 부분만 검사) |
| NAT와 함께 쓰기 | 어려움(NAT가 주소를 바꾸면 검사 실패) | NAT 통과 기능(NAT-T, UDP 4500)으로 가능 |

### 전송 모드와 터널 모드

```text
원래 패킷 : [IP][TCP | 데이터]
전송 모드 : [IP][ESP][TCP | 데이터][ESP 끝]
터널 모드 : [새 IP][ESP][IP][TCP | 데이터][ESP 끝]
```

([ESP 끝]은 ESP 트레일러와 인증 데이터를 줄여 쓴 거예요.)

- **전송 모드(Transport Mode)**: 원래 IP 헤더는 그대로 두고 그 안의 데이터(상위 계층 부분)만 보호해요. 두 호스트가 직접 주고받는 종단 간(End-to-End) 보호에 써요.
- **터널 모드(Tunnel Mode)**: 원래 IP 패킷 전체를 보호하고 그 앞에 새 IP 헤더를 붙여요. 원래 출발지·목적지 주소까지 감춰져요. 두 VPN 게이트웨이(라우터, 방화벽) 사이를 잇는 사이트 간 VPN에 주로 써요.

> [!EXAM]
> - 암호화를 제공하는 것은 ESP, 암호화 없이 인증·무결성만 제공하는 것은 AH예요.
> - 원래 IP 헤더까지 감싸서 새 IP 헤더를 붙이는 것은 터널 모드예요.
> - IKE는 키 교환을 맡고 UDP 500번을 써요.

## VPN

### VPN이란
VPN(Virtual Private Network, 가상 사설망)은 인터넷 같은 공용망 위에 암호화된 터널을 만들어, 마치 전용선으로 연결된 사설망처럼 쓰는 기술이에요. 비싼 전용 회선 없이도 본사와 지사, 재택 근무자를 안전하게 이을 수 있어요. 핵심 기술은 터널링, 암호화, 인증, 접근 제어예요.

### 연결 형태

| 형태 | 연결 대상 | 특징 |
|---|---|---|
| 사이트 간(Site-to-Site) VPN | 본사 네트워크와 지사 네트워크 | 양쪽 VPN 장비가 상시 터널을 유지. 사용자는 VPN을 의식하지 않음. 주로 IPSec 터널 모드 |
| 원격 접속(Remote Access) VPN | 외부의 개인 PC·휴대폰과 회사 네트워크 | 사용자가 필요할 때 접속. VPN 클라이언트 프로그램이나 웹 브라우저 사용 |

### IPSec VPN과 SSL VPN

| 항목 | IPSec VPN | SSL VPN |
|---|---|---|
| 동작 계층 | 3계층(IP) | TLS 사용(전송 계층과 응용 계층 사이) |
| 클라이언트 | 전용 클라이언트 소프트웨어 필요 | 웹 브라우저만으로도 가능 |
| 보호 범위 | 모든 IP 트래픽 | 주로 웹과 허용된 응용 프로그램 |
| 방화벽·NAT 통과 | 포트·프로토콜 허용 설정이 필요할 수 있음 | 보통 열려 있는 TCP 443을 써서 쉬움 |
| 주 용도 | 사이트 간 연결, 원격 접속 | 원격 접속 |

> [!NOTE]
> VPN 터널을 만드는 프로토콜을 계층으로 나누는 문제도 나와요. 2계층 터널링 프로토콜은 PPTP, L2F, L2TP이고, 3계층은 IPSec이에요. L2TP는 자체 암호화가 없어 보통 IPSec과 함께(L2TP/IPSec) 써요. PPTP는 보안이 약해 지금은 권하지 않아요.

방화벽, IDS·IPS, VPN 장비 같은 보안 장비는 [보안 장비](/textbook/dev-security-appliances)에서 자세히 배워요.

## 대표적인 공격 기법

### 공격과 기본 대응

| 공격 | 원리(한 줄) | 기본 대응 |
|---|---|---|
| 스니핑(Sniffing) | 네트워크를 지나는 패킷을 몰래 엿보는 도청. 랜카드를 무차별 모드(Promiscuous Mode)로 두고 남의 패킷까지 수집 | 암호화 통신(TLS, SSH, VPN), 스위치 사용, 무차별 모드 탐지 |
| IP 스푸핑(IP Spoofing) | 출발지 IP 주소를 위조해 믿을 만한 호스트인 척함 | 경계 라우터에서 위조된 출발지 주소 필터링, IP 주소만으로 인증하지 않기 |
| ARP 스푸핑(ARP Spoofing) | 가짜 ARP 응답으로 상대의 ARP 캐시에 "게이트웨이 IP = 공격자 MAC"을 심어 트래픽을 가로챔 | 중요한 장비에 정적 ARP 항목, 스위치의 ARP 검사 기능, ARP 감시 |
| DNS 스푸핑(DNS Spoofing) | 위조한 DNS 응답이나 오염된 캐시로 사용자를 가짜 사이트로 보냄 | DNSSEC, 믿을 수 있는 DNS 서버 사용, hosts 파일 관리 |
| DoS(Denial of Service, 서비스 거부) | 대량의 요청이나 비정상 패킷으로 자원을 고갈시켜 정상 서비스를 못 하게 함 | 트래픽 임계값 설정과 차단, 대역폭 여유 확보 |
| DDoS(Distributed DoS, 분산 서비스 거부) | 악성코드에 감염된 수많은 좀비 PC(봇넷)가 한꺼번에 DoS 공격 | DDoS 방어 장비·서비스, 트래픽 분산, 감염 PC 치료 |
| SYN 플러딩(SYN Flooding) | TCP 연결 요청(SYN)만 대량으로 보내고 마지막 ACK는 보내지 않아 서버의 대기 큐를 반쯤 열린 연결로 가득 채움 | SYN 쿠키, 대기 큐 늘리기, 대기 시간 줄이기, 방화벽 임계값 |
| 스머프(Smurf) | 출발지를 피해자 IP로 위조한 ICMP 에코 요청을 지시 브로드캐스트 주소로 보내, 그 망의 모든 호스트가 피해자에게 응답하게 만듦(증폭) | 라우터에서 지시 브로드캐스트 전달 차단, 브로드캐스트 ICMP에 응답하지 않기 |
| 랜드 공격(Land Attack) | 출발지 IP·포트를 목적지와 똑같이 만든 패킷을 보내, 피해 시스템이 자기 자신에게 응답하며 자원을 소모하게 함 | 출발지와 목적지가 같은 패킷 차단, 운영체제 패치 |
| 죽음의 핑(Ping of Death) | IP 패킷의 최대 크기(65,535바이트)를 넘는 ICMP 패킷을 조각내어 보내, 재조립할 때 오류를 일으킴 | 운영체제 패치, 비정상적으로 큰 ICMP 패킷 차단 |
| 티어드롭(Teardrop) | 조각난 패킷의 단편 오프셋(Fragment Offset)을 겹치거나 어긋나게 조작해 재조립 오류를 일으킴 | 운영체제 패치, 비정상 단편 차단 |
| 세션 하이재킹(Session Hijacking) | 인증이 끝난 정상 세션(TCP 순서 번호, 웹 세션 쿠키 등)을 가로채 사용자인 척함 | 암호화 통신, 세션 토큰 보호와 만료 시간 설정, 중요한 작업 전 재인증 |
| 중간자 공격(MITM, Man-in-the-Middle) | 두 사람 사이에 몰래 끼어들어 대화를 엿보거나 바꿈. ARP 스푸핑 등으로 자리를 잡음 | 인증서 검증을 포함한 TLS, 상호 인증, 종단 간 암호화 |
| 무차별 대입 공격(Brute Force) | 가능한 비밀번호나 키를 하나씩 모두 대입. 자주 쓰는 단어 목록을 쓰면 사전 공격(Dictionary Attack) | 길고 복잡한 비밀번호, 로그인 실패 시 잠금·지연, 다중 인증(MFA) |
| 피싱(Phishing) | 은행·기관을 사칭한 메일이나 문자로 가짜 사이트에 유도해 개인정보를 빼냄. 문자를 쓰면 스미싱 | 사용자 교육, 링크 주소 확인, 메일 필터링, 다중 인증 |

> [!NOTE]
> 비슷한 이름도 함께 알아 두세요. 프래글(Fraggle)은 스머프와 원리가 같지만 ICMP 대신 UDP를 써요. 파밍(Pharming)은 DNS나 hosts 파일을 조작해서, 사용자가 주소를 올바르게 입력해도 가짜 사이트로 가게 만드는 공격이에요.

### 시험에서 구별하는 열쇠말

> [!EXAM]
> - **출발지 = 목적지**로 같은 패킷 → 랜드 공격
> - **ICMP + 브로드캐스트 + 증폭** → 스머프
> - **단편 오프셋 조작** → 티어드롭
> - **65,535바이트를 넘는 ICMP** → 죽음의 핑
> - **SYN만 보내고 ACK 없음, 반쯤 열린 연결** → SYN 플러딩
> - **패킷 엿보기** → 스니핑, **주소 위조로 위장** → 스푸핑
> - 위 다섯 가지 패킷 공격(랜드, 스머프, 티어드롭, 죽음의 핑, SYN 플러딩)은 모두 가용성을 해치는 DoS 계열이에요.

> [!TIP]
> 공격 이름을 장면으로 외워 보세요. 랜드는 "자기 땅(Land)에 자기가 편지 보내기", 티어드롭은 "눈물방울처럼 어긋나 떨어진 조각", 스머프는 "한 번 외쳤는데 온 동네가 한꺼번에 대답하는 메아리"예요.

## 핵심 정리
- 보안 목표: 기밀성(암호화), 무결성(해시·메시지 인증 코드), 가용성(이중화·DoS 대응), 인증, 부인 방지(전자 서명).
- 대칭키: 같은 키, 빠름, 키 분배가 어려움, n(n-1)/2개. DES·3DES·AES·SEED·ARIA.
- 공개키: 공개키와 개인키 한 쌍, 느림, 키 분배가 쉬움, 2n개. RSA(소인수분해)·ECC·디피-헬만(키 교환)·DSA.
- 해시는 일방향이고 복호화가 없어요. MD5·SHA-1은 약하고 SHA-2 계열을 써요.
- 전자 서명은 보내는 사람의 개인키로 만들고 공개키로 확인해요. 인증서는 CA가 공개키의 주인을 보증한 X.509 문서예요.
- TLS는 TCP 위에서 인증서로 서버를 확인하고 세션 키로 암호화해요. HTTPS는 TCP 443.
- IPSec: AH(51, 인증·무결성만), ESP(50, 암호화 포함), IKE(UDP 500, 키 교환). 전송 모드는 데이터만, 터널 모드는 패킷 전체를 보호해요.
- VPN: 사이트 간과 원격 접속. IPSec VPN은 3계층, SSL VPN은 웹 브라우저로도 쓸 수 있어요.
- 랜드(출발지=목적지), 스머프(ICMP 브로드캐스트 증폭), 티어드롭(오프셋 조작), 죽음의 핑(초대형 ICMP), SYN 플러딩(반쯤 열린 연결)은 DoS 계열이에요.

## 스스로 확인하기

**1.** 다음 중 대칭키 암호 알고리즘이 아닌 것은?
① AES ② SEED ③ RSA ④ ARIA

> [!ANSWER]
> 정답: ③
> RSA는 큰 수의 소인수분해가 어렵다는 점을 이용한 공개키 암호예요. 나머지는 모두 블록 128비트 대칭키 암호예요.

**2.** 20명이 서로 1:1로 비밀 통신을 하려고 해요. 대칭키 암호만 쓴다면 필요한 키는 몇 개일까요?
① 20개 ② 40개 ③ 190개 ④ 380개

> [!ANSWER]
> 정답: ③
> 대칭키는 짝마다 하나씩 필요하므로 20 × 19 ÷ 2 = 190개예요. 공개키 암호라면 2 × 20 = 40개면 돼요.

**3.** IPSec에서 데이터의 기밀성(암호화)을 제공하는 프로토콜은?
① AH ② ESP ③ IKE ④ SA

> [!ANSWER]
> 정답: ②
> ESP는 암호화와 함께 무결성·인증을 제공해요. AH는 암호화 없이 인증·무결성만, IKE는 키 교환을 맡아요.

**4.** 공격자가 출발지 IP 주소와 포트를 목적지 시스템의 IP 주소와 포트로 똑같이 꾸민 패킷을 보내는 공격은?
① 티어드롭 ② 스머프 ③ 랜드 공격 ④ 세션 하이재킹

> [!ANSWER]
> 정답: ③
> 출발지와 목적지가 같으면 피해 시스템이 자기 자신에게 응답하며 자원을 소모해요. 출발지와 목적지가 같은 패킷을 차단해 막아요.

**5.** SSL VPN에 대한 설명으로 가장 알맞은 것은?
① IP 계층에서 동작하며 전용 클라이언트가 반드시 필요하다. ② 웹 브라우저만으로도 접속할 수 있어 원격 접속에 많이 쓰인다. ③ AH 프로토콜로 데이터를 암호화한다. ④ 2계층 터널링 프로토콜이다.

> [!ANSWER]
> 정답: ②
> SSL VPN은 TLS를 이용하므로 브라우저만으로 쓸 수 있고 TCP 443을 써서 방화벽 통과도 쉬워요. ①은 IPSec VPN의 특징이고, AH는 암호화를 하지 않아요.
