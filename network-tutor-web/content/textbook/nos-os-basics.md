컴퓨터를 켜면 가장 먼저 올라와서 프로그램과 하드웨어 사이를 조율하는 소프트웨어가 운영체제예요. 3과목에서는 Windows Server와 리눅스를 깊게 다루는데, 이 단원에서는 그 바탕이 되는 운영체제의 공통 개념을 먼저 정리해요. 여기서 익히는 커널, 프로세스, 파일 시스템 같은 용어는 뒤 단원에서 계속 나오니 확실히 잡아 두세요.

> [!GOAL]
> - 운영체제의 역할과 커널·셸의 차이를 설명할 수 있다
> - 프로세스와 스레드를 구분하고 프로세스 상태 변화를 따라갈 수 있다
> - 가상 메모리와 페이징, 대표 파일 시스템(FAT32·NTFS·ext4)의 특징을 말할 수 있다
> - 네트워크 운영체제의 개념과 클라이언트-서버·P2P 방식, 서버 운영체제 계열을 구분할 수 있다

## 운영체제란 무엇인가

### 운영체제의 두 가지 역할

식당을 떠올려 보세요. 주방의 화구와 조리대는 한정되어 있는데 주문은 계속 들어와요. 매니저는 어느 주문부터 어느 화구에서 만들지 정하고, 손님이 주문할 수 있는 메뉴판과 창구도 마련해 둬요. 컴퓨터에서 이 매니저 역할을 하는 것이 운영체제예요.

운영체제(OS, Operating System)는 하드웨어와 사용자(또는 응용 프로그램) 사이에서 동작하는 시스템 소프트웨어예요. 역할은 크게 두 가지로 나눠요.

| 역할 | 내용 | 예 |
|---|---|---|
| 자원 관리(Resource Management) | CPU, 메모리, 저장 장치, 입출력 장치를 여러 프로그램에 효율적이고 안전하게 나눠 줌 | CPU 시간 배분, 메모리 할당, 파일 저장 위치 결정 |
| 사용자 인터페이스(User Interface) 제공 | 사람이 컴퓨터를 쉽게 쓰도록 창구를 마련함 | CLI(명령 줄 인터페이스), GUI(그래픽 사용자 인터페이스) |

이 밖에도 사용자 인증과 접근 권한 같은 보안, 오류 감지와 처리, 네트워크 통신도 운영체제가 맡아요.

> [!EXAM]
> 운영체제의 성능 평가 기준은 처리 능력(Throughput) 향상, 반환 시간(Turnaround Time) 단축, 사용 가능도(Availability) 향상, 신뢰도(Reliability) 향상의 네 가지예요. "반환 시간 증가"처럼 방향을 거꾸로 적은 보기가 함정으로 나와요.

### 운영체제의 운영 방식

운영체제가 작업을 처리하는 방식에도 이름이 붙어 있어요. 한 운영체제가 여러 방식을 함께 쓰는 경우가 많아요.

| 방식 | 핵심 아이디어 | 쓰이는 곳 |
|---|---|---|
| 일괄 처리(Batch Processing) | 작업을 모아 두었다가 한꺼번에 처리 | 월말 급여 계산 |
| 다중 프로그래밍(Multiprogramming) | 메모리에 여러 프로그램을 올려 두고, 하나가 입출력을 기다리는 동안 다른 프로그램이 CPU를 사용 | CPU가 노는 시간 줄이기 |
| 시분할(Time Sharing) | CPU 시간을 아주 짧게 쪼개 여러 사용자·프로그램에 번갈아 줌 | 여러 사람이 동시에 쓰는 대화형 시스템 |
| 다중 처리(Multiprocessing) | CPU(프로세서) 여러 개가 동시에 작업 | 멀티코어 서버 |
| 실시간 처리(Real-time Processing) | 정해진 시간 안에 반드시 응답 | 항공기 제어, 공장 설비 |
| 분산 처리(Distributed Processing) | 네트워크로 연결된 여러 컴퓨터가 작업을 나눠 처리 | 클러스터, 클라우드 |

## 커널과 셸

### 커널

커널(Kernel)은 운영체제의 핵심 부분이에요. 컴퓨터가 켜져 있는 동안 메모리에 계속 머물면서 프로세스 관리, 메모리 관리, 파일 시스템, 장치 드라이버를 통한 입출력, 네트워크 처리를 담당해요. 하드웨어를 직접 다루기 때문에 일반 프로그램이 함부로 건드릴 수 없는 보호된 실행 모드인 커널 모드(Kernel Mode)에서 동작해요.

### 셸

셸(Shell)은 사용자가 입력한 명령을 해석해서 커널에 전달하는 명령 해석기(Command Interpreter)예요. Windows의 명령 프롬프트(cmd.exe)와 PowerShell, 리눅스의 bash가 대표적인 텍스트 셸이에요. 넓게 보면 Windows 탐색기처럼 아이콘을 눌러 일을 시키는 그래픽 화면도 셸의 한 종류예요.

응용 프로그램이 파일을 열거나 메모리를 더 달라고 할 때는 커널에 직접 손대지 못하고 시스템 호출(System Call)이라는 정해진 통로로 요청해요.

```text
  사용자
    |  명령 입력
  [셸, 응용 프로그램]        사용자 모드
    |  시스템 호출
  [커널]                     커널 모드
    |  장치 드라이버
  [하드웨어: CPU, 메모리, 디스크, NIC]
```

> [!TIP]
> 이름 그대로 기억하세요. 커널(kernel)은 씨앗의 '알맹이', 셸(shell)은 '껍데기'예요. 사용자는 껍데기를 만지고, 실제 일은 알맹이가 해요.

## 프로세스와 스레드

### 프로그램과 프로세스

요리책에 적힌 레시피는 그 자체로는 아무 일도 하지 않아요. 요리사가 레시피를 펼치고 재료를 꺼내 요리를 시작해야 비로소 '일'이 돼요. 디스크에 저장된 실행 파일이 레시피라면, 그것을 실행해 메모리에 올라온 상태가 프로세스예요.

- 프로그램(Program): 디스크에 저장된 실행 파일. 움직이지 않는 정적인 상태예요.
- 프로세스(Process): 실행 중인 프로그램. 메모리에 올라와 CPU를 할당받을 수 있는 작업 단위예요. 메모장을 두 번 실행하면 같은 프로그램이지만 프로세스는 두 개가 돼요.

각 프로세스는 다른 프로세스와 분리된 자기만의 메모리 공간(코드, 데이터, 힙, 스택 영역)을 가져요. 운영체제는 프로세스마다 PCB(Process Control Block, 프로세스 제어 블록)를 만들어 관리하는데, 여기에는 프로세스 번호(PID), 현재 상태, 다음에 실행할 명령의 위치(프로그램 카운터), 레지스터 값, 메모리 정보, 우선순위 등이 들어 있어요.

### 스레드

스레드(Thread)는 프로세스 안에서 실제로 CPU 위에서 실행되는 흐름의 단위예요. 프로세스 하나에는 스레드가 하나 이상 있어요. 웹 브라우저가 파일을 내려받으면서 동시에 화면을 스크롤할 수 있는 것은 여러 스레드가 나눠서 일하기 때문이에요.

같은 프로세스의 스레드끼리는 코드, 데이터, 힙 영역과 열린 파일을 공유하고, 스택과 레지스터(프로그램 카운터 포함)는 각자 따로 가져요.

| 구분 | 프로세스 | 스레드 |
|---|---|---|
| 정의 | 실행 중인 프로그램 | 프로세스 안의 실행 흐름 |
| 메모리 | 프로세스마다 독립된 공간 | 같은 프로세스 안에서 공유(스택은 각자) |
| 만들고 전환하는 비용 | 큼 | 작음 |
| 오류의 영향 | 다른 프로세스에 거의 영향 없음 | 같은 프로세스 전체가 멈출 수 있음 |
| 다른 이름 | 작업(Task) | 경량 프로세스(Lightweight Process) |

### 프로세스의 상태 변화

프로세스는 생겨나서 끝날 때까지 여러 상태를 오가요.

- 생성(New): 프로세스가 막 만들어지는 중
- 준비(Ready): 실행할 준비가 끝나 CPU 차례를 기다리는 중
- 실행(Running): CPU를 받아 명령을 실행하는 중
- 대기(Waiting, Blocked): 입출력 완료 같은 사건을 기다리느라 CPU를 쓸 수 없는 중
- 종료(Terminated): 실행이 끝남

| 전이 | 언제 일어나나 |
|---|---|
| 준비 → 실행 | 디스패치(Dispatch): 스케줄러가 CPU를 넘겨줌 |
| 실행 → 준비 | 할당 시간이 끝남(Timer Runout), 또는 우선순위가 더 높은 프로세스에게 CPU를 빼앗김 |
| 실행 → 대기 | 디스크 읽기 같은 입출력을 요청해 결과를 기다려야 함(Block) |
| 대기 → 준비 | 기다리던 입출력이 끝남(Wake Up) |

CPU가 한 프로세스에서 다른 프로세스로 넘어갈 때는 지금 프로세스의 상태를 PCB에 저장하고 다음 프로세스의 상태를 불러와야 해요. 이 작업을 문맥 교환(Context Switching)이라고 해요.

> [!WARNING]
> 대기 상태에서 입출력이 끝나도 곧바로 실행 상태로 가지 않아요. 먼저 준비 상태로 돌아가 다시 CPU 차례를 기다려요. "대기 → 실행" 전이는 없어요.

### CPU 스케줄링 맛보기

준비 상태에 있는 여러 프로세스 가운데 누구에게 CPU를 줄지 정하는 일을 CPU 스케줄링이라고 해요. 실행 중인 프로세스에게서 CPU를 강제로 빼앗을 수 있으면 선점형(Preemptive), 스스로 끝내거나 대기 상태로 갈 때까지 기다리면 비선점형(Non-preemptive)이에요.

| 기법 | 방식 | 분류 |
|---|---|---|
| FCFS(First Come First Served), FIFO | 먼저 도착한 순서대로 처리 | 비선점 |
| SJF(Shortest Job First) | 실행 시간이 가장 짧은 작업부터 처리 | 비선점(선점형으로 바꾼 것이 SRT) |
| RR(Round Robin) | 정해진 시간 할당량(Time Quantum)만큼씩 돌아가며 처리 | 선점 |

RR은 시분할 시스템에 잘 맞아요. 할당량이 너무 크면 FCFS와 다를 바 없어지고, 너무 작으면 문맥 교환이 지나치게 잦아져요.

## 메모리 관리

### 가상 메모리

책상(RAM)이 좁아서 책을 다 펼쳐 놓을 수 없을 때는 당장 볼 책만 책상에 올리고 나머지는 책장(디스크)에 꽂아 두었다가 필요할 때 바꿔 오면 돼요. 가상 메모리가 바로 이 방법이에요.

가상 메모리(Virtual Memory)는 보조 기억 장치(디스크)의 일부를 주기억 장치(RAM)처럼 함께 써서, 실제 RAM보다 큰 프로그램도 실행할 수 있게 하는 기법이에요. 프로세스는 자기만의 가상 주소 공간을 갖고, CPU 안의 MMU(Memory Management Unit, 메모리 관리 장치)가 운영체제와 함께 가상 주소를 실제 메모리 주소로 바꿔 줘요. 디스크 쪽 공간을 Windows에서는 페이지 파일(pagefile.sys), 리눅스에서는 스왑(Swap) 영역이라고 불러요.

### 페이징과 세그먼테이션

- 페이징(Paging): 가상 주소 공간을 같은 크기의 페이지(Page)로, 실제 메모리를 같은 크기의 프레임(Frame)으로 나눈 뒤 페이지를 빈 프레임에 배치해요. 어느 페이지가 어느 프레임에 있는지는 페이지 테이블(Page Table)에 기록해요. 일반적인 PC에서 페이지 크기는 4KB예요.
- 세그먼테이션(Segmentation): 프로그램을 코드, 데이터, 스택처럼 의미 있는 단위로 나누는데, 단위마다 크기가 달라요.

| 구분 | 페이징 | 세그먼테이션 |
|---|---|---|
| 나누는 크기 | 고정 크기 | 가변 크기 |
| 생기는 낭비 | 내부 단편화(마지막 페이지의 남는 공간) | 외부 단편화(조각난 빈 공간) |

필요한 페이지가 RAM에 없어서 디스크에서 가져와야 하는 상황을 페이지 부재(Page Fault)라고 해요. 페이지 부재가 너무 잦아서 실제 일보다 페이지를 바꾸는 데 시간을 더 쓰는 상태가 스래싱(Thrashing)이에요. 스래싱이 생기면 성능이 급격히 떨어지므로 메모리를 늘리거나 동시에 실행하는 프로그램 수를 줄여야 해요.

RAM이 꽉 찼을 때 어떤 페이지를 디스크로 내보낼지 정하는 방법으로는 FIFO(가장 먼저 들어온 것), LRU(Least Recently Used, 가장 오랫동안 쓰지 않은 것), LFU(Least Frequently Used, 사용 횟수가 가장 적은 것) 등이 있어요.

> [!EXAM]
> "페이징은 고정 크기라 내부 단편화, 세그먼테이션은 가변 크기라 외부 단편화"를 짝지어 외우세요. 가상 메모리를 쓰면 실제 메모리보다 큰 프로그램을 실행할 수 있다는 점도 자주 물어요.

## 파일 시스템

파일 시스템(File System)은 디스크에 파일을 어떤 구조로 저장하고, 찾고, 보호할지 정한 규칙이에요. 같은 디스크라도 어떤 파일 시스템으로 포맷하느냐에 따라 파일 하나의 최대 크기, 권한 기능, 장애 복구 능력이 달라져요.

중요한 개념 하나가 저널링(Journaling)이에요. 파일 시스템을 바꾸기 전에 무엇을 바꿀지 먼저 로그(저널)에 적어 두는 방식인데, 작업 도중 전원이 갑자기 꺼져도 로그를 보고 빠르게 일관된 상태로 되돌릴 수 있어요.

| 파일 시스템 | 주로 쓰는 곳 | 특징 |
|---|---|---|
| FAT32 | USB 메모리, 여러 기기 간 호환 | 구조가 단순하고 거의 모든 기기에서 읽힘. 파일 하나 최대 4GB, 권한·암호화·저널링 없음 |
| NTFS | Windows(서버 포함)의 기본 | 저널링, 파일·폴더 권한(ACL), EFS 암호화, 압축, 디스크 할당량 지원 |
| ext4 | 리눅스 | ext2 → ext3(저널링 추가) → ext4로 발전. 저널링, 대용량 볼륨과 파일 지원 |

리눅스에서는 배포판에 따라 XFS를 기본으로 쓰기도 해요(Red Hat 계열이 대표적이에요). Windows 파일 시스템은 [Windows 파일 시스템과 권한](/textbook/nos-windows-file-permissions)에서, 리눅스 디렉터리 구조는 [리눅스 기초](/textbook/nos-linux-intro)에서 자세히 배워요.

## 네트워크 운영체제(NOS)

### NOS란

네트워크 운영체제(NOS, Network Operating System)는 여러 컴퓨터가 네트워크를 통해 자원을 공유하고, 그 자원을 한곳에서 관리할 수 있도록 네트워크 기능을 갖춘 운영체제예요. 주요 기능은 다음과 같아요.

- 파일과 프린터 공유
- 사용자 계정 관리와 로그인 인증
- 자원별 접근 권한 관리
- 디렉터리 서비스(누가 어떤 자원을 가졌는지 찾아 주는 서비스)
- 원격 접속과 원격 관리
- TCP/IP 같은 네트워크 프로토콜과 웹·DNS·DHCP 등 각종 서버 서비스

요즘 Windows와 리눅스는 데스크톱용이라도 기본 네트워크 기능을 다 갖추고 있어서 '일반 운영체제'와 'NOS'의 경계가 흐려졌어요. 시험에서는 주로 서버로 쓰는 운영체제를 NOS로 보고 문제를 내요.

### 클라이언트-서버와 P2P

네트워크에서 컴퓨터끼리 역할을 나누는 방식은 [네트워크의 분류와 토폴로지](/textbook/net-topology-types)에서 배웠어요. NOS 관점에서 다시 정리하면 다음과 같아요.

| 구분 | 클라이언트-서버(Client/Server) | P2P(Peer-to-Peer) |
|---|---|---|
| 구조 | 서비스를 주는 서버와 요청하는 클라이언트로 역할이 나뉨 | 모든 컴퓨터가 동등하게 주고받음 |
| 계정·자원 관리 | 서버에서 중앙 관리 | 컴퓨터마다 따로 관리 |
| 보안과 확장성 | 높음, 대규모에 적합 | 낮음, 소규모에 적합 |
| 구축 비용 | 서버 장비와 관리 인력 필요 | 저렴하고 설치가 쉬움 |
| 약점 | 서버가 멈추면 서비스 전체가 멈춤 | 컴퓨터가 늘수록 관리가 어려워짐 |
| Windows에서의 예 | 도메인(Active Directory) | 작업 그룹(Workgroup) |

도메인과 작업 그룹은 [Active Directory와 그룹 정책](/textbook/nos-windows-ad)에서 자세히 다뤄요.

### 서버 운영체제 계열

| 계열 | 특징 | 예 |
|---|---|---|
| Windows Server | Microsoft의 상용 서버 운영체제. GUI 관리 도구가 풍부하고 Active Directory로 계정을 통합 관리 | Windows Server 2016, 2019, 2022 |
| 리눅스(Linux) | 1991년 리누스 토르발스가 공개한 커널을 바탕으로 한 오픈 소스 운영체제. 여러 회사·단체가 배포판으로 묶어 제공 | Red Hat Enterprise Linux, Rocky Linux, Ubuntu Server, Debian |
| 유닉스(UNIX) | 1960년대 말 AT&T 벨 연구소에서 개발. 대부분이 C 언어로 다시 작성되어 다른 하드웨어로 옮기기 쉬움. 대형 시스템에서 안정성으로 유명 | IBM AIX, HP-UX, Oracle Solaris |

유닉스와 리눅스는 다중 사용자(Multi-user), 다중 작업(Multi-tasking), 트리 모양의 계층형 파일 시스템, 높은 이식성(Portability)이라는 공통 특징을 가져요. 리눅스는 유닉스의 설계를 따르면서 처음부터 새로 작성된 운영체제라 유닉스 계열(Unix-like)이라고 불러요.

> [!NOTE]
> 오래된 문제에는 노벨 넷웨어(NetWare)가 NOS의 예로 나오기도 해요. 한때 파일·프린터 서버로 널리 쓰였고 IPX/SPX 프로토콜을 사용했지만, 지금 현장에서는 거의 쓰지 않아요.

## 핵심 정리

- 운영체제의 2대 역할은 자원 관리와 사용자 인터페이스 제공이에요. 성능 평가 기준은 처리 능력 향상, 반환 시간 단축, 사용 가능도 향상, 신뢰도 향상이에요.
- 커널은 하드웨어를 직접 다루는 핵심(커널 모드), 셸은 사용자 명령을 해석해 커널에 전달하는 명령 해석기예요.
- 프로세스는 실행 중인 프로그램이고 독립된 메모리를 가져요. 스레드는 프로세스 안의 실행 흐름으로, 메모리를 공유하고 스택은 각자 가져요.
- 프로세스 상태는 생성·준비·실행·대기·종료이고, 대기에서 끝나면 준비로 돌아가요(대기 → 실행은 없음).
- FCFS·SJF는 비선점, RR은 시간 할당량을 쓰는 선점형 스케줄링이에요.
- 가상 메모리는 디스크를 RAM처럼 함께 써요. 페이징은 고정 크기(내부 단편화), 세그먼테이션은 가변 크기(외부 단편화)예요.
- FAT32는 호환성이 좋지만 파일 하나 최대 4GB에 권한이 없어요. NTFS는 Windows 기본으로 권한·암호화·할당량을 지원하고, ext4는 저널링을 갖춘 리눅스 파일 시스템이에요.
- NOS는 자원 공유, 계정·권한 관리, 원격 관리를 지원하는 운영체제예요. 클라이언트-서버는 중앙 관리, P2P는 동등한 관계예요.

## 스스로 확인하기

**1.** 프로세스 상태 전이 중 일어나지 않는 것은?
① 준비 → 실행 ② 실행 → 대기 ③ 대기 → 실행 ④ 실행 → 준비

> [!ANSWER]
> 정답: ③
> 대기 상태의 프로세스는 기다리던 사건이 끝나면 먼저 준비 상태로 돌아가 CPU 차례를 기다려요.

**2.** 스레드에 대한 설명으로 옳지 않은 것은?
① 같은 프로세스의 스레드는 힙 영역을 공유한다 ② 스레드마다 스택을 따로 가진다 ③ 프로세스보다 만들고 전환하는 비용이 크다 ④ 경량 프로세스라고도 부른다

> [!ANSWER]
> 정답: ③
> 스레드는 메모리를 공유하므로 프로세스보다 만들고 전환하는 비용이 작아요.

**3.** 사용자가 입력한 명령을 해석해 커널에 전달하는 프로그램을 무엇이라고 하는가?
① 장치 드라이버 ② 셸 ③ 페이지 테이블 ④ PCB

> [!ANSWER]
> 정답: ②
> 셸은 사용자와 커널 사이의 명령 해석기예요. cmd, PowerShell, bash가 대표적이에요.

**4.** 정해진 시간 할당량만큼씩 프로세스에 CPU를 돌아가며 주는 선점형 스케줄링 기법은?
① FCFS ② SJF ③ FIFO ④ RR

> [!ANSWER]
> 정답: ④
> 라운드 로빈(RR)은 시간 할당량이 끝나면 CPU를 다음 프로세스에 넘기는 선점형 방식으로, 시분할 시스템에 적합해요.

**5.** 다음 중 FAT32 파일 시스템의 특징으로 옳은 것은?
① 파일·폴더마다 접근 권한을 줄 수 있다 ② 파일 하나의 최대 크기가 4GB이다 ③ 저널링으로 장애 후 빠르게 복구한다 ④ 사용자별 디스크 할당량을 설정할 수 있다

> [!ANSWER]
> 정답: ②
> FAT32는 호환성이 좋은 대신 파일 하나가 4GB를 넘을 수 없고, 권한·저널링·할당량 기능이 없어요. 나머지는 NTFS의 특징이에요.
