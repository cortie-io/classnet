OSI 7계층이 네트워크를 설명하는 교과서용 설계도라면, TCP/IP는 지금 인터넷이 실제로 움직이는 방식이에요. 이 단원에서는 TCP/IP의 4계층 구조와 OSI와의 대응, 계층별 대표 프로토콜을 정리하고, 웹 페이지 요청 하나가 실제 헤더를 달고 떼며 목적지까지 가는 과정을 따라가 봐요. 2과목의 모든 내용이 이 4계층 위에 놓이니, 각 프로토콜이 어느 계층에 속하는지 정확히 짚어 두세요.

> [!GOAL]
> - TCP/IP 4계층의 이름과 각 계층의 역할을 말할 수 있다.
> - OSI 7계층과 TCP/IP 4계층을 서로 대응시킬 수 있다.
> - 주요 프로토콜이 TCP/IP의 어느 계층에 속하는지 구분할 수 있다.
> - 계층별 헤더, 데이터 단위, 주소를 짝짓고 캡슐화 과정을 실제 헤더 크기로 설명할 수 있다.
> - 라우터를 지날 때 바뀌는 정보와 바뀌지 않는 정보를 구분할 수 있다.

## TCP/IP는 무엇인가

**TCP/IP**는 인터넷에서 쓰는 여러 프로토콜의 묶음(Protocol Suite)이에요. 그중 핵심인 TCP와 IP의 이름을 따서 전체를 TCP/IP라고 불러요.

- 미국 국방부(DoD)가 지원한 ARPANET 연구에서 출발해서 **DoD 모델**이라고도 불러요. ARPANET은 1983년에 TCP/IP로 전환했어요.
- 표준은 **RFC(Request for Comments)**라는 공개 문서로 정하고, IETF가 관리해요.
- OSI가 국제 표준 기구(ISO)가 먼저 틀을 짜고 만든 **참조 모델**이라면, TCP/IP는 실제로 구현해 쓰면서 자리 잡은 **사실상의 표준(De facto Standard)**이에요.

| 비교 | OSI 모델 | TCP/IP 모델 |
|---|---|---|
| 만든 곳 | ISO | 미국 국방부 연구에서 출발, IETF가 표준화 |
| 계층 수 | 7계층 | 4계층 |
| 성격 | 이론적 참조 모델 | 실제 인터넷에서 쓰는 구현 중심 모델 |
| 쓰임 | 개념 설명, 장비·프로토콜 분류 기준 | 실제 통신 |

## TCP/IP 4계층

| 계층 | 이름 | 하는 일 | 데이터 단위 | 주소·식별자 | 대표 프로토콜 |
|---|---|---|---|---|---|
| 4 | 응용 계층(Application) | 사용자 프로그램에 네트워크 서비스 제공 | 메시지(데이터) | 도메인 이름, URL 등 | HTTP, FTP, SMTP, POP3, IMAP, DNS, DHCP, SNMP, Telnet, SSH, TFTP |
| 3 | 전송 계층(Transport) | 양 끝 컴퓨터의 프로세스끼리 데이터 전달, 신뢰성 제공 | 세그먼트(TCP), 데이터그램(UDP) | **포트 번호** | TCP, UDP |
| 2 | 인터넷 계층(Internet) | 논리 주소 지정과 경로 선택(라우팅) | 패킷(IP 데이터그램) | **IP 주소** | IP, ICMP, IGMP, ARP, RARP |
| 1 | 네트워크 접근 계층(Network Access) | 같은 링크 안에서 프레임 전달, 물리 신호 전송 | 프레임 | **MAC 주소** | 이더넷, 무선 LAN(802.11), PPP, 프레임 릴레이 |

맨 아래 계층은 책에 따라 **네트워크 인터페이스 계층**, **링크 계층**이라고도 불러요. 또 이 계층을 물리 계층과 데이터 링크 계층으로 나눠 **5계층**으로 설명하는 책도 있어요. 시험에서는 4계층 이름이 주로 나와요.

### OSI 7계층과의 대응

```text
   OSI 7계층                 TCP/IP 4계층
 7 응용        --+
 6 표현          +------>  응용 계층
 5 세션        --+
 4 전송        --------->  전송 계층
 3 네트워크    --------->  인터넷 계층
 2 데이터 링크 --+
 1 물리          +------>  네트워크 접근 계층
```

OSI 각 계층의 역할은 [OSI 7계층](/textbook/net-osi-model)에서 배웠어요. TCP/IP에서는 OSI의 세션·표현 계층이 하던 일(대화 관리, 암호화, 압축 등)을 응용 프로그램이나 TLS 같은 프로토콜이 알아서 처리한다고 보면 돼요.

### 계층별 대표 프로토콜

**응용 계층**은 사용자가 직접 느끼는 서비스를 만들어요. 각 프로토콜이 아래에서 TCP와 UDP 중 무엇을 주로 쓰는지도 함께 알아 두면 좋아요.

| 프로토콜 | 하는 일 | 주로 쓰는 전송 프로토콜 |
|---|---|---|
| HTTP·HTTPS | 웹 페이지 전송 | TCP |
| FTP | 파일 전송 | TCP |
| SMTP·POP3·IMAP | 메일 보내기·받기 | TCP |
| Telnet·SSH | 원격 접속 | TCP |
| DNS | 도메인 이름을 IP 주소로 변환 | 주로 UDP (큰 응답 등은 TCP) |
| DHCP | IP 주소 자동 할당 | UDP |
| SNMP | 네트워크 장비 관리 | UDP |
| TFTP | 간단한 파일 전송 | UDP |

각 프로토콜의 포트 번호는 [UDP와 포트 번호](/textbook/tcpip-udp-ports)에서 정리해요.

**전송 계층**의 두 주인공은 성격이 정반대예요.

- **TCP(Transmission Control Protocol)**: 연결을 맺고, 순서를 맞추고, 빠진 것은 다시 보내는 **연결형·신뢰성** 프로토콜이에요.
- **UDP(User Datagram Protocol)**: 연결 없이 바로 보내는 **비연결형** 프로토콜이에요. 단순하고 빨라서 실시간 통신이나 짧은 질의응답에 써요.

**인터넷 계층**은 패킷을 목적지 네트워크까지 데려가요.

- **IP**: 주소를 붙이고 라우터를 거쳐 전달해요. 연결을 맺지 않고, 도착을 보장하지 않는 **최선형(Best Effort)** 전달을 해요.
- **ICMP**: 전달 중 생긴 오류를 알리고 진단해요. `ping`이 ICMP를 써요.
- **IGMP**: 멀티캐스트 그룹 가입·탈퇴를 관리해요.
- **ARP**: IP 주소로 같은 네트워크 안 상대의 MAC 주소를 알아내요. **RARP**는 반대로 MAC 주소로 자기 IP를 알아내던 옛 프로토콜이에요.

> [!WARNING]
> ARP는 IP 주소(3계층)와 MAC 주소(2계층)를 잇는 경계에 있어서 자료마다 위치를 다르게 설명하기도 해요. **TCP/IP 모델 문제에서는 인터넷 계층**으로 분류하는 것이 일반적이에요. 자세한 동작은 [ARP·ICMP·IGMP](/textbook/tcpip-arp-icmp)에서 배워요.

> [!EXAM]
> "다음 중 인터넷 계층 프로토콜이 **아닌** 것은?" 같은 문제에 TCP·UDP를 섞어 내는 경우가 많아요. **IP·ICMP·IGMP·ARP·RARP는 인터넷 계층, TCP·UDP는 전송 계층**으로 확실히 나눠 두세요.

## 캡슐화를 실제 헤더로 따라가기

캡슐화와 역캡슐화의 기본 개념은 [OSI 7계층](/textbook/net-osi-model)에서 배웠어요. 여기서는 TCP/IP에서 실제로 어떤 헤더가 얼마만큼 붙는지 구체적으로 볼게요. 편지를 봉투에 넣고, 봉투를 택배 상자에 넣고, 상자에 운송장을 붙이는 과정을 떠올리면 돼요.

```text
응용   [         HTTP 데이터         ]
전송   [TCP 20][   HTTP 데이터       ]     세그먼트
인터넷 [IP 20][TCP 20][ HTTP 데이터  ]     패킷
접근   [Eth 14][IP][TCP][데이터][FCS 4]    프레임
        -> 비트로 바뀌어 케이블·전파로 전송
                         (숫자는 기본 크기, 바이트)
```

| 헤더 | 기본 크기 | 담고 있는 주요 정보 |
|---|---|---|
| TCP 헤더 | 20바이트 (옵션 있으면 최대 60) | 출발지·목적지 포트, 순서 번호, 확인 응답 번호, 플래그 |
| UDP 헤더 | 8바이트 (고정) | 출발지·목적지 포트, 길이, 체크섬 |
| IPv4 헤더 | 20바이트 (옵션 있으면 최대 60) | 출발지·목적지 IP 주소, TTL, 프로토콜 번호 |
| 이더넷 헤더 + 트레일러 | 14바이트 + FCS 4바이트 | 목적지 MAC(6), 출발지 MAC(6), 타입(2), 오류 검사(FCS) |

### 계산으로 확인하기

응용 데이터 1,000바이트를 TCP로 보낸다고 해 볼게요. 옵션이 없다면 이더넷 프레임의 크기는 이렇게 돼요.

```text
1,000(데이터) + 20(TCP) + 20(IP) + 14(이더넷 헤더) + 4(FCS)
= 1,058바이트
```

또 이더넷의 **MTU(Maximum Transmission Unit, 프레임 하나의 데이터 부분에 실을 수 있는 최대 크기)**는 보통 1,500바이트예요. 즉 MTU는 IP 패킷 전체 크기(IP 헤더 포함)의 상한이므로, 옵션 없는 TCP 세그먼트 하나에 실을 수 있는 응용 데이터는 1,500 − 20(IP) − 20(TCP) = **1,460바이트**예요. 이 값을 MSS(Maximum Segment Size)라고 불러요.

> [!TIP]
> 헤더가 붙는 만큼 실제 데이터 비율은 줄어요. 작은 데이터를 잘게 많이 보내면 헤더 부담이 커지고, 큰 데이터를 모아 보내면 효율이 좋아져요.

### 받는 쪽은 어떻게 위 계층을 찾을까

받는 쪽은 아래 계층부터 헤더를 떼며 올라가요(역캡슐화). 이때 각 헤더에는 **"내 안에 든 것은 누구에게 넘겨야 하는가"**를 알려 주는 칸이 있어요. 이렇게 받은 데이터를 알맞은 위 계층 프로토콜로 나눠 주는 것을 **역다중화(Demultiplexing)**라고 해요.

| 위치 | 필드 | 예 |
|---|---|---|
| 이더넷 헤더 | 타입(EtherType) | 0x0800 = IPv4, 0x0806 = ARP, 0x86DD = IPv6 |
| IP 헤더 | 프로토콜 번호 | 1 = ICMP, 6 = TCP, 17 = UDP |
| TCP·UDP 헤더 | 목적지 포트 번호 | 80 = HTTP, 53 = DNS |

IP 헤더의 각 필드는 [IP 패킷의 구조와 단편화](/textbook/tcpip-ip-header)에서 자세히 다뤄요.

## 라우터를 지날 때 무엇이 바뀔까

라우터는 프레임을 받으면 2계층 헤더를 떼어 내고, IP 헤더의 목적지 주소를 보고 다음 경로를 정한 뒤, **다음 링크에 맞는 새 2계층 헤더를 붙여** 내보내요. 이 과정에서 바뀌는 것과 그대로인 것이 나뉘어요.

| 정보 | 라우터를 지날 때 |
|---|---|
| 출발지·목적지 **MAC 주소** | 구간(홉)마다 **바뀜** |
| 출발지·목적지 **IP 주소** | 처음부터 끝까지 **그대로** (NAT를 거치는 경우는 예외) |
| TTL | 라우터마다 1씩 줄어듦 |
| 포트 번호, 응용 데이터 | 그대로 (일반 라우터는 4계층 이상을 고치지 않음) |

> [!TIP]
> 택배에 빗대면 **IP 주소는 최종 받는 사람 주소**, **MAC 주소는 이번 구간의 출발 터미널과 도착 터미널**이에요. 최종 주소는 끝까지 같지만, 터미널 정보는 구간마다 새로 붙여요.

## 한 번에 따라가 보기: 웹 페이지 요청

민수가 회사 PC(192.168.0.10)에서 브라우저로 `http://www.example.com`에 접속하는 과정을 계층별로 따라가 볼게요. 웹 서버 주소는 DNS로 이미 203.0.113.80임을 알아냈다고 가정해요.

1. **응용 계층**: 브라우저가 "이 페이지를 주세요"라는 HTTP 요청 메시지를 만들어요.
2. **전송 계층**: TCP가 서버와 연결을 맺은 뒤, 요청에 TCP 헤더를 붙여요. 목적지 포트는 웹 서비스의 80번, 출발지 포트는 운영체제가 임의로 고른 번호예요.
3. **인터넷 계층**: IP 헤더를 붙여요. 출발지 192.168.0.10, 목적지 203.0.113.80이에요. 목적지가 다른 네트워크이므로 이 패킷은 **기본 게이트웨이(라우터)**로 보내야 해요.
4. **네트워크 접근 계층**: 이더넷 헤더의 목적지 MAC에는 웹 서버가 아니라 **기본 게이트웨이의 MAC 주소**를 넣어요. 게이트웨이의 MAC은 ARP로 알아내요. 끝에 FCS를 붙여 비트로 내보내요.
5. **중간 라우터들**: 각 라우터가 2계층 헤더를 새로 붙이며 패킷을 넘겨요. IP 주소는 그대로예요. (회사 공유기나 방화벽이 NAT를 하면 출발지 IP는 공인 주소로 바뀌는데, 이 내용은 [NAT와 전송 방식](/textbook/tcpip-nat-multicast)에서 배워요.)
6. **웹 서버**: 프레임 → 패킷 → 세그먼트 → 메시지 순서로 헤더를 떼어 내고, 목적지 포트 80번을 보고 웹 서버 프로그램에 요청을 넘겨요. 응답은 같은 과정을 반대 방향으로 거쳐 돌아와요.

> [!NOTE]
> IP 주소와 포트 번호를 합친 것(예: 203.0.113.80:80)을 **소켓(Socket)**이라고 해요. 한 컴퓨터에서 여러 프로그램이 동시에 통신해도 포트 번호 덕분에 데이터가 섞이지 않아요.

## 핵심 정리

- TCP/IP 4계층은 아래부터 **네트워크 접근 – 인터넷 – 전송 – 응용** 계층이에요.
- OSI 5~7계층은 TCP/IP **응용 계층**, 4계층은 **전송 계층**, 3계층은 **인터넷 계층**, 1~2계층은 **네트워크 접근 계층**에 대응해요.
- 응용: HTTP·FTP·SMTP·DNS·DHCP·SNMP 등, 전송: **TCP·UDP**, 인터넷: **IP·ICMP·IGMP·ARP·RARP**, 네트워크 접근: 이더넷·802.11·PPP 등이에요.
- 데이터 단위는 메시지 → 세그먼트(UDP는 데이터그램) → 패킷 → 프레임이고, 주소는 **포트 번호(전송)**, **IP 주소(인터넷)**, **MAC 주소(네트워크 접근)**예요.
- 기본 헤더 크기는 **TCP 20바이트, UDP 8바이트, IPv4 20바이트, 이더넷 헤더 14바이트 + FCS 4바이트**예요. MTU 1,500이면 TCP 데이터는 최대 **1,460바이트(MSS)**예요.
- 받는 쪽은 **EtherType → IP 프로토콜 번호 → 포트 번호**를 보고 위 계층을 찾아 넘겨요.
- 라우터를 지날 때 **MAC 주소는 구간마다 바뀌고 IP 주소는 그대로**예요(NAT 제외). TTL은 1씩 줄어요.

## 스스로 확인하기

**1.** TCP/IP 모델에서 인터넷 계층에 속하지 **않는** 프로토콜은?
① IP ② ICMP ③ ARP ④ UDP

> [!ANSWER]
> 정답: ④
> UDP는 TCP와 함께 전송 계층 프로토콜이에요. IP·ICMP·ARP는 인터넷 계층으로 분류해요.

**2.** OSI 7계층의 세션·표현·응용 계층이 모두 대응하는 TCP/IP 계층은?
① 네트워크 접근 계층 ② 인터넷 계층 ③ 전송 계층 ④ 응용 계층

> [!ANSWER]
> 정답: ④
> TCP/IP는 OSI 5~7계층의 역할을 응용 계층 하나로 묶어요.

**3.** 이더넷 MTU가 1,500바이트이고 IPv4 헤더와 TCP 헤더에 옵션이 없을 때, TCP 세그먼트 하나에 실을 수 있는 응용 데이터의 최대 크기는?
① 1,442바이트 ② 1,460바이트 ③ 1,480바이트 ④ 1,500바이트

> [!ANSWER]
> 정답: ②
> MTU 1,500에서 IP 헤더 20바이트와 TCP 헤더 20바이트를 빼면 1,460바이트예요. 이더넷 헤더와 FCS는 MTU에 포함되지 않아요.

**4.** NAT를 거치지 않는 경로에서 패킷이 라우터를 하나 지날 때 바뀌는 값은?
① 목적지 IP 주소 ② 출발지 IP 주소 ③ 목적지 MAC 주소 ④ 목적지 포트 번호

> [!ANSWER]
> 정답: ③
> 라우터는 다음 구간에 맞게 2계층 헤더를 새로 붙이므로 MAC 주소가 바뀌어요. IP 주소와 포트 번호는 그대로예요.

**5.** 받는 컴퓨터가 IP 헤더를 떼어 낸 뒤, 안에 든 데이터를 TCP에 넘길지 UDP에 넘길지 판단할 때 보는 값은?
① 이더넷 헤더의 타입 필드 ② IP 헤더의 프로토콜 번호 ③ TCP 헤더의 순서 번호 ④ 목적지 MAC 주소

> [!ANSWER]
> 정답: ②
> IP 헤더의 프로토콜 번호가 6이면 TCP, 17이면 UDP로 넘겨요. 이더넷 타입 필드는 그 아래 단계에서 IPv4인지 ARP인지 등을 가려요.
