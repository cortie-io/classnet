네트워크를 인터넷에 연결하는 순간부터 원하지 않는 접속과 공격도 함께 들어와요. 이 단원에서는 그것을 막고 감시하는 **보안 장비**를 정리해요. 방화벽의 종류와 배치 구조, DMZ, 침입 탐지·차단 시스템(IDS·IPS), 여러 기능을 합친 UTM, 웹 전용 방화벽 WAF, VPN 장비, 접속 단말을 검사하는 NAC까지 "무엇을 어디서 막는가"를 기준으로 비교해요.

> [!GOAL]
> - 패킷 필터링·상태 기반 검사·응용 계층 게이트웨이·회로 레벨 게이트웨이 방화벽을 구분할 수 있다.
> - 이중 홈·스크린드 호스트·스크린드 서브넷 구조와 DMZ의 역할을 설명할 수 있다.
> - IDS와 IPS, 오용 탐지와 이상 탐지, 오탐과 미탐의 차이를 설명할 수 있다.
> - UTM·WAF·VPN 장비·NAC·SIEM·허니팟의 용도를 구분할 수 있다.

## 방화벽

**방화벽**(Firewall)은 내부 네트워크와 외부 네트워크 사이에서 **정해 둔 규칙(정책)에 따라 트래픽을 허용하거나 차단**하는 장비 또는 소프트웨어예요. 건물 출입구의 보안 검색대와 비슷해요. 규칙은 보통 "명시적으로 허용한 것만 통과시키고 나머지는 모두 막는다"는 원칙으로 짜요.

### 방화벽의 종류

방화벽은 **얼마나 깊이 들여다보는가**에 따라 나뉘어요.

| 종류 | 주로 보는 계층 | 검사하는 것 | 장점 | 단점 |
|---|---|---|---|---|
| 패킷 필터링 | 3·4계층 | 출발지·목적지 IP, 포트, 프로토콜(헤더만) | 빠르고 단순, 사용자에게 투명 | 내용 검사 불가, 주소 위조(스푸핑)에 약함 |
| 상태 기반 검사 | 3·4계층 + 연결 상태 | 헤더 + 상태 테이블에 기록된 연결 정보 | 응답 트래픽 자동 허용, 위조 패킷 차단 | 상태 테이블 유지에 자원 소모 |
| 응용 계층 게이트웨이 | 7계층 | 응용 데이터 내용, 사용자 인증 | 가장 세밀한 검사, 로그 풍부 | 느림, 서비스마다 프록시 필요 |
| 회로 레벨 게이트웨이 | 5계층(세션) | TCP 연결(세션) 단위 중계, 내용은 안 봄 | 하나의 프록시로 여러 응용 처리 | 클라이언트에 전용 프로그램이 필요한 경우가 많음 |

**패킷 필터링**(Packet Filtering) 방화벽은 1세대 방식이에요. 패킷 하나하나를 독립적으로 보고 헤더 정보만으로 판단하므로, 이 패킷이 정상 연결의 일부인지는 알지 못해요.

**상태 기반 검사**(Stateful Inspection) 방화벽은 지나가는 연결을 **상태 테이블**(State Table)에 기록해요. 내부 PC가 웹 서버에 접속하면 그 연결을 기억해 두었다가, 돌아오는 응답만 자동으로 들여보내고 기록에 없는 패킷은 막아요. 오늘날 방화벽의 기본 방식이에요.

**응용 계층 게이트웨이**(Application-Level Gateway)는 **프록시 방화벽**이라고도 해요. 내부 사용자 대신 외부와 통신하는 대리인이라서 내부와 외부가 직접 연결되지 않아요. HTTP·FTP·메일처럼 서비스별 프록시가 데이터 내용까지 검사하고 사용자 인증도 할 수 있어요.

**회로 레벨 게이트웨이**(Circuit-Level Gateway)는 세션 계층에서 TCP 연결을 중계해요. 연결이 정상적으로 맺어졌는지만 확인하고 그 안의 데이터는 들여다보지 않아요. 대표적인 예가 **SOCKS** 프록시예요.

> [!NOTE]
> 요즘 많이 쓰는 **차세대 방화벽**(NGFW, Next-Generation Firewall)은 상태 기반 검사에 응용 프로그램 식별, 사용자 식별, 침입 차단 기능을 더한 제품이에요. 포트 번호가 아니라 "어떤 앱의 트래픽인가"로 규칙을 정할 수 있어요.

> [!EXAM]
> "상태 테이블", "연결 정보 추적" → 상태 기반 검사, "프록시", "7계층 내용 검사", "사용자 인증" → 응용 계층 게이트웨이, "SOCKS", "세션 계층" → 회로 레벨 게이트웨이로 짝지어 외우세요.

## 방화벽 구축 구조

### 구성 요소

- **스크리닝 라우터**(Screening Router): 패킷 필터링 기능을 가진 라우터예요. 혼자 쓰면 값싸지만 보호 수준이 낮아요.
- **배스천 호스트**(Bastion Host): 외부 공격에 노출되는 것을 전제로 **불필요한 서비스를 모두 지우고 단단히 강화한** 컴퓨터예요. 성의 요새처럼 맨 앞에서 공격을 받아 내고, 프록시와 로그 기록을 맡아요.

### 대표적인 배치 구조

| 구조 | 구성 | 특징 |
|---|---|---|
| 이중 홈 게이트웨이(Dual-Homed Gateway) | NIC가 2개인 배스천 호스트 하나 | 두 NIC 사이의 IP 전달 기능을 끄고 모든 트래픽을 프록시로 중계. 단순하지만 이 호스트가 뚫리면 내부가 노출됨 |
| 스크린드 호스트 게이트웨이(Screened Host Gateway) | 스크리닝 라우터 + 내부망의 배스천 호스트 | 라우터가 1차로 거르고, 외부 트래픽은 배스천 호스트로만 보내도록 허용. 2단계 방어 |
| 스크린드 서브넷 게이트웨이(Screened Subnet Gateway) | 외부 라우터 + 배스천 호스트가 있는 서브넷 + 내부 라우터 | 두 라우터 사이에 완충 지대(DMZ)를 만듦. 가장 안전하지만 구축 비용과 관리 부담이 큼 |

```text
 [스크린드 호스트 게이트웨이]

 인터넷 --[스크리닝 라우터]--+-- 내부망 PC들
                             |
                       [배스천 호스트]

 [스크린드 서브넷 게이트웨이]

 인터넷 --[외부 라우터]-- DMZ --[내부 라우터]-- 내부망
                           |
                  [배스천 호스트, 공개 서버]
```

> [!TIP]
> 이름에 "서브넷"이 들어가면 **별도의 서브넷(DMZ)을 하나 더 만든다**는 뜻이에요. 그래서 스크린드 서브넷이 가장 안전한 구조예요.

## DMZ

**DMZ**(DeMilitarized Zone, 비무장 지대)는 외부에 공개해야 하는 서버를 내부망과 분리해 두는 **완충 구역**이에요. 웹 서버, 메일 서버, 외부용 DNS 서버처럼 인터넷 사용자가 접속해야 하는 서버를 이곳에 둬요.

| 방향 | 일반적인 정책 |
|---|---|
| 인터넷 → DMZ | 필요한 서비스(예: 웹 443번)만 허용 |
| 인터넷 → 내부망 | 차단 |
| DMZ → 내부망 | 원칙적으로 차단(꼭 필요한 연결만 예외) |
| 내부망 → DMZ, 인터넷 | 정책에 따라 허용 |

이렇게 하면 공개 서버가 해킹당해도 공격자가 곧바로 내부망까지 들어오기 어려워요. 실무에서는 방화벽 한 대에 인터페이스 3개(외부·DMZ·내부)를 두거나, 방화벽 두 대 사이에 DMZ를 두는 방식으로 만들어요.

## IDS와 IPS

### 탐지냐 차단이냐

방화벽은 주소와 포트로 문을 지키지만, 허용된 포트로 들어오는 공격까지 알아보지는 못해요. 그래서 트래픽 내용을 분석해 공격을 찾아내는 장비를 함께 써요.

| 구분 | IDS(Intrusion Detection System) | IPS(Intrusion Prevention System) |
|---|---|---|
| 우리말 | 침입 탐지 시스템 | 침입 차단(방지) 시스템 |
| 설치 위치 | 포트 미러링(SPAN)이나 TAP으로 **복사본**을 받아 감시 | 트래픽이 지나가는 **경로 한가운데(인라인)** |
| 대응 | 탐지하고 경보(수동적) | 탐지 즉시 차단(능동적) |
| 장애 시 영향 | 고장 나도 통신에는 영향이 적음 | 고장이나 오탐이 정상 통신을 끊을 수 있음 |

IDS는 CCTV와 경보기, IPS는 출입구의 경비원이라고 생각하면 쉬워요. 포트 미러링은 [스위치 심화 — VLAN과 STP](/textbook/dev-switch-vlan-stp) 단원에서 배웠어요.

### 감시 대상에 따른 분류

| 구분 | NIDS(네트워크 기반) | HIDS(호스트 기반) |
|---|---|---|
| 감시 대상 | 네트워크를 지나는 패킷 | 설치된 서버의 로그, 파일 변경, 프로세스 |
| 장점 | 장비 하나로 넓은 구간 감시, 서버에 부담 없음 | 공격이 성공했는지, 내부자 행위까지 확인 가능 |
| 단점 | 암호화된 트래픽 분석이 어려움 | 서버마다 설치해야 하고 서버 자원을 씀 |

### 탐지 방법

| 구분 | 오용 탐지(Misuse Detection) | 이상 탐지(Anomaly Detection) |
|---|---|---|
| 다른 이름 | 시그니처 기반, 지식 기반 | 행위 기반, 통계 기반 |
| 원리 | 알려진 공격 패턴(시그니처)과 비교 | 평소 정상 상태를 학습한 뒤 크게 벗어나면 경보 |
| 장점 | 오탐이 적고 어떤 공격인지 명확함 | 처음 보는 새로운 공격(제로데이)도 잡을 수 있음 |
| 단점 | 패턴이 없는 새 공격은 못 잡음, 지속적인 패턴 업데이트 필요 | 오탐이 많고, 정상 기준을 정하기 어려움 |

### 오탐과 미탐

| 실제 상황 → / 판정 ↓ | 실제 공격 | 실제 정상 |
|---|---|---|
| 공격이라고 판정 | 정탐(True Positive) | **오탐**(False Positive) |
| 정상이라고 판정 | **미탐**(False Negative) | 정상(True Negative) |

- **오탐**은 정상 트래픽을 공격으로 잘못 판단하는 거예요. 관리자가 쓸데없는 경보에 시달리고, IPS라면 정상 통신이 끊겨요.
- **미탐**은 실제 공격을 놓치는 거예요. 보안 측면에서 더 위험해요.

> [!WARNING]
> 오탐과 미탐을 거꾸로 외우기 쉬워요. "**양성**(Positive) = 공격이라고 경보를 울렸다"를 기준으로 삼고, 그 판단이 틀렸으면 False를 붙이면 돼요. 그래서 경보를 울렸는데 틀린 것이 False Positive, 즉 오탐이에요.

## 여러 기능을 합친 장비와 전용 장비

### UTM

**UTM**(Unified Threat Management, 통합 위협 관리)은 방화벽, IPS, 바이러스 차단, VPN, 웹 콘텐츠 필터링, 스팸 차단 같은 여러 보안 기능을 **장비 한 대에 모은** 제품이에요.

- 장점: 장비를 따로 사는 것보다 저렴하고, 한 화면에서 관리할 수 있어 중소규모 조직에 알맞아요.
- 단점: 모든 기능을 켜면 성능이 떨어지고, 장비 한 대가 고장 나면 모든 보안 기능이 함께 멈춰요(단일 장애점).

### WAF

**WAF**(Web Application Firewall, 웹 방화벽)는 **HTTP·HTTPS 트래픽의 내용**을 분석해 웹 애플리케이션을 노리는 공격을 막는 장비예요. 일반 방화벽은 웹 서비스를 위해 80·443번 포트를 열어 둘 수밖에 없으므로, 그 포트로 들어오는 SQL 인젝션, 크로스 사이트 스크립팅(XSS), 악성 파일 업로드, 쿠키 변조 같은 공격은 걸러 내지 못해요. WAF는 웹 서버 앞에 두고 이런 요청을 찾아내 차단해요. 응답에 주민등록번호 같은 민감 정보가 섞여 나가는 것을 막는 기능도 있어요.

### VPN 게이트웨이와 VPN 집중 장치

**VPN 게이트웨이**는 공용 인터넷 위에 암호화된 터널을 만들어 주는 장비예요. 본사와 지사를 잇는 **사이트 간**(Site-to-Site) VPN에서는 양쪽 게이트웨이끼리 터널을 맺고, 재택 근무자가 접속하는 **원격 접속**(Remote Access) VPN에서는 사용자 PC의 VPN 클라이언트가 게이트웨이에 접속해요. 수많은 원격 사용자의 터널을 한꺼번에 처리하도록 만든 장비를 **VPN 집중 장치**(VPN Concentrator)라고 해요. IPSec·SSL VPN의 원리는 [네트워크 보안 기초](/textbook/tcpip-security-protocols) 단원에서 배워요.

### NAC

**NAC**(Network Access Control, 네트워크 접근 제어)는 단말이 네트워크에 **접속하기 전에** 자격과 보안 상태를 검사하는 시스템이에요.

1. **인증**: 누구의 어떤 장치인지 확인해요. 주로 IEEE 802.1X를 써요.
2. **보안 상태 검사**: 운영체제 패치, 백신 설치·업데이트 여부 같은 회사 정책을 지키는지 확인해요.
3. **격리와 치료**: 정책을 어긴 단말은 격리용 VLAN 등에 가두고, 패치를 받게 한 뒤 접속을 허용해요.
4. **지속 감시**: 접속한 뒤에도 정책 위반이 생기면 차단해요.

802.1X에서는 단말을 **서플리컨트**(Supplicant), 단말이 연결된 스위치나 AP를 **인증자**(Authenticator), 실제로 계정을 확인하는 서버(보통 RADIUS)를 **인증 서버**(Authentication Server)라고 불러요.

### ESM과 SIEM

보안 장비가 많아지면 각각의 로그를 따로 보기 어려워요.

- **ESM**(Enterprise Security Management, 통합 보안 관리): 방화벽·IDS·VPN 같은 여러 보안 장비를 한 콘솔에서 통합해 관리하고 이벤트를 모아 보여 줘요.
- **SIEM**(Security Information and Event Management): 보안 장비뿐 아니라 서버·네트워크 장비의 로그까지 대량으로 모아 **상관 분석**(Correlation)해요. 예를 들어 "같은 IP가 로그인 실패를 수십 번 한 뒤 방화벽 규칙 변경을 시도"처럼 흩어진 이벤트를 엮어 공격을 찾아내고 경보를 울려요.

### 허니팟

**허니팟**(Honeypot)은 공격자를 끌어들이려고 일부러 취약해 보이게 만든 **미끼 시스템**이에요. 실제 업무에 쓰지 않으므로 이곳에 들어오는 접속은 대부분 공격으로 볼 수 있어요. 공격자의 관심을 진짜 시스템에서 돌리고, 공격 수법을 기록·분석하는 데 써요. 허니팟 여러 대로 이루어진 네트워크를 **허니넷**(Honeynet)이라고 해요. 허니팟이 공격의 발판이 되지 않도록 다른 시스템과 철저히 분리해야 해요.

## 장비 한눈에 비교

| 장비 | 한 줄 요약 |
|---|---|
| 방화벽 | 규칙에 따라 IP·포트(또는 내용)를 보고 허용·차단 |
| IDS | 복사된 트래픽을 분석해 침입을 탐지하고 경보 |
| IPS | 인라인으로 설치해 침입을 탐지 즉시 차단 |
| UTM | 방화벽·IPS·백신·VPN 등을 한 장비로 통합 |
| WAF | HTTP 내용을 분석해 웹 공격(SQL 인젝션, XSS 등) 차단 |
| VPN 게이트웨이 | 인터넷 위에 암호화 터널 생성 |
| NAC | 접속하려는 단말의 인증과 보안 상태 검사 |
| SIEM | 여러 장비의 로그를 모아 상관 분석 |
| 허니팟 | 공격자를 유인하는 미끼 시스템 |

## 핵심 정리

- 패킷 필터링은 **헤더만**, 상태 기반 검사는 **상태 테이블로 연결 추적**, 응용 계층 게이트웨이는 **프록시로 7계층 내용 검사**, 회로 레벨 게이트웨이는 **세션 계층 중계**(SOCKS)예요.
- 배스천 호스트는 외부에 노출되는 강화된 호스트, 스크리닝 라우터는 패킷 필터링 라우터예요.
- 이중 홈 게이트웨이는 NIC 2개 호스트, 스크린드 호스트는 라우터 + 배스천 호스트, **스크린드 서브넷은 두 라우터 사이에 DMZ**를 두는 가장 안전한 구조예요.
- DMZ에는 웹·메일·DNS처럼 외부에 공개할 서버를 두고, DMZ에서 내부망으로 가는 연결은 원칙적으로 막아요.
- IDS는 **탐지·경보**(복사본 감시), IPS는 **인라인 차단**이에요. NIDS는 네트워크, HIDS는 호스트를 감시해요.
- 오용(시그니처) 탐지는 오탐이 적지만 새 공격에 약하고, 이상(행위) 탐지는 새 공격을 잡지만 오탐이 많아요.
- 오탐(False Positive)은 정상을 공격으로, 미탐(False Negative)은 공격을 정상으로 판단한 것이에요.
- UTM은 보안 기능 통합 장비, WAF는 웹 공격 전용 방화벽, NAC는 접속 전 단말 검사, SIEM은 로그 상관 분석, 허니팟은 미끼예요.

## 스스로 확인하기

**1.** 내부에서 시작된 연결을 테이블에 기록해 두었다가 그에 대한 응답 패킷만 자동으로 통과시키는 방화벽 방식은?
① 패킷 필터링 ② 상태 기반 검사 ③ 회로 레벨 게이트웨이 ④ 이중 홈 게이트웨이

> [!ANSWER]
> 정답: ②
> 상태 기반 검사 방화벽은 상태 테이블로 연결을 추적해요. 패킷 필터링은 패킷을 하나씩 따로 볼 뿐 연결 상태를 기억하지 않아요.

**2.** 외부 라우터와 내부 라우터 사이에 배스천 호스트가 있는 별도의 서브넷을 두어 내부망을 보호하는 구조는?
① 스크리닝 라우터 ② 이중 홈 게이트웨이 ③ 스크린드 호스트 게이트웨이 ④ 스크린드 서브넷 게이트웨이

> [!ANSWER]
> 정답: ④
> 두 라우터 사이의 서브넷이 DMZ 역할을 하는 스크린드 서브넷 구조예요. 보호 수준이 가장 높지만 구축 비용이 커요.

**3.** 이상 탐지(Anomaly Detection) 방식 침입 탐지 시스템의 특징으로 옳은 것은?
① 알려진 공격 패턴 데이터베이스와 비교한다 ② 오탐이 거의 없다 ③ 처음 보는 새로운 유형의 공격도 탐지할 수 있다 ④ 패턴 업데이트를 하지 않으면 동작하지 않는다

> [!ANSWER]
> 정답: ③
> 이상 탐지는 정상 상태에서 벗어난 행위를 찾으므로 새 공격도 잡을 수 있지만 오탐이 많아요. ①과 ④는 오용(시그니처) 탐지의 특징이에요.

**4.** 침입 탐지 시스템이 정상적인 백업 트래픽을 공격으로 판단해 경보를 울렸다. 이를 무엇이라 하는가?
① 정탐(True Positive) ② 오탐(False Positive) ③ 미탐(False Negative) ④ 정상(True Negative)

> [!ANSWER]
> 정답: ②
> 경보를 울렸으니 Positive, 그 판단이 틀렸으니 False예요. 공격을 놓친 경우가 미탐(False Negative)이에요.

**5.** 방화벽에서 443번 포트를 허용한 웹 서버에 SQL 인젝션 공격이 들어오고 있다. 이를 막는 데 가장 알맞은 장비는?
① WAF ② 스크리닝 라우터 ③ VPN 집중 장치 ④ 허니팟

> [!ANSWER]
> 정답: ①
> WAF는 HTTP·HTTPS 요청 내용을 분석해 SQL 인젝션 같은 웹 애플리케이션 공격을 차단해요.
