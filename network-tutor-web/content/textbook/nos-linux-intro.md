리눅스(Linux)는 웹 서버, 클라우드, 공유기, 스마트폰(안드로이드)까지 곳곳에서 돌아가는 운영체제예요. 이 단원에서는 리눅스가 어떻게 생겨났는지, 어떤 부품으로 이루어져 있는지, 디렉터리가 어떻게 배치되어 있는지, 그리고 전원을 켠 뒤 로그인 화면이 뜨기까지 무슨 일이 일어나는지를 배워요. 뒤에 이어지는 리눅스 단원들은 모두 이 지도 위에서 움직이니, 여기서 큰 그림을 단단히 잡아 두세요.

> [!GOAL]
> - 리눅스의 탄생 배경과 GPL·오픈 소스의 의미를 설명할 수 있다.
> - 커널·셸·유틸리티의 역할과 대표 배포판 계열을 구분할 수 있다.
> - 주요 디렉터리(/etc, /var, /dev, /proc 등)에 무엇이 들어 있는지 말할 수 있다.
> - 부팅 순서와 런레벨·systemd 타깃의 대응 관계를 외우고, 종료·재부팅 명령을 쓸 수 있다.

## 리눅스는 어떻게 태어났나

### 한 학생의 취미 프로젝트

1991년, 핀란드 헬싱키 대학의 학생이던 **리누스 토르발스**(Linus Torvalds)가 개인 컴퓨터에서 돌릴 운영체제의 핵심부, 즉 **커널**(Kernel)을 직접 만들어 인터넷에 공개했어요. 이것이 리눅스의 시작이에요. 리눅스는 당시 대학과 기업에서 널리 쓰이던 **유닉스**(UNIX)와 비슷하게 동작하도록 만들어졌기 때문에 "유닉스 계열(Unix-like) 운영체제"라고 불러요.

커널만으로는 컴퓨터를 쓸 수 없어요. 명령을 입력받는 프로그램, 파일을 복사하는 도구, 컴파일러 같은 것이 함께 있어야 하죠. 이 부분은 리처드 스톨먼(Richard Stallman)이 이끈 **GNU 프로젝트**가 이미 만들어 두고 있었어요. 그래서 리눅스 커널과 GNU 도구를 합친 전체 시스템을 "GNU/Linux"라고 부르기도 해요.

### GPL과 오픈 소스

리눅스 커널은 **GPL**(GNU General Public License)이라는 라이선스로 배포돼요. GPL의 핵심은 다음과 같아요.

- 누구나 무료로 사용하고, 소스 코드를 읽고, 고치고, 다시 배포할 수 있어요.
- 단, 고친 프로그램을 배포할 때는 **그 소스 코드도 같은 GPL 조건으로 공개**해야 해요. 자유를 물려받은 사람은 그 자유를 다음 사람에게도 넘겨야 한다는 뜻으로, 이런 방식을 **카피레프트**(Copyleft)라고 해요.

이처럼 소스 코드를 공개하고 여러 사람이 함께 고쳐 나가는 개발 방식을 **오픈 소스**(Open Source)라고 해요. 전 세계 개발자와 기업이 참여한 덕분에 리눅스는 빠르게 발전했어요.

### 리눅스의 특징

| 특징 | 뜻 |
|---|---|
| 다중 사용자(Multi-user) | 여러 사용자가 동시에 접속해 각자 작업할 수 있어요 |
| 다중 작업(Multitasking) | 여러 프로그램을 동시에 실행할 수 있어요 |
| 이식성(Portability) | 대부분 C 언어로 작성되어 다양한 하드웨어로 옮기기 쉬워요 |
| 강력한 네트워크 기능 | TCP/IP를 기본으로 지원하고 서버 프로그램이 풍부해요 |
| 계층형 파일 시스템 | 루트(/)에서 시작하는 하나의 나무 구조로 파일을 관리해요 |
| 공개·무료 | 소스 코드가 공개되어 있고 대부분의 배포판을 무료로 쓸 수 있어요 |

> [!EXAM]
> "리눅스의 특징으로 옳지 않은 것"을 고르는 문제가 자주 나와요. "단일 사용자 전용", "소스 코드 비공개", "특정 하드웨어에서만 동작" 같은 보기는 틀린 설명이에요. 리눅스 커널은 기능 대부분이 하나의 큰 커널 안에 들어 있는 **모놀리식(Monolithic) 커널**이면서, 필요한 드라이버를 **모듈**로 나중에 올렸다 내렸다 할 수 있다는 점도 알아 두세요.

## 리눅스의 구조: 커널, 셸, 유틸리티

리눅스는 여러 층이 쌓인 구조예요. 사용자가 맨 위에서 명령을 내리면, 그 명령이 아래층으로 전달되어 결국 하드웨어를 움직여요.

```text
        사용자
          |  명령 입력
+---------v------------------------+
| 유틸리티·응용 프로그램 (ls, vi)  |
+----------------------------------+
| 셸 (bash 등, 명령어 해석기)      |
+----------------------------------+
| 커널 (프로세스·메모리·파일·장치) |
+----------------------------------+
| 하드웨어 (CPU, 메모리, 디스크)   |
+----------------------------------+
```

| 구성 요소 | 하는 일 |
|---|---|
| 커널(Kernel) | 운영체제의 심장. 프로세스·메모리·파일 시스템·장치 드라이버·네트워크를 관리하고 하드웨어를 직접 다뤄요 |
| 셸(Shell) | 사용자가 입력한 명령을 해석해 커널에 전달하는 **명령어 해석기(Command Interpreter)**. 리눅스 기본 셸은 대부분 bash예요 |
| 유틸리티(Utility) | 파일 복사, 편집, 압축, 네트워크 점검처럼 실제 작업을 하는 프로그램들 |

커널 버전은 `uname -r`, 시스템 전체 정보는 `uname -a`로 확인해요. 운영체제와 커널의 일반적인 역할은 [운영체제와 네트워크 운영체제](/textbook/nos-os-basics)에서 이미 배웠고, 셸은 [vi 편집기와 셸](/textbook/nos-vi-shell)에서 자세히 배워요.

## 배포판

리눅스 커널에 GNU 도구, 설치 프로그램, 패키지 관리 도구, 기본 설정을 묶어 바로 설치해서 쓸 수 있게 만든 꾸러미를 **배포판**(Distribution)이라고 해요. 같은 커널을 쓰더라도 배포판마다 패키지 형식과 설정 파일 위치가 조금씩 달라요. 크게 두 계열만 기억하면 돼요.

| 계열 | 대표 배포판 | 패키지 형식 | 패키지 도구 |
|---|---|---|---|
| 레드햇(Red Hat) 계열 | RHEL(Red Hat Enterprise Linux), Fedora, CentOS, Rocky Linux, AlmaLinux | `.rpm` | `rpm`, `yum`, `dnf` |
| 데비안(Debian) 계열 | Debian, Ubuntu, Linux Mint | `.deb` | `dpkg`, `apt`(`apt-get`) |

- **RHEL**은 레드햇 사가 기술 지원을 붙여 판매하는 기업용 배포판이에요.
- **CentOS**는 RHEL과 거의 똑같이 만든 무료 배포판으로 서버에서 오랫동안 인기가 많았어요. 지금은 기존 CentOS Linux의 지원이 끝났고, 그 자리를 **Rocky Linux**, **AlmaLinux** 같은 RHEL 호환 배포판이 이어받았어요.
- **Ubuntu**는 데비안을 바탕으로 만든 배포판으로, 데스크톱과 클라우드 서버에서 많이 쓰여요.

> [!TIP]
> 시험 문제에는 레드햇 계열(CentOS 등)의 명령과 파일 경로가 자주 나와요. 이 교재는 레드햇 계열을 기준으로 설명하고, 데비안 계열과 다른 부분은 함께 적어 둘게요.

## 디렉터리 구조

### 하나의 나무, 루트(/)

Windows는 `C:`, `D:`처럼 드라이브마다 따로 시작점이 있지만, 리눅스는 모든 파일이 **루트**(/)라는 단 하나의 꼭대기에서 뻗어 나가요. 새 디스크나 USB 메모리를 꽂으면 나무의 한 가지(디렉터리)에 붙여서 쓰는데, 이것을 **마운트**(Mount)라고 해요.

어떤 디렉터리에 무엇을 둘지는 **FHS**(Filesystem Hierarchy Standard, 파일 시스템 계층 구조 표준)라는 약속으로 정해져 있어서, 배포판이 달라도 큰 틀은 같아요.

```text
/
├── bin   etc   home   root   var   tmp
├── usr   dev   proc   boot   lib   mnt   opt
└── ...
```

### 주요 디렉터리

| 디렉터리 | 들어 있는 것 | 예 |
|---|---|---|
| `/` | 루트 디렉터리. 모든 디렉터리의 시작점 | |
| `/bin` | 일반 사용자도 쓰는 기본 명령어 | `ls`, `cp`, `mv`, `cat` |
| `/sbin` | 시스템 관리용 명령어(주로 root가 사용) | `fdisk`, `mkfs`, `shutdown` |
| `/etc` | 시스템과 서비스의 **설정 파일** | `/etc/passwd`, `/etc/fstab`, `/etc/hosts` |
| `/home` | 일반 사용자의 홈 디렉터리 | `/home/minsu` |
| `/root` | 관리자(root)의 홈 디렉터리 | |
| `/var` | 내용이 자주 바뀌는 가변(variable) 데이터 | 메일 대기열, 캐시, 웹 문서 |
| `/var/log` | **로그 파일** | `/var/log/messages` |
| `/tmp` | 임시 파일. 누구나 쓸 수 있어요 | |
| `/usr` | 설치된 프로그램, 라이브러리, 문서 | `/usr/bin`, `/usr/share`, `/usr/local` |
| `/dev` | **장치 파일**(하드웨어를 파일처럼 표현) | `/dev/sda`, `/dev/null` |
| `/proc` | 커널과 프로세스 정보를 보여 주는 **가상 파일 시스템** | `/proc/cpuinfo`, `/proc/meminfo` |
| `/boot` | 부팅에 필요한 커널 이미지와 부트로더 파일 | `vmlinuz-...`, `grub2/` |
| `/lib` | 공유 라이브러리와 커널 모듈 | `/lib/modules` |
| `/mnt` | 관리자가 임시로 마운트할 때 쓰는 자리 | |
| `/opt` | 따로 설치하는 추가 응용 프로그램 | |

몇 가지는 꼭 짚고 넘어가요.

- `/root`와 `/`는 달라요. `/`는 나무 전체의 꼭대기이고, `/root`는 관리자 계정의 홈 디렉터리예요.
- `/proc`의 파일들은 디스크에 저장된 것이 아니라, 읽는 순간 커널이 메모리의 정보를 만들어 보여 주는 거예요. 그래서 대부분 크기가 0으로 표시돼요.
- `/dev`에는 장치가 파일 모양으로 있어요. 예를 들어 `/dev/null`은 넣는 것을 모두 버리는 "블랙홀" 장치예요.
- 이동식 미디어는 보통 `/media` 아래에 자동으로 마운트되고, `/mnt`는 관리자가 손으로 마운트할 때 많이 써요.

> [!NOTE]
> 최근 배포판(RHEL 7 이후, 최신 Debian·Ubuntu 등)은 `/bin`, `/sbin`, `/lib`의 실제 내용을 `/usr/bin`, `/usr/sbin`, `/usr/lib`로 합치고, 원래 자리에는 그곳을 가리키는 링크만 남겨 두었어요. 그래도 시험에서는 표에 정리한 전통적인 역할로 물어봐요.

> [!EXAM]
> "설정 파일은 어디에?" → `/etc`, "로그는?" → `/var/log`, "장치 파일은?" → `/dev`, "커널 이미지는?" → `/boot`, "CPU·메모리 정보를 담은 가상 파일 시스템은?" → `/proc`. 디렉터리와 역할을 짝지어 묻는 문제가 거의 매번 나와요.

## 부팅 과정

전원 버튼을 누르고 로그인 화면이 나타나기까지는 바통 터치하듯 단계가 이어져요.

```text
[전원 ON]
   |
[1] BIOS / UEFI  : POST(하드웨어 점검), 부팅 장치 선택
   |
[2] 부트로더 GRUB2 : 커널 선택 메뉴, 커널을 메모리에 올림
   |
[3] 커널          : 하드웨어 인식, 루트 파일 시스템 마운트
   |
[4] systemd(PID 1): 서비스 시작, 목표 타깃 도달
   |
[로그인 화면]
```

1. **BIOS 또는 UEFI** — 메인보드에 들어 있는 펌웨어예요. 먼저 **POST**(Power-On Self Test)로 CPU, 메모리 같은 하드웨어를 점검하고, 설정된 순서대로 부팅할 장치를 찾아요. 예전 방식인 BIOS는 디스크 맨 앞의 **MBR**(Master Boot Record, 512바이트)에서 부트로더를 읽고, 요즘 방식인 UEFI는 디스크의 EFI 시스템 파티션에 있는 부트로더 파일을 실행해요.
2. **부트로더 GRUB2(GRand Unified Bootloader 2)** — 어떤 커널로 부팅할지 메뉴를 보여 주고, 고른 커널과 초기 램 디스크(initramfs)를 메모리에 올려요. 옛날에는 LILO라는 부트로더도 쓰였지만 지금은 GRUB2가 표준이에요.
3. **커널 초기화** — 커널이 하드웨어를 인식하고 드라이버를 올린 뒤 루트 파일 시스템(/)을 마운트해요.
4. **첫 번째 프로세스 실행** — 커널은 **PID 1**번 프로세스를 실행해요. 예전에는 **init(SysV init)**, 지금 대부분의 배포판에서는 **systemd**예요. 이 프로세스가 네트워크, 로그, 웹 서버 같은 서비스를 차례로 띄우고 로그인 화면을 준비해요.

> [!NOTE]
> GRUB2 설정은 `/etc/default/grub`을 고친 뒤 설정 파일을 다시 만드는 방식으로 바꿔요. 레드햇 계열은 `grub2-mkconfig -o /boot/grub2/grub.cfg`, 데비안 계열은 `update-grub` 명령을 써요. 부팅 중 커널이 남긴 메시지는 `dmesg` 명령으로 볼 수 있어요.

## 런레벨과 systemd 타깃

### SysV init의 런레벨

예전 init 방식에서는 시스템이 어떤 상태로 동작할지를 0~6의 숫자, **런레벨**(Runlevel)로 정했어요. 기본 런레벨은 `/etc/inittab` 파일에 적었어요.

| 런레벨 | 의미 (레드햇 계열 기준) |
|---|---|
| 0 | 시스템 종료(halt) |
| 1 | 단일 사용자 모드(Single User Mode). root만 쓰는 복구용 모드 |
| 2 | 다중 사용자 모드, 네트워크 파일 공유(NFS) 없음 |
| 3 | 다중 사용자 모드, 텍스트(CLI) 환경. 서버의 일반적인 상태 |
| 4 | 사용하지 않음(사용자 정의용 예약) |
| 5 | 다중 사용자 모드, 그래픽(GUI) 환경 |
| 6 | 재부팅 |

### systemd의 타깃

systemd는 숫자 대신 이름이 붙은 **타깃**(Target)으로 시스템 상태를 표현해요. 옛 런레벨과는 다음처럼 대응돼요.

| 런레벨 | systemd 타깃 | 상태 |
|---|---|---|
| 0 | `poweroff.target` | 전원 끄기 |
| 1 | `rescue.target` | 복구(단일 사용자) 모드 |
| 2, 3, 4 | `multi-user.target` | 텍스트 다중 사용자 모드 |
| 5 | `graphical.target` | 그래픽 다중 사용자 모드 |
| 6 | `reboot.target` | 재부팅 |

`rescue.target`보다 더 적은 것만 띄우는 `emergency.target`도 있어요. 또 `runlevel3.target`처럼 옛 이름으로 된 별칭도 남아 있어서, 예전 습관대로 써도 대부분 통해요.

```bash
systemctl get-default                       # 기본 타깃 확인
systemctl set-default multi-user.target     # 다음 부팅부터 텍스트 모드로
systemctl isolate graphical.target          # 지금 바로 그래픽 모드로 전환
runlevel                                    # 이전·현재 런레벨 출력 (예: N 3)
init 3                                      # 옛 방식으로 런레벨 3 전환
```

> [!EXAM]
> 숫자와 의미를 짝짓는 문제가 단골이에요. **0 = 종료, 1 = 단일 사용자(복구), 3 = 텍스트 다중 사용자, 5 = 그래픽, 6 = 재부팅**. 그리고 3은 `multi-user.target`, 5는 `graphical.target`과 연결해 두세요. `init 0`은 종료, `init 6`은 재부팅이에요.

> [!WARNING]
> `systemctl set-default`는 "다음 부팅부터"의 기본값을 바꾸고, `systemctl isolate`는 "지금 당장" 전환해요. 둘을 헷갈리지 마세요.

## 종료와 재부팅

리눅스 서버는 여러 사람이 동시에 쓰고 있을 수 있어서, 전원을 바로 끄지 않고 명령으로 정리 작업을 한 뒤 종료해요.

| 명령 | 동작 |
|---|---|
| `shutdown -h now` | 지금 바로 종료 |
| `shutdown -r now` | 지금 바로 재부팅 |
| `shutdown -h +10 "점검으로 10분 뒤 종료합니다"` | 10분 뒤 종료하고 접속자에게 메시지 알림 |
| `shutdown -h 23:00` | 23시에 종료 예약 |
| `shutdown -c` | 예약된 종료 취소 |
| `poweroff` / `systemctl poweroff` / `init 0` | 종료 |
| `reboot` / `systemctl reboot` / `init 6` | 재부팅 |
| `halt` | 시스템 정지(전원은 꺼지지 않을 수 있어요) |

`shutdown`의 `-h`는 halt(멈춤), `-r`은 reboot(다시 시작)의 머리글자예요. 시간 자리에는 `now`, `+분`, `시:분` 형식을 써요.

## 가상 콘솔과 로그인

### 가상 콘솔

모니터와 키보드는 하나뿐이지만, 리눅스는 그 위에 서로 독립된 로그인 화면 여러 개를 띄워 둘 수 있어요. 이것을 **가상 콘솔**(Virtual Console)이라고 해요. 기본으로 6개 정도가 준비되어 있고, 장치 이름은 `/dev/tty1`, `/dev/tty2`처럼 붙어요.

- 그래픽 화면에서 텍스트 콘솔로 가려면 `Ctrl + Alt + F1` ~ `F6`
- 텍스트 콘솔끼리 오갈 때는 `Alt + F1` ~ `F6`도 쓸 수 있어요.
- 그래픽 화면이 몇 번 콘솔에 붙는지는 배포판마다 달라요(예전에는 F7, 요즘은 F1이나 F2인 경우가 많아요).

지금 내가 어느 터미널에 있는지는 `tty` 명령으로 확인해요.

### 로그인과 프롬프트

로그인할 때 비밀번호를 입력해도 화면에는 아무것도 표시되지 않아요. 고장이 아니라 보안을 위한 동작이에요. 로그인에 성공하면 이런 **프롬프트**(Prompt)가 나타나요.

```text
[minsu@web01 ~]$      ← 일반 사용자 (끝이 $)
[root@web01 ~]#       ← 관리자 root (끝이 #)
```

`사용자@호스트이름 현재디렉터리` 순서이고, `~`는 홈 디렉터리를 뜻해요. **root**는 모든 권한을 가진 관리자(슈퍼유저, Superuser) 계정으로, 사용자 번호(UID)가 0이에요.

| 명령 | 하는 일 |
|---|---|
| `whoami` | 지금 내 사용자 이름 |
| `who` | 현재 로그인한 사용자 목록 |
| `w` | 로그인한 사용자와 각자 하는 작업 |
| `last` | 최근 로그인 기록 |
| `exit` / `logout` | 로그아웃 |

멀리 있는 서버에는 SSH로 원격 로그인하는데, 이것은 [리눅스 네트워크 설정과 서버](/textbook/nos-linux-network-servers)에서 다뤄요.

## 핵심 정리

- 리눅스는 1991년 리누스 토르발스가 만든 유닉스 계열 커널에서 출발했고, GPL 라이선스로 소스 코드가 공개된 오픈 소스예요.
- GPL: 자유롭게 사용·수정·배포할 수 있지만, 수정본을 배포하면 소스도 같은 조건으로 공개해야 해요.
- 구조: 하드웨어 ← **커널**(자원 관리) ← **셸**(명령 해석기) ← **유틸리티**.
- 배포판 두 계열: 레드햇(RHEL·CentOS·Rocky, `.rpm`, `dnf`/`yum`) / 데비안(Debian·Ubuntu, `.deb`, `apt`).
- 설정 `/etc`, 로그 `/var/log`, 장치 `/dev`, 가상 정보 `/proc`, 커널 `/boot`, 사용자 홈 `/home`, 관리자 홈 `/root`, 임시 `/tmp`.
- 부팅: BIOS/UEFI(POST) → GRUB2 → 커널 → systemd(PID 1, 예전 init).
- 런레벨 0 종료, 1 단일 사용자, 3 텍스트 다중 사용자(`multi-user.target`), 5 그래픽(`graphical.target`), 6 재부팅.
- `shutdown -h now` 종료, `shutdown -r now` 재부팅, `shutdown -c` 예약 취소.
- 프롬프트 `$`는 일반 사용자, `#`은 root.

## 스스로 확인하기

**1.** 다음 중 GPL 라이선스에 대한 설명으로 옳은 것은?
① 소스 코드를 수정하면 배포할 수 없다 ② 수정한 프로그램을 배포할 때 소스 코드도 같은 조건으로 공개해야 한다 ③ 상업적으로 판매하는 것은 금지된다 ④ 소스 코드는 개발자만 볼 수 있다

> [!ANSWER]
> 정답: ②
> GPL은 사용·수정·배포의 자유를 주는 대신, 수정본을 배포할 때 소스 코드도 GPL로 공개하도록 요구해요(카피레프트). 판매 자체를 막지는 않아요.

**2.** 웹 서버 관리자인 지우는 서비스의 설정 파일과, 접속 기록이 쌓이는 로그 파일을 찾으려고 해요. 각각 찾아볼 디렉터리를 순서대로 고르면?
① `/usr`, `/tmp` ② `/etc`, `/var/log` ③ `/boot`, `/proc` ④ `/dev`, `/opt`

> [!ANSWER]
> 정답: ②
> 시스템과 서비스의 설정 파일은 `/etc`에, 로그 파일은 `/var/log`에 모여 있어요.

**3.** systemd를 쓰는 서버를 다음 부팅부터 그래픽 화면 없이 텍스트 다중 사용자 모드로 시작하게 하려면 어떤 명령을 써야 할까요?
① `systemctl set-default multi-user.target` ② `systemctl isolate rescue.target` ③ `systemctl set-default graphical.target` ④ `init 6`

> [!ANSWER]
> 정답: ①
> 기본 타깃을 바꾸는 것은 `set-default`이고, 텍스트 다중 사용자 모드(옛 런레벨 3)는 `multi-user.target`이에요. `isolate`는 지금 바로 전환하는 명령이고, `init 6`은 재부팅이에요.

**4.** 커널 정보와 프로세스 정보를 파일 형태로 보여 주지만 실제 디스크에는 저장되지 않는 가상 파일 시스템이 연결된 디렉터리는?
① `/dev` ② `/var` ③ `/proc` ④ `/mnt`

> [!ANSWER]
> 정답: ③
> `/proc`은 커널이 메모리의 정보를 읽을 때마다 만들어 보여 주는 가상 파일 시스템이에요. `/proc/cpuinfo`, `/proc/meminfo`가 대표적이에요.

**5.** 리눅스 부팅 과정을 순서대로 바르게 나열한 것은?
① GRUB2 → BIOS → 커널 → systemd ② BIOS → 커널 → GRUB2 → systemd ③ BIOS → GRUB2 → 커널 → systemd ④ systemd → BIOS → GRUB2 → 커널

> [!ANSWER]
> 정답: ③
> 펌웨어(BIOS/UEFI)가 하드웨어를 점검하고 부트로더(GRUB2)를 실행하면, 부트로더가 커널을 메모리에 올리고, 커널이 첫 프로세스인 systemd를 실행해요.
