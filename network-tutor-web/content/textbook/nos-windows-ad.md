직원이 수백 명인 회사에서 PC마다 계정을 따로 만들고 암호 규칙을 하나하나 설정한다면 관리자는 하루 종일 같은 일만 반복하게 될 거예요. Active Directory는 계정, 컴퓨터, 보안 정책을 한곳에 모아 관리하게 해 주는 Windows Server의 디렉터리 서비스예요. 이 단원에서는 AD의 구조와 구성 요소, 그룹을 쓰는 원칙, 그룹 정책이 적용되는 순서, 그리고 AD를 떠받치는 Kerberos와 DNS를 배워요.

> [!GOAL]
> - 작업 그룹과 도메인의 차이를 설명할 수 있다
> - 도메인·트리·포리스트·OU·사이트와 도메인 컨트롤러, 글로벌 카탈로그의 역할을 구분할 수 있다
> - 그룹의 종류와 범위를 구분하고 AGDLP 원칙을 적용할 수 있다
> - 그룹 정책의 적용 순서(LSDOU)와 관련 명령, AD가 Kerberos와 DNS에 의존하는 이유를 설명할 수 있다

## 작업 그룹과 도메인

작업 그룹은 각자 자기 방 열쇠를 들고 다니는 셰어하우스와 비슷해요. 다른 방에 들어가려면 그 방 주인에게 따로 열쇠를 받아야 해요. 도메인은 회사 건물과 비슷해요. 관리실에서 출입증 하나를 발급받으면 권한이 있는 모든 문을 그 출입증으로 열 수 있어요.

| 구분 | 작업 그룹(Workgroup) | 도메인(Domain) |
|---|---|---|
| 구조 | P2P, 모든 컴퓨터가 동등 | 클라이언트-서버, 도메인 컨트롤러가 중앙 관리 |
| 계정 저장 위치 | 컴퓨터마다 로컬 SAM(Security Accounts Manager) 데이터베이스 | 도메인 컨트롤러의 AD 데이터베이스 |
| 로그온 | 컴퓨터마다 그 컴퓨터의 계정으로 | 도메인 계정 하나로 가입된 어느 PC에서나 |
| 알맞은 규모 | 소규모(대략 10~20대 이하) | 수십 대부터 수만 대까지 |
| 필요한 것 | 없음 | Windows Server 도메인 컨트롤러, DNS |
| 정책 적용 | PC마다 로컬 정책 | 그룹 정책으로 한 번에 |

한 번 로그온하면 다시 암호를 묻지 않고 여러 서버 자원을 쓰는 것을 SSO(Single Sign-On, 통합 인증)라고 해요. 도메인의 큰 장점이에요.

> [!NOTE]
> Windows의 Home 에디션은 도메인에 가입할 수 없어요. 회사 PC에 Pro 이상 에디션을 쓰는 이유 중 하나예요.

## Active Directory의 기본 개념

디렉터리 서비스(Directory Service)는 네트워크에 있는 사용자, 컴퓨터, 프린터 같은 자원의 정보를 저장하고 필요할 때 찾아 주는 서비스예요. 잘 정리된 회사 전화번호부를 떠올리면 돼요. Windows Server에서는 AD DS(Active Directory Domain Services, Active Directory 도메인 서비스) 역할이 이 일을 해요.

- 개체(Object): AD에 저장되는 하나하나의 항목이에요. 사용자, 그룹, 컴퓨터, 프린터, 공유 폴더, 연락처, OU가 모두 개체예요.
- 특성(Attribute): 개체가 가진 정보예요. 사용자라면 이름, 부서, 전화번호, 이메일 같은 것이에요.
- 스키마(Schema): 어떤 종류의 개체와 특성이 있을 수 있는지 정의한 설계도예요. 포리스트 전체가 스키마 하나를 공유해요.
- LDAP(Lightweight Directory Access Protocol): 디렉터리를 조회하고 수정할 때 쓰는 프로토콜이에요. 포트는 389(SSL을 쓰는 LDAPS는 636)예요.

AD 데이터베이스는 도메인 컨트롤러의 `NTDS.DIT` 파일(기본 위치 `C:\Windows\NTDS`)에 저장돼요. 그룹 정책 파일과 로그온 스크립트는 SYSVOL이라는 공유 폴더에 저장되어 모든 도메인 컨트롤러에 복제돼요.

사용자가 도메인에 로그온할 때는 두 가지 형식의 이름을 쓸 수 있어요.

| 형식 | 예 |
|---|---|
| UPN(User Principal Name, 사용자 계정 이름) | `minsu@hanbit.example.com` |
| 이전 형식(Windows 2000 이전 이름) | `HANBIT\minsu` |

## 논리 구조: 도메인, 트리, 포리스트, OU

### 도메인

도메인(Domain)은 AD의 기본 관리 단위예요. 같은 도메인의 계정과 정책은 그 도메인의 모든 도메인 컨트롤러가 똑같이 나눠 가져요. 도메인 이름은 `hanbit.example.com`처럼 DNS 이름을 그대로 써요.

### 트리와 포리스트

- 트리(Tree): 이름이 이어지는 도메인들의 계층이에요. `hanbit.example.com` 아래에 `sales.hanbit.example.com`, `dev.hanbit.example.com` 같은 자식 도메인을 두면 하나의 트리가 돼요.
- 포리스트(Forest): 트리 하나 이상의 묶음이에요. 처음 만든 도메인이 포리스트 루트 도메인(Forest Root Domain)이 돼요. 같은 포리스트의 모든 도메인은 스키마, 구성 정보, 글로벌 카탈로그를 공유하고 서로 자동으로 신뢰해요. 포리스트는 AD의 가장 바깥 보안 경계예요.

```text
포리스트
 +-- 트리 1: hanbit.example.com (포리스트 루트)
 |     +-- sales.hanbit.example.com
 |     +-- dev.hanbit.example.com
 +-- 트리 2: lab.example.org
```

이름이 전혀 다른 `lab.example.org`도 같은 포리스트에 들어올 수 있어요. 이름이 이어지지 않으니 별도의 트리가 되는 거예요.

### OU

OU(Organizational Unit, 조직 구성 단위)는 도메인 안에서 개체를 부서나 지역별로 묶는 폴더 같은 컨테이너예요. OU 안에 OU를 넣을 수 있고, 두 가지 중요한 쓰임이 있어요.

- 그룹 정책(GPO)을 연결하는 단위
- 관리 권한 위임(Delegation)의 단위. 예를 들어 '영업부 OU의 암호 재설정만 영업팀장에게 맡기기'가 가능해요.

> [!WARNING]
> AD를 처음 만들면 보이는 'Users'와 'Computers'는 OU가 아니라 일반 컨테이너(Container)예요. 여기에는 그룹 정책을 직접 연결할 수 없어요. 정책을 적용하려면 OU를 만들어 개체를 옮겨야 해요.

> [!TIP]
> OU와 그룹을 헷갈리지 마세요. OU는 관리와 정책 적용을 위한 '서랍'이고, 그룹은 권한을 주기 위한 '명단'이에요. 공유 폴더 권한은 OU가 아니라 그룹이나 사용자에게 줘요.

## 물리 구조: 사이트와 도메인 컨트롤러

### 사이트

사이트(Site)는 빠른 네트워크로 잘 연결된 IP 서브넷들의 묶음이에요. 보통 본사, 부산 지사처럼 물리적인 사무실 하나가 사이트 하나가 돼요. 사이트를 나눠 두면 사용자는 같은 사이트의 도메인 컨트롤러에서 먼저 로그온하고, 사이트 사이의 느린 WAN 구간에서는 복제 시간과 빈도를 조절할 수 있어요. 도메인은 논리 구조, 사이트는 물리 구조라서 서로 독립적이에요.

### 도메인 컨트롤러

도메인 컨트롤러(DC, Domain Controller)는 AD DS 역할을 설치하고 도메인 컨트롤러로 '승격(Promote)'한 서버예요. AD 데이터베이스 사본을 가지고 로그온 인증을 처리해요.

- 다중 마스터 복제(Multi-master Replication): 어느 DC에서 바꾼 내용이든 다른 DC로 복제돼요. 한 대가 고장 나도 인증이 멈추지 않도록 DC는 최소 2대를 권장해요.
- RODC(Read-Only Domain Controller, 읽기 전용 도메인 컨트롤러): 물리 보안이 약한 지사에 두는, 읽기만 가능한 DC예요.
- 멤버 서버(Member Server): 도메인에 가입했지만 DC는 아닌 서버예요.

승격은 서버 관리자에서 AD DS 역할을 설치한 뒤 알림에 나오는 '이 서버를 도메인 컨트롤러로 승격'을 눌러 진행해요. 예전에 쓰던 `dcpromo` 명령은 Windows Server 2012부터 이 방식으로 바뀌었어요. PowerShell로는 다음처럼 새 포리스트를 만들어요.

```powershell
Install-WindowsFeature -Name AD-Domain-Services -IncludeManagementTools
Install-ADDSForest -DomainName "hanbit.example.com" -InstallDns
```

### 글로벌 카탈로그

글로벌 카탈로그(GC, Global Catalog)는 포리스트 안 모든 도메인 개체의 '요약본'(자주 찾는 일부 특성만)을 가진 DC예요. 포리스트 전체를 검색할 때, UPN으로 로그온할 때, 로그온하는 사용자가 속한 유니버설 그룹을 확인할 때 쓰여요. 포리스트의 첫 번째 DC는 자동으로 글로벌 카탈로그가 되고, 포트는 TCP 3268(SSL은 3269)이에요.

### FSMO 역할

AD는 다중 마스터 방식이지만 동시에 두 곳에서 처리하면 충돌하는 일부 작업은 정해진 DC 한 대만 맡아요. 이를 FSMO(Flexible Single Master Operations, 작업 마스터) 역할이라고 해요.

| 범위 | 역할 | 하는 일 |
|---|---|---|
| 포리스트당 1개 | 스키마 마스터(Schema Master) | 스키마 변경 처리 |
| 포리스트당 1개 | 도메인 명명 마스터(Domain Naming Master) | 포리스트에 도메인 추가·제거 |
| 도메인당 1개 | RID 마스터(RID Master) | 개체의 보안 식별자(SID)를 만들 때 쓰는 RID 묶음을 각 DC에 나눠 줌 |
| 도메인당 1개 | PDC 에뮬레이터(PDC Emulator) | 도메인 시간 동기화의 기준, 암호 변경과 계정 잠금 우선 처리 |
| 도메인당 1개 | 인프라 마스터(Infrastructure Master) | 다른 도메인 개체를 가리키는 참조 정보 갱신 |

> [!TIP]
> "포리스트 2개(스키마, 도메인 명명) + 도메인 3개(RID, PDC, 인프라) = 5개"로 외우세요. 어느 DC가 맡고 있는지는 `netdom query fsmo`로 확인해요.

### 트러스트

트러스트(Trust, 신뢰 관계)는 한 도메인의 사용자가 다른 도메인의 자원을 쓸 수 있게 해 주는 인증 연결이에요. 자원을 가진 쪽이 신뢰하는 도메인(Trusting), 계정을 가진 쪽이 신뢰받는 도메인(Trusted)이에요.

- 방향: 단방향 또는 양방향
- 전이성: 전이적(Transitive)이면 A가 B를, B가 C를 신뢰할 때 A도 C를 신뢰해요. 비전이적이면 직접 맺은 상대만 신뢰해요.
- 같은 포리스트 안의 도메인끼리는 자동으로 양방향·전이적 트러스트가 만들어져요.
- 직접 만드는 트러스트에는 외부(External, 다른 포리스트의 특정 도메인, 비전이적), 포리스트(Forest, 두 포리스트 사이), 바로 가기(Shortcut, 같은 포리스트 안에서 인증 경로 단축), 영역(Realm, Windows가 아닌 Kerberos 영역과 연결) 트러스트가 있어요.

## 사용자 계정과 그룹

### 사용자 계정

계정은 각 컴퓨터에만 있는 로컬 계정과 AD에 저장되는 도메인 계정으로 나뉘어요. 기본으로 만들어지는 Administrator 계정은 공격 대상이 되기 쉬워서 이름을 바꾸기도 하고, Guest 계정은 기본적으로 사용 안 함 상태예요.

도메인 계정의 암호 규칙은 도메인에 연결된 기본 GPO(Default Domain Policy)에서 정해요. 기본값으로 암호 복잡성이 켜져 있는데, 대문자·소문자·숫자·특수 문자 중 세 종류 이상을 섞어야 하고 계정 이름을 포함하면 안 돼요. 최소 길이 기본값은 7자예요.

### 그룹의 종류

| 종류 | 용도 |
|---|---|
| 보안 그룹(Security Group) | 공유 폴더, 프린터 등의 권한을 줄 때 사용. 메일 배포 목록으로도 쓸 수 있음 |
| 배포 그룹(Distribution Group) | 이메일 배포 목록 전용. 권한을 줄 수 없음 |

### 그룹의 범위

| 범위 | 구성원으로 넣을 수 있는 것 | 권한을 줄 수 있는 곳 |
|---|---|---|
| 도메인 로컬(Domain Local) | 어느 도메인(신뢰 도메인 포함)의 사용자·글로벌 그룹이든, 같은 포리스트의 유니버설 그룹, 같은 도메인의 도메인 로컬 그룹 | 그 그룹이 속한 도메인의 자원 |
| 글로벌(Global) | 같은 도메인의 사용자와 글로벌 그룹 | 포리스트와 신뢰 관계에 있는 모든 도메인 |
| 유니버설(Universal) | 포리스트 내 모든 도메인의 사용자·글로벌 그룹·유니버설 그룹 | 포리스트의 모든 도메인 |

유니버설 그룹의 구성원 목록은 글로벌 카탈로그에 저장되므로, 구성원이 자주 바뀌면 포리스트 전체의 복제 부담이 커져요.

### AGDLP 원칙

권한을 사용자 한 명 한 명에게 직접 주면 사람이 바뀔 때마다 모든 자원을 찾아다니며 고쳐야 해요. 그래서 다음 순서로 권한을 연결하는 것을 권장해요.

- A(Accounts): 사용자 계정을
- G(Global groups): 역할별 글로벌 그룹에 넣고
- DL(Domain Local groups): 그 글로벌 그룹을 자원별 도메인 로컬 그룹에 넣은 다음
- P(Permissions): 도메인 로컬 그룹에 권한을 줘요.

예를 들어 영업부 직원들을 `G_영업부` 글로벌 그룹에 넣고, `G_영업부`를 `DL_영업자료_수정` 도메인 로컬 그룹에 넣은 뒤, 공유 폴더 '영업자료'에 `DL_영업자료_수정` 그룹으로 '수정' 권한을 줘요. 신입 사원이 오면 `G_영업부`에만 넣으면 되고, 자료 폴더가 늘어나면 도메인 로컬 그룹만 연결하면 돼요. 도메인이 여러 개인 포리스트에서는 중간에 유니버설 그룹을 끼워 AGUDLP로 확장해요.

## 그룹 정책

### GPO의 구성

그룹 정책(Group Policy)은 사용자와 컴퓨터의 설정을 중앙에서 한 번에 적용하는 기능이에요. 암호 규칙, USB 사용 금지, 바탕 화면 고정, 프로그램 배포, 로그온 스크립트 같은 설정을 묶은 것을 GPO(Group Policy Object, 그룹 정책 개체)라고 하고, GPO를 사이트·도메인·OU에 연결(Link)해서 적용해요.

- 컴퓨터 구성(Computer Configuration): 컴퓨터가 시작될 때 적용
- 사용자 구성(User Configuration): 사용자가 로그온할 때 적용

도메인을 만들면 기본 GPO 두 개가 생겨요. Default Domain Policy는 도메인에 연결되어 암호·계정 잠금·Kerberos 정책을 담고, Default Domain Controllers Policy는 Domain Controllers OU에 연결돼요. GPO는 그룹 정책 관리 콘솔(`gpmc.msc`)에서 만들고 연결하며, 한 컴퓨터에만 적용되는 로컬 정책은 `gpedit.msc`로 편집해요.

### 적용 순서 LSDOU

GPO는 다음 순서로 적용돼요.

1. 로컬(Local) 정책
2. 사이트(Site)에 연결된 GPO
3. 도메인(Domain)에 연결된 GPO
4. OU에 연결된 GPO(상위 OU부터 하위 OU 순서로)

설정이 서로 부딪히면 나중에 적용된 것이 이겨요. 즉, 사용자나 컴퓨터가 들어 있는 OU에 가장 가까운 GPO가 최종적으로 우선해요. 같은 위치에 GPO가 여러 개 연결되어 있으면 연결 순서(Link Order) 숫자가 작은 GPO가 우선해요.

- 상속 차단(Block Inheritance): OU에서 위쪽 GPO를 물려받지 않게 막아요.
- 강제(Enforced): 해당 GPO의 설정이 아래쪽에서 덮어쓰이거나 상속 차단으로 막히지 않게 해요. 강제가 상속 차단보다 우선해요.
- 보안 필터링: 특정 그룹에만 GPO가 적용되게 걸러요.

> [!EXAM]
> 적용 순서 L → S → D → OU와 "나중에 적용된 것이 우선"을 함께 기억하세요. 보기에 "도메인 GPO가 OU GPO보다 우선한다"가 나오면 틀린 말이에요(강제 설정이 없는 경우).

### 적용 시점과 관련 명령

그룹 정책은 컴퓨터 시작과 사용자 로그온 때 적용되고, 그 뒤로는 백그라운드에서 약 90분마다(0~30분 사이의 무작위 지연 포함) 새로 고쳐져요. 도메인 컨트롤러는 5분마다 새로 고쳐요. 바꾼 정책을 바로 확인하고 싶을 때는 명령을 써요.

| 명령 | 하는 일 |
|---|---|
| `gpupdate` | 바뀐 정책만 지금 적용 |
| `gpupdate /force` | 바뀌지 않은 것까지 모든 정책을 다시 적용 |
| `gpupdate /target:computer` | 컴퓨터 구성만 적용(`user`면 사용자 구성만) |
| `gpresult /r` | 실제로 적용된 GPO 목록 요약(RSoP, 결과 정책 집합) |
| `gpresult /h report.html` | 적용 결과를 HTML 보고서로 저장 |

```text
C:\> gpupdate /force
정책을 업데이트하는 중...

컴퓨터 정책 업데이트를 완료했습니다.
사용자 정책 업데이트를 완료했습니다.
```

소프트웨어 설치나 폴더 리디렉션 같은 일부 정책은 다시 시작하거나 다시 로그온해야 적용돼요. PowerShell의 `Invoke-GPUpdate`를 쓰면 다른 컴퓨터의 정책 새로 고침도 원격으로 시킬 수 있어요.

## Kerberos 인증

Kerberos는 Windows 2000부터 도메인의 기본 인증 프로토콜이에요. 모든 도메인 컨트롤러에서 KDC(Key Distribution Center, 키 배포 센터) 서비스가 돌아가요. 놀이공원에 비유하면, 입구에서 신분 확인 후 자유이용권(TGT)을 받고, 놀이기구마다 그 자유이용권을 보여 주고 탑승권(서비스 티켓)을 받는 방식이에요.

1. 로그온할 때 KDC에 신원을 증명하고 TGT(Ticket Granting Ticket, 티켓 발급 티켓)를 받아요.
2. 파일 서버 같은 자원에 접근할 때 TGT를 KDC에 보여 주고 그 서버용 서비스 티켓을 받아요.
3. 서비스 티켓을 파일 서버에 제시해서 접근해요. 암호를 네트워크로 다시 보내지 않아요.

- 포트: TCP/UDP 88
- 시간에 민감해요. 클라이언트와 DC의 시계가 기본 5분 넘게 차이 나면 인증이 실패해요. 그래서 도메인 컴퓨터들은 PDC 에뮬레이터를 기준으로 시간을 맞춰요.
- 작업 그룹 환경이나 IP 주소로 직접 접속하는 경우처럼 Kerberos를 쓸 수 없을 때는 예전 방식인 NTLM으로 인증해요.
- 받은 티켓 목록은 `klist` 명령으로 볼 수 있어요.

## AD와 DNS

AD는 DNS 없이는 동작하지 않아요. 도메인 이름 자체가 DNS 이름이고, 클라이언트는 DNS에 질의해서 도메인 컨트롤러의 위치를 찾아요. 이때 쓰는 것이 서비스 위치를 알려 주는 SRV 레코드예요(예: `_ldap._tcp.dc._msdcs.hanbit.example.com`). DC는 시작할 때 이런 SRV 레코드를 DNS에 자동으로 등록해요.

- DC로 승격할 때 DNS 서버 역할을 함께 설치하는 것이 기본 선택이고, 영역은 보통 AD 통합 영역으로 만들어요. DNS 영역의 종류는 [Windows 네트워크 서비스](/textbook/nos-windows-network-services)에서 다뤄요.
- 도메인에 가입할 PC의 DNS 서버 설정은 반드시 사내 AD DNS 서버(예: 192.168.10.10)로 해야 해요. 인터넷 공용 DNS를 지정하면 DC를 찾지 못해 도메인 가입과 로그온이 실패해요. 외부 인터넷 이름은 AD DNS 서버의 전달자(Forwarder) 설정으로 해결해요.
- 문제를 진단할 때는 `nslookup -type=srv _ldap._tcp.dc._msdcs.hanbit.example.com`으로 SRV 레코드를 확인하고, `dcdiag`로 DC 상태를 점검해요.

| 서비스 | 포트 |
|---|---|
| DNS | 53 |
| Kerberos | 88 |
| LDAP / LDAPS | 389 / 636 |
| 글로벌 카탈로그 | 3268 / 3269 |
| SMB(SYSVOL 접근) | 445 |

## 핵심 정리

- 작업 그룹은 P2P·로컬 SAM 기반이고, 도메인은 도메인 컨트롤러가 계정과 정책을 중앙 관리해요.
- 도메인은 기본 관리 단위, 트리는 이름이 이어지는 도메인 계층, 포리스트는 트리의 묶음이자 스키마를 공유하는 보안 경계예요.
- OU는 그룹 정책 연결과 관리 위임의 단위예요. 기본 Users·Computers 컨테이너는 OU가 아니에요.
- 사이트는 빠르게 연결된 서브넷의 묶음으로, 로그온과 복제 트래픽을 조절해요.
- 글로벌 카탈로그는 포리스트 전체 개체의 요약본(포트 3268)이에요. FSMO는 포리스트 2개(스키마, 도메인 명명) + 도메인 3개(RID, PDC, 인프라)예요.
- 보안 그룹은 권한용, 배포 그룹은 메일용이에요. 범위는 도메인 로컬·글로벌·유니버설이고, 권한은 AGDLP 순서로 연결해요.
- GPO 적용 순서는 로컬 → 사이트 → 도메인 → OU이고, 나중에 적용된 것이 우선해요. 강제는 상속 차단보다 우선해요.
- `gpupdate /force`는 정책을 즉시 다시 적용하고, `gpresult /r`은 적용 결과를 보여 줘요.
- 도메인 기본 인증은 Kerberos(포트 88, 시간 차 5분 제한)이고, AD는 DNS의 SRV 레코드로 DC를 찾아요.

## 스스로 확인하기

**1.** 사용자 '민수'가 속한 OU, 도메인, 사이트에 각각 GPO가 연결되어 있고 같은 항목을 서로 다르게 설정했다. 강제나 상속 차단 설정이 없을 때 민수에게 최종 적용되는 것은?
① 로컬 정책 ② 사이트 GPO ③ 도메인 GPO ④ OU GPO

> [!ANSWER]
> 정답: ④
> GPO는 로컬 → 사이트 → 도메인 → OU 순서로 적용되고, 나중에 적용된 OU GPO의 설정이 최종적으로 우선해요.

**2.** 다음 FSMO 역할 중 포리스트 전체에 하나만 존재하는 것은?
① RID 마스터 ② PDC 에뮬레이터 ③ 스키마 마스터 ④ 인프라 마스터

> [!ANSWER]
> 정답: ③
> 포리스트당 하나인 역할은 스키마 마스터와 도메인 명명 마스터예요. 나머지 셋은 도메인마다 하나씩 있어요.

**3.** AGDLP 원칙에 따라 공유 폴더 권한을 줄 때, 실제로 폴더의 권한 목록에 등록하는 대상은?
① 사용자 계정 ② 글로벌 그룹 ③ 도메인 로컬 그룹 ④ OU

> [!ANSWER]
> 정답: ③
> 계정 → 글로벌 그룹 → 도메인 로컬 그룹 순서로 넣고, 권한은 도메인 로컬 그룹에 줘요. OU에는 권한을 줄 수 없어요.

**4.** 도메인에 가입한 PC가 도메인 컨트롤러의 위치를 찾을 때 DNS에서 조회하는 레코드는?
① MX ② PTR ③ SRV ④ CNAME

> [!ANSWER]
> 정답: ③
> SRV 레코드는 특정 서비스(LDAP, Kerberos 등)를 제공하는 서버의 위치를 알려 줘요. 그래서 PC의 DNS 서버는 AD DNS 서버로 설정해야 해요.

**5.** 지사 PC의 시계가 도메인 컨트롤러보다 15분 빠르게 맞춰져 있어 도메인 로그온이 실패했다. 이와 가장 관련 깊은 인증 프로토콜은?
① Kerberos ② LDAP ③ DHCP ④ SMB

> [!ANSWER]
> 정답: ①
> Kerberos는 티켓에 시간 정보를 담아 재사용 공격을 막기 때문에, 기본 5분 넘게 시간이 어긋나면 인증이 실패해요.
