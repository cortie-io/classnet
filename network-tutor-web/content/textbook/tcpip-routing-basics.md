택배 물류센터는 송장에 적힌 주소만 보고 상자를 다음 거점으로 넘겨요. 라우터(Router)도 똑같이 패킷의 목적지 IP 주소를 보고 "다음에 누구에게 넘길지"만 정하고, 이런 판단이 이어져서 패킷이 지구 반대편까지 도착해요. 이 단원에서는 라우터가 이 판단에 쓰는 라우팅 테이블을 읽는 법과, 갈 수 있는 경로가 여럿일 때 하나를 고르는 규칙을 배워요.

> [!GOAL]
> - 라우터가 목적지 주소를 보고 다음 홉을 정하는 과정을 설명할 수 있어요.
> - 라우팅 테이블의 각 열을 읽고, 최장 일치 규칙으로 경로를 골라낼 수 있어요.
> - 정적 경로, 기본 경로(0.0.0.0/0), 호스트의 기본 게이트웨이를 구분할 수 있어요.
> - 메트릭과 관리 거리의 차이를 알고, 시스코 기준 기본 관리 거리 값을 기억해요.

## 라우터는 무엇을 결정하나

### 라우팅의 정의
라우팅(Routing)은 패킷이 목적지 네트워크까지 갈 경로를 고르고, 그쪽으로 패킷을 내보내는 일이에요. OSI 3계층(네트워크 계층)이 맡는 기능이고, 이 일을 전문으로 하는 장비가 라우터예요.

라우터는 목적지까지 가는 전체 경로를 알 필요가 없어요. 자기 다음에 넘겨줄 라우터 하나만 정하면, 그 라우터가 또 그다음을 정해요. 이렇게 한 구간씩 넘겨주는 방식을 홉 단위 전달(Hop-by-Hop)이라고 하고, 라우터 하나를 지나는 것을 한 홉(Hop)이라고 세요.

### 라우터가 하는 두 가지 일

| 하는 일 | 내용 | 물류센터 비유 |
|---|---|---|
| 경로 결정(Path Determination) | 어느 네트워크로 가려면 어디로 보내야 하는지 알아내서 라우팅 테이블에 적어 둠 | 노선표 만들기 |
| 전달(Forwarding) | 들어온 패킷의 목적지를 테이블과 비교해 알맞은 인터페이스로 내보냄 | 상자를 노선표대로 트럭에 싣기 |

패킷이 라우터를 하나 지날 때마다 이런 일이 일어나요.
- 출발지·목적지 IP 주소는 그대로예요(NAT 같은 주소 변환이 없다면).
- TTL이 1 줄고, 0이 되면 패킷을 버려요. 자세한 내용은 [IP 패킷의 구조와 단편화](/textbook/tcpip-ip-header)에서 다뤘어요.
- 2계층 헤더(출발지·목적지 MAC 주소)는 구간마다 새로 붙어요.
- 테이블에 맞는 경로가 하나도 없으면 패킷을 버리고, 출발지에 ICMP 목적지 도달 불가(Destination Unreachable) 메시지를 보내요.

> [!WARNING]
> "라우터를 지나면 IP 주소가 바뀐다"는 틀린 말이에요. 구간마다 바뀌는 것은 MAC 주소이고, IP 주소는 주소 변환이 없는 한 끝까지 그대로예요.

## 라우팅 테이블 읽기

### 테이블의 열
라우팅 테이블(Routing Table)은 "이 목적지로 가려면 이쪽으로"라는 줄을 모아 둔 표예요. 줄 하나하나를 경로(Route)라고 불러요.

| 열 | 뜻 |
|---|---|
| 목적지(Destination) | 도달하려는 네트워크의 주소 |
| 서브넷 마스크 또는 프리픽스 길이 | 목적지 주소의 앞 몇 비트가 네트워크 부분인지 (예: 255.255.255.0 = /24) |
| 다음 홉(Next Hop) | 패킷을 넘겨줄 이웃 라우터의 IP 주소. 직접 연결된 네트워크면 없음 |
| 출구 인터페이스(Interface) | 패킷을 내보낼 라우터의 포트 |
| 메트릭(Metric) | 그 경로의 거리나 비용. 작을수록 좋은 경로 |
| 출처(Source) | 경로를 어떻게 알게 됐는지: 직접 연결, 정적, OSPF, RIP 등 |

### 예제 라우터 R1
아래처럼 연결된 라우터 R1이 있다고 해 봐요. R2의 주소는 10.0.12.2, R3은 10.0.13.2, ISP 쪽 라우터는 203.0.113.1이에요.

```text
               192.168.10.0/24 (사내 LAN)
                        |
                      G0/0
  [R2]---------- G0/1 [R1] G0/3 ----------[ISP]
    10.0.12.0/30      G0/2      203.0.113.0/30
                        |
                   10.0.13.0/30
                        |
                      [R3]
```

R1의 라우팅 테이블은 다음과 같아요.

| 목적지 | 다음 홉 | 출구 인터페이스 | 출처 | 메트릭 |
|---|---|---|---|---|
| 192.168.10.0/24 | 직접 연결 | G0/0 | 직접 연결 | 0 |
| 10.0.12.0/30 | 직접 연결 | G0/1 | 직접 연결 | 0 |
| 10.0.13.0/30 | 직접 연결 | G0/2 | 직접 연결 | 0 |
| 203.0.113.0/30 | 직접 연결 | G0/3 | 직접 연결 | 0 |
| 172.16.0.0/16 | 10.0.12.2 | G0/1 | OSPF | 20 |
| 172.16.32.0/20 | 10.0.13.2 | G0/2 | OSPF | 30 |
| 0.0.0.0/0 | 203.0.113.1 | G0/3 | 정적 | 0 |

- 직접 연결(Connected) 경로는 인터페이스에 IP 주소를 설정하고 켜기만 하면 저절로 생겨요.
- 172.16으로 시작하는 두 줄은 "172.16.0.0/16 대역은 대부분 R2 뒤에 있지만, 그중 172.16.32.0/20 부분만은 R3 뒤에 있다"는 뜻이에요.

### 최장 일치 규칙
목적지 주소 하나가 여러 줄과 동시에 맞을 수 있어요. 이때 라우터는 프리픽스가 가장 긴, 즉 가장 구체적인 줄을 골라요. 이것을 최장 일치(Longest Prefix Match) 규칙이라고 해요.

길 안내판에 비유하면, "서울 방면"이라는 안내판과 "서울 마포구 방면"이라는 안내판이 둘 다 맞을 때 더 자세한 쪽을 따르는 것과 같아요.

어떤 줄과 "일치한다"는 것은 목적지 IP와 그 줄의 마스크를 AND 연산한 결과가 그 줄의 목적지 네트워크 주소와 같다는 뜻이에요. 마스크가 /8, /16, /24처럼 옥텟 경계에 딱 맞으면 앞쪽 옥텟만 비교하면 되고, 그렇지 않으면 경계에 걸친 옥텟을 2진수로 바꿔 앞 비트를 비교해요.

### 단계별 예제
**예제 1. 목적지 172.16.45.10**
1. 172.16.0.0/16: 앞 두 옥텟이 172.16으로 같아요 → 일치
2. 172.16.32.0/20: /20은 셋째 옥텟의 앞 4비트까지 비교해요.
   - 45 = 0010 1101 → 앞 4비트 0010
   - 32 = 0010 0000 → 앞 4비트 0010
   - 같으므로 일치예요. (172.16.32.0/20의 범위는 172.16.32.0 ~ 172.16.47.255)
3. 0.0.0.0/0: 모든 주소와 일치
4. 일치한 세 줄 중 가장 긴 /20을 골라요 → 다음 홉 10.0.13.2(R3), G0/2로 내보내요.

**예제 2. 목적지 172.16.50.1**
1. /16: 일치
2. /20: 50 = 0011 0010 → 앞 4비트 0011, 32의 0010과 달라요 → 불일치 (50은 32~47 범위 밖)
3. /0: 일치
4. 가장 긴 /16을 골라요 → 다음 홉 10.0.12.2(R2)

**예제 3. 목적지 192.168.10.77**
- 직접 연결된 192.168.10.0/24와 일치해요(/0도 일치하지만 /24가 더 길어요). 다음 홉 없이 G0/0으로 바로 내보내요. 이때 R1은 ARP로 192.168.10.77의 MAC 주소를 알아내 그 호스트에게 직접 프레임을 보내요.

**예제 4. 목적지 198.51.100.9**
- 0.0.0.0/0만 일치해요 → 203.0.113.1(ISP)로 보내요.

> [!EXAM]
> 경로 몇 줄을 보여 주고 "목적지가 ○○인 패킷은 어느 인터페이스로 나가는가"를 묻는 문제가 나와요. 순서는 언제나 (1) 일치하는 줄을 모두 찾고 (2) 그중 프리픽스가 가장 긴 줄을 고르기예요. 이 단계에서는 메트릭이나 관리 거리를 따지지 않아요.

### 장비와 PC에서 테이블 보기
시스코 IOS 계열 예시예요. 실제 출력에서 일부 줄을 빼고 단순하게 정리했어요.

```text
R1# show ip route
Gateway of last resort is 203.0.113.1 to network 0.0.0.0

S*    0.0.0.0/0 [1/0] via 203.0.113.1
O     172.16.0.0/16 [110/20] via 10.0.12.2, GigabitEthernet0/1
O     172.16.32.0/20 [110/30] via 10.0.13.2, GigabitEthernet0/2
C     192.168.10.0/24 is directly connected, GigabitEthernet0/0
L     192.168.10.1/32 is directly connected, GigabitEthernet0/0
```

- 맨 앞 글자는 출처예요: C 직접 연결, L 라우터 자기 인터페이스 주소, S 정적, R RIP, O OSPF, D EIGRP, B BGP. `*`는 기본 경로 후보라는 표시예요.
- `[110/20]`은 `[관리 거리/메트릭]`이에요. 관리 거리는 이 단원 뒤쪽에서 배워요.
- Gateway of last resort는 기본 경로가 가리키는 곳이에요.

PC에도 라우팅 테이블이 있어요.

```bash
ip route
```

```text
default via 192.168.10.1 dev eth0
192.168.10.0/24 dev eth0 proto kernel scope link src 192.168.10.23
```

리눅스에서는 `ip route`(옛 명령은 `route -n`), Windows에서는 `route print` 또는 `netstat -r`로 봐요. 리눅스 출력의 `default` 줄, Windows 출력에서 네트워크 대상과 넷마스크가 모두 0.0.0.0인 줄에 적힌 게이트웨이가 그 PC의 기본 게이트웨이예요.

```powershell
route print -4
```

## 정적 경로와 기본 경로

### 정적 라우팅과 동적 라우팅
정적 라우팅(Static Routing)은 관리자가 경로를 손으로 입력하는 방식이고, 동적 라우팅(Dynamic Routing)은 라우터끼리 라우팅 프로토콜로 정보를 주고받아 테이블을 자동으로 만드는 방식이에요. 동적 라우팅은 다음 단원 [동적 라우팅 프로토콜](/textbook/tcpip-routing-protocols)에서 자세히 배워요.

| 항목 | 정적 라우팅 | 동적 라우팅 |
|---|---|---|
| 경로 입력 | 관리자가 직접 | 라우팅 프로토콜이 자동으로 |
| 망 변화·장애 대응 | 사람이 고칠 때까지 그대로 | 스스로 다른 경로를 계산 |
| 라우터 부담(CPU·메모리·대역폭) | 거의 없음 | 정보 교환과 계산에 자원 사용 |
| 보안 | 경로 정보를 주고받지 않아 유리 | 인증 등 추가 설정 필요 |
| 알맞은 곳 | 작은 망, 출구가 하나뿐인 망, 백업 경로 | 크고 자주 바뀌는 망 |

시스코 IOS 계열 예시로, R1에 172.16.32.0/20 경로를 정적으로 넣는다면 이렇게 써요. 형식은 `ip route <목적지 네트워크> <서브넷 마스크> <다음 홉 주소 또는 출구 인터페이스>`예요.

```text
R1(config)# ip route 172.16.32.0 255.255.240.0 10.0.13.2
```

장비 설정은 [라우터·스위치 기본 설정](/textbook/dev-router-config)에서 더 연습해요.

### 기본 경로
기본 경로(Default Route)는 "테이블에 없는 나머지 모든 목적지는 이쪽으로"라는 경로예요. 목적지 주소와 마스크를 모두 0으로 써서 0.0.0.0/0(마스크 0.0.0.0)으로 나타내요. 프리픽스 길이가 0이라 모든 주소와 일치하지만 가장 짧기 때문에, 더 구체적인 경로가 하나도 없을 때만 쓰여요. 시스코 장비는 이 경로가 가리키는 곳을 최후의 게이트웨이(Gateway of Last Resort)라고 표시해요.

바깥으로 나가는 길이 하나뿐인 네트워크를 스텁 네트워크(Stub Network)라고 해요. 인터넷에 붙은 작은 회사가 대표적인데, 인터넷의 수많은 경로를 다 알 필요 없이 ISP 쪽으로 향하는 기본 경로 한 줄이면 충분해요.

```text
R1(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1
```

> [!TIP]
> 0.0.0.0/0은 "어떤 주소든 다 맞는 길"이에요. "갈 곳을 모르겠으면 일단 큰길(ISP)로 나가세요"라는 안내판이라고 기억해요.

### 호스트의 기본 게이트웨이
PC나 서버 같은 호스트도 패킷을 보내기 전에 작은 라우팅 판단을 해요. 목적지가 나와 같은 네트워크에 있는지 확인하는 거예요.

1. 내 IP AND 내 서브넷 마스크 → 내 네트워크 주소
2. 목적지 IP AND 내 서브넷 마스크 → 목적지의 네트워크 주소
3. 둘이 같으면 ARP로 목적지의 MAC 주소를 알아내 직접 보내요.
4. 다르면 기본 게이트웨이(Default Gateway)로 보내요.

기본 게이트웨이는 같은 LAN에 붙어 있는 라우터 인터페이스의 IP 주소예요. 호스트에게는 기본 경로와 같은 역할을 해요.

예를 들어 PC가 192.168.10.23/24이고 기본 게이트웨이가 192.168.10.1이라면,
- 192.168.10.77로 보낼 때: 둘 다 192.168.10.0 네트워크 → 직접 전달
- 198.51.100.9로 보낼 때: 198.51.100.0은 192.168.10.0과 다름 → 192.168.10.1로 전달

게이트웨이로 보낼 때 이더넷 프레임의 목적지 MAC 주소는 게이트웨이(라우터)의 MAC 주소이고, 패킷의 목적지 IP 주소는 최종 목적지인 198.51.100.9 그대로예요.

> [!EXAM]
> - "같은 네트워크의 PC와는 통신되는데 외부 네트워크와는 안 된다"면 기본 게이트웨이가 비어 있거나 틀렸을 가능성이 커요.
> - 기본 게이트웨이는 반드시 호스트와 같은 서브넷에 있는 주소여야 해요.
> - 다른 네트워크로 보낼 때 프레임의 목적지 MAC은 게이트웨이의 MAC이에요.

## 메트릭과 관리 거리

### 메트릭
메트릭(Metric)은 같은 라우팅 프로토콜 안에서, 같은 목적지로 가는 여러 경로 중 어느 쪽이 더 좋은지 비교하는 숫자예요. 작을수록 좋은 경로예요. 무엇으로 계산하는지는 프로토콜마다 달라요.

| 메트릭 요소 | 뜻 | 쓰는 프로토콜 예 |
|---|---|---|
| 홉 수(Hop Count) | 거쳐 가는 라우터의 수 | RIP |
| 비용(Cost) | 대역폭으로 계산하거나 관리자가 정한 값 | OSPF |
| 대역폭(Bandwidth) | 링크의 전송 속도 | EIGRP |
| 지연(Delay) | 링크를 지나는 데 걸리는 시간 | EIGRP |
| 부하(Load)·신뢰성(Reliability) | 링크 사용률, 오류가 적은 정도 | EIGRP (기본 설정에서는 쓰지 않음) |

### 관리 거리
RIP의 "3홉"과 OSPF의 "비용 20"은 단위가 달라서 직접 비교할 수 없어요. 그래서 서로 다른 출처가 같은 목적지를 알려 오면 "어느 출처를 더 믿을지"를 먼저 정해요. 이 신뢰도 값을 관리 거리(AD, Administrative Distance)라고 해요. 0~255 범위이고 작을수록 더 믿어요. 255는 "믿을 수 없음"이라 테이블에 올리지 않아요.

길을 물었더니 내비게이션은 "12분", 지나가던 사람은 "세 블록"이라고 답했다고 해 봐요. 단위가 달라 어느 쪽이 가까운지 비교할 수 없으니, 평소 더 믿는 쪽의 말을 따르게 되죠. 관리 거리가 바로 이 "평소 믿는 정도"예요.

시스코 기준 기본 관리 거리는 다음과 같아요.

| 경로 출처 | 기본 관리 거리 |
|---|---|
| 직접 연결(Connected) | 0 |
| 정적 경로(Static) | 1 |
| eBGP(외부 BGP) | 20 |
| EIGRP(내부) | 90 |
| OSPF | 110 |
| IS-IS | 115 |
| RIP | 120 |
| EIGRP(외부) | 170 |
| iBGP(내부 BGP) | 200 |
| 알 수 없음 | 255 |

> [!TIP]
> 먼저 "0, 1, 20, 90, 110, 120"을 순서대로 외워요. 직접 연결 → 정적 → eBGP → EIGRP → OSPF → RIP. 라우터에 직접 붙은 네트워크와 관리자가 손으로 넣은 정적 경로가 가장 믿을 만하고, 동적 프로토콜 중에서는 RIP가 가장 뒤라고 기억하면 돼요.

> [!NOTE]
> 관리 거리는 시스코 장비의 용어이고 위 값도 시스코 기준이에요. 다른 제조사는 '우선순위(Preference)' 같은 다른 이름과 다른 값을 쓰기도 해요.

### 경로를 고르는 순서
1. **최장 일치**: 프리픽스가 가장 긴 경로가 이겨요.
2. **관리 거리**: 프리픽스 길이까지 같은 경로끼리는 관리 거리가 작은 출처가 이겨요.
3. **메트릭**: 같은 프로토콜이 알려 준 경로끼리는 메트릭이 작은 쪽이 이겨요.
4. 메트릭까지 같으면 여러 경로를 함께 써서 트래픽을 나눠요. 이것을 동일 비용 다중 경로(ECMP, Equal-Cost Multi-Path)라고 해요.

**예제.** R1이 다음 네 가지 경로 정보를 받았어요.

| 출처 | 경로 | 관리 거리/메트릭 |
|---|---|---|
| RIP | 10.5.0.0/16 | 120/2 |
| OSPF | 10.5.0.0/16 | 110/50 |
| 정적 | 10.5.0.0/16 | 1/0 |
| RIP | 10.5.7.0/24 | 120/3 |

- 10.5.0.0/16 세 개 중에는 관리 거리가 가장 작은 정적 경로만 테이블에 올라가요. 메트릭 2와 50은 서로 다른 프로토콜의 값이라 비교하지 않아요.
- 10.5.7.0/24는 프리픽스가 다른 별개의 경로라서 그대로 올라가요.
- 목적지 10.5.7.20 → /16(정적)과 /24(RIP)에 모두 일치 → 최장 일치로 RIP의 /24가 선택돼요. 관리 거리가 더 큰데도 이겨요.
- 목적지 10.5.9.1 → /16에만 일치 → 정적 경로로 나가요.

> [!WARNING]
> 관리 거리는 프리픽스가 똑같은 경로끼리 비교할 때만 써요. 더 긴(구체적인) 경로는 관리 거리가 커도 먼저 선택돼요. 메트릭은 같은 프로토콜 안에서만 비교해요.

### 플로팅 정적 경로
정적 경로의 관리 거리를 일부러 크게 주어 백업 경로로 쓰는 방법도 있어요. 예를 들어 주 경로를 OSPF(110)로 배우고 있을 때 관리 거리 130짜리 정적 경로를 넣어 두면, 평소에는 OSPF 경로에 밀려 테이블에 올라가지 않다가 OSPF 경로가 사라지면 그때 테이블에 떠올라요. 그래서 플로팅 정적 경로(Floating Static Route)라고 해요. 아래는 시스코 IOS 계열 예시로, 다른 ISP(198.51.100.1)로 향하는 백업 기본 경로를 관리 거리 130으로 넣는 명령이에요. 명령 끝의 숫자가 관리 거리예요.

```text
R1(config)# ip route 0.0.0.0 0.0.0.0 198.51.100.1 130
```

## 핵심 정리
- 라우팅은 목적지 IP를 보고 다음 홉과 출구 인터페이스를 정하는 3계층 기능이에요. IP 주소는 유지되고, MAC 주소는 구간마다 바뀌어요.
- 라우팅 테이블의 열: 목적지, 마스크(프리픽스 길이), 다음 홉, 출구 인터페이스, 메트릭, 출처.
- 여러 경로가 일치하면 프리픽스가 가장 긴 경로를 고르는 최장 일치 규칙이 가장 먼저예요.
- 정적 경로는 관리자가 직접 넣어요. 부담은 적지만 장애가 나도 스스로 우회하지 못해요.
- 기본 경로 0.0.0.0/0은 일치하는 경로가 없을 때 쓰는 마지막 길(Gateway of Last Resort)이에요.
- 호스트는 목적지가 다른 네트워크면 기본 게이트웨이로 보내요. 기본 게이트웨이는 같은 서브넷에 있어야 해요.
- 메트릭은 같은 프로토콜 안에서 경로를 비교하는 값, 관리 거리는 서로 다른 출처 사이의 신뢰도예요. 둘 다 작을수록 우선이에요.
- 시스코 기준 관리 거리: 직접 연결 0, 정적 1, eBGP 20, EIGRP 90, OSPF 110, RIP 120.

## 스스로 확인하기

**1.** 라우터에 다음 경로가 있어요. 목적지가 10.1.6.9인 패킷은 어느 경로로 나갈까요?
① 10.0.0.0/8 → 경로 A ② 10.1.0.0/16 → 경로 B ③ 10.1.4.0/22 → 경로 C ④ 0.0.0.0/0 → 경로 D

> [!ANSWER]
> 정답: ③
> /22는 셋째 옥텟의 앞 6비트를 비교해요. 4 = 000001 00, 6 = 000001 10으로 앞 6비트가 같아 10.1.4.0/22(10.1.4.0~10.1.7.255)에 속하고, 일치하는 네 경로 중 가장 길어요.

**2.** 같은 목적지 192.168.50.0/24를 RIP, OSPF, EIGRP가 모두 알려 왔어요. 시스코 라우터의 기본 설정이라면 어느 경로가 라우팅 테이블에 올라갈까요?
① RIP 경로 ② OSPF 경로 ③ EIGRP 경로 ④ 메트릭 숫자가 가장 작은 경로

> [!ANSWER]
> 정답: ③
> 프리픽스가 같으므로 관리 거리로 비교해요. EIGRP 90 < OSPF 110 < RIP 120이라 EIGRP 경로가 선택되고, 서로 다른 프로토콜의 메트릭은 비교하지 않아요.

**3.** 민수의 PC(192.168.20.15/24)는 같은 사무실 프린터(192.168.20.40)와는 통신이 잘 되는데, 외부 서버 198.51.100.10으로 ping을 보내면 응답이 없어요. 가장 먼저 확인할 설정은 무엇일까요?
① 서브넷 마스크 ② 기본 게이트웨이 ③ PC의 MAC 주소 ④ 프린터의 IP 주소

> [!ANSWER]
> 정답: ②
> 같은 네트워크와는 통신되므로 IP 주소와 마스크는 대체로 정상이에요. 다른 네트워크로 나가는 길인 기본 게이트웨이가 비었거나 틀렸을 가능성이 가장 커요.

**4.** 정적 라우팅에 대한 설명으로 옳지 않은 것은?
① 관리자가 경로를 직접 입력한다. ② 라우터끼리 경로 정보를 주고받지 않아 대역폭 부담이 적다. ③ 링크에 장애가 나면 스스로 다른 경로를 계산해 우회한다. ④ 출구가 하나뿐인 스텁 네트워크에 알맞다.

> [!ANSWER]
> 정답: ③
> 장애가 났을 때 스스로 새 경로를 계산하는 것은 동적 라우팅의 특징이에요. 정적 경로는 관리자가 고치기 전까지 그대로예요.

**5.** 기본 경로를 프리픽스 표기(CIDR)로 쓰면 어떻게 될까요?

> [!ANSWER]
> 정답: 0.0.0.0/0
> 목적지와 마스크가 모두 0.0.0.0이라 모든 주소와 일치하지만, 프리픽스가 가장 짧아서 다른 일치 경로가 없을 때만 쓰여요.
