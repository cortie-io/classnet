이 단원에서는 3계층 이상에서 일하는 장비를 다뤄요. 서로 다른 네트워크를 이어 주는 라우터가 안에 어떤 부품을 가지고 있고 패킷을 어떻게 넘기는지 살펴본 뒤, L3·L4·L7 스위치와 로드 밸런서, 게이트웨이와 프록시까지 정리해요. "장비가 패킷의 어디까지 들여다보는가"가 이 단원을 관통하는 질문이에요.

> [!GOAL]
> - 라우터의 주요 기능과 패킷 전달 과정을 설명할 수 있다.
> - 라우터 내부 메모리(ROM·플래시·NVRAM·RAM)에 각각 무엇이 저장되는지 구분할 수 있다.
> - L3·L4·L7 스위치와 라우터의 차이를 판단 기준으로 비교할 수 있다.
> - 로드 밸런싱 알고리즘과 게이트웨이·프록시의 역할을 설명할 수 있다.

## 라우터가 하는 일

**라우터**(Router)는 서로 다른 네트워크를 연결하고, **IP 주소를 보고 패킷이 갈 길을 정하는** 3계층(네트워크 계층) 장비예요. 스위치가 아파트 단지 안에서 택배를 나르는 경비원이라면, 라우터는 도시와 도시를 잇는 물류 센터예요.

| 기능 | 설명 |
|---|---|
| 경로 결정(Path Determination) | 라우팅 테이블을 보고 목적지까지 가장 좋은 경로를 고름 |
| 패킷 전달(Packet Forwarding) | 고른 인터페이스로 패킷을 실제로 내보냄(스위칭이라고도 함) |
| 브로드캐스트 도메인 분리 | 브로드캐스트를 다른 인터페이스로 넘기지 않음 |
| 이종 네트워크 연결 | LAN과 WAN처럼 서로 다른 매체·프레임 형식을 연결 |
| 부가 기능 | NAT(주소 변환), ACL(접근 제어 목록), QoS, VPN 등 |

라우팅 테이블이 어떻게 만들어지는지는 [라우팅의 원리](/textbook/tcpip-routing-basics)와 [동적 라우팅 프로토콜](/textbook/tcpip-routing-protocols) 단원에서 배워요.

### 패킷 하나가 라우터를 지나는 과정

1. 프레임을 받아 FCS로 오류를 검사하고, 목적지 MAC이 자기 인터페이스 주소인지 확인해요.
2. 2계층 헤더를 벗겨 내고 IP 헤더의 **목적지 IP 주소**를 읽어요.
3. 라우팅 테이블에서 목적지와 **가장 길게 일치하는 경로**(Longest Prefix Match)를 찾아요. 맞는 경로가 없으면 기본 경로를 쓰고, 그것도 없으면 패킷을 버리고 ICMP 목적지 도달 불가 메시지를 보내요.
4. **TTL을 1 줄이고** 헤더 체크섬을 다시 계산해요. TTL이 0이 되면 버리고 출발지에 ICMP 시간 초과 메시지를 보내요.
5. 다음 홉 장치의 MAC 주소를 ARP로 알아내 **새 프레임으로 감싸** 내보내요.

> [!EXAM]
> 패킷이 라우터를 지날 때 **IP 주소는 그대로**(NAT가 없을 때), **MAC 주소는 구간마다 바뀐다**는 점을 자주 물어요. IP는 최종 목적지, MAC은 바로 다음 장치를 가리키기 때문이에요.

## 라우터의 내부 구성 요소

라우터도 CPU와 메모리를 가진 작은 컴퓨터예요. 시험은 시스코 라우터를 기준으로 **어느 메모리에 무엇이 저장되는지**를 많이 물어요.

| 구성 요소 | 전원을 끄면 | 저장하는 것 |
|---|---|---|
| CPU | — | 명령 실행, 라우팅 계산 |
| ROM | 유지(비휘발성) | POST(자체 진단), 부트스트랩 프로그램, ROMMON(비상용 최소 운영 환경) |
| 플래시 메모리(Flash) | 유지(비휘발성) | **운영체제 IOS 이미지** |
| NVRAM | 유지(비휘발성) | **startup-config**(부팅할 때 읽는 저장된 설정), 설정 레지스터 값 |
| RAM | 사라짐(휘발성) | **running-config**(지금 동작 중인 설정), 라우팅 테이블, ARP 캐시, 패킷 버퍼, 실행 중인 IOS |

관리자가 명령을 입력하면 **RAM의 running-config만 바뀌어요.** 저장하지 않고 전원을 끄면 그 설정은 사라지므로, NVRAM의 startup-config로 복사해 둬야 해요. 저장 명령은 [라우터·스위치 기본 설정](/textbook/dev-router-config) 단원에서 배워요.

> [!TIP]
> "**롬은 부팅, 플래시는 OS, 엔브이램은 저장된 설정, 램은 지금 설정**"으로 외우세요. NVRAM의 NV는 Non-Volatile(비휘발성)이라는 뜻이라 이름에 힌트가 있어요.

### 부팅 순서

1. **POST**: ROM에 있는 자체 진단으로 하드웨어를 점검해요.
2. **부트스트랩 실행**: ROM의 부트스트랩 프로그램이 IOS를 찾아요.
3. **IOS 적재**: 보통 플래시에서 IOS를 찾아 RAM으로 올려요. 플래시에 없으면 TFTP 서버에서 찾고, 그래도 없으면 ROMMON으로 들어가요.
4. **설정 적재**: NVRAM의 startup-config를 RAM으로 불러와 running-config로 써요. 저장된 설정이 없으면 대화형 **초기 설정 모드**(Setup Mode)로 들어가요.

## 라우터의 인터페이스

| 인터페이스 | 용도 |
|---|---|
| LAN 인터페이스 | 이더넷(FastEthernet, GigabitEthernet 등). 내부 네트워크 연결 |
| WAN 인터페이스 | 시리얼(Serial) 등. 전용 회선처럼 멀리 떨어진 네트워크 연결 |
| 콘솔 포트(Console) | 관리자 PC를 직접 연결해 처음 설정하거나 복구할 때 사용 |
| AUX 포트 | 모뎀을 연결해 원격에서 관리할 때 사용(보조 포트) |

- 인터페이스 이름은 종류와 위치 번호로 붙여요. 예: `GigabitEthernet0/0`(슬롯 0의 포트 0).
- 시리얼 링크에서는 한쪽이 **DCE**(클럭 신호를 주는 쪽), 다른 쪽이 **DTE**(클럭을 받는 쪽)가 되며, 실습 환경에서는 DCE 쪽에 클럭 속도를 설정해야 해요.
- 콘솔·AUX처럼 데이터망과 별도로 관리하는 경로를 **대역 외 관리**(Out-of-Band Management)라고 하고, 텔넷·SSH처럼 데이터망을 통해 관리하는 것을 **대역 내 관리**(In-Band)라고 해요.

## 스위치의 계층별 진화 — L3·L4·L7

스위치 이름 앞의 숫자는 **판단할 때 들여다보는 OSI 계층**을 뜻해요.

| 장비 | 판단 기준 | 대표 용도 |
|---|---|---|
| L2 스위치 | 목적지 MAC 주소 | 같은 네트워크 안의 프레임 전달 |
| L3 스위치 | 목적지 IP 주소 | VLAN 간 라우팅, 내부망 고속 라우팅 |
| L4 스위치 | IP 주소 + TCP/UDP 포트 번호 | 서버 부하 분산(로드 밸런싱) |
| L7 스위치 | 응용 계층 내용(URL, HTTP 헤더, 쿠키 등) | 내용 기반 분산, 콘텐츠 필터링 |

### L3 스위치와 라우터

둘 다 IP로 라우팅하지만 쓰임새가 달라요.

| 구분 | L3 스위치 | 라우터 |
|---|---|---|
| 처리 방식 | 전용 하드웨어(ASIC), 매우 빠름 | 소프트웨어 비중이 큼(고급 기종은 하드웨어 가속) |
| 포트 | 이더넷 포트가 많음 | 포트 수는 적고 WAN 인터페이스를 다양하게 지원 |
| 주 용도 | 건물 내부망의 VLAN 간 라우팅 | 인터넷·지사 연결, NAT·VPN 같은 경계 기능 |

### L4 스위치

**L4 스위치**는 IP 주소에 더해 **TCP/UDP 포트 번호**까지 보고 트래픽을 나눠요. 대표 용도는 **서버 부하 분산**이에요. 웹 서버 여러 대 앞에 L4 스위치를 두고 **가상 IP(VIP)** 하나를 외부에 알려 주면, 사용자는 그 주소로 접속하고 L4 스위치가 실제 서버들에 요청을 골고루 나눠 줘요. 포트 80·443은 웹 서버 묶음으로, 포트 25는 메일 서버로 보내는 식의 구분도 할 수 있어요.

### L7 스위치

**L7 스위치**는 패킷의 데이터 내용, 즉 응용 계층 정보까지 들여다봐요. 예를 들어 같은 웹 사이트라도 URL이 `/images/`로 시작하면 이미지 서버로, `/api/`로 시작하면 API 서버로 보낼 수 있어요. 쿠키를 보고 같은 사용자를 같은 서버로 묶거나, 특정 문자열이 든 악성 요청을 걸러 내는 데도 써요.

## 로드 밸런서와 분산 알고리즘

**로드 밸런서**(Load Balancer)는 요청을 여러 서버에 나눠 한 서버에 부하가 몰리지 않게 하는 장치예요. L4·L7 스위치가 이 역할을 하고, 소프트웨어로 구현하기도 해요. 주기적으로 서버 상태를 점검(**헬스 체크**, Health Check)해서 응답이 없는 서버에는 요청을 보내지 않아요.

| 알고리즘 | 동작 | 어울리는 상황 |
|---|---|---|
| 라운드 로빈(Round Robin) | 서버에 차례대로 하나씩 돌아가며 배정 | 서버 성능이 비슷할 때 |
| 가중치 라운드 로빈(Weighted RR) | 서버마다 정한 비율대로 배정 | 서버 성능이 서로 다를 때 |
| 최소 연결(Least Connections) | 현재 연결 수가 가장 적은 서버에 배정 | 연결 유지 시간이 들쭉날쭉할 때 |
| 최소 응답 시간(Least Response Time) | 응답이 가장 빠른 서버에 배정 | 서버 상태가 자주 변할 때 |
| 해시(Hash) | 출발지 IP 등을 해시해서 항상 같은 서버로 배정 | 같은 사용자를 같은 서버에 붙여야 할 때 |

같은 사용자의 요청을 계속 같은 서버로 보내는 것을 **세션 유지**(Session Persistence, 스티키 세션)라고 해요. 로그인 정보를 서버마다 따로 저장하는 웹 서비스에 필요해요.

### 계산 예제

서버 A·B·C에 가중치를 5 : 3 : 2로 준 가중치 라운드 로빈에 요청 1,000건이 들어왔어요.

1. 가중치 합: `5 + 3 + 2 = 10`
2. 서버 A: `1,000 × 5/10 = 500건`
3. 서버 B: `1,000 × 3/10 = 300건`
4. 서버 C: `1,000 × 2/10 = 200건`

## 게이트웨이

**게이트웨이**(Gateway)라는 말은 두 가지 뜻으로 쓰여요.

1. **프로토콜 변환 장치**: 서로 **다른 프로토콜**을 쓰는 네트워크를 연결하면서 형식을 변환해 주는 장치예요. 통역사처럼 한쪽 언어를 다른 쪽 언어로 바꿔요. 전화망과 인터넷 전화를 잇는 VoIP 게이트웨이, 서로 다른 메일 시스템을 잇는 메일 게이트웨이가 예예요. 필요하면 OSI 전 계층에 걸쳐 변환하므로, 시험에서는 "**전 계층(주로 상위 계층)에서 동작하는 장비**"로 설명해요.
2. **기본 게이트웨이(Default Gateway)**: TCP/IP 설정에서 쓰는 말로, 자기 네트워크 밖으로 나갈 때 패킷을 넘길 **라우터 인터페이스의 IP 주소**예요.

> [!NOTE]
> 옛 장비 분류에는 **브라우터**(Brouter, Bridge + Router)도 있어요. 라우팅이 가능한 프로토콜은 라우팅하고, 라우팅할 수 없는 프로토콜은 브리지처럼 MAC 주소로 넘기는 장비예요. 이름과 개념 정도만 알아 두세요.

## 프록시 서버

**프록시 서버**(Proxy Server)는 클라이언트와 서버 사이에서 **대신 요청하고 대신 받아 주는** 중계 서버예요.

| 종류 | 위치 | 주요 역할 |
|---|---|---|
| 포워드 프록시(Forward Proxy) | 내부 사용자 쪽 | 자주 보는 웹 페이지 캐싱으로 속도 향상, 유해 사이트 차단, 내부 IP 숨김 |
| 리버스 프록시(Reverse Proxy) | 서버 쪽 | 실제 서버를 숨김, 부하 분산, 암호화(TLS) 처리 대행 |

방화벽의 한 종류인 프록시 방화벽은 [보안 장비](/textbook/dev-security-appliances) 단원에서 다시 만나요.

## 핵심 정리

- 라우터는 **IP 주소**로 경로를 결정하고 패킷을 전달하는 3계층 장비이며, 인터페이스마다 **브로드캐스트 도메인을 나눠요.**
- 라우터를 지날 때 IP 주소는 유지되고(NAT 없을 때), MAC 주소는 구간마다 바뀌며, TTL은 1씩 줄어요.
- ROM = POST·부트스트랩·ROMMON, 플래시 = **IOS**, NVRAM = **startup-config**, RAM = **running-config**·라우팅 테이블(휘발성).
- 부팅 순서: POST → 부트스트랩 → IOS 적재(플래시) → 설정 적재(NVRAM, 없으면 초기 설정 모드).
- 콘솔 포트는 직접 연결 관리, AUX 포트는 모뎀 원격 관리용이에요.
- L3 스위치는 IP, **L4 스위치는 IP + 포트 번호**, **L7 스위치는 URL·쿠키 같은 응용 내용**으로 판단해요.
- 로드 밸런싱 알고리즘: 라운드 로빈(차례로), 가중치 라운드 로빈(비율대로), 최소 연결(연결 수 적은 서버), 해시(같은 사용자 → 같은 서버).
- 게이트웨이는 **서로 다른 프로토콜을 변환**해 연결하는 장치, 프록시는 클라이언트와 서버 사이의 **중계 서버**예요.

**3.** L4 스위치로는 할 수 없지만 L7 스위치로는 할 수 있는 것은?
① TCP 포트 번호에 따라 서버 묶음을 나눈다 ② HTTP 요청의 URL 경로에 따라 서로 다른 서버로 보낸다 ③ 목적지 IP 주소로 라우팅한다 ④ MAC 주소 테이블로 프레임을 전달한다

> [!ANSWER]
> 정답: ②
> URL 경로는 응용 계층의 내용이라 L7 스위치만 볼 수 있어요. 포트 번호까지는 L4 스위치도 판단할 수 있어요.

**4.** NAT를 사용하지 않는 환경에서 패킷이 라우터를 지나 다음 홉으로 갈 때 바뀌는 값은?
① 출발지 IP 주소 ② 목적지 IP 주소 ③ 목적지 MAC 주소 ④ TCP 목적지 포트 번호

> [!ANSWER]
> 정답: ③
> 라우터는 다음 홉 장치의 MAC 주소로 새 프레임을 만들어요. IP 주소와 포트 번호는 NAT가 없다면 그대로예요.

**5.** 서버 X·Y·Z에 가중치를 4 : 1 : 3으로 준 가중치 라운드 로빈 방식에 요청 1,600건이 들어왔다. 서버 Y가 받는 요청 수는?
① 200건 ② 400건 ③ 533건 ④ 800건

> [!ANSWER]
> 정답: ①
> 가중치 합이 4 + 1 + 3 = 8이므로 Y는 1,600 × 1/8 = 200건을 받아요.
